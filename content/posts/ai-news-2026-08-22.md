# 📚 주목 논문

## Demystifying Agent Skills: Why They Work—Until They Don't

- **저자**: Zhiyuan Jiang, Fangrui Huang, Mengdi Wang, Shilong Liu 외 (arXiv 페이지에 소속 미표기)
- **arXiv**: [2608.14036](https://arxiv.org/abs/2608.14036) (cs.AI)
- **핵심 기여**: 스킬이 "언제 돕고, 왜 작동하고, 어디서 깨지는지"를 통제 실험으로 분리해낸 첫 해부 연구.
- **방법**: 여러 벤치마크·하네스·LLM에 걸친 통제 실험에서 8,135개 트라이얼 기록을 정규화하고, 240개 오픈 코딩 기록에서 238개 유효 레이블을 추려 12가지 스킬 사용 모드 분류 체계를 만들었다.
- **결과**: 스킬 성공 사례의 65.7%는 **절차적 앵커링**(흔들리는 행동 궤적을 절차로 고정), 명시적 지식 주입은 4.5%에 불과. 동일 조건 비교에서 Workflow Memory 대비 +6.06점. 스킬 풀이 5→100개로 커지면 실사용 정밀도는 29.6%→3.3%로 급감.
- 🛠 **에이전트 빌더 시사점**: 스킬은 "지식 창고"가 아니라 "행동 안정 장치"다. 많이 쌓는 것보다 적게 유지하고 검색 가능하게 만드는 게 성능에 직결된다.
- **한계**: 깨지기 쉬운 가정, 맞지 않는 컨텍스트, 적응 부족 상황에서는 스킬이 오히려 실패를 유발한다.

![Agent Skills 작동 원리와 스킬 풀 정밀도 급감](/images/ai-news-2026-08-22/skills-anatomy.svg)

*스킬이 성공에 기여한 방식(좌)과 스킬 풀 크기에 따른 실사용 정밀도 급감(우). 수치는 논문 초록 기준. (자체 제작)*

## SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science?

- **저자**: Zhipeng Xu, Jiahao Lu, Xipeng Qiu 외 (OpenMOSS 팀)
- **arXiv**: [2608.19799](https://arxiv.org/abs/2608.19799) (cs.CL)
- **핵심 기여**: 20개 과학 도메인, 98개 리포에서 뽑은 119개 태스크로 만든 리포지토리 수준 과학 소프트웨어 수리 벤치마크.
- **방법**: 태스크를 이슈 기반·전문가 탐색형·엔지니어링 통합의 3가지 패러다임으로 구성하고, 실패 궤적을 정성 분석했다.
- **결과**: 최고 성적인 Claude Code + Opus 5 (max)조차 pass@1 50% 미만. 과학 지식 결핍, 표면적 수리, 수리 범위 미완, 일반화 실패의 4가지 실패 메커니즘이 반복 관찰됐다.
- 🛠 **에이전트 빌더 시사점**: 도메인 힌트를 프롬프트에 넣는다고 무조건 좋아지지 않는다. 잘못 정렬된 가이드는 앵커링을 유발해 오히려 수리를 제약했다 — 도메인 지식 주입도 A/B로 검증할 것.
- **한계**: 119개 태스크로 규모가 작고, 도메인당 태스크 수 편차가 있다.

![SWE-bench Science 구조와 4가지 실패 메커니즘](/images/ai-news-2026-08-22/swe-science.svg)

*벤치마크 구성과 최고 성적, 반복 관찰된 실패 유형 요약. (자체 제작)*

# 🛠 오픈소스 스포트라이트

- **[OpenMOSS/SWE-bench-Science](https://github.com/OpenMOSS/SWE-bench-Science)** — Python 기반 평가 하네스. 위 논문의 공식 구현으로, [HF 데이터셋](https://huggingface.co/datasets/OpenMOSS-Team/SWE-bench-Science)(다운로드 1,431회, 8/20 업데이트 확인)과 [리더보드](https://swescience.github.io)가 함께 공개됐다. 과학·수치 계산 코드가 섞인 사내 리포에서 자기 에이전트의 약점을 미리 재보는 용도로 좋다. (GitHub 스타 수는 이번 실행 환경에서 API 접근이 막혀 미확인)
- **[zz1358m/Agentic-ESOpt](https://github.com/zz1358m/Agentic-ESOpt)** — 진화 전략(ES)으로 장기 에이전트를 역전파 없이 전체 파라미터 파인튜닝하는 공식 코드 ([arXiv 2608.17310](https://arxiv.org/abs/2608.17310), HF 추천 101개). 추론 수준 GPU 메모리만으로 돌아가 RL 학습 스택 없이도 시도해볼 수 있고, 스킬 최적화 같은 프롬프트 공간 진화와 합성 가능하다. 소규모 GPU로 자체 에이전트를 태스크에 맞춰 튜닝하고 싶은 팀에게 실용적 대안. (스타 수 미확인, 동일 사유)

## 🟪 공통 — 스킬 풀 다이어트와 "절차형" 스킬 작성

- **분류**: Context·Eval / [출처](https://arxiv.org/abs/2608.14036)
- 💡 스킬 풀이 커질수록 맞는 스킬을 고르는 검색이 병목이 된다(정밀도 29.6%→3.3%). 스킬의 효용 대부분은 절차 고정에서 나온다.
- 📝 실행 체크리스트:

```text
1. 스킬 인벤토리에서 최근 미사용 스킬 제거 — 풀을 작게 유지
2. 남은 스킬을 "배경 설명" 대신 "1→2→3 단계 절차"로 재작성
3. 스킬 유/무 A/B로 태스크 성공률을 실제로 비교
4. 자주 깨지는 스킬은 가정(경로·버전·환경)을 명시하고 실패 시 폴백 기록
```

- 🎯 `.claude/skills` 또는 자체 스킬 라이브러리가 10개를 넘어가기 시작했다면 지금.
- ⚠️ 논문 수치는 특정 실험 조건 기준 — 자기 하네스에서 재측정 후 적용할 것.
- ⭐ 추천도: 스킬 쓰는 팀이라면 이번 주 최우선 점검 항목.
