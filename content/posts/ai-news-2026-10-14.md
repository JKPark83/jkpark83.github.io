# 📚 주목 논문

## DREAM: 오염된 메모리만 골라서 잊게 하기

- **저자**: Lei Liu, Yunji Liang, Xiaowen Zhang 외 (초록에 소속 미표기)
- **arXiv**: [2610.13267](https://arxiv.org/abs/2610.13267) (cs.AI, 10/9 공개, arXiv API 검증)
- **핵심 기여**: 메모리 포이즈닝을 당한 에이전트에서, 외부 감사 모듈 없이 **에이전트 내재적으로 오염 항목만 '기능적 망각'** 시키는 트레이닝 프리 프레임워크.
- **방법**: ① 섭동을 가해 메모리를 암묵 재활성화 → 악성 기억의 구조적 취약성 노출 ② 활성 패턴 다차원 이상 진단 ③ 유해 기억은 억제, 양성 기억은 강화하는 동적 복구. 신경과학의 "약한 재활성화는 기억을 불안정화한다"는 메커니즘에서 착안.
- **결과(저자 보고)**: 백도어 포이즈닝 공격 성공률 **95% 이상 감소**, 양성 성능 유지. 기존 방어(A-MemGuard) 대비 최대 2.13배 빠르고 토큰 37.7% 절감. 오염된 멀티 에이전트 시스템에서 태스크 성공률 92.96%.
- 🛠 **에이전트 빌더 시사점**: 장기 메모리를 켠 에이전트라면 "한 번 저장된 악성 항목이 계속 소환되는" 문제가 현실입니다. 저장 시 검열만으로는 부족하고, **저장 후에도 재검증·감쇠시키는 메모리 수명 주기**가 필요하다는 방향 제시.
- **한계**: 활성 패턴 접근이 가능한 구성을 전제하므로, 폐쇄형 API 모델 + 외부 벡터 스토어 조합에 바로 이식하기는 어렵습니다.

## SOAP: 실패 로그만 갖고 "어디서부터 틀렸나" 찾기

- **저자**: Do Nguyen-Thanh, Junlin Fang, Bing Li, Zhen Fang, Sean Du (초록에 소속 미표기)
- **arXiv**: [2610.13105](https://arxiv.org/abs/2610.13105) (cs.LG, 10/9 공개, arXiv API 검증)
- **핵심 기여**: 실패한 궤적만 있고 스텝 단위 레이블이 없는 상태에서 **결정적 오류 스텝을 귀속(failure attribution)** 하는 SOAP 프레임워크. LLM 프롬프팅 채점도, 성공 궤적 참조 세트도 필요 없습니다.
- **방법**: LLM 내부 표현으로 스펙트럴 참조 공간을 만들어 스텝별 기본 오류 점수를 매기고, 어텐션 패턴에서 스텝 간 의존성을 뽑아 **하류로 전파된 오류 증거를 상류의 원인 스텝으로 되돌려** 보냅니다.
- **결과(저자 보고)**: 경쟁 베이스라인 대비 귀속 성능 일관 개선. 핵심 통찰은 "뒤쪽 스텝이 오류 신호가 더 강해 보이는 건 **앞의 실수를 상속했기 때문**"이라는 하류 오염 문제의 정식화.
- 🛠 **에이전트 빌더 시사점**: 에이전트 디버깅에서 "마지막에 이상해진 스텝"을 고치는 건 증상 치료일 때가 많습니다. 실패 궤적을 버리지 말고 모아두세요 — 레이블 없이도 원인 분석 자산이 됩니다.
- **한계**: 내부 표현·어텐션 접근이 필요해 오픈 웨이트 모델 중심이며, 귀속 정확도는 과제 유형에 따라 편차가 있습니다.

# 🛠 오픈소스 스포트라이트

- **[mvschwarz/openrig](https://github.com/mvschwarz/openrig)** (TypeScript, Apache-2.0, v0.6.10) — "하네스가 모델을 감싸면, **rig는 하네스들을 감싼다**." Claude Code와 Codex 시트(seat)를 YAML로 한 팀으로 정의하고 `rig up` 한 번에 띄우는 에이전트 팀 런타임입니다. 데몬 + tmux 기반 TUI로 팀을 상시 운영하고, 리드 에이전트(operator)에게 결과만 보고받는 구조. starter(빌더+리뷰어 2석)부터 factory(리드·어드바이저·빌드·QA·디자인·리뷰어 7석)까지 프리셋 팀이 있습니다. 10/13~14에도 커밋이 이어지는 활발한 프로젝트입니다(클론 검증, 스타 수는 세션 API 제한으로 미검증). **활용**: CC와 Codex를 번갈아 띄워 수동으로 조율하고 있다면, 그 운영 루틴을 선언형으로 굳히는 가장 구체적인 레퍼런스.
- **[HKUDS/nanobot](https://github.com/HKUDS/nanobot)** (Python 3.11+, MIT) — LightRAG를 만든 HKUDS의 **퍼스널 AI 어시스턴트 게이트웨이**. WebUI·터미널은 물론 Telegram·Discord·Slack·WeChat·이메일·Linear까지 채널로 연결하고, MCP·셸·웹 검색·cron 자동화·장기 메모리·멀티 에이전트 위임을 작은 코어에 담았습니다. OpenAI 호환 API와 Python SDK로 외부 통합도 됩니다. 10/13~14에도 커밋 활발(클론 검증, 스타 수 미검증). **활용**: "내 에이전트를 메신저에서 쓰고 싶다"는 요구를 채널별 봇 코드 없이 해결하는 자기 호스팅 출발점.

# 🧑‍💻 Codex & Claude Code 실전 팁

![Codex 비동기 압축 vs Claude Code sec-default 고정 변수](/images/ai-news-2026-10-14/tips-card.svg)

*왼쪽: Codex의 백그라운드 컨텍스트 압축 설정. 오른쪽: Claude Code sec-default가 고정하는 코드 로딩 환경변수. (자체 제작)*

**🟩 Codex / Context** — [커밋 669449b (PR #53595, 10/13 머지)](https://github.com/openai/codex/commit/669449b02c4b58de4bcd22485eb60c98a6e38a54)

- 💡 **핵심**: 컨텍스트가 꽉 찬 뒤 멈춰서 압축하는 대신, **창의 65%에 도달하면 백그라운드에서 미리 압축을 시작**하는 `async_compaction` 기능 설정이 들어왔습니다. 같은 날 투기적(speculative) 원격 압축 인프라 커밋들도 함께 머지됐습니다.
- 📝 **방법**: `config.toml`에서 —

```toml
[features.async_compaction]
enabled = true
model_async_compact_threshold_percent = 65  # 1~100, 기본 65
```

  불리언 단축형 `async_compaction = true`도 됩니다. 임계값만 적으면 기능은 켜지지 않는다는 점에 주의.
- 🎯 **언제**: 긴 세션에서 압축 타이밍에 작업 흐름이 끊기는 게 체감될 때.
- ⚠️ **주의**: 기본 꺼짐(opt-in)이고 주변 인프라가 10/13에도 계속 머지 중인 실험 단계 기능입니다. 중요한 세션보다 일상 세션에서 먼저 켜보세요.
- ⭐ **추천도**: 컨텍스트 엔지니어링에 민감한 헤비 유저라면 지금 체험해 볼 가치가 있습니다.

**🟦 Claude Code / Hook·Review** — [커밋 b0b7bed (mods/ 10/13 업데이트)](https://github.com/anthropics/claude-code/commit/b0b7bed9820350bb0942e32c7f00752a99ea3555)

- 💡 **핵심**: 내장 보안 mod인 **sec-default**가 10/13 업데이트로 `env.set` 정책에 **코드 로딩 환경변수 10종 고정(pinning)** 을 추가했습니다. `LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `BASH_ENV`, `NODE_OPTIONS` 같은, 자식 프로세스에 코드를 주입할 수 있는 변수들을 user 티어 플러그인이 설정·해제하지 못하게 막습니다.
- 📝 **방법**: 조직 관리 설정에서 sec-default를 켜두면 적용됩니다. 소스는 레포의 `mods/sec-default/`에 공개돼 있어, `hooks/policy/code-loading-variables.ts`에서 고정 목록을 직접 확인할 수 있습니다.
- 🎯 **언제**: 서드파티 플러그인을 여럿 쓰는 팀 — 조직이 걸어둔 훅 커맨드나 툴 실행이 플러그인의 환경변수 조작으로 바꿔치기되는 경로를 기본값으로 차단하고 싶을 때.
- ⚠️ **주의**: 소스 주석이 명시하듯 이건 **경계(boundary)가 아니라 목록**입니다. 플러그인이 프로세스를 띄울 다른 길은 남아 있으니, 신뢰 안 되는 플러그인은 애초에 설치하지 않는 게 원칙입니다.
- ⭐ **추천도**: 관리 설정을 운영하는 조직이라면 이번 주 점검 목록에 올릴 만합니다.

**🟪 공통 / Debugging** — [SOAP (arXiv 2610.13105)](https://arxiv.org/abs/2610.13105)

- 💡 **핵심**: 실패한 에이전트 런을 디버깅할 때 **가장 이상해 보이는 스텝은 보통 범인이 아니라 피해자**입니다. 오류 신호는 하류로 상속·증폭됩니다.
- 📝 **방법**: 실패 궤적을 지우지 말고 전부 적재하고, 리뷰할 때는 "이상 징후가 처음 나타난 스텝"에서 **의존 관계를 따라 상류로** 거슬러 올라가며 각 스텝의 입력이 이미 오염돼 있었는지 확인합니다.
- 🎯 **언제**: "마지막 툴 호출이 이상했다"고 고쳤는데 같은 실패가 반복될 때.
- ⚠️ **주의**: 상류 탐색도 레이블 없이는 추정입니다. 결정적 스텝 후보를 찾으면 그 지점부터 재실행해 가설을 검증하세요.
