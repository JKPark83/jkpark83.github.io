# 🔥 오늘의 핵심

오늘 신호는 **"컨텍스트는 많이 넣는 게 아니라 잘 관리하는 것"** 으로 모인다. 논문 두 편이 같은 결론을 다른 각도에서 낸다. 하나는 **풀 히스토리를 다 넣는 대신 최근 툴콜 5개만 남기고 압축 요약하면 완료율 71.0% → 91.6%, 토큰은 ~2.7배·시간은 ~2.5배 줄었다.** 다른 하나는 **모델이 자기 컨텍스트에 무감각하다는 점을 지적** — 각 블록의 토큰·나이·사용도를 대시보드로 보여주기만 해도(학습 X) Gemini-3-Flash가 22.7 → 50.7%로 뛴다. 오늘 할 일: (1) 에이전트 루프에서 **오래되고·크고·안 쓰이는 툴 결과부터 prune + 요약**하고, (2) 지운 건 archive로 복구 가능하게 남겨라.

# 📚 주목 논문

## 1) Less Context, Better Agents — 다 넣지 말고, 최근 것만 남기고 요약하라
- **저자**: Abhilasha Lodha 외 (Microsoft, arXiv `2606.10209`, cs.AI, 2026-06-08)
- **핵심**: 엔터프라이즈 툴은 응답이 장황해서 **컨텍스트 오버플로·stale-state 오류·비용 폭증**을 유발한다. 풀 히스토리를 계속 쌓는 게 정답이 아니다.
- **방법(요약)**: MS Dynamics 365의 경비 항목화 태스크(호텔 경비 50개)에서 GPT-5 4가지 구성을 5회 평균 비교 — ① 유저모델 없음 ② 풀 히스토리 ③ **최근 툴콜 5개로 prune** ④ **prune + 자동 요약**.
- **결과(검증됨)**: 완료율이 ① 8.0% → ② 71.0%(1.48M 토큰·14.56h) → ③ 79.0%(535K 토큰·5.39h) → ④ **91.6%**(553K 토큰·5.79h, 금액 항목화 99.64%). 즉 **prune+요약이 풀 히스토리보다 정확도는 높고 토큰은 ~2.7배·시간은 ~2.5배 적다.** Claude Sonnet 4.5 교차검증도 동일 경향.
- **🛠 agent-builder 시사점**: "컨텍스트 창 크니까 다 넣자"는 손해다. **최근 상호작용 선택 보존 + 압축 요약**을 기본 루프로. 특히 툴 응답이 큰 엔터프라이즈 연동에서 효과가 크다.
- **한계**: 단일 도메인(경비 항목화)·GPT-5 중심. prune/요약 윈도 크기 튜닝이 도메인마다 필요.
- 링크: [arxiv.org/abs/2606.10209](https://arxiv.org/abs/2606.10209)

![컨텍스트 전략별 완료율 막대그래프. 유저모델 없음 8.0%, 풀 히스토리 71.0%(1.48M 토큰·14.6시간), 최근 5개 prune 79.0%(535K 토큰·5.4시간), prune+요약 91.6%(553K 토큰·5.8시간). prune+요약이 완료율은 가장 높고 토큰·시간은 절반 이하](/images/ai-news-2026-07-28/context-configs.svg)
*더 넣을수록 좋지 않다 — prune+요약이 정확도·비용·속도를 동시에 잡는다. (자체 제작 SVG, 값 출처 arXiv 2606.10209)*

## 2) VISTA — 에이전트에게 '자기 컨텍스트'를 보여주면 관리 능력이 깨어난다
- **저자**: Binyan Xu, Haitao Li, Kehuan Zhang (arXiv `2606.30005`, cs.CL, 2026-06-29)
- **핵심**: 기존 컨텍스트 관리는 (a) 증거를 버리는 압축 정책을 학습시키거나 (b) 에이전트가 못 보는 레이어에서 처리한다. 진짜 문제는 따로 있다 — **프런티어 모델은 자기 컨텍스트에 대해 '자각(proprioception)'이 없다.** 어떤 블록이 얼마나 크고·오래됐고·쓰였는지 프롬프트만으론 모른다.
- **방법(요약)**: **VISTA**는 학습 불필요·모델 무관 레이어. 워킹메모리를 **타입 있는 주소 지정 블록**으로 표현하고, **블록별 토큰/최근성/접근이력을 런타임 대시보드로 노출**하며, 버린 블록은 **full-fidelity로 복구 가능한 archive**로 남긴다. 정책을 새로 학습시키는 게 아니라 **상태를 보여주는 인터페이스**만 준다.
- **결과(검증됨)**: LOCA-Bench·BrowseComp-Plus·GAIA에서 같은 인터페이스가 1M/100K/10K 스케일 궤적에 전이. LOCA-Bench에서 4개 백본을 향상시키고 **Gemini-3-Flash를 22.7 → 50.7%로** 끌어올렸다. **컨텍스트 압력이 클수록 이득이 커진다.**
- **🛠 agent-builder 시사점**: 컨텍스트 관리를 모델의 암묵 능력에 맡기지 말고 **관측 가능하게** 만들어라. 하니스에 "블록별 크기·나이·사용도" 뷰를 넣으면 keep/drop 판단 품질이 오른다.
- **한계**: 벤치마크 스냅샷 기준. 블록 타이핑·archive 설계가 시스템마다 필요.
- 링크: [arxiv.org/abs/2606.30005](https://arxiv.org/abs/2606.30005)

![VISTA 구조 다이어그램. 왼쪽 런타임 대시보드에 tool_result·browse_dump·plan.md·task_goal 블록이 토큰/최근성/접근이력과 함께 표시되고, 크고 오래되고 안 쓰인 browse_dump가 drop 후보로 강조된다. 오른쪽은 LOCA-Bench에서 Gemini-3-Flash가 22.7에서 50.7%로 오른 결과](/images/ai-news-2026-07-28/vista-dashboard.svg)
*모델은 자기 컨텍스트에 무감각하다 — 상태를 노출하면 관리 능력이 이미 잠재해 있다. (자체 제작 SVG, 값 출처 arXiv 2606.30005)*

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — Hook/Context: compaction 전후에 훅으로 컨텍스트 지키기
- 출처: [OpenAI Codex 체인지로그](https://developers.openai.com/codex/changelog)
- 💡 **핵심 아이디어**: 이제 훅을 `/hooks`에서 켜고/끄고 확인할 수 있고, **compaction 직전·직후에 훅을 돌릴 수 있다.** 요약으로 사실이 증발하기 전에 붙잡고, 압축 후 필요한 상태를 다시 심는다.
- 📝 **How-to**: `/hooks`로 등록된 훅을 확인 → compaction 전 훅에서 "지워지면 안 될 사실"을 파일/메모로 외부화하고, compaction 후 훅에서 그 요약을 다시 주입. PreToolUse 훅으로 툴 실행 직전 컨텍스트도 보강할 수 있다.

```text
# /hooks 에서 토글 가능한 훅 예시 흐름
pre-compaction   → 핵심 사실을 notes.md로 덤프(요약에 안 잃도록)
post-compaction  → notes.md 요약을 컨텍스트에 재주입
pre-tool-use     → 툴 실행 직전 필요한 상태 보강
```

- 🎯 **언제**: 장시간 세션에서 compaction으로 결정·제약이 사라져 에이전트가 헤맬 때.
- ⚠️ **주의**: 훅이 매 compaction마다 도니 **덤프를 작게** 유지하라(오늘 Less Context 교훈과 동일 — 다 남기면 다시 비대해진다).
- ⭐ **추천**: 긴 리팩터·멀티스텝 작업이라면 pre/post-compaction 훅 한 쌍은 기본 세팅.

## 🟦 Claude Code — Workflow: `/fork` 백그라운드 세션 + 예산 캡
- 출처: [Claude Code 체인지로그](https://code.claude.com/docs/en/changelog)
- 💡 **핵심 아이디어**: 본 세션을 막지 않고 대안 경로를 **백그라운드로 분기**해 병렬 탐색하되, 런어웨이를 예산 캡으로 막는다.
- 📝 **How-to**: 위험하거나 갈림길인 지점에서 `/fork` → 대화가 새 백그라운드 세션으로 복사되고 본 세션은 계속. 분기 세션은 `claude agents` 또는 `/resume`로 재개. 인-세션 위임이 필요하면 `/subtask`.

```bash
/fork                 # 현재 대화를 백그라운드 세션으로 복사, 본 세션은 계속
/subtask "…"          # 인-세션 서브에이전트로 위임
# 자동화/CI에서는 예산 캡을 낮춰 런어웨이 방지
export CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=40
export CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION=20
```

- 🎯 **언제**: "이 방향이 맞나?" 두 갈래를 동시에 밀어볼 때, 혹은 리뷰를 `/code-review`로 백그라운드에 돌리고 본 작업을 이어갈 때.
- ⚠️ **주의**: `/clear`는 두 예산(검색·서브에이전트)을 리셋한다. 무한 위임을 막으려면 CI 환경변수로 캡을 명시.
- ⭐ **추천**: 병렬 실험을 자주 한다면 Orca 같은 함대 도구로 확장하기 전, `/fork`부터 익혀라.

## 🟪 공통 — Context: 루프에 'prune + 요약'을 기본으로
- 출처: [arxiv.org/abs/2606.10209](https://arxiv.org/abs/2606.10209)
- 💡 **핵심 아이디어**: 풀 히스토리 retention은 정확도·비용 둘 다 손해. **최근 툴콜만 남기고 나머지는 압축 요약**하는 게 오늘 검증된 스윗스팟.
- 📝 **How-to**: (1) 에이전트 스텝마다 툴 결과를 "최근 N개 원본 + 그 이전은 요약"으로 유지, (2) 요약 실패·손실 대비 원본은 archive/파일로 복구 가능하게, (3) 블록별 토큰·나이·사용도를 로깅해 **drop 후보를 관측**(VISTA 아이디어), (4) N과 요약 윈도를 태스크로 튜닝.
- 🎯 **언제**: 툴 응답이 큰 연동(문서·DB·브라우저 덤프)을 오래 도는 에이전트 전부.
- ⚠️ **주의**: 요약은 증거를 버릴 위험이 있으니 **복구 경로(archive)** 를 반드시 남겨라. 무손실이 필요한 값(금액·ID)은 요약 대상에서 제외.
- ⭐ **추천**: "컨텍스트 창 크니 다 넣자"를 쓰고 있다면 오늘 가장 먼저 바꿀 것.
