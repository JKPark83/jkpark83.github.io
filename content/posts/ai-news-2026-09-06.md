# 📚 주목 논문

## Compile by Training — 자연어 스펙을 "로컬 함수"로 컴파일하기

- **저자**: Yuntian Deng, Pengyu Nie, Stuart Shieber (arXiv 초록 페이지에 소속 미표기)
- **arXiv**: [2609.04199](https://arxiv.org/abs/2609.04199) (cs.CL, cs.AI, cs.LG) — 9/3 공개, HF Daily Papers 1위
- **핵심 기여**: 반복 호출되는 자연어 지시를 매번 원격 LLM에 보내는 대신, 교사 모델로 학습 데이터를 생성해 **소형 어댑터를 파인튜닝한 "로컬 뉴럴 함수"로 컴파일**한다. 컴파일된 함수는 원격 의존 없이 독립 실행되고, 일반 소프트웨어 컴포넌트처럼 버전 관리·배포된다.
- **방법**: 자연어 스펙 → 교사 모델이 입출력 예시 합성 → 어댑터 학습 → 로컬 함수 배포. 컴파일에 약 1분.
- **결과**: 기존의 빠른 컴파일 방식이 사실상 전멸하는 난이도의 벤치마크에서 약 84% 의미 정확도(자체 보고). 웹사이트 헬퍼, 3D 아바타 제어, 양방향 번역 데모를 공개 서비스로 시연.
- 🛠 **에이전트 빌더 시사점**: 에이전트 루프 안에서 매번 LLM을 부르던 고정 패턴 서브태스크(분류·포맷 변환·라우팅 판단)를 컴파일해 두면 토큰 비용과 지연이 상수로 떨어진다.
- **한계**: 컴파일 1분은 인터랙티브 용도로는 길고, 스펙이 바뀔 때마다 재컴파일이 필요하다.

## LatentPress — 대화 이력을 텍스트 말고 "메모리 토큰"으로

- **저자**: Zhengze Zhou, Hejian Sang (arXiv 초록 페이지에 소속 미표기)
- **arXiv**: [2609.01507](https://arxiv.org/abs/2609.01507) (cs.LG, cs.AI) — v2 9/3
- **핵심 기여**: 대화 이력·긴 문서를 **연속(continuous) 메모리 토큰**으로 압축해 동결된 LLM의 입력 임베딩 레이어로 직접 읽게 한다. 추론 시 텍스트 복원이 없다.
- **방법**: 디코더의 약 0.1% 크기(4.2M~26.2M 파라미터) 어댑터가 4~16배 압축을 담당. 쓰기 43ms/대화, 읽기는 원문 대비 5~9배 빠름.
- **결과**: LongMemEval에서 7.70배 압축으로 정확도 0.504 — 비압축 원문(0.490)보다 오히려 높다. 텍스트 요약(0.184), OCR 기반 압축(0.426~0.312)을 크게 앞선다(자체 보고).
- 🛠 **에이전트 빌더 시사점**: 장기 세션 에이전트의 메모리 레이어를 "요약문 저장"으로 설계했다면 재고할 근거가 생겼다. 요약은 세부를 잃지만, 소프트 토큰은 기계가 읽기 좋은 형태로 세부를 보존한다.
- **한계**: 모델별 어댑터 학습이 필요해 상용 API 모델에는 바로 못 쓴다. 자체 호스팅 오픈 웨이트 스택 전용.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — 기본 모델이 바뀌기 전에 핀부터 박자

- **카테고리**: Workflow / **출처**: [Codex 릴리즈 노트](https://releasebot.io/updates/openai/codex)
- 💡 0.153.4부터 모델 미지정 설치는 번들 기본이 GPT-6 Astra다. CI나 스크립트에서 Codex를 돌리고 있다면 업데이트 순간 모델이 조용히 바뀔 수 있다.
- 📝 `~/.codex/config.toml`에 모델을 명시해 고정한다:

```toml
model = "gpt-5.6-sol"   # 또는 검증 후 "gpt-6-astra"
```

- 🎯 자동화 파이프라인·평가 하네스처럼 모델이 바뀌면 결과 비교가 무너지는 곳.
- ⚠️ 반대로 Astra를 쓰고 싶은데 단계적 롤아웃 대상이 아니면 기본값이어도 접근이 안 될 수 있다.
- ⭐ 추천도: ★★★★★ — 1분이면 끝나는 보험.

## 🟦 Claude Code — /cost로 프롬프트 캐시 미스 원인 잡기

- **카테고리**: Debugging / **출처**: [v2.1.260 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.260)
- 💡 2.1.260부터 `/cost`와 스테이터스라인의 `prompt_cache` 필드가 **캐시 미스의 추정 원인**(툴 정의 변경, 시스템 프롬프트 변경, TTL 초과 유휴 등)을 보여준다.
- 📝 세션이 이상하게 비싸질 때:

```
/cost
```

원인이 "tool definitions changed"라면 MCP 서버가 툴 목록을 흔들고 있는지, "idle past TTL"이라면 세션 방치 패턴인지 확인하고 워크플로를 조정한다.

- 🎯 장시간 에이전트 세션, MCP 서버를 여럿 붙인 구성의 비용 최적화.
- ⚠️ 표시는 추정 원인이다. 확정 진단이 아니라 조사 시작점으로 쓰자.
- ⭐ 추천도: ★★★★☆ — 캐시 미스는 조용한 비용 킬러다.

## 🟪 공통 — 반복 서브태스크는 "호출" 말고 "컴파일"을 검토

- **카테고리**: Context / Workflow / **출처**: [arXiv 2609.04199](https://arxiv.org/abs/2609.04199)
- 💡 에이전트 루프에서 매번 LLM을 부르는 고정 패턴 작업(인텐트 분류, 포맷 정규화, 라우팅 판단)은 스펙이 안정된 순간부터 "컴파일 대상"이다.
- 📝 이번 주에 할 수 있는 일: 에이전트 트레이스에서 프롬프트가 거의 동일한 호출을 집계하고, 상위 1~2개를 소형 모델 파인튜닝이나 증류로 대체하는 실험을 잡는다. Compile by Training은 이 방향의 자동화가 실용 단계에 왔다는 신호다.
- 🎯 호출량이 많고 지연에 민감한 프로덕션 에이전트.
- ⚠️ 스펙이 자주 바뀌는 작업은 재컴파일 비용이 더 든다. 안정된 경로부터.
- ⭐ 추천도: ★★★★☆
