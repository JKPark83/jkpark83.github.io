# 📚 주목 논문

## 1. Second Thought — 툴이 도는 동안 추론을 병렬로

- **저자**: Zhensu Sun, Chengran Yang, Yunbo Lyu, Jieke Shi, David Lo
- **arXiv**: [2608.13667](https://arxiv.org/abs/2608.13667) (cs.AI / cs.SE, 8/13 제출)
- **핵심 기여**: ReAct 패러다임에서 Action 직렬화와 환경 실행 대기 구간을 **reasoning idle window**로 규정하고, 그 시간을 미래 턴을 위한 추론으로 채우는 학습 불필요(training-free) 추론 프레임워크.
- **방법**: Thought 단계가 끝나는 즉시 보조 브랜치 **4개를 포크**해 주 루프와 동시에 디코딩하고, 환경 관측이 도착하면 생성된 생각들을 다시 병합한다. 추가 추론이 주 스레드의 순차 디코딩 경로 **바깥**에 놓이는 게 핵심.
- **결과**: 에이전틱 벤치 3종 × 추론 LLM 3종 = 9쌍에서 **평균 턴 수가 전부 감소**. 주 스레드 디코딩은 6쌍에서 감소(최대 **−43%**, 해당 설정 평균 약 20%), 1쌍은 사실상 동일. Pass@1은 9쌍 중 7쌍에서 유의차 없음, 유의한 2쌍은 **+12.4 / +10.2**. 동일 연산량을 주 스레드 자체 추론에 몰아준 대조군 대비, 적용 가능한 4개 설정 전부에서 순차 디코딩이 **1.3~3.2배 적으면서** Pass@1은 더 높았다.
- **🛠 에이전트 빌더 시사점**: 지연시간 최적화를 "모델을 바꾼다"에서 **"대기 구간을 스케줄링한다"**로 옮길 수 있다. 툴 호출이 느린 파이프라인(코드 실행, 브라우저, 원격 API)일수록 회수할 시간이 크다.
- **⚠️ 한계**: 총 연산량(토큰 소비)은 늘어난다 — 줄어드는 건 체감 지연을 만드는 **순차** 디코딩이다. 배치 처리량이 병목인 서빙 환경에서는 이득이 상쇄될 수 있다.

*브랜치 내용 예시는 이해를 돕기 위한 재구성이고, 하단 수치는 논문 초록의 검증된 결과다. 근거: arXiv 2608.13667. 자체 제작 도식.*

## 2. Beyond Final Scores — 장기 R&D 에이전트를 최종 점수로 보면 놓치는 것

- **저자**: Yiwei Li, Wanli Yang, Hexiang Tan 외 10인 (소속은 arXiv 메타데이터에 미표기)
- **arXiv**: [2608.13417](https://arxiv.org/abs/2608.13417) (cs.AI, 8/13 제출)
- **핵심 기여**: 프런티어 모델 7종 × 장기 실험 과제 36개를, 최종 점수가 아니라 **실행 과정 지표**로 분해한 체계적 평가.
- **방법**: 룰 기반 지표로 런 내부 행동을 **Solution Framing / Execution / Feedback Control** 세 축으로 특성화하고, 과제 내·과제 간 **경험 재사용**을 통제 비교로 측정한다.
- **결과**: 현재 에이전트는 자율 연구자보다 **엔지니어링 최적화기**에 가깝다. 실행 가능한 해법은 만들지만 런마다 성능 편차가 크고, 가장 좋은 해법도 기존 기법의 조합·변형에 머물며 방법론적 신규성은 드물다. 같은 최종 점수 뒤에 **서로 다른 병목**이 있고, 경험 재사용은 도움이 되기도 **오도하기도** 하며, 하니스 설계가 안정성을 좌우한다.
- **🛠 에이전트 빌더 시사점**: 에이전트 eval을 성공률 하나로 보고 있다면 오늘 **런 간 분산**과 **어느 단계에서 실패했는지**를 같이 찍어라. 평균이 같아도 원인이 다르면 고칠 대상이 다르다.
- **⚠️ 한계**: 룰 기반 지표라 단계 분류가 과제 유형에 의존한다. 36개 과제 범위 밖 일반화는 미검증.

**🟪 공통 — 카테고리: Context / Workflow**

- 출처: [arXiv 2608.13667](https://arxiv.org/abs/2608.13667)
- 💡 **핵심**: 툴 호출 대기 구간에 "다음 턴을 위한 준비"를 미리 굽는다. 모델을 바꾸지 않고 체감 지연을 줄이는 축.
- 📝 **하는 법**: 오늘 할 수 있는 최소 버전은 한 줄이다 — 액션을 보내고 **await 하기 전에** 보조 추론 태스크를 함께 띄운다.

```python
# 액션을 보내고 결과를 기다리는 동안, 보조 추론을 같이 굽는다
action_future = asyncio.create_task(run_tool(action))
probe_future  = asyncio.create_task(llm("이 액션이 실패하면 다음 후보는?"))
obs, probe = await asyncio.gather(action_future, probe_future)
```

- 🎯 **언제**: 툴 왕복이 수 초 이상인 파이프라인(원격 실행, 브라우저 자동화, 느린 사내 API).
- ⚠️ **주의**: 총 토큰 소비는 늘어난다. 보조 브랜치 결과를 무조건 컨텍스트에 넣으면 오히려 오염되니, **다음 턴에 실제로 쓰인 것만** 병합하고 나머지는 버려라.
- ⭐ **추천도**: 4/5 — 툴이 느릴수록 이득이 커진다.
