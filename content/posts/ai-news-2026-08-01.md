# 🔥 오늘의 핵심

# 📚 주목 논문

## 1) MemHarness — "기억은 재생이 아니라 재구성된다"

- **저자/소속**: Rong Wu, Daocheng Fu, Licheng Wen, Xuemeng Yang, Shu Zou 외 (총 13인)
- **arXiv**: [2607.28272](https://arxiv.org/abs/2607.28272) · category `cs.AI` · 2026-07-30
- **핵심 기여**: 대부분의 memory-augmented 에이전트는 검색한 경험을 **정적 기록으로 그대로 재생(replay)**한다. 이 논문은 그게 **negative transfer**의 원인이라고 짚고, 사람이 기억을 그때그때 재조직하듯 **재구성(reconstruct)**하는 프레임워크를 제안한다.
- **방법(2–3줄)**: 매 결정 스텝마다 **통합 policy 모델이 검색된 경험을 현재 state 조건부로 비평·재구성**해, 행동 전에 "맥락에 밀착된 지침"을 만든다. 이 재구성 능력은 **GRPO 기반 end-to-end 학습**으로 자연스럽게 창발한다.
- **핵심 결과(검증)**: ALFWorld·WebShop에서 **순수 RL과 정적 메모리 베이스라인을 모두 상회**, OOD(분포 밖) 상황에서 강건. 재구성 목표가 학습 중 잠재 지침으로도 작동해 **에이전트의 내재적 추론 능력 자체를 끌어올림**.
- 🛠 **agent-builder 시사점**: RAG/메모리 스토어에서 뽑은 과거 사례를 **프롬프트에 그대로 붙이지 말 것.** "지금 상태에서 이 경험이 유효한가?"를 한 번 걸러서 **요약·수정한 뒤** 주입하는 단계를 넣어라.
- ⚠️ **한계**: 평가가 ALFWorld·WebShop 등 시뮬레이션 벤치 중심 — 실제 툴 환경 일반화는 추가 검증 필요.

![MemHarness 핵심 다이어그램. 위쪽 replay(과거 경험→verbatim 주입→현재 상태와 불일치→negative transfer), 아래쪽 reconstruct(과거 경험→policy가 현재 state 조건부로 비평·재구성, GRPO 학습→맥락 기반 지침→OOD 강건 행동). 하단에 ALFWorld·WebShop에서 순수 RL·정적 메모리 대비 우위.](/images/ai-news-2026-08-01/replay-vs-reconstruct.svg)
*replay는 불일치를 부르고, reconstruct는 맥락에 밀착시킨다 — 수치·설명은 arXiv 2607.28272 초록 기준. (자체 제작 SVG)*

## 2) Trajectory Graph Copilot — "실행하기 전에 궤적으로 오류를 진단하라"

- **저자**: Xu Zheng, Zhuomin Chen, Chaohao Lin, Hua Wei, Haifeng Chen 외 (총 7인)
- **arXiv**: [2607.27443](https://arxiv.org/abs/2607.27443) · category `cs.AI` · 2026-07-29
- **핵심 기여**: 롱-호라이즌 과제에서 한 번의 나쁜 행동이 궤적 전체를 무너뜨리는 **compounding error** 문제를, **소프트웨어 디버깅처럼 "실행 로그로 사전에 잡는"** 방식으로 접근한다.
- **방법(2–3줄)**: **Graph Debugger**가 과거 궤적을 **확률 그래프**로 모델링하고, GNN으로 **자주 실패로 이어지는 행동 패턴**을 식별. 실행 직전에 위험한 액션에 경고를 주는 **사전 진단 샌드박스**로 작동해 에이전트가 스스로 교정하게 한다(파인튜닝 불필요).
- **핵심 결과(검증)**: 4개 벤치마크·3개 LLM 에이전트에서 **평균 pass ratio +14.69%**.
- 🛠 **agent-builder 시사점**: 실패한 궤적 로그를 버리지 말고 **"이 다음 액션이 과거에 얼마나 실패했나"**를 조회하는 가드로 재활용하라. 스텝 예산이 제한된 에이전트일수록 **실행 전 진단**의 ROI가 크다.
- ⚠️ **한계**: 그래프 품질이 과거 궤적 분포에 의존 — 새로운 도메인에선 콜드스타트 이슈 가능.

## 🟦 Claude Code — [Context] `CLAUDE.md`(명시) + `MEMORY.md`(학습) 두 층을 분리하라

- 출처: [code.claude.com/docs/en/memory](https://code.claude.com/docs/en/memory)
- 💡 **핵심**: Claude Code의 기억은 두 층이다. **`CLAUDE.md`** = 내가 직접 쓰는 지속 규칙, **auto memory(`MEMORY.md`)** = Claude가 내 수정·선호를 보고 스스로 적어두는 학습 층. 세션 시작 시 `MEMORY.md`는 앞부분(약 200줄/25KB)만 로드된다.
- 📝 **how-to**:

```bash
# 프로젝트 규칙은 CLAUDE.md에 명시적으로 (리포에 체크인)
cat > CLAUDE.md <<'EOF'
# 프로젝트 규칙
- 테스트: `pytest -q`, 커밋 전 필수
- API 응답은 pydantic 모델로만 파싱
EOF
```

- 세션 중에는 프롬프트에서 `#` 로 시작하는 줄로 메모리를 즉석 추가할 수 있다.
- 🎯 **언제**: 반복 지시("항상 X 하지 마")를 매번 다시 쓰기 싫을 때, 팀 규칙을 버전 관리하고 싶을 때.
- ⚠️ **주의**: `MEMORY.md`는 앞부분만 로드되니 **중요한 규칙은 위로**. 학습 층을 신뢰하기 전에 주기적으로 열어 **잘못 적힌 기억을 정리**하라(오늘 논문의 "verbatim 재생은 위험" 교훈과 동일).
- ⭐ **추천**: 명시(CLAUDE.md)를 1차 소스로, 학습(MEMORY.md)은 보조로. 반대로 두면 통제가 흔들린다.

## 🟪 공통 — [Context] 검색한 기억을 verbatim으로 주입하지 말고 재구성하라

- 출처: [MemHarness (arXiv 2607.28272)](https://arxiv.org/abs/2607.28272)
- 💡 **핵심**: 오늘 논문의 실무 번역판. RAG/메모리에서 뽑은 과거 사례를 **그대로 붙이면 negative transfer**. 현재 상태에 맞게 **한 번 걸러 재구성**하라.
- 📝 **how-to (체크리스트)**:
  - [ ] 검색 결과를 주입 전에 **"지금 과제와 관련 있나?"** 필터 스텝 추가
  - [ ] 관련 있으면 **원문 복붙이 아니라 현재 맥락으로 요약·각색**해서 주입
  - [ ] 실패 궤적은 버리지 말고 **"이 다음 액션이 과거에 실패했나"** 가드로 재활용(Trajectory Graph 아이디어)
  - [ ] 기억 파일(CLAUDE.md/MEMORY.md/AGENTS.md)도 주기적으로 **가지치기(prune)**
- 🎯 **언제**: 장기 기억·경험 재사용을 붙이는 모든 에이전트.
- ⚠️ **주의**: "많이 넣을수록 좋다"는 틀렸다. 무관한 과거는 **노이즈이자 오답 유도**다.
- ⭐ **추천**: `retrieve → filter → reconstruct → act` 4단계를 최소 파이프라인으로 고정.
