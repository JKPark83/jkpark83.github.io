# 📚 주목 논문

## LoopArena: 루프의 "판단력"만 따로 채점하는 벤치마크

- **저자/소속**: Yi Wang 외 7인, AMAP-ML(Alibaba) DreamX Team
- **arXiv**: [2608.28281](https://arxiv.org/abs/2608.28281) (cs.AI) · [코드](https://github.com/AMAP-ML/LoopArena)
- **핵심 기여**: 코딩 에이전트를 지휘하는 컨트롤러 모델의 능력을, 실행하는 워커와 분리해서 측정하는 최초의 체계적 벤치마크.
- **방법**: 평가 대상 모델은 Controller. 매 라운드 구조화된 실행 요약을 받고, 고정된 코딩 에이전트(Worker)에게 다음 작업·검증을 지시하거나 중단을 결정한다. 실행 없이 다음 수 선택을 채점하는 Type I, 과제 일부 구간만 실행하는 Type II, 전체 과제 Type III의 3단 구성.
- **결과**: 전체 과제 기준 최고 Strict 성공률 24.69%. Type II는 전체 실행 대비 추정 추론 비용을 평균 64.4% 줄이면서 순위 상관 ρ=0.9747을 유지.
- 🛠 **에이전트 빌더 시사점**: "루프가 실패한 게 모델 탓인지 루프 설계 탓인지"를 이제 분리해서 물을 수 있다. 오케스트레이터 모델 선정을 감이 아니라 측정으로 하자.
- **한계**: Worker가 하나의 고정 에이전트라 조합 일반화는 미검증. 릴리즈 0.1.0 초기 단계.

![LoopArena의 Controller-Worker 분리 평가 구조](/images/ai-news-2026-09-01/looparena-loop.svg)

*LoopArena 구조. 판단(Controller)과 실행(Worker)을 분리하고, 비용이 다른 3가지 평가 타입을 제공한다.*

## J-Zero: 데이터 0에서 출제자·풀이자·심판이 같이 진화

- **저자**: Gyouk Chu, Myeongho Jeon, Eunho Yang (소속은 arXiv에 미표기)
- **arXiv**: [2608.26582](https://arxiv.org/abs/2608.26582) (cs.LG)
- **핵심 기여**: 검증 불가능한 도메인까지 커버하는 Challenger–Solver–Judge 3자 공동 진화 프레임워크.
- **방법**: Challenger는 점점 어려운 과제를 만들고 Solver는 답을 개선한다. Judge는 자기 점수가 아니라 "생성 방식상 우열이 미리 알려진" 선호쌍(예: Solver 답 > Challenger 답)으로 학습해 보상 해킹을 피한다.
- **결과**: 베이스라인 대비 검증 가능 도메인 평균 +4.2점, 검증 불가 도메인 +8.0점. 베이스라인은 2회 반복 후 퇴화하지만 J-Zero는 10회 이상 계속 개선.
- 🛠 **에이전트 빌더 시사점**: LLM-judge를 고정해 두면 self-improvement 루프가 금방 망가진다. 심판도 함께 갱신하되, "정답을 몰라도 순서를 아는" 선호쌍을 쓰는 트릭은 에이전트 eval 설계에 바로 응용할 만하다.
- **한계**: 코드 미공개. 10회 이후 장기 동역학은 미검증.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — 훅 이벤트는 12종, 서브에이전트 수명주기까지 걸린다

- **카테고리**: Hook · **출처**: [HookEventName 스키마](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/HookEventName.ts)
- 💡 Codex 훅이 걸리는 이벤트를 소스에서 확인하면 12종이다: `preToolUse`, `permissionRequest`, `postToolUse`, `preCompact`, `postCompact`, `sessionStart`, `sessionEnd`, `userPromptSubmit`, `subagentStart`, `subagentStop`, `stop`, `interrupt`.
- 📝 `/hooks` 명령으로 현재 세션의 훅을 훑고, 멀티에이전트 작업이라면 `subagentStop`에 로깅 핸들러를 달아 서브에이전트가 무엇을 하고 끝났는지 파일로 남기자. `permissionRequest`는 승인 요청 시점을 잡는 감사 로그 지점으로 쓸 수 있다.
- 🎯 서브에이전트를 여럿 띄우는 작업에서 "누가 뭘 했는지" 관측성이 필요할 때.
- ⚠️ app-server 프로토콜 스키마 기준이라 developer preview 단계에서 이벤트 구성이 바뀔 수 있다.
- ⭐ 서브에이전트 쓰는 팀이라면 지금 로깅부터.

## 🟦 Claude Code — 공식 리포의 Bash 명령 검증 훅 예제

- **카테고리**: Hook · **출처**: [bash_command_validator_example.py](https://github.com/anthropics/claude-code/blob/main/examples/hooks/bash_command_validator_example.py)
- 💡 PreToolUse 훅 스크립트가 exit code 2로 종료하면 도구 호출이 차단되고 stderr 메시지가 Claude에게 전달된다. exit 1은 사용자에게만 보인다. 이 규약으로 팀의 명령 정책을 강제할 수 있다.
- 📝 공식 예제는 `grep`을 `rg`로 유도하는 정규식 규칙을 보여준다. 설정은 이렇게 건다:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "python3 /path/to/validator.py" }
        ]
      }
    ]
  }
}
```

- 🎯 "우리 리포에서는 이 명령 금지/이 도구 사용" 같은 규칙을 리뷰가 아니라 런타임에서 강제하고 싶을 때.
- ⚠️ 규칙 정규식이 과하면 정상 명령까지 막는다. 규칙마다 대안 명령을 stderr 메시지에 꼭 적자.
- ⭐ 30분 투자로 팀 전체에 적용되는 가드레일.

## 🟪 공통 — 컨트롤러의 "다음 한 수"를 회귀 테스트로

- **카테고리**: Eval · **출처**: [AMAP-ML/LoopArena](https://github.com/AMAP-ML/LoopArena)
- 💡 LoopArena의 Type I 아이디어는 그대로 훔칠 만하다: 루프 전체를 돌리지 않고, "이 실행 요약에서 다음 행동은?"을 고정 시나리오 선택 문제로 만들어 채점한다.
- 📝 과거 실행 로그에서 분기점 10~20개를 뽑아 (실행 요약, 정답 행동) 쌍으로 저장하고, 오케스트레이터 프롬프트나 모델을 바꿀 때마다 이 세트를 돌려 정답률을 비교하자.
- 🎯 오케스트레이터 모델 교체·프롬프트 수정 때 전체 e2e 실행 비용 없이 퇴행을 잡고 싶을 때.
- ⚠️ 선택 문제 정답률이 높아도 장기 실행 성공을 보장하진 않는다(논문에서도 전체 과제 성공률은 24.69%가 최고).
- ⭐ e2e 평가 전 1차 필터로 강력 추천.
