# 📚 주목 논문

**When Tool Outputs Become Commands (SARA)**

- 저자: Xiaokun Guo, Zhen Xu, Dongdong Huo 외 8인 (소속은 arXiv 초록 페이지에 미표기)
- arXiv: [2608.27146](https://arxiv.org/abs/2608.27146) (cs.AI, 8/27)
- 핵심: 도구 출력(Observation)이 데이터를 넘어 "다음 행동"을 지정하기 시작하면 사실상 명령이 된다. 문제의 근원은 **행동 유도와 실행 승인의 혼동**이라는 진단.
- 방법: 격리된 Action Probe가 도구 출력 속 행동 유도 의미를 노출하고 출처를 기록. 실제 도구 호출은 사용자 목표와 승인된 실행 증거에 대해서만 별도 승인. 반복 등장한 이력이 권한으로 "세탁"되는 걸 막는 No-History-Promotion 규칙 포함.
- 결과: AgentDojo·AgentDyn 4개 주요 설정에서 공격 성공률(ASR) 0.63% 이하, 태스크 성능은 유지.
- 🛠 시사점: 프롬프트에 "도구 출력을 믿지 마" 라고 쓰는 대신, 유도 탐지와 실행 승인을 **코드 레벨에서 분리**하는 아키텍처 패턴. MCP 도구를 많이 붙인 에이전트일수록 바로 적용 가치가 있다.
- 한계: 초록 기준 승인 단계의 지연·비용 오버헤드는 본문 확인 필요.

**SWE-Prime: Fewer Trajectories, Better Performance**

- 저자: Dewu Zheng, Ruizhe Ye, Yanlin Wang, Hongyu Zhang 외 (소속은 arXiv 초록 페이지에 미표기)
- arXiv: [2608.27449](https://arxiv.org/abs/2608.27449) (cs.SE, 8/27)
- 핵심: 코딩 에이전트 SFT에서 "성공한 트래젝터리"라도 비효율·위험 단계가 섞여 있어 그대로 학습하면 나쁜 습관까지 배운다. 성공 ≠ 좋은 교사.
- 방법: 2단계 선별 — ① 트래젝터리 수준(과정 품질·결과 품질·대표성)으로 상위 부분집합 선택, ② 세그먼트 수준(기여도·학습성·위험)으로 나쁜 구간은 컨텍스트에는 남기되 손실 계산에서 제외.
- 결과: 선별된 10% 데이터 학습이 전체 데이터 학습을 능가 — SWE-Bench Pro 최대 +12.2%, Verified 최대 +24.2% (상대 개선).
- 🛠 시사점: 자체 에이전트 트래젝터리로 파인튜닝하는 팀이라면 "성공 여부"만으로 필터링하지 말 것. 어제 다룬 ACE 프레임워크의 "정확성" 축을 실제로 구현한 사례다.
- 한계: 선별 파이프라인 자체의 LLM 평가 비용, 기반 모델 정보는 본문 확인 필요.

![SWE-Prime 상대 개선폭](/images/ai-news-2026-08-30/swe-prime-gains.svg)

*데이터를 90% 버리고도 성능이 오른다 — 트래젝터리 선별의 힘. (제작: 본 블로그, 출처: arXiv:2608.27449 초록)*

# 🛠 오픈소스 스포트라이트

**NVIDIA/SkillSpector** — [github.com/NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector)

- 언어: Python (3.12+), Apache-2.0 (클론으로 확인, 스타 수는 API 제한으로 미확인)
- Claude Code·Codex·MCP 스킬을 **설치 전에** 스캔하는 보안 스캐너. 71개 취약 패턴 × 17개 범주(프롬프트 주입, 데이터 유출, 공급망, MCP 도구 오염 등)를 정적 분석하고, 필요하면 LLM 의미 분석을 2차로 돌린다. OSV.dev로 의존성 CVE도 실시간 조회.
- 리스크 점수 0–100과 SARIF 리포트를 내놓아 CI 게이트로 붙이기 좋다. README가 인용한 연구 기준 공개 스킬의 26.1%가 취약점을 갖고 있고 5.2%는 악성 의도로 추정된다.
- 활용: 팀 스킬 마켓플레이스에 "스캔 통과해야 설치" 규칙을 거는 것. 아래 실전 팁 참고.

**NousResearch/hermes-agent** — [github.com/NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

- 언어: Python, MIT (클론으로 확인, 최근 커밋 8/29 — 활발히 개발 중)
- "스스로 성장하는" 오픈소스 에이전트. 복잡한 작업을 끝내면 `skill_manage` 도구로 자기 스킬을 만들고, 쓰면서 개선하는 학습 루프가 내장돼 있다. agentskills.io 스킬 표준과 호환.
- Telegram·Discord·Slack·WhatsApp·Signal 게이트웨이, 7종 터미널 백엔드(로컬/Docker/SSH/Modal/Daytona 등), 크론 스케줄러까지 포함. $5 VPS에서 상시 구동하는 개인 에이전트 실험대로 적합하다.
- 활용: 스킬 자가 생성 루프를 직접 관찰해 보기. 단, 자가 생성 스킬은 이번 주 다룬 EVOMAL(자가 오염)류 리스크가 있으니 저장 게이트와 함께 쓸 것.

![스킬 공급망 보안 파이프라인](/images/ai-news-2026-08-30/skill-supply-chain.svg)

*생성 → 스캔 → 설치 → 런타임: 두 개의 게이트(설치 전 스캔, 실행 승인 분리)가 오늘 소개한 도구·논문으로 전부 채워진다. (제작: 본 블로그)*

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — `/import`로 Claude Code 설정 통째로 가져오기** (카테고리: Workflow)

- 출처: [openai/codex 소스](https://github.com/openai/codex/blob/main/codex-rs/tui/src/slash_command.rs) (slash_command.rs에서 확인)
- 💡 Codex CLI에 `/import` 슬래시 명령이 있다. 설명 문자열 그대로 "import setup, this project, and recent chats from Claude Code" — Claude Code(그리고 Cursor)의 설정, 스킬 디렉토리, 메모리(Claude Code만), 플러그인, 최근 세션을 Codex 쪽으로 마이그레이션한다.
- 📝 방법:

```bash
codex          # 대화형 세션 시작
/import        # 감지된 Claude Code/Cursor 설정·스킬·세션 중 가져올 항목 선택
```

- 🎯 두 도구를 병행하는 팀에서 AGENTS.md·스킬·세션 히스토리를 이중 관리하지 않고 한쪽 셋업을 재사용하고 싶을 때.
- ⚠️ 가져온 훅·권한 설정은 Codex의 승인 모델에 맞게 번역되므로 반드시 결과를 검토할 것. 스킬도 "새로 설치"에 해당하니 아래 공통 팁의 스캔 게이트를 같이 통과시키자.
- ⭐ 추천도: 병행 사용자라면 ★★★★☆

**🟦 Claude Code — `/cost`의 프롬프트 캐시 지표로 토큰 비용 진단** (카테고리: Context)

- 출처: [Claude Code CHANGELOG v2.1.251](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 2.1.251부터 `/cost`에 세션별 프롬프트 캐시 라인이 생겼다: 히트율, 미스 횟수, 재캐시된 토큰, warm/cold 여부. 스테이터스 라인 스크립트용 `prompt_cache` 객체도 함께 노출된다.
- 📝 방법:

```text
/cost   → "prompt cache" 라인에서 히트율 확인
```

  히트율이 낮다면 시스템 프롬프트·CLAUDE.md·MCP 도구 목록이 턴마다 바뀌고 있다는 신호다. 동적으로 변하는 내용(타임스탬프, 상태 요약)은 프롬프트 앞부분이 아니라 뒤쪽·메시지 쪽으로 옮기면 캐시 미스가 줄어든다.
- 🎯 장시간 도는 에이전트 세션에서 토큰 비용이 이상하게 클 때 원인을 숫자로 잡는 용도.
- ⚠️ 캐시는 TTL이 있어 오래 쉰 세션은 cold로 시작하는 게 정상이다. 히트율만 보고 무조건 튜닝하지 말 것.
- ⭐ 추천도: 비용 민감한 팀이라면 ★★★★★

**🟪 공통 — 스킬 설치에 스캔 게이트 달기** (카테고리: Review)

- 출처: [NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector)
- 💡 스킬은 코드처럼 리뷰 없이 설치되는 경우가 많지만, 에이전트 권한으로 실행된다는 점에서 npm 패키지보다 위험하다. 설치 전 정적 스캔을 기본 절차로 만들자.
- 📝 방법:

```bash
uv tool install git+https://github.com/NVIDIA/skillspector.git
skillspector scan ./my-skill/ --no-llm   # 수 초 내 정적 분석
skillspector scan ./my-skill/            # LLM 의미 분석까지 (API 키 필요)
```

  CI에서는 SARIF 출력을 받아 리스크 점수 임계값 초과 시 머지를 차단하면 된다.
- 🎯 외부 스킬을 설치할 때, 그리고 에이전트가 자가 생성한 스킬을 저장소에 커밋하기 전.
- ⚠️ 정적 분석이 모든 악성 패턴을 잡지는 못한다. SARA식 런타임 권한 분리와 병행해야 방어가 완성된다.
- ⭐ 추천도: 스킬 쓰는 모든 팀에 ★★★★★
