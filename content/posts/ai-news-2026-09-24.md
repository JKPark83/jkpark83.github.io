# 🔥 오늘의 핵심

Xiaomi가 **MiMo-V2.6**을 MIT 라이선스 오픈 웨이트로 풀었다. 자체 보고치 기준 DeepSWE v1.1 71.9로 Claude Opus 5(74.0)와 1~2점 차이다. 한편 CMU 팀의 **CliffCompaction**은 base URL만 바꾸면 되는 압축 프록시로 코딩 에이전트 비용을 최대 50% 줄였고, **A2M** 논문은 MCP 생태계에서 악성 툴이 93.6% 확률로 호출되게 만들 수 있음을 보였다. 오늘 해볼 것: `cliff enable` 한 줄로 압축 프록시를 붙여보고, 내 에이전트의 MCP 서버 목록을 다시 점검하자.

# 📚 주목 논문

## CliffCompaction: 긴 코딩 세션, 자르기만 하는 압축

- **저자/소속**: Trang Nguyen, Eulrang Cho, Tim Dettmers (CMU), Bingqing Chen (Bosch Center for AI)
- **arXiv**: [2609.26779](https://arxiv.org/abs/2609.26779) (cs.AI, 9/22)
- **핵심 기여**: 요약(재작성) 대신 **절단만 하는** 컨텍스트 압축. 토큰 예산을 넘으면 한 번에 '클리프' 압축을 실행 — 500자 넘는 툴 결과는 드롭, 툴 호출은 시그니처로 축약, 사고 과정은 300자 컷. 시스템 프롬프트·태스크·최근 K턴은 원문 유지.
- **차별점**: 이전 압축분을 다시 압축하지 않고 통째로 버린다. LLM이 다시 쓰는 요약이 만드는 '컨텍스트 드리프트'를 구조적으로 차단.
- **결과**: Terminal-Bench 2.0에서 성능 유지·향상하며 인스턴스당 비용 25~52%(Kimi K2.6), 36~65%(GLM 5.1) 절감. 32K/16K 예산이 풀 컨텍스트보다 높은 61.42% 기록. KernelBench L3에서 400스텝 3.58× 커널 속도 향상.
- 🛠 **시사점**: 압축을 하니스가 아니라 **프록시 계층**에 두면 어떤 에이전트든 무수정으로 적용된다. 아래 오픈소스 항목의 구현체를 바로 쓸 수 있다.
- **한계**: 멀티세션 장기 기억(recall)은 의도적으로 포기한 설계. 세션을 넘는 기억이 필요하면 별도 메모리 계층이 필요하다.

![CliffCompaction의 API 프록시 구조와 압축 규칙, 보고된 결과 요약 다이어그램](/images/ai-news-2026-09-24/cliff-proxy.svg)

*에이전트 → cliff 프록시 → 상류 API 흐름. 에이전트는 압축 사실 자체를 모른다. (자체 제작, 데이터: 논문)*

## A2M: MCP 툴 하이재킹, 이제는 최적화 공격이다

- **저자**: Laizhen Li, Xuan Wang, Peicheng Zhao, Juanjuan Zhao, Kejiang Ye, Cheng-zhong Xu, Xitong Gao
- **arXiv**: [2609.26761](https://arxiv.org/abs/2609.26761) (cs.CR, 9/22, AACL-IJCNLP 2026 채택)
- **핵심 기여**: MCP 서버의 툴 **메타데이터를 최적화**해 에이전트가 악성 툴을 선택할 확률을 끌어올리고, 실행 트레이스로 악성 출력까지 다듬는 2단계 공격 프레임워크.
- **결과**: LiveMCPBench에서 4개 시나리오 매크로 평균 **93.6%** 악성 툴 호출률(GLM-4.6 최적화 기준). 다른 모델로도 상당 부분 전이됨.
- 🛠 **시사점**: 툴 설명(description)은 이제 **공급망 공격 표면**이다. 서드파티 MCP 서버의 메타데이터 변경을 diff로 추적하고, 실행은 격리 런타임에서. 저자들도 사전 심사 + 런타임 격리를 권고한다. 코드: [Lilaizhen/A2M](https://github.com/Lilaizhen/A2M)
- **한계**: 공격 성공률은 벤치마크 환경 기준이며, 툴 선택 정책이 다른 하니스에선 수치가 달라질 수 있다.

# 🛠 오픈소스 스포트라이트

> 참고: 이번 세션은 GitHub API 접근이 제한돼 스타 수는 확인하지 못했다. 두 저장소 모두 클론으로 실존·활동 여부를 검증했다.

**1. [nguyenvuthientrang/cliffcompaction](https://github.com/nguyenvuthientrang/cliffcompaction)** — Python

위 논문의 공식 구현체. 스캐폴드 불문 API 프록시로, 데몬을 띄우고 base URL만 바꾸면 긴 세션이 자동으로 토큰 예산 안에 머문다. 최근 커밋 9/22의 신생 저장소.

```bash
pip install cliffcompaction
cliff enable      # 기본값: Claude Code에 연결
cliff watch       # 요청·압축 실시간 확인
cliff disable     # 원상 복구
```

**활용처**: 야간 배치로 도는 장시간 코딩 에이전트, Terminal-Bench류 평가 러너의 API 비용 절감.

**2. [agent-sandbox/agent-sandbox](https://github.com/agent-sandbox/agent-sandbox)** — Go, v0.8.4

Kubernetes를 REST API와 MCP 서버 뒤로 감춘 셀프호스팅 샌드박스 런타임. 멀티세션·멀티테넌트 격리가 목표라, A2M이 권고하는 "신뢰 못 하는 툴 실행은 격리"를 실제로 구현할 때 쓸 수 있다. 최근 커밋 9/20으로 활발히 유지 중.

**활용처**: LLM 생성 코드 실행, 브라우저 유즈 등 위험 작업을 에이전트별 샌드박스로 분리. `kubectl` 없이 에이전트가 스스로 샌드박스를 만들고 지운다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — skill-installer로 스킬 설치 자동화

- **카테고리**: Workflow / Skill
- **소스**: [codex 저장소 내장 스킬](https://github.com/openai/codex/tree/main/codex-rs/skills/src/assets/samples/skill-installer), [openai/skills](https://github.com/openai/skills)
- 💡 **핵심**: Codex에는 skill-installer 스킬이 내장돼 있어, 대화로 "설치 가능한 스킬 목록 보여줘"라고 하면 [openai/skills](https://github.com/openai/skills)의 큐레이션 목록을 보여주고 `$CODEX_HOME/skills`에 설치까지 해준다.
- 📝 **방법**: Codex 세션에서 아래처럼 요청하면 된다.

```text
List installable skills            # .curated 목록
Install the review skill
Install skills from <owner>/<repo> # 사설 저장소 포함 임의 repo에서 설치
```

- 🎯 **언제**: 팀 공통 워크플로(리뷰, 릴리즈 노트 등)를 여러 명의 Codex에 배포할 때. 사설 repo 지원이 핵심.
- ⚠️ **주의**: 스킬도 결국 프롬프트 공급망이다. 설치 전 SKILL.md를 열어 읽자(오늘의 A2M 교훈과 같은 맥락).
- ⭐ **추천도**: 스킬을 2개 이상 쓰는 팀이라면 바로 도입.

## 🟦 Claude Code — `claude plugin validate`가 MCP 설정까지 검사

- **카테고리**: MCP / Debugging
- **소스**: [CHANGELOG 2.1.281](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 **핵심**: 2.1.281부터 `claude plugin validate`가 로드 시 조용히 무시되던 `.mcp.json` 항목, 선언 안 된 `user_config` 참조, 비보안 URL을 잡아낸다. "왜 내 MCP 서버가 안 뜨지?"의 상당수가 이걸로 해결된다.
- 📝 **방법**:

```bash
claude plugin validate ./my-plugin
# 출력에서 확인할 것:
# - 드롭되는 .mcp.json 엔트리
# - 미선언 user_config 변수 참조
# - http:// 등 비보안 URL
```

- 🎯 **언제**: 플러그인·MCP 설정을 만졌는데 서버가 목록에 안 보일 때, 플러그인 배포 전 CI에서.
- ⚠️ **주의**: 실행 중 세션에는 반영 안 되니 검증 후 재시작할 것.
- ⭐ **추천도**: MCP 서버를 플러그인으로 배포한다면 CI 필수 단계로.

## 🟪 공통 — MCP 서버 도입 전 5분 체크리스트

- **카테고리**: Review / MCP
- **소스**: [A2M 논문](https://arxiv.org/abs/2609.26761)
- 💡 **핵심**: A2M이 보여준 공격 경로는 전부 "메타데이터를 믿었기 때문"이다. 도입 시점과 업데이트 시점에 다음을 확인하자.
- 📝 **방법**:
  1. 툴 이름·설명에 "always use this tool" 류의 유도 문구가 있는지 훑기
  2. 서버 버전을 고정(pin)하고, 업데이트 시 툴 메타데이터 diff 확인
  3. 파일·네트워크를 만지는 툴은 샌드박스(위 agent-sandbox 등)에서 실행
  4. 툴 호출 로그를 남겨 "왜 이 툴이 선택됐는지" 추적 가능하게
- 🎯 **언제**: 서드파티 MCP 서버를 처음 붙일 때, 그리고 자동 업데이트를 켜기 전.
- ⚠️ **주의**: 체크리스트는 완화책이지 방어 보장이 아니다. 최적화 공격은 정상처럼 보이는 문구로도 가능하다.
- ⭐ **추천도**: MCP 서버 3개 이상 쓰는 모든 에이전트 운영자.
