# 🔥 오늘의 핵심

MCP·API 툴 응답이 길어질수록 에이전트는 컨텍스트 오버플로우와 stale-state 오류로 무너진다. 오늘 나온 벤치마크의 결론은 단순하다 — **최근 도구호출 5쌍만 원문으로 남기고 나머지는 요약**하면 완성률이 8%→**91.6%**로 뛰고 토큰은 **2.7배** 줄었다. 이 한 가지 정책을 Claude Code·Codex 워크플로에 오늘 바로 넣을 수 있다.

![컨텍스트 전략별 완성률과 토큰 비용 막대 차트](/images/ai-news-2026-08-14/context-eng-chart.svg)
*전체 히스토리 유지(71%, 1.48M 토큰)보다 프루닝+요약(91.6%, 553K 토큰)이 정확도·비용 모두 우세. 출처: arXiv:2606.10209 (검증 완료).*

# 📚 주목 논문

## Less Context, Better Agents — 긴 도구 응답을 위한 컨텍스트 엔지니어링

- **저자**: Abhilasha Lodha 외 (기업 워크플로 대상 연구)
- **arXiv**: [2606.10209](https://arxiv.org/abs/2606.10209) · cs.AI
- **핵심 기여**: Microsoft Dynamics 365 경비 항목화(MCP 툴 사용) 실무 태스크에서 네 가지 컨텍스트 전략을 정량 비교.
- **방법 (3줄)**: 호텔 경비 50태스크 벤치를 GPT-5 4개 구성(유저모델 없음 / 전체 히스토리 / 최근 5쌍 프루닝 / 프루닝+자동요약)으로 각 5회 실행. 완성률·토큰·런타임을 함께 측정. Claude Sonnet 4.5로 교차 검증도 포함.
- **핵심 결과 (검증)**:
  - 전체 히스토리: 71.0% / **1,480,996 토큰** / 14.56시간
  - 최근 5쌍 프루닝: 79.0% / 535,274 토큰 / 5.39시간
  - **프루닝+요약: 91.6% / 553,374 토큰 / 5.79시간** (평균 금액 정확도 99.64%)
- 🛠 **에이전트 빌더 시사점**: "컨텍스트는 많을수록 좋다"는 직관이 틀렸다. 장황한 툴 응답은 오히려 stale-state 오류를 유발한다. **최근 N쌍 원문 + 이전은 요약**을 기본 정책으로.
- ⚠️ **한계**: 단일 도메인(경비 항목화)·GPT-5 중심 결과라 태스크별 최적 N은 직접 튜닝 필요.

![도구 응답 프루닝+요약 워크플로 다이어그램](/images/ai-news-2026-08-14/prune-summarize-flow.svg)
*최근 5쌍은 원문 보존, 나머지는 상태·금액만 압축 요약 → 매 스텝 반복해 컨텍스트가 넘치지 않게 유지. 출처: 위 논문 기반 재구성.*

# 🧑‍💻 Codex & Claude Code 실전 팁

오늘의 세 팁은 모두 **컨텍스트 압축(compaction)**이라는 한 주제로 묶었다 — 위 논문의 교훈을 도구별로 그대로 적용한다.

### 🟩 Codex — 커스텀 compaction 프롬프트
- **category**: Context
- **source**: [Codex 변경 로그](https://developers.openai.com/codex/changelog?type=codex-cli)
- 💡 **core idea**: Codex는 `auto_compact_limit` 초과 시 대화를 자동 압축한다. 압축 방식을 요약 프롬프트로 커스터마이즈할 수 있다.
- 📝 **how-to**:
  ```toml
  # ~/.codex/config.toml
  experimental_compact_prompt_file = "~/.codex/prompts/compaction.md"
  ```
  압축 프롬프트에 "툴 응답의 최종 상태·금액·ID만 남기고 원문은 버려라" 식으로 요약 규칙을 명시.
- 🎯 **when**: 긴 세션·다단계 툴 호출로 컨텍스트가 자주 차는 워크플로.
- ⚠️ **caveat**: OpenAI 호스트 모델은 **요약이 서버 측에서 처리**되어 `compact_prompt` 설정이 무시될 수 있음(로컬 경로에만 반영).
- ⭐ **추천**: 셀프호스트/로컬 모델 사용 시 강력 추천, 호스트 모델이면 효과 확인 후 적용.

### 🟦 Claude Code — 서브에이전트로 장황한 툴 출력 격리
- **category**: Subagent / Context
- **source**: [Claude Code 변경 로그](https://www.gradually.ai/en/changelogs/claude-code/)
- 💡 **core idea**: 검색·빌드 로그처럼 토큰만 잡아먹는 툴 출력은 서브에이전트에 위임하고, 메인 컨텍스트에는 **결론만** 돌려받는다.
- 📝 **how-to**: 대량 로그를 훑는 작업은 Explore/general-purpose 서브에이전트에 맡기고, 오래된 히스토리는 `/compact`로 주기적으로 압축.
- 🎯 **when**: 대형 코드베이스 탐색, 반복 grep, CI 로그 분석.
- ⚠️ **caveat**: 서브에이전트의 최종 텍스트만 남으므로, 다음 단계에 필요한 세부는 반환값에 명시적으로 담게 지시할 것.
- ⭐ **추천**: 컨텍스트 상한이 부담되는 모든 세션에 기본값으로.

### 🟪 공통 — "최근 N쌍 + 요약"을 컨텍스트 정책으로 코드화
- **category**: Context / Eval
- **source**: [arXiv:2606.10209](https://arxiv.org/abs/2606.10209)
- 💡 **core idea**: 프레임워크와 무관하게, 도구 히스토리를 "최근 N쌍 원문 + 그 이전은 압축 요약"으로 유지.
- 📝 **how-to**: N(예: 5)을 파라미터로 두고, 릴리즈마다 완성률·토큰·런타임을 함께 재는 회귀 평가를 붙인다. 완성률만 보지 말고 **토큰/시간 비용을 같은 대시보드**에 둘 것.
- 🎯 **when**: MCP 툴 여러 개를 오케스트레이션하는 장기 실행 에이전트.
- ⚠️ **caveat**: 최적 N은 도메인마다 다르다 — 논문 결과(경비 항목화)를 그대로 이식하지 말고 자기 태스크에서 튜닝.
- ⭐ **추천**: 오늘의 단 하나만 가져간다면 이것.
