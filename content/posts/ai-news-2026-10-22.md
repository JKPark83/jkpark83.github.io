# 🔥 오늘의 핵심

# 📚 주목 논문

## More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents

- **저자**: Ruhan Wang, Kishan Panaganti, Dongruo Zhou (3명)
- **arXiv**: [2610.27406](https://arxiv.org/abs/2610.27406) (cs.AI, 10/19, 31p)
- **핵심 기여**: 에이전트 메모리가 규칙·요약·스킬 같은 **추상화를 저장하면, 그 안의 오류가 "추상화 → 실행 → 재추상화" 사이클을 돌며 영속화**된다는 메커니즘(error reproduction)을 정식화했다.
- **방법**: 제안하는 Anti-Persistence는 트래젝터리와 성공/실패 결과만 축적하고, 과제별 가이드는 매번 즉석에서 합성한 뒤 실행이 끝나면 폐기한다. 적응형 선택기가 과거 결과를 보고 합성 여부·방식을 결정한다.
- **결과**: 복수 벤치마크·백본에서 비교 대상 메모리 설계 중 **홀드아웃 성공률 최고, 평균 LLM 호출 비용 최저** (초록 기준, 구체 수치는 본문 참조).
- 🛠 **Agent Builder 시사점**: "lessons learned를 메모리에 적립"하는 설계 — 스킬 자동 추출, CLAUDE.md 자동 갱신, ai-memory류 교훈 저장 — 전부에 대한 경고다. 아래 공통 팁 참고.
- **한계**: 저장된 트래젝터리를 통한 간접 오류 전파는 여전히 가능하고, 가이드 합성이 매 과제마다 추가된다.

![오류 재생산 루프와 Anti-Persistence 설계 비교 다이어그램](/images/ai-news-2026-10-22/memory-loop.svg)

*왼쪽이 기존 "교훈 저장" 메모리의 오류 재생산 루프, 오른쪽이 Anti-Persistence. 차이는 추상화를 저장하느냐, 쓰고 버리느냐다.*

## Evolving Agent Interfaces (Agent S4)

- **저자**: Saaket Agashe, Xin Eric Wang 등 8명 (Agent S 시리즈의 Simular 팀)
- **arXiv**: [2610.28601](https://arxiv.org/abs/2610.28601) (cs.AI, 10/20)
- **핵심 기여**: 컴퓨터 사용 에이전트의 도구/인터페이스 설계를 사람이 아니라 **메타 에이전트가 과제 경험에서 만들어내게** 했다. 셀 단위로 스프레드시트를 치는 대신 코드 한 줄짜리 인터페이스를 스스로 만드는 식.
- **방법**: 메타 에이전트가 성공 라벨 없이 합성 훈련 과제의 트래젝터리를 분석해 인터페이스와 사용 지식 저장소를 만들고 수정한다. 집단 기반 진화(population-based evolution)가 메타 에이전트가 본 적 없는 검증 과제 성적으로 어느 저장소를 키울지 고른다.
- **결과**: OSWorld V2에서 Qwen3.8-27B + 진화된 인터페이스로 **21.3%** — 오픈소스 SOTA. 고정 인터페이스 대비 3.8배이고, GPT-5.5(13.0%)·Claude Opus 4.8(20.6%)보다 높다(이진 채점, 부분 점수 없음).
- 🛠 **Agent Builder 시사점**: 도구 설계도 하네스처럼 최적화 변수다. 이번 주 Self-HPO(하네스), 오늘 Agent S4(인터페이스)로 "손으로 짜는 영역"이 계속 줄고 있다.
- **한계**: 컴퓨터 사용 도메인 검증이고, 훈련 과제가 합성이라 실환경 분포와의 간극은 남는다.
- **코드**: [simular-ai/Agent-S](https://github.com/simular-ai/Agent-S) (10/20 릴리즈, 클론으로 확인)

![Agent S4의 OSWorld V2 성공률 비교 차트 — 21.3%로 GPT-5.5와 Claude Opus 4.8을 상회](/images/ai-news-2026-10-22/agent-s4-osworld.svg)

*27B 오픈 모델이 인터페이스 진화만으로 프런티어 모델을 넘었다. 수치는 논문 초록과 공식 README 기준.*

**🟪 공통 / Context·Memory** — [arXiv 2610.27406](https://arxiv.org/abs/2610.27406)

- 💡 Anti-Persistence를 지금 쓰는 메모리 계층에 수동으로 적용할 수 있다: **LLM이 쓴 '교훈'을 검색 가능한 영구 객체로 저장하지 말 것.**
- 📝 메모리에는 원본 에피소드(무엇을 했고 결과가 어땠는지)만 남기고, 과제 시작 시점에 관련 에피소드 몇 개를 넣어 일회용 가이드를 생성한 뒤 과제가 끝나면 버린다. 저장은 사실, 합성은 즉석.
- 🎯 스킬 자동 추출이나 "자가 개선 메모리"를 운영 중인데 특정 실수가 계속 재발할 때 — 그 실수, 메모리에 저장된 교훈이 원인일 수 있다.
- ⚠️ 매 과제 합성 비용이 추가되고(논문에선 전체 호출 비용이 오히려 줄었다고 보고), 트래젝터리 자체에 남은 오류까지 막아주진 않는다.
- ⭐ 메모리 설계 리팩터링 전 일독 추천.
