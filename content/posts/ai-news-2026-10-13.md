# 🔥 오늘의 핵심

Meta가 에이전트 특화 프런티어 모델 **Muse Wonder**를 공개하며 유료 에이전트 경쟁에 합류했습니다. 같은 날 공개가 이어진 벤치마크 **AgentSWE**는 코딩 에이전트에게 에이전트 제작을 의뢰하면 **held-out 검수에서 평균 11.2/100점**에 그친다는 결과를 보여줍니다. 오늘 해볼 일: **내 에이전트의 "완료" 보고를, 에이전트가 본 적 없는 케이스로 검수하는 단계 하나 추가하기.**

# 🤖 모델 & 릴리즈 레이더

- **Meta, Muse Wonder·Muse Wonder Full 공개 (10/12)** — 코드명 Watermelon. 예약·업무 처리 같은 "개인·업무용 에이전트" 과제를 겨냥한 프런티어 모델입니다. 소비자용은 Muse 앱의 **월 $20/$100 구독**, API는 **입력 $4/M(캐시 $0.20)·출력 $20/M, 1M 컨텍스트**로 보도됐습니다. 상위 모델 **Wonder Full은 API가 아니라 Muse Code 에이전트 구독($50/$200)을 통해서만** 접근 가능하다는 점이 특징입니다. 사이버 오남용 대비 "역대 가장 강한 안전장치"를 내세웠고, 오픈 웨이트 공개 언급은 없습니다. **에이전트 빌더에게 중요한 이유**: 최상위 모델을 API가 아닌 자사 에이전트 제품 안에만 넣는 배급 방식이 늘면, "최고 모델로 내 하네스를 돌린다"는 전제 자체가 흔들립니다. — [CNBC](https://www.cnbc.com/2026/10/12/meta-muse-wonder-ai-model-agent.html) · [Axios](https://axios.com/2026/10/12/meta-new-ai-models-anthropic-openai) · [VentureBeat](https://venturebeat.com/technology/metas-new-muse-wonder-and-muse-wonder-full-models-achieve-frontier-performance-but-only-the-weaker-one-is-available-via-api)
- **GPT-5.5 API 제공 중단이 내일(10/14)** 입니다. 파이프라인에 모델 ID가 하드코딩돼 있다면 오늘이 마지막 점검일입니다.

# 📚 주목 논문

## AgentSWE: 에이전트가 만든 에이전트, 믿을 수 있나

- **저자**: Jiahao Wang, Hongjin Qian, Yuyang Hu, Jiajun Zhang, Zheng Liu (소속은 초록 미표기, 레포는 VectorSpaceLab 조직)
- **arXiv**: [2610.13361](https://arxiv.org/abs/2610.13361) (10/9 공개, arXiv API 검증)
- **핵심 기여**: 코딩 에이전트에게 **에이전트 제작을 '의뢰(commission)'하는 벤치마크**. 시험이 아니라 의뢰라는 점이 핵심입니다 — 빌더는 요구사항과 예시 케이스 몇 개만 보고 반복 개선하고, 동결된 제출본은 **본 적 없는 held-out 케이스**로 검수받습니다.
- **방법**: 생성(빈 디렉터리에서 에이전트 구축) 10개, 편집(Aider·OpenHands·Codex 등 프로덕션 에이전트 코드베이스 수정) 10개, 최적화(BrowseComp·Terminal-Bench 등 지표 개선) 5개 과제. 요구사항 기반 루브릭과 pass/fail 게이트로 채점.
- **결과**: 공식 레포 기준 **Creation 50회 실행 평균 11.2/100점, 20회는 0점**. 어떤 모델·하네스 조합도 요구사항을 제대로 납품하지 못했습니다.
- 🛠 **에이전트 빌더 시사점**: 반복 실패 모드 세 가지 — 보이는 케이스 과적합, 겉만 완성된 '할로우 런타임', 근거 없는 완료 보고 — 는 벤치마크 밖 여러분의 바이브 코딩 세션에서도 그대로 나타나는 패턴입니다. 해법도 같습니다: **빌더가 못 보는 검수 세트를 처음부터 분리**해 두세요.
- **한계**: 과제가 25개로 적고, 루브릭 채점의 주관성이 완전히 제거되진 않습니다.
- [GitHub 레포](https://github.com/VectorSpaceLab/AgentSWE) (10/12에도 커밋, 클론 검증 — 자기 빌더를 넣어 돌리는 가이드 포함)

## RATED: 툴이 죽어 있을 때를 아는 툴 검색

- **저자**: Weiliang Chen, Song Liao (소속은 초록 미표기) — **CIKM 2026 채택**
- **arXiv**: [2610.13889](https://arxiv.org/abs/2610.13889) (10/9 공개, arXiv API 검증)
- **핵심 기여**: 기존 툴 검색은 의미적 유사도만 보고 **실행 시점의 가용성은 무시**합니다. RATED는 고정 듀얼 인코더(대조 학습)로 의미 매칭을 하고, 그 위에 **경량 컨텍스추얼 밴딧이 실시간 실행 피드백으로 후보를 재정렬**합니다. 재훈련 없이 장애에 적응합니다.
- **결과**: 실제 툴 5,172개·쿼리-툴 쌍 21만 개의 자체 벤치마크 EcoAgent에서 ToolLLM API 리트리버 대비 **MRR 상대 52.2% 개선**. 30% 장애율 시나리오에서 **죽은 툴 선택률 86.2% → 2.9%**, 추가 지연은 1ms 미만.
- 🛠 **에이전트 빌더 시사점**: MCP 서버 수십 개를 물린 에이전트라면 "시맨틱 검색으로 고른 툴이 지금 죽어 있는" 상황이 익숙할 겁니다. 툴 선택 레이어에 **최근 호출 성공률을 점수로 섞는 것**만으로도 이 논문의 절반은 가져올 수 있습니다.
- **한계**: 밴딧이 피드백을 모으기 전까지의 콜드 스타트 구간이 있고, 벤치마크가 자체 제작입니다.
- [GitHub 레포 (EcoAgent)](https://github.com/Elliotes/EcoAgent)

# 🛠 오픈소스 스포트라이트

- **[trycua/cua](https://github.com/trycua/cua)** (Python/TypeScript 모노레포, MIT) — "에이전트에게 쓸 수 있는 컴퓨터를 주자"는 프로젝트. **Cua Spaces**로 내 Mac과 보유 머신 위에 에이전트 전용 데스크톱을 띄우고, 데스크톱 자동화 드라이버(Cua Driver), 로컬 VM(Lume), 컴퓨터 사용 평가(Cua Bench), 자체 의사결정 모델(CUA-S1)까지 한 레포에 담았습니다. 10/12 당일까지 커밋이 이어지는 활발한 프로젝트로, 팀 공유 기능(Teams)이 실험 플래그로 들어오는 중입니다(클론 검증, 스타 수는 세션 API 제한으로 미검증). **활용**: 컴퓨터 사용 에이전트를 클라우드 VM 없이 **내 하드웨어에서 격리 실행**하고 싶을 때 가장 완성도 높은 출발점.
- **[docker/docker-agent](https://github.com/docker/docker-agent)** (Go, Apache-2.0) — `docker agent run agent.yaml` 한 줄로 도는 **선언형 멀티 에이전트 런타임**. 에이전트를 YAML로 정의하고, 툴은 MCP 서버(로컬·리모트·Docker 컨테이너)로 물리고, 완성된 에이전트를 **OCI 레지스트리에 push/pull**로 배포합니다. OpenAI·Anthropic·Gemini·Bedrock 등 프로바이더 무관, RAG·메모리·todo 툴 내장. v1.150.0이 10/9에 나왔고 커밋도 그 주까지 활발합니다(클론 검증). **활용**: 에이전트 구성을 코드 리뷰 가능한 YAML + 컨테이너 배포 파이프라인에 태우고 싶은 팀이라면, 직접 짠 오케스트레이터를 대체할 후보입니다.

# 🧑‍💻 Codex & Claude Code 실전 팁

![Codex 메시지 보드 vs Claude Code frontmatter 훅](/images/ai-news-2026-10-13/tips-card.svg)

*왼쪽: Codex 로컬 메시지 보드의 권한 분리. 오른쪽: Claude Code frontmatter 훅의 스코프. (자체 제작)*

**🟩 Codex / Subagent·Workflow** — [커밋 97239fd (PR #53400, 10/12 머지)](https://github.com/openai/codex/commit/97239fd052db455bd08c41afcdab738e0fe83b87)

- 💡 **핵심**: Codex 내부의 **에이전트 메시지 보드**가 확장됐습니다. 이제 독립적으로 생성된 Codex 런타임들이 하나의 로컬 보드(SQLite)를 공유하되, **런타임마다 read_only/read_write 권한을 다르게** 줄 수 있습니다.
- 📝 **방법**: 호스트가 시작 시 연결을 주입합니다.

```rust
let board = LocalBoard::new(sqlite_config, board_id);
guardian_options.thread_extension_init.insert(board.read_only());
writer_options.thread_extension_init.insert(board.read_write());
```

  초기 채널 구성은 `just agent-board-config ~/.codex <root-session-id> setup.json`으로 템플릿을 적재합니다.
- 🎯 **언제**: 작업자 에이전트와 감시자(Guardian) 에이전트를 분리 운용할 때 — 감시자는 보드를 읽기만 하고, 포스트·채널 생성 시도는 권한 오류로 거부됩니다.
- ⚠️ **주의**: 연결은 `spawn_agent`로 상속되지 않고 DB ACL도 아닙니다. cold resume·fork 때마다 호스트가 다시 공급해야 하며, 로컬 파일시스템에 쓸 수 있는 프로세스는 여전히 신뢰 경계 안입니다.
- ⭐ **추천도**: 멀티 런타임 오케스트레이션을 직접 짜는 팀이라면 지금 코드를 읽어둘 가치가 충분합니다.

**🟦 Claude Code / Hook** — [hooks 공식 문서](https://code.claude.com/docs/en/hooks)

- 💡 **핵심**: 훅을 `settings.json`이 아니라 **스킬·서브에이전트 파일의 frontmatter에 선언**하면 스코프가 자동으로 관리됩니다. 스킬 훅은 스킬이 호출될 때 등록돼 세션 끝까지 유지되고, 서브에이전트 훅은 그 서브에이전트가 도는 동안만 활성입니다.
- 📝 **방법**: 배포 스킬에만 붙는 검증 훅 예시 —

```yaml
---
name: deploy
description: 배포 절차 스킬
hooks:
  PostToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: ./scripts/verify-deploy.sh
          once: true
---
```

  `once: true`는 **첫 성공 후 훅을 제거**합니다. 실패(exit 2)나 타임아웃이면 훅이 남아 다음 기회에 다시 돕니다 — "성공할 때까지 보장" 패턴에 맞습니다.
- 🎯 **언제**: 특정 워크플로(배포, 마이그레이션)에서만 필요한 검증을 전역 훅으로 두면 모든 턴이 느려질 때.
- ⚠️ **주의**: `context: fork`로 도는 스킬에서 frontmatter 훅이 실행되지 않는다는 [사용자 버그 리포트](https://github.com/yonatangross/orchestkit/issues/4683)가 최근 올라와 있습니다. fork 스킬이라면 동작을 먼저 확인하세요.
- ⭐ **추천도**: 전역 settings 훅이 늘어져 가는 레포라면 오늘 바로 정리 효과를 봅니다.

**🟪 공통 / Eval** — [AgentSWE (arXiv 2610.13361)](https://arxiv.org/abs/2610.13361)

- 💡 **핵심**: 빌더 에이전트가 보는 케이스와 검수 케이스를 분리하는 **'의뢰-검수' 구조**는 벤치마크가 아니라도 그대로 쓸 수 있습니다.
- 📝 **방법**: 에이전트에게 기능을 맡길 때 요구사항에서 테스트 케이스를 두 벌 뽑고, 한 벌은 프롬프트에, 한 벌은 에이전트가 접근 못 하는 CI 단계에 둡니다. "완료" 보고는 CI 벌이 통과해야 인정.
- 🎯 **언제**: 에이전트의 자체 완료 보고를 믿었다가 데인 적이 있다면 — 논문에 따르면 그게 예외가 아니라 기본값입니다.
- ⚠️ **주의**: held-out 케이스가 요구사항의 같은 부분만 반복 커버하면 의미가 없습니다. 요구사항 문장별로 최소 1개씩 매핑하세요.
