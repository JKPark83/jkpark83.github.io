# 📚 주목 논문

## AutoSaddler: 하네스를 코드처럼 자동 최적화

- **저자**: Sungho Park, Wonjoong Kim, Jue Zhang, Wook-Shin Han, Chanyoung Park 외 (총 13명)
- **arXiv**: [2608.23041](https://arxiv.org/abs/2608.23041) (cs.AI, 8/24 공개)
- **핵심 기여**: 수작업 영역이던 하네스 설계(프롬프트·도구 구성·제어 로직)를 오프라인 학습 문제로 정식화하고, 실패 신호로 하네스를 반복 개선하는 프레임워크.
- **방법**: 미니배치 실행 → 실패 트레이스 심층 진단 → 하네스를 코드로 취급한 구조화 패치 생성 → 검증 기반 채택 선택의 루프를 돈다.
- **결과**: 기본 하네스 대비 GAIA2 +9.0%p, SWE-Bench Pro +9.6%p, Terminal-Bench 2.0 +10.0%p.
- 🛠 **에이전트 빌더 시사점**: ablation이 말하는 세 가지 재료가 실무 지침이다 — 얕은 반성이 아닌 깊은 디버깅, 무제한 편집이 아닌 표적 수정, 트라젝토리 맞춤 수리가 아닌 일반화 인지 선택. 사람이 하네스를 고칠 때도 그대로 적용된다.
- **한계**: 오프라인 배치 학습이라 실시간 적응은 아니고, 검증 태스크 풀의 대표성에 성능이 좌우된다.

![AutoSaddler 루프와 벤치마크 향상](/images/ai-news-2026-08-27/autosaddler-loop.svg)

*AutoSaddler의 4단계 루프와 세 벤치마크 향상 폭. 수치는 논문 초록 기준. (자체 제작)*

## When "Must" Becomes "Maybe": 핸드오프에서 제약이 약해진다

- **저자**: Yiheng Sun, Huifei Wang, Yancheng Zhu 외 (총 6명)
- **arXiv**: [2608.24569](https://arxiv.org/abs/2608.24569) (cs.AI, 8/25 공개)
- **핵심 기여**: 멀티 에이전트 워크플로에서 요약·계획·티켓·메모리 같은 중간 아티팩트가 "실행을 구속하는 상태"를 "참고 정보"로 바꿔버리는 현상(operational state preservation 실패)을 통제 실험으로 규명.
- **방법**: 명시적 전제조건·권한·폴백·실행 결과를 가진 안전 차단 조건(safety blocker)을 심고, 핸드오프 변환 방식만 바꿔가며 1,296개 합성 에피소드에서 다운스트림 실행자를 평가.
- **결과**: 일반적인 압축 핸드오프에서 차단 조건 100% 비활성화, 금지 행동 실행 54.2%. 상태 4필드를 복원하면 보존 100%, 금지 행동 0%. 다운스트림 검증만 붙여도 금지 행동은 사라지지만 아티팩트 자체의 비활성화는 95.3%로 남는다.
- 🛠 **에이전트 빌더 시사점**: "요약에 언급됐다"와 "구속력이 유지됐다"는 완전히 별개다. 핸드오프는 자유 서술이 아니라 스키마(차단 조건 필드 필수)로 만들고, 실행 직전 검증 게이트를 따로 둘 것.
- **한계**: 합성 에피소드 기반이라 실제 프로덕션 워크플로의 잡음(부정확한 업스트림 탐지 등)은 실험 범위 밖이다.

![제약 약화 실험 결과](/images/ai-news-2026-08-27/constraint-weakening.svg)

*같은 정보라도 핸드오프 형식에 따라 구속력이 극단적으로 달라진다. 수치는 논문 초록 기준. (자체 제작)*

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code — Hook (규칙은 문서가 아니라 보증으로)**

- **출처**: [Nick Liu — Hooks are guarantees, skills are knowledge, subagents are other people](https://nick-liu.com/posts/claude-code-skills-hooks-subagents/)
- 💡 **핵심 아이디어**: 세 가지 커스터마이징 프리미티브의 역할 구분 — Hook은 "반드시 일어나는 보증", Skill은 "필요할 때 로드되는 지식", 서브에이전트는 "별도 컨텍스트를 가진 타인". "항상 지켜야 하는 규칙"을 CLAUDE.md에 산문으로 적어두면 컨텍스트가 길어질수록 무시될 수 있다.
- 📝 **How-to**: 예를 들어 "수정 후 반드시 포맷"은 지시문 대신 PostToolUse 훅으로 강제한다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\"" }]
      }
    ]
  }
}
```

- 🎯 **언제 쓰나**: 포맷팅·린트·테스트 실행·보호 브랜치 차단처럼 "예외 없이" 적용돼야 하는 규칙 전부.
- ⚠️ **주의**: 훅은 셸 명령이므로 실패 시 동작(차단 vs 경고)을 명확히 하고, 느린 명령은 세션 전체를 굼뜨게 만든다.
- ⭐ **추천도**: 오늘 논문(제약 약화)과 정확히 같은 교훈 — 지켜져야 할 것은 산문이 아니라 구조로. 강력 추천.

**🟩 Codex — Context (AGENTS.md를 계층으로 나누기)**

- **출처**: [Kanaries — How to Use Codex: 5 Tips and Best Practices](https://docs.kanaries.net/topics/AICoding/codex-how-to-use)
- 💡 **핵심 아이디어**: `/init`으로 만든 AGENTS.md를 그대로 두지 말고 정보를 수명별로 재배치한다 — 일회성 요구는 프롬프트에, 장수 규칙만 AGENTS.md에, 반복 절차는 skill로, 정기 작업은 automation으로.
- 📝 **How-to**: AGENTS.md에는 빌드·테스트 명령, 코딩 컨벤션, 금지사항 같은 "6개월 뒤에도 참일 것"만 남기고 나머지는 걷어낸다. 같은 이슈로 두 번 실패하면 세션을 새로 시작하는 것도 함께 권장된다 — 긴 세션은 컨텍스트 압축으로 성능이 떨어진다.
- 🎯 **언제 쓰나**: AGENTS.md가 온갖 지시로 비대해져 정작 중요한 규칙이 묻히기 시작할 때.
- ⚠️ **주의**: AGENTS.md가 커질수록 매 세션 고정 토큰 비용이 늘어난다. "짧게 유지"가 곧 성능이다.
- ⭐ **추천도**: Claude Code의 CLAUDE.md에도 그대로 통하는 원칙. 추천.

**🟪 공통 — Workflow (핸드오프 아티팩트에 차단 조건 스키마 강제)**

- **출처**: [arXiv:2608.24569](https://arxiv.org/abs/2608.24569)
- 💡 **핵심 아이디어**: 플래너→실행자, 리서치→코딩 에이전트 사이의 핸드오프 문서에서 "하지 마라/먼저 해라"류 조건은 자유 서술로 두면 100% 비활성화된다(위 논문). 필드를 강제하면 보존율이 100%로 돌아온다.
- 📝 **How-to**: 핸드오프 JSON/마크다운에 blocker 섹션을 필수로 두고, 각 항목에 전제조건·권한(누가 해제 가능한지)·폴백·위반 시 결과 4필드를 채우게 한다. 실행 에이전트 쪽에는 "blocker가 비어 있지 않으면 해당 액션 전 검증"을 시스템 프롬프트가 아닌 코드 게이트로 넣는다.
- 🎯 **언제 쓰나**: 서브에이전트 오케스트레이션, 세션 간 인수인계 문서, 계획서 기반 자동 실행 전부.
- ⚠️ **주의**: 다운스트림 검증만으로는 금지 행동은 막아도 아티팩트의 구속력 상실 자체는 못 고친다(95.3% 비활성화 유지). 생성 시점 스키마 강제가 우선이다.
- ⭐ **추천도**: 멀티 에이전트 돌리는 팀이라면 오늘 바로 적용 가능. 강력 추천.
