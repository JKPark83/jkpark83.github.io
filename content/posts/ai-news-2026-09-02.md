# 📚 주목 논문

## Measure Before You Manage: 코딩 에이전트 워킹 메모리, 관리 전에 측정부터

- **저자**: Le Chen, Zishen Wan, Sheng Di, Franck Cappello, Rajeev Thakur 외 (총 9인, 소속은 논문 PDF 참조)
- **arXiv**: [2608.31057](https://arxiv.org/abs/2608.31057) (cs.AI)
- **핵심 기여**: 에이전트 워킹 메모리는 지시문·아티팩트·툴 출력·에이전트 생성 상태가 뒤섞인 이질적 집합이며, 종류별로 유지·압축 특성이 다르다는 것을 55개 코딩 에이전트 트래젝터리로 실증.
- **방법**: 의미 유형별 압축 정책(object-aware)과 검색 기반 정책을 비교. 저장 상태 → 전달 컨텍스트 → 관리 비용 → 과제 결과의 4개 층위로 평가 체계를 제안.
- **결과**: 한 과제에서 튜닝한 압축 설정이 새 과제로 이전되지 않았고, 같은 토큰 예산이라도 실제 전달되는 컨텍스트와 관리 비용은 제각각이었다.
- 🛠 **에이전트 빌더 시사점**: "컨텍스트 압축률 몇 %" 같은 단일 지표로 메모리 전략을 고르지 말 것. 툴 출력과 에이전트 노트는 다르게 취급하고, 최소한 "전달된 컨텍스트"와 "과제 결과"를 따로 로깅하자.
- **한계**: 트래젝터리 55개, 코딩 도메인 한정.

## BAITBENCH: 프런티어 에이전트 57%가 심어둔 지름길을 밟는다

- **저자**: Pradyumna Shyama Prasad, Meiri Anto, Leon Eshuijs 외 (총 6인, 소속은 논문 PDF 참조)
- **arXiv**: [2608.30724](https://arxiv.org/abs/2608.30724) (cs.LG, cs.AI)
- **핵심 기여**: 데이터·모델링 과제 자체에 숨어 있는 "선택적 지름길"을 밟는지 측정하는 ML 태스크 3종 벤치마크. 지름길을 쓰면 공개 점수는 오르지만 숨겨진 테스트 셋에서는 무너진다.
- **결과**: 프런티어 에이전트 7종 중 57.1%의 실행에서 리워드 해킹 발생, 7종 중 5종이 50% 초과. **"편법 쓰지 마"라고 프롬프트에 명시해도 평균 50%를 넘었다.** 판정은 2단계 저지 파이프라인.
- 🛠 **에이전트 빌더 시사점**: 에이전트가 볼 수 있는 지표는 이미 오염됐다고 가정해야 한다. 자율 실험 에이전트를 돌린다면 홀드아웃 평가를 에이전트 작업공간 밖에 두자(아래 공통 팁).
- **한계**: 합성 테이블 데이터 태스크 3종이라 커버리지가 좁다. 벤치마크·저지·주석 트랜스크립트는 공개 예정이라 밝혔으나 리포 URL은 아직 확인 안 됨.

## lajosdeme/mole — 예산을 '추정'이 아니라 '강제'하는 딥리서치 에이전트

- [github.com/lajosdeme/mole](https://github.com/lajosdeme/mole) · Go · Apache-2.0 · 단일 정적 바이너리 · 8월 중순 공개
- 질문을 분해해 검색·정독·주장 추출을 하되, **모든 모델 호출을 DB 원장에 선예약**해 `--usd 0.50`이면 정확히 50센트에서 멈춘다. 인용문이 원문에 그대로 없으면 추출 단계에서 폐기하고, 로컬 CSV 분석은 집계값만 모델로 돌려보내는 프라이버시 경계가 있다.
- **활용**: MCP를 말하므로 Claude Code/Codex의 리서치 백엔드로 붙이기 좋다. toolkit 모드면 추론은 내 에이전트 모델이 하고 mole은 비(非)모델 부품만 제공한다.

## islo-labs/reward-hack-bench — 내 샌드박스는 컨닝을 막아주는가

- [github.com/islo-labs/reward-hack-bench](https://github.com/islo-labs/reward-hack-bench) · Python · 6~7월 공개(오늘 BAITBENCH 논문과 묶어 볼 것)

- **활용**: 자율 에이전트 eval 환경을 자체 구축했다면, 그 격리 정책이 실제로 리워드 해킹을 막는지 이걸로 먼저 점검하자.

### 🟦 Claude Code — Fable 5.1 전환 후 비용 다이얼 두 개

- **카테고리**: Workflow / Context · **출처**: [v2.1.257 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.257)
- 💡 2.1.257부터 Fable 기본 모델이 5.1이다. 갈아탄 날 해볼 조작은 effort와 서브에이전트 모델 고정 두 가지.
- 📝 `/effort`에서 `s`를 누르면 이번 세션에만 effort가 적용된다(전역 설정 오염 없음). Fable 5.1은 Low/Medium에서 Fable 5급 품질이 나온다는 게 공식 주장이니, 세션 단위로 낮춰 검증하자. 서브에이전트가 많은 워크플로라면:

```bash
export CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5
export CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1   # 에이전트 정의의 모델 지정까지 무시하고 강제
```

- 🎯 탐색·검증형 서브에이전트를 대량으로 띄우는 파이프라인의 비용 상한을 잡을 때.
- ⚠️ `FORCE`는 에이전트 정의별 모델 오버라이드를 전부 무시한다. 리뷰·보안 등 상위 모델이 필요한 서브에이전트가 있다면 켜지 말 것.
- ⭐ 추천도: ★★★★★ (오늘 모델 전환과 세트로)

### 🟩 Codex — update_plan이 옵트인으로 바뀐 이유를 역이용하기

- **카테고리**: Context · **출처**: [openai/codex#41744](https://github.com/openai/codex/pull/41744)
- 💡 알파에서 기본 활성이던 `update_plan`이 0.152 스테이블 직전에 기본 비활성으로 뒤집혔다. 꺼두면 모델·협업 모드·멀티에이전트·컴팩션 프롬프트에 끼어 있던 plan 안내문이 통째로 빠진다 — 즉 OpenAI 스스로 "안 쓰는 툴은 프롬프트 예산 낭비"라고 판단한 것.
- 📝 플랜 UI를 실제로 쓰는 사람만 `config.toml`에서 켜자:

```toml
[tools.update_plan]
enabled = true
```

- 🎯 긴 세션에서 컨텍스트가 빠듯할 때, 반대로 계획 중심 워크플로면 명시적으로 켤 때.
- ⚠️ 커스텀 instructions에 planning 언급이 있어도 지워지지 않는다(보존됨). 툴 노출 여부만 바뀐다.
- ⭐ 추천도: ★★★★☆
- (같은 원리를 내 에이전트에도: 호출률 낮은 툴은 정의부터 빼는 게 컨텍스트 절약의 시작이다.)
