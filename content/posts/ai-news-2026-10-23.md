# 🔥 오늘의 핵심

히스토리가 길어지면 요약(compaction)하는 게 지금까지의 상식이었다. 오늘 논문은 그 요약이 **프리픽스 캐시를 전부 날리는 비싼 습관**이라고 지적하고, 에이전트가 KV 캐시 항목을 직접 drop·재배치하는 "캐시 엔지니어링"으로 성능과 비용을 동시에 잡았다. 코드(AKV)도 공개됐다. 한편 Anthropic은 사용자가 부르기 전에 먼저 말을 거는 에이전트 앱 **Claude Duet**을 리서치 프리뷰로 열었다.

# 🤖 모델 & 릴리즈 레이더

- **Claude Duet 리서치 프리뷰** (10/21) — Claude가 선제적(proactive) 에이전트로 동작하는 별도 앱. 아침 브리핑을 보내고, 연결된 앱을 모니터링하다가 사용자가 필요한 순간에만 먼저 연락하며, 자리를 비워도 계속 일한다. Opus 5.5 기반이고 기존 계정의 메모리·스킬·커넥터를 승계한다. 미국 Pro/Max 대기열 순차 오픈, Team/Enterprise는 아직 아니다. 에이전트 빌더에겐 "모델 턴 안의 에이전트"가 아니라 **상주형 에이전트 UX**(언제 말 걸지 판단하는 설계)가 상용화 단계에 왔다는 신호다. [공식 발표(X)](https://x.com/claudeai/status/2112984664256241837) · [9to5Google 정리](https://9to5google.com/2026/10/21/claude-duet-anthropic-ai-agent-waitlist/)
- **MiniMax M3.1-Flash 웨이트, 아직 없음** — 10/23 공개 예고였지만 KST 아침 기준 [HF 조직 페이지](https://huggingface.co/MiniMaxAI)에 M3.1 계열이 없는 것을 직접 확인했다. 풀리면 내일 다룬다.

# 📚 주목 논문

## Cache Engineering for Agents

- **저자**: Tianyu Fu, Ruoxi Wang, Yu Wang 등 9명 (코드 조직이 칭화대 NICS 연구실 `thu-nics`)
- **arXiv**: [2610.28577](https://arxiv.org/abs/2610.28577) (cs.CL, 10/20)
- **핵심 기여**: 히스토리를 자를 때 텍스트를 고치는(요약·트리밍) 대신, **에이전트가 활성 KV 캐시를 직접 관리**하게 했다. 캐시 항목을 미래 어텐션에서 제외(drop)하고 남은 키의 포지션 인코딩만 당겨 쓰면 re-prefill이 필요 없다.
- **방법**: 에이전트 쪽 정책이 "무엇을 언제 drop할지"를 정하고, SGLang 기반 서빙 엔진 **AKV**가 stateless API 뒤에서 캐시 재사용을 처리한다.
- **결과**: 소비가 끝난 tool response를 굴려서 버리는(rolling-drop) 정책만으로 임계치 요약 대비 벤치마크 평균 **+1.7점, 비용 -27.7%**. AKV 엔진은 출력 처리량 최대 1.2배, P95 지연 1.5배 개선. LLM이 캐시 정책 자체를 재귀적으로 개선하면 비용이 7.1% 더 내려갔다.
- 🛠 **Agent Builder 시사점**: autocompact에 의존하는 모든 하네스에 대한 도전. 서빙을 직접 하는 팀이라면 AKV를 바로 실험해볼 수 있고, API만 쓰는 팀도 "요약 대신 통째 삭제" 원칙(아래 공통 팁)은 오늘 적용 가능하다.
- **한계**: drop 결정이 틀리면 필요한 정보가 사라진다. 그리고 캐시 조작은 서빙 엔진 협조가 필요해 상용 API에선 아직 못 쓴다.
- **코드**: [thu-nics/AKV](https://github.com/thu-nics/AKV) (10/21 커밋, 클론으로 확인)

![요약 기반 compaction과 AKV 캐시 엔지니어링 비교, 검증된 수치 카드](/images/ai-news-2026-10-23/cache-engineering.svg)

*왼쪽이 캐시를 전부 무효화하는 기존 요약, 오른쪽이 drop·재배치만 하는 AKV. 수치는 논문 초록 기준.*

## Agent World Model in the Wild (WildAWM)

- **저자**: Zhaoyang Wang, Qianhui Wu, Jianfeng Gao, Huaxiu Yao 등 12명 (코드 조직 `MSR-Orchard` — Microsoft Research 중심)
- **arXiv**: [2610.26828](https://arxiv.org/abs/2610.26828) (cs.AI, 10/19, 35p)
- **핵심 기여**: 컴퓨터 사용 에이전트 훈련의 병목인 "환경"을 합성한다. GUI + MCP 서비스 + CLI가 섞인 **조절 가능한 환경·과제 쌍 341개**를 오픈소스 모델만으로 만들어냈다.
- **방법**: 생성 파이프라인에 과제 풀이 가능성·난이도·검증기 신뢰도 체크를 넣어 불량 과제를 걸러낸다. 에이전트는 시각 조작, 툴 호출, 코드 실행을 섞어 풀어야 한다.
- **결과**: 이 합성 환경만으로 훈련한 Qwen 모델 2종이 OOD 벤치마크 8개에서 개선(초록 기준).
- 🛠 **Agent Builder 시사점**: 평가·훈련용 환경을 손으로 짜고 있다면, "GUI+MCP+CLI 혼합 환경 합성 + 검증기 신뢰도 체크"라는 레시피 자체가 참고가 된다. 어제 Agent S4(인터페이스), 그제 Self-HPO(하네스)에 이어 이번엔 **환경**이 자동화 대상이다.
- **한계**: 341개는 아직 작은 규모이고, 합성 과제 분포와 실사용 분포의 간극 검증은 남아 있다.
- **코드**: [MSR-Orchard/WildAWM](https://github.com/MSR-Orchard/WildAWM)

# 🛠 오픈소스 스포트라이트

GitHub API가 세션 제약으로 막혀 있어 스타 수는 생략한다. 두 저장소 모두 클론으로 실존·활동을 확인했다.

- **[slackapi/slack-skills-plugin](https://github.com/slackapi/slack-skills-plugin)** (Python·TypeScript, MIT) — **Slack 공식** 플러그인. Claude Code(`/plugin install slack@claude-plugins-official`), Cursor, Codex 마켓플레이스에 모두 올라왔고, Slack MCP 서버와 사용자·개발자용 스킬(Block Kit 등)을 한 번에 깐다. v1.5.0이 10/19에 릴리즈됐다. "에이전트가 스탠드업 요약을 슬랙에 올리는" 류의 워크플로를 OAuth 포함 10분 안에 세울 수 있다. Codex는 아직 스킬만 지원(MCP 서버 미연결)이라는 점은 유의.
- **[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)** (Python, MIT) — Nous Research의 상주형 자기개선 에이전트. 복잡한 과제를 끝내면 **스스로 스킬을 만들고, 쓰면서 고치고**, FTS5로 자기 과거 세션을 검색한다. Telegram·Discord·Slack 게이트웨이, cron 자동화, local/Docker/SSH/Modal/Daytona/Vercel 6종 실행 백엔드까지 내장. 재미있는 지점: 어제 다룬 Anti-Persistence 논문이 "위험하다"고 경고한 교훈·스킬 영속화 설계의 대표 사례다. 두 접근을 같은 과제로 비교해보기 좋은 실험대. 10/22에도 커밋이 활발하다.

### 🟩 Codex — 내장 Vertex AI 프로바이더 (카테고리: Workflow)

- **소스**: [openai/codex#56265](https://github.com/openai/codex/commit/3fd148a20c18cfc72beb7dedfa52951b1f9c4cb1) (10/22 머지)
- 💡 OpenAI 계정 없이 **GCP 크레덴셜로 Codex를 돌리는** 공식 경로가 생겼다.
- 📝 설정:

```toml
# ~/.codex/config.toml
model_provider = "gcp"
```

환경 변수 `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`(기본 `global`)으로 엔드포인트를 만들고, 인증은 `gcloud auth application-default print-access-token`으로 자동 획득한다. `[model_providers.gcp]` 아래 `base_url`, `auth`, `http_headers` 오버라이드도 된다.
- 🎯 회사 결제·거버넌스가 GCP에 묶여 있는 팀, Vertex 크레딧을 쓰고 싶은 팀.
- ⚠️ 추론 요약·웹 검색·이미지 생성·커스텀 툴은 이 프로바이더에선 비활성. 같은 날 Bedrock 설정 마법사도 기본 활성화([#56033](https://github.com/openai/codex/commit/8440e76ae6d4875a6f01398e09bd27734da741e7))돼, Codex의 클라우드 프로바이더 라인업이 빠르게 넓어지는 중이다.
- ⭐ 추천도: GCP 조직이라면 바로 시도할 가치.

### 🟦 Claude Code — `claude_code.safety_event`로 거버넌스 관측 (카테고리: Debugging/Review)

- **소스**: [CHANGELOG 2.1.307](https://github.com/anthropics/claude-code/commit/1132b8a98e93300bb3822197fb7eee12ce4fb906) (10/21)
- 💡 퍼미션 규칙, auto mode, 안전 체크, 훅, 샌드박스가 **막거나·물어보거나·되돌려 보낸 툴 콜마다 OpenTelemetry 이벤트가 1건씩** 발행된다.
- 📝 설정:

```bash
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_LOGS_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_ENDPOINT=http://your-collector:4317
```

컬렉터에서 `claude_code.safety_event`를 집계하면 "어떤 규칙이 뭘 자꾸 막는지", "훅이 실제로 일하는지"가 대시보드로 보인다.
- 🎯 팀 단위로 Claude Code를 깔아둔 조직의 퍼미션 룰 튜닝, 샌드박스 정책 검증.
- ⚠️ 2.1.307 이상 필요, OTel 수신단은 직접 준비해야 한다. 덤: 같은 버전에서 코드 리뷰 구독을 끄는 `@claude review stop`도 추가됐다.
- ⭐ 추천도: 플릿 운영자라면 필수에 가깝다.

### 🟪 공통 — 요약하지 말고 통째로 버려라 (카테고리: Context)

- **소스**: [arXiv 2610.28577](https://arxiv.org/abs/2610.28577)
- 💡 히스토리 압축 시 메시지를 고쳐 쓰면(요약) 그 지점 이후 프리픽스 캐시가 전부 무효화된다. **소비가 끝난 tool response를 메시지 단위로 삭제**하면 프리픽스가 보존돼 캐시 적중이 유지된다.
- 📝 자체 에이전트 루프라면: 요약 트리거 대신 "N턴 지난 tool response는 제거" 정책부터 시도. 삭제는 항상 꼬리 쪽이 아니라 **소비 완료가 확실한 중간 툴 출력**에 한정한다.
- 🎯 긴 툴 루프(크롤링, 테스트 반복, 로그 분석)를 도는 에이전트의 비용 절감.
- ⚠️ 상용 API에선 메시지를 빼도 그 뒤 프리픽스가 바뀌므로 캐시 이득은 부분적이다. 논문 수준 이득은 서빙 제어가 가능할 때 나온다.
- ⭐ 추천도: 비용이 아픈 팀부터.
