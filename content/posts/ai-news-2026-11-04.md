# 📚 주목 논문

## 1. LeanGuard: 증명으로 막는 툴 콜 가드레일

- **저자**: Sreehari Sankar, Debargha Ganguly, Vikash Singh 외 20인 (초록에 소속 미표기)
- **arXiv**: [2611.02332](https://arxiv.org/abs/2611.02332) (cs.AI)
- **핵심 기여**: 에이전트가 제안한 **모든 툴 콜을 환경에 닿기 전에** Lean4로 작성된 정책에 대해 검사하는 런타임. 평가는 fail-closed이고, 판정 절차가 LeanLTL 의미론과 동치임을 증명했다.
- **방법**: 정책은 상태 술어 + 실행 이력에 대한 과거시제 시간 연산자의 조합. 거부된 콜은 두 경로로 복구한다 — ① 위반 규칙과 힌트를 에이전트에 피드백, ② Lean 메타프로그래밍이 사용자 의도를 보존하는 인접 콜을 찾아 정책 허용을 **증명한 뒤** 모델 없이 실행.
- **결과**: τ-Bench(Qwen 0.8B~27B 5종)에서 비보호 에이전트는 정책이 금지한 콜을 33회 이상 실행, LeanGuard는 0회. DTap에서 직접 프롬프트 인젝션 성공률 57.9% → 5.9%. 피드백 모드에서는 과제 성공률이 유의미하게 떨어지지 않았다.
- 🛠 **에이전트 빌더 시사점**: "정규식 + 프롬프트로 된 가드레일"의 다음 단계가 뭔지 보여준다. 정책을 코드(증명 가능한 형식)로 내리고, 거부 시 구조화된 피드백을 돌려주는 설계는 지금 스택에서도 흉내 낼 수 있다.
- **한계**: 정책을 Lean4로 작성해야 하므로 진입 장벽이 높고, 평가가 Qwen 계열·벤치마크 환경에 한정된다.

## 2. CrossSWE: 멀티 레포 공동 개발 벤치마크

- **저자**: Silin Chen, Yuling Shi, Heng Lian, Zihan Zhang, Xiaodong Gu 외 (초록에 소속 미표기)
- **arXiv**: [2611.01484](https://arxiv.org/abs/2611.01484) (cs.SE)
- **핵심 기여**: 한 레포 안에서 난이도를 올리는 대신, **서로 의존하는 여러 레포를 동시에 고쳐야 하는** 실제 과제 171개(레포 165개, 기술 도메인 20개, 언어 13개)로 벤치마크를 구성했다.
- **방법**: 일부 레포만 고치면 의도한 동작이 안 나오도록 테스트로 "조율된 변경의 필요성"을 검증한 인스턴스만 채택.
- **결과**: 평가한 5개 LLM 중 최고 모델(GPT-6.1 Sol)이 Pass@1 58.48%. 가장 흔한 실패 유형은 레포 간 불일치(44.2%) — 인터페이스는 바꿨는데 호출부는 안 바꾸는 식이다.
- 🛠 **에이전트 빌더 시사점**: 단일 레포 SWE-bench가 포화되는 동안, 멀티 레포 작업(모노레포 아닌 폴리레포)은 아직 크게 열려 있다. 레포 간 인터페이스 일관성 검사를 에이전트 루프에 명시적 단계로 넣을 이유가 생겼다.
- **한계**: 5개 모델만 평가했고, 하네스 설계에 따라 수치가 크게 달라질 수 있다.

### 🟩 Codex — Guardian 거부, 한 번 더 따져 묻기 (opt-in)

- **분류**: Review / Workflow · **출처**: [commit a805143](https://github.com/openai/codex/commit/a8051434868233a8ba2d916440c20e92900d41a7)
- 💡 Guardian(위험 액션을 동기 검사하는 리뷰어)의 거부가 과하게 보수적일 때, 최종 판정 전에 **딱 한 번** 같은 리뷰 세션·증거·마감시한으로 재평가하는 `guardian_denial_reconsideration` 기능이 들어갔다(기본 off).
- 📝 config에서 기능을 켜고, 필요하면 재심용 개발자 메시지를 추가한다:

```toml
# ~/.codex/config.toml
[auto_review]
experimental_denial_reconsideration_prompt = "모노레포 내부 스크립트 실행은 낮은 위험으로 간주"
```

  커스텀 프롬프트는 1,000바이트 제한이고, 비워두면 "새 권한을 부여하지 않는" 내장 프롬프트를 쓴다.
- 🎯 거짓 양성 거부가 잦은 사내 레포(자체 CLI, 특이한 빌드 스크립트)에서 승인 피로를 줄일 때.
- ⚠️ 유효한 재평가만 거부를 뒤집는다. 재심이 실패하거나 타임아웃이면 원래 거부가 유지된다 — 즉 이 기능을 켜도 fail-closed는 깨지지 않지만, 재심 프롬프트에 권한을 넓히는 문구를 넣는 건 설계 취지에 어긋난다.
- ⭐ 추천도: Guardian 거부에 자주 걸리는 팀이라면 ★★★★☆, 아니면 기본 off 유지.

### 🟦 Claude Code — 훅 콜백에 onFailure: "block" (v2.1.317)

- **분류**: Hook · **출처**: [v2.1.317 릴리즈 노트](https://github.com/anthropics/claude-code/releases/tag/v2.1.317)
- 💡 지금까지 Agent SDK 훅 콜백이 죽으면 액션은 **그냥 실행**됐다(fail-open). 이제 `onFailure: "block"`을 주면 콜백 실패 시 액션이 차단된다.
- 📝 권한·보안 검사 훅에 적용:

```ts
// Agent SDK
hooks: {
  PreToolUse: [{
    hooks: [checkPermissions],   // 예외가 나면
    onFailure: "block",          // 액션을 실행하지 않고 차단
  }],
}
```

- 🎯 훅으로 시크릿 유출 검사, 프로덕션 경로 쓰기 금지 같은 **보안 불변식**을 지키는 경우. 검사 코드의 버그가 곧 가드레일 구멍이 되는 걸 막는다.
- ⚠️ 로깅·메트릭처럼 실패해도 무해한 훅에까지 걸면 일시적 오류가 세션 전체를 멈춘다. 검사 훅만 block, 관측 훅은 기존 동작으로 나누는 게 맞다.
- ⭐ 추천도: SDK로 가드레일 훅을 운영 중이라면 오늘 바로 적용 ★★★★★.

### 🟪 공통 — 거부할 땐 "왜"를 함께 돌려줘라

- **분류**: Workflow / Debugging · **출처**: [LeanGuard, arXiv 2611.02332](https://arxiv.org/abs/2611.02332)
- 💡 LeanGuard 실험에서, 툴 콜을 말없이 거부(bare denial)하는 것보다 **위반한 규칙 + 힌트**를 에이전트에 돌려주는 쪽이 반복 차단을 줄이고 5개 모델 중 4개에서 과제 성공률을 올렸다.
- 📝 가드레일이 거부를 반환할 때 에러 메시지를 구조화한다: `{"denied": true, "rule": "환불은 주문 상태가 delivered일 때만", "hint": "먼저 get_order_status를 호출"}` 식으로. 에이전트는 이걸 보고 스스로 경로를 수정한다.
- 🎯 자체 툴 게이트웨이, MCP 프록시, 승인 훅 등 거부를 반환하는 모든 지점.
- ⚠️ 힌트에 민감한 정책 내부 정보(탐지 기준 등)를 너무 자세히 쓰면 인젝션 공격자에게 우회 지도를 주는 셈이 된다. 규칙 이름과 다음 행동 수준까지만.
- ⭐ 추천도: 비용 제로에 효과 검증된 패턴 ★★★★★.
