# 📚 주목 논문

## Doc2Harness: 하네스 엔지니어링을 측정하다

- **저자**: Yuyao Ge, Shenghua Liu, Jiafeng Guo, Xueqi Cheng 외 (중국과학원 ICT·칭화대·북경대·동남대)
- **arXiv**: [2610.20344](https://arxiv.org/abs/2610.20344) (cs.SE, 10/14 공개, arXiv API 검증)
- **핵심 기여**: 에이전트 성능은 모델만큼 **하네스(루프·툴·컨텍스트 관리 코드)**에 달렸는데, 기존 벤치는 고정된 하네스 아래 과제 성공률만 쟀습니다. Doc2Harness는 **"하네스를 직접 만드는 능력" 자체를 측정**하는 첫 결정적(deterministic) 벤치마크입니다.
- **방법**: 1단계 — 모델이 인터페이스 스켈레톤 + 프런티어 하네스 12종의 동작을 정리한 개발 문서를 받고 컨테이너 안에서 하네스를 완성. 2단계 — 완성된 하네스를 **스크립트된 목 모델**이 구동하며 328개 테스트를 통과하는지, 모델로 간 요청·디스크 파일·종료 코드·출력 4개 채널로 채점.
- **결과(저자 보고)**: 19개 모델 중 최고 GPT-6 Astra가 53.05%, 최하위는 27.44%. **1등도 절반 가까이 실패**하고, 실패는 횡단 기능(cross-cutting)을 모듈로 쪼개는 지점에 몰립니다.
- 🛠 **에이전트 빌더 시사점**: "하네스 코드도 에이전트에게 맡기면 되지"가 아직은 환상이라는 데이터. 그리고 목 모델 + 4채널 관측이라는 채점 설계는 그대로 내 하네스의 테스트 레시피로 쓸 수 있습니다.
- **한계**: 문서 기반 재구축이라는 과제 설정이 실무의 점진적 하네스 개선과는 다르고, 코드가 아직 공개되지 않았습니다(프로젝트 페이지만 존재).

## Cortex: 컨텍스트를 가중치 메모리로 통합

- **저자**: Jintian Zhang, Ningyu Zhang 외 8인 (arXiv 페이지에 소속 미표기)
- **arXiv**: [2610.20399](https://arxiv.org/abs/2610.20399) (cs.CL, 10/14 공개, arXiv API 검증)
- **핵심 기여**: 컨텍스트로 얻은 성능 향상은 컨텍스트를 빼는 순간 사라집니다. Cortex는 이를 생물학적 기억 통합(consolidation)에 빗대 **"컨텍스트 이득을 가중치에 내재화하되 다른 능력은 보존"**하는 Memory Consolidation 문제로 정식화하고, 5개 과제군 테스트베드를 함께 제안합니다.
- **방법**: 컨텍스트가 쓰일 상황을 **예상 쿼리로 미리 생성**한 뒤, 컨텍스트 조건부 출력을 머지 가능한 저랭크/구조적 FFN 업데이트로 증류.
- **결과(저자 보고)**: 4B~120B 덴스·MoE 백본에서 통합-보존 파레토 프런티어 달성. 14B 모델에 순차 사실 편집 50회 후에도 **컨텍스트 이득의 88.9% 회복, 비대상 성능 99.8% 유지**.
- 🛠 **에이전트 빌더 시사점**: "매 세션 같은 문서를 다시 읽히는" 비용을 가중치로 옮기는 경로가 현실화되는 중. 장기 운영 에이전트의 메모리 설계에서 RAG·컨텍스트 캐시와 비교할 세 번째 선택지입니다.
- **한계**: 편집 50회 수준의 검증이고, 코드 링크가 아직 없습니다.

# 🛠 오픈소스 스포트라이트

실행 격리와 스킬 표준화 — 에이전트 운영 레이어의 양 날개가 나란히 트렌딩입니다.

- **[NVIDIA/openshell](https://github.com/NVIDIA/openshell)** (Rust, Apache-2.0, 0.1.x) — **자율 에이전트 플릿용 샌드박스 런타임**. 커널 수준에서 파일 접근·시스템 콜·네트워크를 정책으로 강제하고, 정책 변경은 적용 전에 형식 검증으로 "새로 열리는 위험한 접근"을 사람 리뷰로 돌립니다. 에이전트는 실제 크리덴셜을 보지 못하고, 승인된 엔드포인트로 나가는 요청에만 주입됩니다. Claude Code·Codex·OpenCode·Copilot 지원. 10/15에도 커밋이 활발합니다(클론 검증, 스타 수는 세션 API 제한으로 미검증). **활용**: `openshell sandbox create`로 에이전트별 정책 격리 — "에이전트에게 프로덕션 크리덴셜을 어떻게 주지?" 문제의 오픈소스 답안.
- **[addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)** (MIT, v0.6.13) — Addy Osmani의 **코딩 에이전트용 엔지니어링 스킬 25종 + 슬래시 커맨드 9개** 패키지. `/spec → /plan → /build → /test → /review → /ship`으로 개발 수명주기를 커맨드에 매핑하고, 서브에이전트 4종(코드 리뷰어·보안 감사 등)과 훅, 자체 평가 스위트까지 동봉. Claude Code 플러그인으로 설치되며 Codex 매니페스트도 유지합니다(클론 검증, 10/13 커밋·릴리즈 확인). **활용**: 팀 컨벤션을 스킬로 포장하는 법을 배우는 레퍼런스 — 특히 스킬마다 평가(evals)를 붙여둔 구조가 볼만합니다.

**1. 🟩 Codex / 카테고리: Workflow** — [커밋 #54380](https://github.com/openai/codex/commit/dcd9e954598cd5e9f80570204896d779c60c1ecd)

- 💡 **핵심**: 10/15 머지된 `/presets` — 자주 쓰는 입력을 **번호 달린 10개 슬롯**에 저장해 두고 꺼내 쓰는 TUI 피커입니다. 저장 대상은 ① 컴포저에 적어둔 프롬프트 텍스트 ② 현재 모델·리즈닝·속도 조합 두 종류이고, 설정의 `tui.presets`에 영속됩니다.
- 📝 **방법**: `/presets`로 피커를 열어 저장·교체·삭제. 같은 연작으로 `/permissions` 인라인 프로파일 선택(#54383), 권한 설정 프리셋 저장(#54385), 프리셋 단축키 메뉴(#54381)도 들어왔습니다.
- 🎯 **언제**: "리뷰 전용 프롬프트 + 상위 모델" 같은 콤보를 하루에도 몇 번씩 번갈아 쓸 때. 실행해도 작성 중이던 초안이 날아가지 않습니다.
- ⚠️ **주의**: 머지 직후 기능이라 릴리즈 버전 반영 시점은 확인 필요. 프리셋은 사용자 설정 레이어에 쓰이므로 팀 공유는 별도입니다.
- ⭐ 추천도: ★★★★☆

**2. 🟦 Claude Code / 카테고리: Workflow(무인 운영)** — [v2.1.301 커밋](https://github.com/anthropics/claude-code/commit/03b5892ee77de289bcd5dfa39f541525ade74aff)

- 💡 **핵심**: 무인 재시도 모드(`CLAUDE_CODE_RETRY_WATCHDOG`)에 **`CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`**가 추가됐습니다. 사용량 한도에 걸렸을 때 리셋 시점이 이 상한보다 멀면, 무한정 기다리는 대신 요청을 끝냅니다.
- 📝 **방법**: cron·CI에서 도는 헤드리스 세션이라면:

```bash
export CLAUDE_CODE_RETRY_WATCHDOG=1
# 429/529 대기 상한 (기존)
export CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS=600000
# 사용량 한도 리셋 대기 상한 (2.1.301 신규)
export CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS=900000
```

- 🎯 **언제**: 야간 배치·자동 리뷰처럼 사람이 없는 파이프라인. "한도 리셋까지 4시간 대기"로 잡이 물려 있는 것보다 빨리 실패하고 다음 스케줄에 재시도하는 편이 낫습니다.
- ⚠️ **주의**: 상한을 너무 짧게 잡으면 일시적 혼잡에도 잡이 죽습니다. 스케줄 간격보다 약간 짧게.
- ⭐ 추천도: ★★★★☆

**3. 🟪 공통 / 카테고리: Eval(하네스 테스트)** — [arXiv 2610.20344](https://arxiv.org/abs/2610.20344)

- 💡 **핵심**: Doc2Harness의 채점 설계를 훔쳐올 것 — **하네스는 진짜 모델 없이 테스트할 수 있습니다.** 스크립트된 목 모델이 정해진 응답(툴 콜 포함)을 돌려주게 하고, 하네스가 올바로 동작하는지를 관측 가능한 4채널로 단언합니다.
- 📝 **방법**: ① 모델 API를 가짜 서버로 치환(요청 기록) ② 시나리오별 고정 응답 스크립트 작성(툴 콜 실패 → 재시도 유도 포함) ③ 모델로 간 요청·디스크 파일·종료 코드·stdout 4가지로 assert.
- 🎯 **언제**: 하네스의 루프·재시도·컨텍스트 조립 로직을 리팩터링할 때. LLM 호출 비용 0원으로 결정적 회귀 테스트가 돕니다.
- ⚠️ **주의**: 목 테스트는 하네스 결함만 잡습니다. 모델 품질 회귀는 별도의 실모델 평가가 필요합니다.
- ⭐ 추천도: ★★★★★
