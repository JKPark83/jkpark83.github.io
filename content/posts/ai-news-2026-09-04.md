# 🔥 오늘의 핵심

Meta [Muse Spark 1.3](https://www.investing.com/news/stock-market-news/meta-unveils-muse-spark-13-with-coding-improvements-93CH-4886657)이 DeepSWE v1.1에서 75.4%로 Claude Opus 5(74.0%)를 넘었다고 발표했다. 단, 모델과 같이 학습된 Muse Code 하네스로 잰 벤더 수치다. 같은 날 BAAI의 [Repo-To-Skill 논문](https://arxiv.org/abs/2609.02749)은 모델·하네스를 그대로 두고 스킬 라이브러리만 붙여 MLE-bench 134% 향상을 보고했다. 결론은 하나로 모인다 — 이제 에이전트 성능은 모델 단독이 아니라 **모델 + 하네스 + 스킬 조합**의 성능이다.

![2026년 9월 4일 AI 변화 지도](/images/ai-news-2026-09-04/change-map.svg)

*오늘의 변화 지도 — 모델 발표·논문·오픈소스가 전부 "스킬과 하네스"를 가리킨다.*

# 🤖 모델 & 릴리즈 레이더

- **Muse Spark 1.3 (9/2)** — DeepSWE v1.1 75.4%(Opus 5 74.0%, GPT-5.6 Sol 72.7%), Terminal-Bench 2.1 88.8%로 GPT-5.6 Sol과 동률. [1.2 대비 DeepSWE +16포인트](https://www.techtimes.com/articles/326417/20260903/muse-spark-13-jumps-16-points-deepswe-how-meta-training-loop-closed-gap.htm) 점프다. 1M 컨텍스트, MRCR 512K–1M 구간 98.1%(GPT-5.6 Sol 73.8%)로 장문 유지력이 특히 세다. 가격은 표준 $1.25/$4.25에 더해 **$0.10/$0.20 Contributor 티어**가 생겼는데, 이쪽은 내 데이터가 Meta 학습에 쓰인다. 에이전트 로그를 통째로 흘려보내게 되니 업무용은 티어 선택을 명시적으로 하자. 1.2 때 약속한 오픈 웨이트는 이번에도 "곧". ([벤치마크 정리](https://www.datacamp.com/blog/muse-spark-1-3), [스펙](https://llm-stats.com/models/muse-spark-1.3))
- **Codex CLI 0.153.1** — 안정판 태그 확인. 터미널이 포커스를 잃으면 자동으로 대화 요약 카드를 만들어주는 `auto_recap`(아래 팁 참고), 앱별 계정 단위 승인 설정, 실험적 `context_management` 모드가 config 스키마에 추가됐다. ([릴리즈 태그](https://github.com/openai/codex/releases/tag/rust-v0.153.1))
- **Claude Code 2.1.259** — 조직이 모든 사용자에게 HTTP/SSE MCP 서버를 배포하는 `managedMcpServers` 관리 설정, 무인 헤드리스 호스트용 `--permission-prompts none` 플래그, `claude plugin validate --json` 추가. 동시 세션이 서로의 `~/.claude.json`을 되돌리던 버그도 잡혔다. ([체인지로그](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

# 📚 주목 논문

## Repo-To-Skill — 리포 1,000개를 스킬 5,000개로 증류하니 MLE-bench +134%

- **저자/소속**: Jianlyu Chen 외, BAAI (VectorSpaceLab)
- **arXiv**: [2609.02749](https://arxiv.org/abs/2609.02749) (cs.AI)
- **핵심 기여**: 에이전트에 빠져 있는 "운영 지식"(방법을 아는 것과 돌아가게 만드는 것의 차이)을 리포지토리·논문에서 **검증된 스킬**로 증류하는 에이전트 DisCo를 제안. 태스크 무관 증류로 널리 쓰이는 ML 리포 1,000개를 스킬 5,000+개(20개 영역·178개 패밀리)의 AREX-Skill Library로 만들고, 태스크 지향 증류로 당장 필요한 스킬을 즉석 생산한다.
- **결과**: GPT-5.5 백본·하네스·실행 예산을 고정한 채 스킬만 장착하면 MLE-bench +134.3%, PaperBench +34.4%, PassNet +14.0%, FrontierCS +9.2%.
- 🛠 **에이전트 빌더 시사점**: Claude Code 스킬을 손으로 짜는 대신, 우리 팀이 매일 쓰는 사내 리포를 스킬로 증류하는 파이프라인 자체를 자동화할 수 있다는 근거 수치가 나왔다.
- **한계**: ML 연구 도메인 중심 검증이라 일반 소프트웨어 엔지니어링으로의 전이는 미확인.

![DisCo 스킬 증류 파이프라인](/images/ai-news-2026-09-04/disco-pipeline.svg)

*Creator 모드가 리포를 스킬 그래프로 증류하고, Researcher 모드가 필요한 만큼만 로드한다.*

## HarnessDev — LLM은 자기 하네스를 만들 수 있는가 (아직은 부분적으로만)

- **저자/소속**: Yuhao Wu 외, ByteDance Seed
- **arXiv**: [2609.01437](https://arxiv.org/abs/2609.01437) (cs.SE)
- **핵심 기여**: 평가 단위를 "태스크 출력"에서 **"실행 가능한 인프라"**로 옮긴 벤치마크. Creation 단계에서 최소 시드로부터 하네스를 처음부터 만들게 하고, Evolution 단계에서 실행 피드백으로 스스로 개선하게 한다. 6개 모델 × 4개 도메인 × 다운스트림 2,207개 인스턴스.
- **결과**: LLM이 만든 하네스는 코드·검색/리서치에서는 성숙한 사람 제작 하네스에 크게 못 미치지만, **글쓰기·ML 실험에서는 대등하거나 앞섰다**. Evolution의 개선은 불안정하고 held-out 태스크로는 부분 전이에 그친다.
- 🛠 **에이전트 빌더 시사점**: "에이전트가 자기 도구를 만든다"는 데모를 믿기 전에 이 축으로 평가해 보자. 특히 실행 토큰 비용 편차가 크다는 결과는 자작 하네스 도입 전 비용 가드레일이 필수라는 뜻.
- **한계**: 하네스 품질을 다운스트림 벤치마크 점수로 환원하므로 유지보수성·보안 같은 축은 안 잡힌다.

# 🛠 오픈소스 스포트라이트

이 세션은 GitHub API 조회가 막혀 있어 스타 수는 검증하지 못했다. 두 리포 모두 클론으로 존재·라이선스·최신 커밋을 직접 확인했다.

## badlogic/pi-mono — Pi Agent Harness

- [github.com/badlogic/pi-mono](https://github.com/badlogic/pi-mono) · TypeScript · 최신 커밋 9/4 (활발)
- 멀티 프로바이더 LLM API(`pi-ai`), 툴 콜링·상태 관리 런타임(`pi-agent-core`), TUI, 코딩 에이전트 CLI(`pi-coding-agent` v0.84.4)를 한 모노리포로 묶은 하네스 툴킷. 내장 권한 시스템이 없다고 명시하고 Docker/샌드박스 패턴 문서를 제공하는 점이 솔직하다.
- **활용**: SDK 없이 자체 에이전트 루프를 처음부터 짜고 있다면, 루프·툴 콜링·프로바이더 추상화를 이걸로 대체하고 도메인 로직에만 집중할 수 있다.

## VectorSpaceLab/AREX-Skill — 스킬 5,000+개 라이브러리

- [github.com/VectorSpaceLab/AREX-Skill](https://github.com/VectorSpaceLab/AREX-Skill) · Apache-2.0 · 최신 커밋 9/3
- 위 Repo-To-Skill 논문의 공식 구현체. 검증된 스킬 5,000+개와 DisCo CLI(npm `@arex-skill/disco` v0.2.1)를 제공하고, README에서 Codex·Claude Code·Pi 연동을 명시한다.
- **활용**: ML 관련 태스크를 시키는 에이전트라면 관련 영역 스킬 몇 개만 설치해 A/B 해볼 것. 논문 수치가 내 워크로드에서도 나오는지가 관전 포인트.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex · 카테고리: Workflow** — [rust-v0.153.1 릴리즈](https://github.com/openai/codex/releases/tag/rust-v0.153.1)

- 💡 0.153부터 터미널이 포커스를 잃으면 자동으로 대화 요약(recap)을 만들어 준다. 기본 켜짐.
- 📝 여러 Codex 세션을 병렬로 돌릴 때 그대로 두면 되고, 요약이 시끄러우면 끄고 수동 `/recap`만 쓴다:

```toml
# ~/.codex/config.toml
[tui]
auto_recap = false   # 끄더라도 /recap은 그대로 사용 가능
```

- 🎯 탭 3~4개로 에이전트를 병렬 운용하며 "저 세션 어디까지 했더라"를 반복하는 사람.
- ⚠️ config 스키마로 확인된 기능이며, recap 생성도 토큰을 쓴다. 저예산 세션은 꺼두는 게 낫다.
- ⭐ 병렬 세션 운용자에게 강추.

**🟦 Claude Code · 카테고리: Workflow** — [v2.1.259 체인지로그](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

- 💡 `--permission-prompts none`: 프롬프트를 띄울 상황이 오면 **무조건 거부**하고 계속 진행한다. 무인 CI·크론 환경의 "프롬프트 대기로 영원히 멈춤"이 사라진다.
- 📝 헤드리스 배치 작업 예시:

```bash
claude -p "리포 스캔 후 리포트 생성" \
  --permission-prompts none \
  --allowedTools "Read,Grep,Glob,Bash(git log:*)"
```

- 🎯 사람이 없는 스케줄 작업. 허용 목록에 없는 행동은 조용히 거부되므로 실패가 예측 가능해진다.
- ⚠️ 거부가 곧 기능 저하일 수 있다. 로그에서 어떤 호출이 거부됐는지 꼭 확인하고 allowlist를 보강하자.
- ⭐ CI에서 Claude Code를 돌린다면 오늘 바로 적용.

**🟪 공통 · 카테고리: Eval** — [EarlyEval, arXiv 2609.02783](https://arxiv.org/abs/2609.02783)

- 💡 SJTU·SMU 연구진: 에이전트 평가는 끝까지 돌려야 채점이 되지만, 실패 궤적 다수는 **초반 몇 스텝에서 이미 판별 가능**하다. 조기 결과 예측으로 평가 비용을 크게 줄인다.
- 📝 자체 에이전트 평가 스위트에 "N스텝 시점 중간 판정자"를 넣고, 확신도가 높으면 조기 종료 → 절약한 예산으로 케이스 수를 늘린다.
- 🎯 평가 1회가 수십 분·수천 툴 콜인 장기 태스크 스위트.
- ⚠️ 늦게 역전하는 궤적(초반 삽질 후 성공)이 많은 태스크에는 판정자 보정 없이 쓰면 위험.
- ⭐ 평가 비용이 병목인 팀에 추천.
