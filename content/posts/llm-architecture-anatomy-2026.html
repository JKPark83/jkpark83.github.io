1. 도입 — 103개 모델을 늘어놓고 보니 보이는 것

이번 주 아키텍처 공부에 불이 붙었습니다. 지난 9월 10일 Sebastian Raschka가 LLM Architecture Gallery를 업데이트했습니다. GPT-2부터 최신 하이브리드 모델까지 오픈 가중치 LLM 103개의 구조도를 팩트 시트(어텐션 방식, 디코더 타입, 파라미터 수, 핵심 설계 선택)와 함께 한 장씩 정리한 자료입니다. 그리고 닷새 뒤인 9월 15일, 이 갤러리에 실린 모델들을 PyTorch로 처음부터 다시 구현하는 레포 OpenArch가 Hacker News 프론트페이지에 올랐습니다(132점, 31댓글). 모델 하나당 읽기 좋은 model.py 파일 하나 — 성능이 아니라 읽기에 최적화한 학습용 레포입니다.

"아키텍처는 연구자들 관심사 아닌가?"라고 생각할 수 있는데, 103개를 시간순으로 늘어놓고 보면 정반대의 그림이 나옵니다. 아키텍처의 변화는 대부분 정확도가 아니라 서빙 경제학을 향해 움직였습니다. GQA도, MLA도, 슬라이딩 윈도우도, MoE도, 하이브리드 어텐션도 전부 "같은 품질을 더 싼 메모리와 더 싼 연산으로"가 목표입니다. 즉 여러분이 모델을 고르고, GPU 메모리를 계산하고, 추론 비용을 견적 낼 때 보는 숫자들이 바로 이 설계 선택에서 결정됩니다. 모델 카드의 "총 파라미터 수" 한 줄만 보고 판단하면 왜 안 되는지, 오늘 글이 끝나면 명확해질 겁니다.

그리고 한 가지 반전이 있습니다. 2026년의 1조 파라미터 모델도, 2019년 GPT-2와 뼈대는 거의 같습니다.

2. 배경 — GPT-2 뼈대와 네 개의 다이얼

모든 디코더 LLM은 이 뼈대를 공유합니다. 토큰 임베딩 → 같은 구조의 트랜스포머 블록 N개(각 블록은 어텐션 + 피드포워드 네트워크(FFN)) → LM 헤드. GPT-2가 이 형태였고, DeepSeek-V3도 Kimi K2도 이 형태입니다. 그래서 아키텍처 비교는 "완전히 다른 기계 100종"이 아니라, 하나의 기계에 달린 다이얼 네 개를 어디에 맞췄는가의 문제가 됩니다.

네 다이얼 중 서빙 비용에 가장 크게 작용하는 것이 어텐션(①)과 MoE(②)입니다. 이 글도 여기에 집중합니다. 정규화(③)와 위치 인코딩(④)은 훈련 안정성과 긴 컨텍스트 일반화에 관한 선택이라 짧게만 짚겠습니다 — LayerNorm은 거의 전부 RMSNorm으로 바뀌었고, OLMo 2는 정규화를 블록 뒤쪽으로 옮기고 쿼리·키에 별도 RMSNorm을 거는 QK-Norm을 채택했으며, Gemma 3는 아예 어텐션 앞뒤 양쪽에 정규화를 둡니다. 위치 인코딩은 RoPE(회전 위치 임베딩)가 표준이 됐고, 최근에는 일부 레이어에서 위치 정보를 아예 빼는(NoPE) 실험까지 등장했습니다.

3. 다이얼 ① 어텐션 — KV 캐시와의 전쟁 (GQA → MLA)

먼저 왜 어텐션이 문제인지부터 봅니다. 추론 중 모델은 새 토큰을 생성할 때마다 이전 토큰 전부의 키(K)·값(V) 벡터가 필요합니다. 매번 다시 계산하면 낭비니까 한 번 계산한 K/V를 GPU 메모리에 쌓아 두는데, 이것이 KV 캐시(KV cache)입니다. 문제는 크기입니다. KV 캐시는 레이어 수 × K/V 헤드 수 × 컨텍스트 길이에 비례해 자랍니다. 컨텍스트가 128K쯤 되면 KV 캐시가 모델 가중치보다 커지는 일도 흔합니다. 동시 접속자를 몇 명 받을 수 있는지가 사실상 KV 캐시 크기로 결정되는 셈입니다.

1단계: GQA(grouped-query attention). 원조 멀티헤드 어텐션(MHA)은 쿼리 헤드 32개면 K/V 헤드도 32개입니다. GQA는 쿼리 헤드 여러 개가 K/V 헤드 하나를 공유하게 만듭니다. 예를 들어 쿼리 32개 : K/V 8개면 캐시가 1/4로 줄어듭니다. 품질 손실이 거의 없다는 것이 확인되면서 Llama, Qwen, Gemma 등 대부분의 모델이 채택한 사실상의 표준입니다. 코드로 보면 놀랄 만큼 단순합니다.

{{< highlight python >}} # GQA의 핵심: K/V 헤드를 쿼리 헤드 수만큼 복제해서 맞춰준다 # n_heads=32, n_kv_heads=8 이면 쿼리 4개가 K/V 1개를 공유 group_size = n_heads // n_kv_heads # 32 // 8 = 4 k = k.repeat_interleave(group_size, dim=1) # (B, 8, T, D) → (B, 32, T, D) v = v.repeat_interleave(group_size, dim=1) # 캐시에는 복제 전의 (B, 8, T, D)만 저장하면 된다 → 캐시 1/4 {{< /highlight >}}

2단계: MLA(multi-head latent attention). DeepSeek이 DeepSeek-V2 논문에서 제안한 방식으로, 헤드 수를 줄이는 대신 K/V를 저차원 잠재(latent) 벡터로 압축해서 캐시합니다. 어텐션을 계산할 때만 잠재 벡터를 헤드별 K/V로 복원합니다. 압축 파일을 저장해 두고 쓸 때만 푸는 것과 같습니다.

{{< highlight python >}} # MLA의 아이디어 (개념 스케치) c_kv = x @ W_down_kv # (B, T, d_latent) ← 캐시에는 이것만 저장 # 어텐션 계산 시점에만 헤드별 K/V로 복원(업프로젝션) k = c_kv @ W_up_k # (B, T, n_heads * d_head) v = c_kv @ W_up_v # 실제 구현은 W_up_k를 쿼리 쪽에 흡수해 복원 비용도 줄인다 {{< /highlight >}}

효과는 극적입니다. DeepSeek-V2는 이전 세대(DeepSeek 67B) 대비 KV 캐시를 93.3% 줄이고 최대 생성 처리량을 5.76배 올렸다고 보고했습니다. 더 흥미로운 건 품질입니다. GQA/MQA가 "캐시를 줄이는 대신 품질을 조금 양보"하는 트레이드오프였다면, DeepSeek의 어블레이션에서 MLA는 MHA보다 오히려 나은 성능을 보였습니다. 이 설계는 DeepSeek-V3와 R1로 이어졌고, Moonshot AI의 1조 파라미터 모델 Kimi K2도 그대로 가져다 썼습니다.

4. 다이얼 ①-보강 — 창문을 좁히다: 슬라이딩 윈도우와 attention sinks

K/V를 작게 만드는 것과 별개로, "애초에 모든 토큰을 다 볼 필요가 있나?"라는 접근도 있습니다. 슬라이딩 윈도우 어텐션(sliding window attention)은 각 토큰이 최근 W개 토큰만 보게 제한합니다. 창문 밖은 못 보는 대신, 해당 레이어의 KV 캐시가 컨텍스트 길이와 무관하게 W로 고정됩니다.

다만 전 레이어를 윈도우로 막으면 먼 거리 정보가 끊기니까, 요즘 모델은 로컬 레이어와 글로벌(전체) 레이어를 섞습니다. Gemma 3는 로컬 5 : 글로벌 1 비율에 윈도우 1024를 썼습니다(Gemma 2는 1:1에 윈도우 4096이었습니다). 이 변경만으로 긴 컨텍스트에서 KV 캐시 메모리 오버헤드를 약 60%에서 15% 미만으로 줄였고, 퍼플렉시티 영향은 미미했다고 보고합니다. OpenAI의 오픈 모델 GPT-OSS도 같은 계열입니다 — 레이어를 하나 걸러 하나씩 윈도우 128짜리 로컬 어텐션과 전체 어텐션을 교대로 배치했습니다.

GPT-OSS에는 재미있는 장치가 하나 더 있습니다. attention sinks입니다. 어텐션의 softmax는 합이 1이 되어야 해서, 볼 게 없는 토큰도 어딘가에는 어텐션을 "쏟아야" 합니다. GPT-OSS는 각 헤드에 학습된 스칼라 편향을 softmax 분모에 추가해, 헤드가 필요 없을 때 아무 토큰에도 주의를 주지 않고 넘어갈 수 있는 배출구를 만들었습니다. 윈도우 어텐션에서 앞쪽 토큰이 잘려 나가도 어텐션 분포가 무너지지 않게 하는 안전장치입니다.

5. 다이얼 ② FFN → MoE — 희소해질수록 이긴다

두 번째 다이얼은 블록의 나머지 절반, FFN입니다. 파라미터가 많을수록 모델은 똑똑해지지만, dense 모델은 토큰 하나를 처리할 때 모든 파라미터가 연산에 참여합니다. MoE(mixture-of-experts)는 FFN을 여러 개의 "전문가"로 쪼개고, 라우터가 토큰마다 소수의 전문가만 골라서 통과시킵니다. 지식(총 파라미터)은 크게, 토큰당 연산(활성 파라미터)은 작게 — 병원에 전문의 수백 명이 있지만 환자 한 명은 두세 과만 들르는 구조입니다.

2026년 기준 주요 오픈 모델의 MoE 설정을 비교하면 방향이 뚜렷하게 보입니다.

모델총 파라미터활성 파라미터활성 비율전문가 수토큰당 활성공유 전문가
DeepSeek-V3 / R1671B~37B~5.5%25681
Kimi K21.04T~32B~3.1%38481
Qwen3-Next-80B80B~3B~3.8%512101
GPT-OSS-20B20B3.6B18%324없음

표에서 두 가지가 읽힙니다. 첫째, 전문가는 많아지고 활성 비율은 낮아지는 초희소(ultra-sparse) 경쟁입니다. DeepSeek-V3의 256개에서 Kimi K2는 384개로, Qwen3-Next는 512개로 늘었고, 활성 비율은 3%대까지 내려왔습니다. Kimi K2가 1조 파라미터인데 토큰당 실제로 도는 건 32B라는 뜻입니다. 둘째, DeepSeek 계열은 항상 통과하는 공유 전문가(shared expert) 1개를 둡니다. 어떤 토큰이든 필요한 공통 패턴(문법 처리 같은)을 여기에 몰아넣어, 나머지 전문가들이 진짜 전문 지식에 집중하게 하는 설계입니다. 세부 설계는 갈립니다 — GPT-OSS는 공유 전문가 없이 32개 중 4개만 뽑고, 라우팅 확률도 뽑힌 4개 안에서만 softmax를 취합니다.

디테일 하나: DeepSeek-V3는 61개 블록 중 첫 3개 블록만 dense FFN을 씁니다. 초반 레이어는 토큰의 기초 표현을 만드는 구간이라 라우팅이 불안정해지기 쉽기 때문입니다. 이런 "논문에는 한 줄, 구현에는 분기 하나"인 선택들이 model.py를 직접 읽을 때 가장 잘 보입니다.

6. 다이얼 ①-교체 — 어텐션을 갈아끼우다: Gated DeltaNet 하이브리드

GQA·MLA·슬라이딩 윈도우가 어텐션을 "다이어트"시키는 접근이라면, 가장 최근의 흐름은 어텐션 자체를 선형 시퀀스 모델로 교체하는 것입니다. 표준 어텐션은 컨텍스트가 길어질수록 연산이 제곱으로 늘고 KV 캐시도 선형으로 자랍니다. 반면 Gated DeltaNet(NVIDIA, ICLR 2025) 같은 선형 어텐션은 고정 크기 행렬 상태 하나를 토큰마다 갱신합니다. RNN처럼 상태가 안 자라니, 컨텍스트가 100만 토큰이어도 메모리는 그대로입니다. 이름의 두 요소가 각각 역할이 있습니다 — 게이트(gate)는 낡은 기억을 빠르게 지우고, 델타 룰(delta rule)은 "지금 저장된 값과 새 값의 차이"만큼만 정밀하게 고쳐 씁니다.

물론 공짜는 아닙니다. 고정 크기 상태는 일종의 손실 압축이라, 아주 먼 과거의 특정 토큰을 정확히 되짚는 회상(recall) 능력은 표준 어텐션보다 약합니다. 그래서 실전 모델은 전부 하이브리드로 갑니다. Qwen 팀의 Qwen3-Next-80B-A3B가 대표적입니다. 48개 레이어를 [Gated DeltaNet ×3 + 게이트 어텐션 ×1] 패턴 12번으로 구성했습니다. 레이어의 75%는 상태가 고정된 선형 계층, 25%만 정밀 회상용 표준 어텐션입니다. 여기에 위에서 본 512-전문가 초희소 MoE와 멀티 토큰 예측(multi-token prediction)까지 얹어, Qwen3-32B 대비 훈련 비용 ~10%로 더 나은 성능을 내고 32K 이상 컨텍스트에서 추론 처리량 10배를 보고했습니다. 네이티브 컨텍스트는 262,144 토큰입니다.

이 계보는 일회성 실험이 아닙니다. 2026년의 Qwen3.5도 같은 하이브리드 구조(4층마다 1층만 전체 어텐션)를 이어받았고, Maxime Labonne이 분석 글 제목을 "Nobody Agrees on Attention Anymore"라고 붙였을 정도로, 지금 어텐션 설계는 오픈 모델 진영에서 가장 뜨거운 분기점입니다.

7. 실전 — OpenArch로 직접 해부해 보기

이제 직접 해부해 볼 차례입니다. OpenArch는 모델마다 폴더 하나, 그 안에 model.py와 설계 선택을 요약한 README.md가 있는 구조입니다. 프로덕션 코드(vLLM, transformers)는 최적화 때문에 읽기 어렵지만, 여기는 학습용이라 한 파일에서 아키텍처 전체가 보입니다.

{{< highlight bash >}} git clone https://github.com/anuj0456/OpenArch.git cd OpenArch/text ls # deepseek-R1 gemma3-27B glm4.5-355B gpt-oss-20B gpt2-1.5B # grok2.5-270B kimmi-K2 llama2-7B llama3-8B llama4-400B ... {{< /highlight >}}

추천 독서 순서는 진화 순서 그대로입니다. 각 단계에서 "이전 모델과의 diff"만 확인하면 되니 부담이 적습니다.

  1. gpt2-1.5B — 기준점. MHA + dense FFN + LayerNorm + 학습된 절대 위치.
  2. llama3-8B — 현대의 기본형. RoPE, GQA, RMSNorm, SwiGLU가 어떻게 갈아 끼워졌는지.
  3. gemma3-27B — 슬라이딩 윈도우 5:1 교대 배치와 정규화 위치 실험.
  4. gpt-oss-20B — 윈도우 128 교대 + attention sinks + 공유 전문가 없는 MoE.
  5. deepseek-R1 — MLA와 256+1 전문가 MoE, 첫 3블록 dense 같은 디테일.
  6. qwen3-80B-A3B(작성 중) — Gated DeltaNet 하이브리드. 완성 전이라면 NVlabs 공식 구현을 보면 됩니다.

읽을 때 팁 하나. 논문 그림보다 먼저 Hugging Face의 config.json을 열어 보세요. 이 글에서 다룬 다이얼이 전부 설정 키로 드러납니다. 아래 키만 읽어도 모델의 서빙 특성을 대략 견적 낼 수 있습니다.

{{< highlight json >}} { "num_hidden_layers": 24, "num_attention_heads": 64, "num_key_value_heads": 8, // < num_attention_heads 이면 GQA "sliding_window": 128, // 있으면 윈도우 어텐션 (교대 패턴은 별도 키) "num_local_experts": 32, // 있으면 MoE "num_experts_per_tok": 4, // 토큰당 활성 전문가 → 활성 파라미터 결정 "rope_theta": 150000 // RoPE 주파수 — 긴 컨텍스트 확장의 흔적 } {{< /highlight >}}

8. 흔한 실수 · 팁

실수 1 — 총 파라미터로 서빙 비용을 견적 낸다. 추론 속도와 토큰당 연산 비용을 결정하는 건 활성 파라미터이고, 동시 처리량을 결정하는 건 KV 캐시입니다. "1조 파라미터 Kimi K2"의 토큰당 연산은 32B급입니다. 반대 방향의 함정도 있습니다 — 활성 3B라고 Qwen3-Next가 3B 모델처럼 "가벼운" 건 아닙니다. 다음 실수로 이어집니다.

실수 2 — MoE가 GPU 메모리를 아껴 준다고 생각한다. 라우터가 어떤 전문가를 고를지 토큰마다 달라지므로, 전문가 전원이 GPU 메모리에 올라가 있어야 합니다. MoE가 아끼는 건 연산(FLOPs)이지 VRAM이 아닙니다. 80B MoE를 서빙하려면 80B 전부를 담을 메모리가 필요합니다.

실수 3 — 슬라이딩 윈도우 모델은 KV 캐시 걱정이 없다고 생각한다. 로컬 레이어의 캐시는 윈도우 크기로 고정되지만, 사이사이의 글로벌 레이어 캐시는 여전히 컨텍스트에 비례해 자랍니다. Gemma 3의 "60% → 15% 미만"이라는 숫자가 정확히 이 이야기입니다 — 극적으로 줄지만 0이 되지는 않습니다.

실수 4 — 선형 어텐션을 무손실 대체재로 이해한다. 고정 크기 상태는 본질적으로 손실 압축입니다. 긴 문서 중간의 특정 문장을 정확히 되짚는 과제에서는 표준 어텐션이 우위입니다. Qwen3-Next가 100%가 아니라 75%만 DeltaNet으로 바꾼 이유, 즉 하이브리드가 기본형이 된 이유가 이것입니다.

팁 — 새 모델이 나오면 세 가지만 확인하세요. ① 어텐션: K/V를 어떻게 줄였나(GQA 비율, MLA, 윈도우, 하이브리드 비율). ② MoE: 총/활성 파라미터와 공유 전문가 유무. ③ 컨텍스트: 네이티브 길이와 RoPE 확장 방식. 이 세 줄이면 벤치마크 표보다 서빙 특성을 더 정확히 예측할 수 있습니다.

9. 마무리 (TL;DR)

  • 오픈 LLM 103개를 정리한 Raschka의 아키텍처 갤러리(9/10 업데이트)와, 이를 PyTorch로 재구현하는 OpenArch 레포(9/15 HN 프론트페이지)가 이번 주 아키텍처 공부 열풍의 진원지입니다.
  • 2026년 모델도 뼈대는 GPT-2와 같습니다. 차이는 네 개의 다이얼 — 어텐션, FFN(MoE), 정규화, 위치 인코딩 — 이고, 변화의 동력은 정확도가 아니라 서빙 경제학입니다.
  • 어텐션의 진화는 KV 캐시와의 전쟁입니다: GQA(헤드 공유, 캐시 1/4) → MLA(잠재 압축, −93.3%에 품질은 MHA 이상) → 슬라이딩 윈도우 + attention sinks(Gemma 3 5:1/1024, GPT-OSS 128 교대).
  • MoE는 초희소 경쟁 중입니다: DeepSeek-V3 671B/37B(256+1 전문가) → Kimi K2 1.04T/32B(384) → Qwen3-Next 80B/3B(512). MoE는 연산을 아끼는 것이지 VRAM을 아끼는 게 아닙니다.
  • 최신 흐름은 어텐션 자체의 교체입니다: Qwen3-Next는 레이어의 75%를 고정 상태 Gated DeltaNet으로 바꾸고 25%만 표준 어텐션을 남겨, 훈련 비용 ~10%·긴 컨텍스트 처리량 ~10배를 보고했습니다. Qwen3.5도 이 계보를 잇습니다.
  • 새 모델 평가는 config.json 세 줄부터: K/V 절감 방식, 총/활성 파라미터, 컨텍스트 처리 방식.
