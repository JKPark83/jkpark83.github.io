# 📚 주목 논문

## Bilevel Coordinated Reflection (BCR)

- **저자/소속**: Yihang Chen, Meng Fang, Jun Wang 외 — UCL AI Centre, University of Liverpool, Huawei
- **arXiv**: [2609.02750](https://arxiv.org/abs/2609.02750) (cs.AI) · HF Daily Papers 상위권
- **핵심 기여**: 오케스트레이터-워커 멀티에이전트 시스템의 리플렉션(자기 개선)을 게임이론으로 모델링하고, "트랜스크립트만 관찰하는 게이트는 텍스트로 구분되지 않는 환경들에서 일관된 개선이 불가능하다"는 불가능성 정리를 증명했다.
- **방법**: 메모리 수정 후보를 실제 평가에서 돌려보고 리스크가 확실히 감소할 때만 채택하는 SRMA(Stochastic Reflective Memory Ascent)를 제안. 보정된 평가 하에서 기하/다항 속도 수렴을 보장한다.
- **결과**: SWE-bench 500 인스턴스에서 72.2% (공개 mini-SWE-agent 기준선 70.8%, 논문 자체 보고).
- 🛠 **에이전트 빌더 시사점**: "성찰 텍스트가 그럴듯한가"가 아니라 "평가 점수가 실제로 올랐는가"로 메모리·프롬프트 업데이트를 승인하라. LLM-as-judge만으로 자기 개선 루프를 돌리는 설계에 대한 이론적 경고다.
- **한계**: 수렴 보장은 평가가 보정돼 있다는 가정에 의존. 평가셋 구축 비용은 별도.

![리플렉션 게이팅 비교](/images/ai-news-2026-09-08/bcr-gate.svg)

*트랜스크립트만 보는 게이트 vs 환경 기반 게이트(SRMA). 오른쪽만 수렴이 보장된다.*

## MaxKernel: TPU 커널 생성 에이전트

- **저자/소속**: Shangkun Wang 외 — Google (AI-Hypercomputer)
- **arXiv**: [2609.04523](https://arxiv.org/abs/2609.04523) (cs.AI)
- **핵심 기여**: TPU 커널 작성을 자동화하는 멀티에이전트 시스템. HITL(협업) / Auto(완전 자동 최적화 루프) / 그래프 기반 탐색, 세 가지 운용 모드를 하나의 서브에이전트 풀(계획·구현·자가 디버깅·테스트·프로파일링) 위에 얹었다.
- **결과**: 자체 벤치마크 JaxBench(커널 과제 50개)에서 전문가 수작업 튜닝 수준의 구현을 생성(논문 자체 보고). 에이전트 [코드 공개](https://github.com/AI-Hypercomputer/accelerator-agents/tree/main/MaxKernel).
- 🛠 **에이전트 빌더 시사점**: "컴파일러 피드백·프로파일러 수치"라는 확실한 보상 신호가 있는 도메인은 에이전트 루프가 가장 잘 먹히는 곳이다. 같은 패턴(실측 지표 → 자동 반복)을 자기 도메인에서 찾아보자.
- **한계**: TPU/JAX 생태계 특화. GPU 커널로의 일반화는 미검증.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — execpolicy로 명령 승인 정책을 코드화** (카테고리: Workflow / 거버넌스)

- 출처: [openai/codex codex-rs/execpolicy](https://github.com/openai/codex/tree/main/codex-rs/execpolicy) (클론으로 확인)
- 💡 어떤 명령을 자동 승인(allow)·확인(prompt)·금지(forbidden)할지 Starlark 규칙 파일로 선언하는 정책 엔진이 CLI에 들어 있다.
- 📝 규칙에 `match` / `not_match`로 예시 명령을 적으면 로드 시점에 규칙 자체가 단위 테스트된다:

```starlark
prefix_rule(
    pattern = ["git", ["status", "log", "diff"]],
    decision = "allow",
    justification = "읽기 전용 git 명령",
    match = ["git status", "git log"],
    not_match = ["git push"],
)
```

검증은 `codex execpolicy check --rules policy.rules git status`.

- 🎯 팀 공용 저장소에서 "에이전트가 실행해도 되는 명령"을 리뷰 가능한 파일로 관리하고 싶을 때.
- ⚠️ 현재는 prefix-rule 서브셋만 지원. 언어가 더 확장될 예정이라 규칙 파일 호환성은 릴리즈 노트를 지켜봐야 한다.
- ⭐ 추천도: 팀 운영 환경이라면 높음.

**🟦 Claude Code — `/diff` 사이드 패널로 편집 실시간 감시** (카테고리: Review)

- 출처: [Claude Code CHANGELOG 2.1.260](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 풀스크린 모드에서 `/diff`를 치면 대화 옆에 미커밋 변경 diff 패널이 열리고, Claude가 편집할 때마다 갱신된다.
- 📝 에이전트에게 리팩터링을 맡긴 뒤 패널을 켜두면, 커밋 전에 의도 밖 파일이 수정되는 순간을 바로 잡아낼 수 있다. 토글이므로 한 번 더 치면 닫힌다.
- 🎯 바이브코딩 중 "다 끝나고 git diff로 몰아서 리뷰"가 부담스러운 중규모 작업.
- ⚠️ 터미널 풀스크린 모드 기준 기능. 좁은 화면에서는 가독성이 떨어진다.
- ⭐ 추천도: 높음 — 리뷰 습관을 바꾸는 작은 기능.

**🟪 공통 — 메모리·프롬프트 자동 갱신에 '환경 게이트' 달기** (카테고리: Eval)

- 출처: [arXiv 2609.02750](https://arxiv.org/abs/2609.02750) (BCR)
- 💡 에이전트가 스스로 교훈을 뽑아 CLAUDE.md·스킬·시스템 프롬프트를 갱신하는 루프에는, "고정 평가셋 점수가 내려가면 채택 거부" 게이트를 기본으로 넣는다.
- 📝 최소 구현: 갱신 후보 적용 → 스모크 평가 N개 실행 → 실패율이 기존보다 낮을 때만 머지. 나머지는 후보 큐에 보관.
- 🎯 자기 개선 루프, 장기 운영되는 에이전트 메모리 전반.
- ⚠️ 평가셋이 실제 작업 분포와 어긋나면 게이트도 같이 어긋난다. 평가셋 자체를 주기적으로 갱신할 것.
- ⭐ 추천도: 자동 갱신 루프 운영자라면 필수.
