# 📚 주목 논문

## 1. Coca-Cola — 도구 출력은 텍스트로 읽을 필요가 없다

- **저자**: Yuetong Liu, Zhehao Zhou, Yitong Zhang, Haorui Chen, Jia Li (코드는 THU-Agent 조직으로 공개)
- **arXiv**: [2611.06500](https://arxiv.org/abs/2611.06500) (cs.AI)
- **핵심 기여**: 에이전트는 보통 도구 출력을 원문 그대로 컨텍스트에 붙인다. 이 논문은 그 전제를 깬다 — 도구 관측을 **연속 잠재 토큰**으로 압축해 에이전트의 입력 임베딩 공간에 직접 주입한다. 텍스트 요약·토큰 프루닝이 못 넘는 압축률 한계를 우회하는 접근.
- **방법**: 압축 모델이 관측을 잠재 토큰으로 변환하고, **Action-Preserving Training**으로 "원본을 봤을 때"와 "압축본을 봤을 때"의 다음 행동 분포를 정렬한다. 행동 결정에 충분한 정보만 남기는 훈련이다.
- **결과**: 웹 검색 에이전트, QA 벤치마크 4종·모델 2계열에서 토큰 소비 70.0~89.2% 절감, 엔드투엔드 런타임 24.5~56.0% 단축, 과제 성능은 오히려 일관되게 개선됐다고 보고.
- 🛠 **시사점**: 당장 이식하긴 어렵지만(임베딩 주입은 셀프 호스팅 모델 전제), "관측은 전부 텍스트로 넣어야 한다"는 가정 자체를 점검하게 한다. API 모델 사용자라면 중간 단계인 '행동 보존' 관점의 요약 — 다음 행동이 달라지지 않을 만큼만 남기기 — 를 컨텍스트 압축 기준으로 삼아볼 것.
- **한계**: 압축 모델을 따로 훈련해야 하고, 평가가 웹 검색 QA 중심이다. 코드: [THU-Agent/Coca-cola](https://github.com/THU-Agent/Coca-cola)

![Coca-Cola 방법 개요: 도구 관측을 잠재 토큰으로 압축해 임베딩 공간에 주입, 토큰 70~89% 절감](/images/ai-news-2026-11-08/coca-cola.svg)

*수치는 arXiv 초록 기준 자기 보고 값. 범위는 벤치마크·모델에 따른 편차다.*

## 2. BestRand — "랜덤 샘플링도 거의 충분하다", 단 꼬리가 문제

- **저자**: George Ling, Shanshan Zhong, Lijin Yang, Hao Yang, Nanxiang Li, Zhongzhan Huang
- **arXiv**: [2611.00883](https://arxiv.org/abs/2611.00883) (cs.CL)
- **핵심 기여**: 벤치마크 일부만 돌려 전체 점수를 추정하는 '벤치마크 압축'의 오차 분포를 해석적으로 근사했다. 결론이 통쾌하다 — 대부분의 랜덤 부분집합은 오차가 작지만, 드물게 큰 오차를 내는 **긴 꼬리**가 있고, 이 불안정성은 모델을 더 평가해도 사라지지 않는다.
- **방법**: 이 이론 위에서 랜덤 샘플링의 효율은 유지하되 고오차 꼬리만 깎아내는 BestRand를 제안. 텍스트·멀티모달·에이전트 벤치마크 70여 종에서 검증했다.
- **결과**: 경쟁 기법 대비 고오차 위험 50.2% 감소, 평균 추정 오차 16.4% 감소, 구축 비용은 51.3% 수준이라고 보고.
- 🛠 **시사점**: 에이전트 평가가 비싸서 "전체 스위트는 릴리즈 전에만, 평소엔 일부만" 식으로 운영 중이라면 정확히 이 논문이 다루는 상황이다. 부분집합을 임의로 한 번 뽑아 고정해 쓰고 있다면, 그 부분집합이 '긴 꼬리'에 속하는지부터 의심해 볼 것.
- **한계**: 전체 벤치마크를 한 번은 돌려본 뒤에야 좋은 부분집합을 고를 수 있는 구조라, 완전히 새 평가 세트에는 바로 못 쓴다.

# 🛠 오픈소스 스포트라이트

오늘의 두 레포는 정확히 반대 방향이다 — 하나는 에이전트의 손을 실기기까지 늘리고, 하나는 그 손이 닿는 범위를 VM 안으로 줄인다.

- **[poki](https://github.com/JosssphZhou/poki)** — JavaScript, AGPL-3.0, 약 490★ (11/5 공개). 에이전트가 **탈옥 없이, 추가 하드웨어 없이 진짜 iPhone을 사람처럼 조작**하게 해주는 로컬 MCP 서버. macOS에서 서버를 띄우고 `claude mcp add` / `codex mcp add` 한 줄로 연결한다. 지난주 다룬 Android 쪽 Mika의 iOS 대응편이 일주일 만에 나온 셈. **용도**: 모바일 앱 E2E 테스트 자동화, iOS 전용 앱 연동 실험. 단, 내 계정으로 로그인된 실기기라는 점을 잊지 말 것 — 행동 범위 제한과 중단 지점("결제 전 멈춤" 같은)을 먼저 설계해야 한다.
- **[devvm](https://github.com/devvmhq/devvm)** — Go, 약 350★ (11/6 공개). 프로젝트 폴더에서 `devvm` 한 번이면 그 프로젝트 전용 **격리 VM**이 생긴다. 파일을 보고 툴체인을 감지해 넣어주고, VM 셸에서 `claude`를 그대로 실행하는 구조(Lima 기반, macOS 13+/Linux). VM별로 네트워크 등급과 크기를 고를 수 있고, 베이스 이미지는 1회 빌드 후 수 초 내 기동. **용도**: `--dangerously-skip-permissions`급 자율 실행을 호스트가 아닌 VM 안에서 돌리고 싶을 때. 어제까지 다룬 '상주 에이전트' 흐름의 안전장치 쪽 부품이다.

![poki와 devvm 비교 카드: 무엇, 구조, 요구사항, 주의](/images/ai-news-2026-11-08/repo-cards.svg)

*능력을 넓히는 쪽(poki)과 피해 반경을 줄이는 쪽(devvm) — 함께 쓰면 된다.*

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟦 Claude Code — 새 내장 privacy mod: 계정 이메일의 User-Agent 유출 차단

- **카테고리**: Hook / **소스**: [mods/privacy README](https://github.com/anthropics/claude-code/blob/main/mods/privacy/README.md) (11/6 커밋, 클론으로 확인)
- 💡 Claude Code는 사용자 식별을 위해 모델 컨텍스트에 계정 이메일을 넣어준다. 새 privacy mod는 `tool.check` 훅 하나로, 그 이메일이 **User-Agent 계열 설정과 함께 Bash/PowerShell 호출에 등장하면 프롬프트 없이 거부**한다 — "자동화 클라이언트는 연락처를 밝히라"는 사이트 요구에 모델이 내 이메일을 써버리는 패턴을 막는 것.
- 📝 내장 mod라 따로 설치할 것은 없다. 끄려면 `/plugin disable` 또는 settings에:

```json
{ "enabledPlugins": { "cc-plugin-privacy@builtin": false } }
```

- 🎯 자율 세션에서 웹 스크래핑·API 탐색을 시키는 경우. 거부당한 호출은 모델이 주소를 빼고 다시 시도한다.
- ⚠️ README가 스스로 한계를 명시한다 — 파서 없는 단어 매칭이라 오탐이 있고, URL·요청 본문·변수로 우회되는 경로는 못 막는다. "boundary가 아니라 courtesy"라는 표현 그대로, 이것만 믿고 비밀 취급 정책을 세우면 안 된다.
- ⭐ 추천도: 기본 켜짐이니 "왜 이 curl이 거부됐지?"의 원인으로 기억해 두는 것만으로 디버깅 시간이 준다.

### 🟩 Codex — exec/review에 `--trust`: 비대화형 실행의 신뢰가 명시적으로

- **카테고리**: Workflow / **소스**: [commit 11ca3f7](https://github.com/openai/codex/commit/11ca3f7531866b22b07bd7ed181e814f087b7ee5) (11/7, 클론으로 확인)
- 💡 비대화형 실행(`codex exec`, `codex review`)에서 신뢰하지 않은 프로젝트의 설정과 MCP 서버가 **`--sandbox workspace-write`를 줘도 비활성 상태로 유지**된다. 대신 새 `--trust` 플래그로 현재·이후 세션에 대한 프로젝트 신뢰를 명시적으로 저장할 수 있다.
- 📝 CI나 cron에서 처음 보는 레포를 돌리는 파이프라인이라면:

```sh
codex exec --trust "run the test suite and summarize failures"
```

- 신뢰 저장은 `--ephemeral`에서도 유지되고, 명시적으로 '신뢰 안 함' 처리한 프로젝트는 덮어쓰지 못하며, `--ignore-user-config`와는 조합 불가.
- 🎯 레포에 심어진 악성 프로젝트 설정·MCP 서버가 무인 실행에서 자동 활성화되는 공급망 경로를 막는다. 어제 Claude Code의 `denyInsteadOfPrompting`과 같은 문제의식 — 사람이 없는 실행은 기본값을 보수적으로.
- ⚠️ 기존에 비대화형으로 잘 돌던 파이프라인이 "project configuration is disabled" 경고와 함께 조용히 기능 축소될 수 있다. 무인 파이프라인 로그를 한 번 확인할 것.
- ⭐ 추천도: `codex exec`를 자동화에 쓰고 있다면 이번 주 필수 점검 항목.

### 🟪 공통 — 설치 문서를 에이전트에게 쓰게 하라: AGENTS.md 주도 셋업

- **카테고리**: Workflow / **소스**: [poki Quick start](https://github.com/JosssphZhou/poki#quick-start)
- 💡 poki의 공식 설치법 1번은 brew 명령이 아니라 **에이전트에게 복사해 줄 프롬프트**다: "이 레포의 AGENTS.md를 따라 설치하고, 내가 행동해야 할 때마다 멈춰라." 지난주 dsh-superagent도 같은 방식(SETUP.md를 에이전트에게 읽히는 대화형 셋업)을 썼다 — 복잡한 셋업의 1차 독자가 사람에서 에이전트로 넘어가는 중이다.
- 📝 내 프로젝트에 적용하기: 레포 루트 AGENTS.md(또는 SETUP.md)에 ① 전제 조건 확인 명령 ② 순서 있는 설치 단계 ③ **사람 확인이 필요한 지점**(로그인, 권한 승인, 결제)을 명시하고, README에는 에이전트에게 건넬 한 줄 프롬프트를 둔다.
- 🎯 환경 의존성이 많은 내부 도구·MCP 서버를 팀에 배포할 때. "설치가 안 돼요" 문의가 에이전트 선에서 소화된다.
- ⚠️ 에이전트더러 스크립트를 실행하게 하는 문서이므로, 단계마다 무엇을 하는지 설명을 붙여 에이전트(와 사람)가 검증하며 진행할 수 있게 써야 한다. "그냥 이거 실행해"식 불투명한 원라이너는 금물.
- ⭐ 추천도: 다음 사이드 프로젝트 README부터 바로 적용할 만한 저비용 습관.
