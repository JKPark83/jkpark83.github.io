# 📚 주목 논문

## NeoHorse-1: 라우팅 하니스로 여는 재귀적 자기개선

- **저자/소속**: NeoHorse Team (TokenRhythm) — Guoliang Cao, Kai Han, Yunhe Wang 외 다수
- **arXiv**: [2609.08183](https://arxiv.org/abs/2609.08183) (cs.CL) · Hugging Face 데일리 1위(367 업보트)
- **핵심 기여**: 재귀적 자기개선(RSI)을 "구체적 메커니즘"으로 만든 첫 프로토타입급 시도. 라우팅 하니스가 사용자 턴마다 능력 수요 예측·선택된 티어·상호작용을 기록하고, 이 기록이 추론·툴 호출·하니스 컨텍스트를 보존한 채 학습 예제가 된다.
- **방법**: 구조 검증 → 6차원 의미 평가 → 장면 단위 라벨링을 통과한 데이터만 입장. 라우팅 신호로 3단계 커리큘럼 SFT와 라우팅 유도 on-policy 증류를 구성하고, 능력 기반 배분이 평가 피드백을 다음 학습 믹스로 변환한다.
- **결과**: 11개 벤치마크 매크로 평균이 4B에서 58.94→64.87, 9B에서 65.60→69.04. 사후학습된 4B가 9B 베이스와의 격차를 크게 좁혔다.
- 🛠 **에이전트 빌더 시사점**: 여러분이 이미 쌓고 있는 에이전트 트랜스크립트가 바로 이 파이프라인의 원료다. "무엇을 배웠는지가 다음에 무엇에서 배울지를 결정하는" 루프 설계는 하니스 로그 스키마를 지금부터 잘 잡아둘 이유가 된다.
- **한계**: 루프 1회전의 결과이고, 여러 이터레이션에 걸친 RSI는 "다음 단계"로 남아 있다. 이득도 베이스 대비 사후학습 효과라 루프 자체의 기여 분리는 아직 거칠다.

## Miles v0.1: 프로덕션급 사후학습 시스템

- **저자/소속**: RadixArk — SGLang·slime 계열 팀의 기술 보고서 (34쪽)
- **arXiv**: [2609.08368](https://arxiv.org/abs/2609.08368) (cs.LG, cs.CL)
- **핵심 기여**: slime의 설계를 이어받아 RL 학습 루프의 각 단계를 "검증되고, 깔끔하고, 교체 가능한" 컴포넌트로 재구성한 풀스택 시스템. 프론티어급 RL을 연구자와 기업 모두가 돌릴 수 있게 하는 것이 목표다.
- **방법**: SGLang 기반 롤아웃 엔진 + Megatron-LM/PyTorch FSDP 트레이너 + 배포 토폴로지별 가중치 동기화 전송 3종. 풀파라미터 RL 외에 LoRA RL, on-policy 증류, SFT, 디퓨전 모델까지 같은 아키텍처로 지원.
- **결과**: GLM-5.2 744B-A40B를 64장의 NVIDIA GB300에서 완전 비동기 에이전틱 RL(터미널 코딩 과제)로 학습, 초기 30스텝 기준 스텝 중앙값 263초를 보고.
- 🛠 **에이전트 빌더 시사점**: "우리 에이전트 과제로 소형 모델을 RL 튜닝"이 점점 인프라 문제가 아니라 레시피 문제가 되고 있다. LoRA RL과 on-policy 증류 지원 덕에 GB300 없이도 시작점이 있다.
- **한계**: 레시피·병렬화·최대 규모 모델은 Megatron-LM 백엔드 중심이고, FSDP는 보조적이다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — /worktree로 세션마다 격리 체크아웃

- **분류**: Workflow · [소스: rust-v0.154.0 릴리즈](https://github.com/openai/codex/releases/tag/rust-v0.154.0)
- 💡 **핵심**: 새 세션이나 포크된 세션을 git worktree 기반 격리 체크아웃에서 돌리고, 나중에 목록을 훑어 재개할 수 있다(실험 기능).
- 📝 **방법**:

```bash
codex --worktree      # 새 세션을 격리된 worktree에서 시작
# 세션 안에서는 /worktree 로 워크트리를 만들고 탐색
```

- 🎯 **언제**: 어제 다룬 `codex exec fork`처럼 같은 저장소에서 여러 접근을 병렬로 실험할 때. 포크한 세션들이 같은 워킹 트리를 두고 서로 파일을 덮어쓰는 사고를 원천 차단한다.
- ⚠️ **주의**: 실험 플래그라 동작이 바뀔 수 있고, worktree마다 빌드 캐시·의존성 설치가 따로 필요할 수 있다.
- ⭐ **추천도**: 병렬 세션을 쓰는 팀이라면 바로 시도할 가치.

## 🟦 Claude Code — maxEffortLevel로 비용 상한 걸기

- **분류**: Context/Workflow · [소스: CHANGELOG 2.1.267](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 **핵심**: settings.json의 `maxEffortLevel`이 모든 프로바이더(Bedrock·Vertex·Foundry 포함)에서 노력 수준의 상한을 강제한다. 사용자는 더 낮은 수준만 고를 수 있다.
- 📝 **방법**: 팀 공유 settings.json에 최상위로 지정하거나, `modelSettings` 아래 모델별로 다르게 걸 수 있다.

```json
{
  "maxEffortLevel": "medium"
}
```

- 🎯 **언제**: CI·배치 에이전트나 조직 공용 설정에서 "high effort 모델 호출로 비용·지연 폭주"를 구조적으로 막고 싶을 때.
- ⚠️ **주의**: 어려운 리팩터링까지 상한에 걸리면 품질이 떨어질 수 있으니, 대화형 세션용 프로필과 분리해 적용하는 편이 안전하다.
- ⭐ **추천도**: 관리형 설정을 쓰는 조직이라면 필수 검토.

## 🟪 공통 — 트랜스크립트를 학습 자산으로 만드는 입장 게이트

- **분류**: Eval/Context · [소스: NeoHorse-1 보고서](https://arxiv.org/abs/2609.08183)
- 💡 **핵심**: NeoHorse-1이 하니스 로그를 학습 데이터로 승격시키는 조건은 세 겹의 게이트다 — 구조 검증, 다차원 의미 평가, 장면 단위 라벨링. 파인튜닝 계획이 없어도 같은 게이트는 메모리·퓨샷 예제 관리에 그대로 쓸 수 있다.
- 📝 **방법**: 에이전트 로그 파이프라인에 최소 체크리스트를 두자.
  - 구조: 툴 호출/응답 스키마가 파싱되는가, 하니스 컨텍스트가 보존됐는가
  - 품질: 성공 여부·근거를 자동 평가로 라벨링했는가
  - 위생: 중복 제거와 평가셋 오염 제거를 거쳤는가
- 🎯 **언제**: 성공 트랜스크립트를 퓨샷 예제나 장기 메모리로 재사용하는 모든 에이전트.
- ⚠️ **주의**: 게이트 없는 로그 재사용은 "틀린 확신"을 증폭한다 — 어제 다룬 FlowBalance·BCR과 같은 교훈이다.
- ⭐ **추천도**: 오늘 가장 이식성 높은 아이디어.
