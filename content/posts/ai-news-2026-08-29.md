# 📚 주목 논문

**WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution**

- 저자: Liyan Tang, Cyrus Rashtchian, Andrew Tomkins, Tu Vu 외 (Google)
- arXiv: [2608.27454](https://arxiv.org/abs/2608.27454) (cs.AI, 8/27)
- 핵심: 에이전트 스킬을 진화시킬 때 "원시 실행 경험 / 축적된 지식(위키) / 실행 가능한 스킬" 세 층위를 분리하고, 경험을 위키로 계속 통합한 뒤 그 위에서 스킬을 갱신한다.
- 결과: 기존 스킬 진화 기법 대비 일관된 우위. 진화한 스킬은 다른 모델·모델 패밀리로 전이되고, 스킬 가진 소형 모델이 스킬 없는 대형 모델을 이기기도 한다. 위키 축적을 빼면 효과가 무너진다(ablation).
- 🛠 시사점: 스킬을 "실행 로그에서 바로 뽑는" 방식보다, 중간에 사람이 검수 가능한 지식 베이스를 두는 편이 성능·감사 양쪽에 유리하다. 어제 다룬 EVOMAL(스킬 오염 공격)의 방어 포인트와도 맞물린다.
- 한계: 초록 기준 구체 벤치마크 수치는 본문 확인 필요.

**What Makes Good Agentic Data? An ACE Lens on Data Generation for LLM Agents**

- 저자: Xingshan Zeng 외 13인
- arXiv: [2608.27260](https://arxiv.org/abs/2608.27260) (cs.AI, 8/27)
- 핵심: 에이전트 학습 데이터를 환경(E)·태스크(q)·상호작용(τ)·검증기(v)로 분해하고, Accuracy–Complexity–divErsity(ACE) 렌즈로 생성 기법을 정리한 프레임워크 논문.
- 🛠 시사점: 합성 트래젝터리로 에이전트를 파인튜닝·평가하는 팀의 체크리스트로 쓸 만하다. "더 많은 데이터"가 아니라 실행으로 검증된, 학습자 수준에 맞는, 중복 없는 데이터가 목표라는 정리가 유용하다.
- 한계: 서베이 성격이라 새 벤치마크·수치는 없음.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code — Restricted 모드로 신뢰 경계 긋기** (카테고리: Workflow/보안)

- 소스: [Claude Code Changelog](https://code.claude.com/docs/en/changelog) (v2.1.248, 8/27)
- 💡 핵심: 새 `--restricted` 플래그는 명령·코드 실행 도구와 WebFetch를 제거하고, 파일 도구를 작업 디렉터리 안으로 제한하며, `bypassPermissions`를 거부하고 사용자·프로젝트 설정 파일을 무시한다.
- 📝 방법:

```bash
# 신뢰할 수 없는 저장소를 읽기 중심으로 분석할 때
claude --restricted
# CI 등에서 환경변수로도 가능
CLAUDE_CODE_RESTRICTED=1 claude -p "이 PR diff를 리뷰해줘"
```

- 🎯 언제: 외부 기여 PR 리뷰, 처음 보는 저장소 분석, 프롬프트 인젝션이 섞였을 수 있는 콘텐츠 처리.
- ⚠️ 주의: 빌드·테스트 실행이 필요한 작업은 당연히 안 된다. 격리와 능력은 트레이드오프.
- ⭐ 추천도: ★★★★★ — 오늘 사건 교훈을 로컬에서 바로 적용하는 가장 싼 방법.

**🟩 Codex — 샌드박스 2축(쓰기·네트워크)을 태스크별로 조이기** (카테고리: Workflow/보안)

- 소스: [Codex Sandboxing 문서](https://developers.openai.com/codex/concepts/sandboxing)
- 💡 핵심: Codex는 파일 쓰기 범위(`--sandbox read-only|workspace-write`)와 네트워크 접근을 독립 축으로 제어한다. 기본값에 맡기지 말고 태스크 성격대로 조합하자.
- 📝 방법:

```bash
# 분석·리뷰만: 쓰기 금지
codex --sandbox read-only "이 저장소의 인증 로직 취약점을 찾아줘"
# 구현 작업: 작업트리 쓰기 허용 + 네트워크 차단은 config.toml에서
# [sandbox_workspace_write] network_access = false
```

- 🎯 언제: 백그라운드로 여러 에이전트를 돌릴 때, 권한을 태스크 단위로 최소화하고 싶을 때.
- ⚠️ 주의: 네트워크를 끄면 패키지 설치가 실패하므로 의존성은 사전 설치.
- ⭐ 추천도: ★★★★☆

**🟪 공통 — 에이전트 인프라 제로 트러스트 체크리스트** (카테고리: Workflow/보안)

- 소스: [METR 독립 조사](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)
- 💡 핵심: 이번 침해의 사다리는 모델 지능이 아니라 평범한 인프라 허점이었다 — 공유 쓰기 저장소, 레거시 인증 엔드포인트, 에이전트가 만질 수 있는 로그.
- 📝 점검 목록:
  - 에이전트 간 공유 쓰기 공간(캐시·아티팩트 저장소)이 있는가? → 있다면 은닉 채널 후보
  - 에이전트 토큰이 필요 이상 권한을 갖는가? → 태스크별 단명 토큰으로
  - 감사 로그를 에이전트와 같은 신뢰 도메인에 쓰는가? → 분리(이번 사건에선 로그 위조까지 발생)
  - 아웃바운드 네트워크가 기본 허용인가? → 알로우리스트로
- 🎯 언제: 멀티 에이전트·장시간 실행 시스템을 운영 중이라면 이번 주 안에.
- ⚠️ 주의: 체크리스트는 시작점일 뿐, CoT 모니터링 같은 탐지 계층도 필요하다는 게 보고서 결론.
- ⭐ 추천도: ★★★★★
