# 📚 주목 논문

## VeriHarness: 롤아웃 다수결을 버려라

- **저자**: Caiqi Zhang, Rujun Han, Zifeng Wang, Nigel Collier, Tomas Pfister, Chen-Yu Lee 외 (Google·케임브리지대)
- **arXiv**: [2610.00972](https://arxiv.org/abs/2610.00972) (cs.AI, 10/1 공개)
- **핵심 기여**: 긴 작업에서 롤아웃을 여러 개 샘플링할 때, **합의(consensus)는 오류를 감추고 불일치(disagreement)가 정답 후보를 드러낸다**는 관찰을 바탕으로, 생성에 쓰던 그 모델을 '에이전틱 검증자'로 바꾸는 하니스를 제안.
- **방법**: 검증자에게 워크스페이스·증거 수집 도구·재사용 가능한 검증 스킬을 부여. ① Disagreement Resolver가 충돌하는 주장을 환경 증거와 대조하고, ② Consensus Challenger가 모두 동의한 주장도 다시 시험한 뒤, 그 결과로 최종 산출물을 선택·수정.
- **결과(논문 보고치)**: 5개 장기 워크스페이스 벤치마크에서 단일 롤아웃 대비 Gemini 3.5 Flash +6.2점, Claude Opus 4.8 +6.4점. 검증 스킬이 실패 피드백으로 자가 개선되는 것도 확인. 약 $100K를 들여 만든 26,000개 롤아웃 풀을 공개.
- 🛠 **에이전트 빌더 시사점**: best-of-N을 LLM-judge 점수나 다수결로 고르고 있다면 구조를 바꿀 근거가 생겼습니다. 판정자에게 **점수 대신 도구를 주세요** — 테스트 실행, 파일 확인, 로그 대조처럼 환경에서 증거를 모을 수 있게 하고, 특히 "모든 롤아웃이 동의하는 부분"을 일부러 공격하게 하세요.
- **한계**: 검증자 롤아웃만큼 비용이 추가되고, 증거를 모을 수 있는 환경(워크스페이스형 과제)이 전제입니다.

![VeriHarness 구조 다이어그램](/images/ai-news-2026-10-06/veriharness-loop.svg)

*VeriHarness의 두 모듈: 불일치는 증거로 판정하고, 합의는 일부러 의심한다. (논문 내용 기반 자체 제작)*

## Recursive Self-Rewrite: 하니스 개입을 '지우고' 배운다

- **저자**: Zongxia Li, Jordan Boyd-Graber(메릴랜드대), Haitao Mi(Tencent) 외
- **arXiv**: [2610.02826](https://arxiv.org/abs/2610.02826) (cs.AI, 10/2 공개)
- **핵심 기여**: 특수 하니스(강한 개입·보조 장치)가 있어야 풀리던 과제의 성공 궤적을, **배포 때 쓸 일반 하니스에서 재현 가능한 형태로 재작성**해 학습 데이터로 바꾸는 프레임워크.
- **방법**: planner가 성공 절차를 runbook으로 추출 → critic이 정답 유출·검증기 유출을 걸러내며 재귀 수정 → executor가 깨끗한 샌드박스에서 runbook을 재실행해 검증. 약 3K개 터미널 과제에서 하니스 3종이 합쳐 759개를 풀었고(최강 단일 하니스보다 +34.3%), 성공 궤적 2,001개를 11,094개로 증폭.
- **결과(논문 보고치)**: Qwen-3.8-27B 기준 Terminal-Bench 2 pass@3 57.0% → 74.2%. 가중치도 공개([RSR-27B](https://huggingface.co/IntelligenceLab/RSR-27B)).
- 🛠 **에이전트 빌더 시사점**: 파인튜닝을 안 해도 교훈은 그대로입니다. 강한 하니스(사람 개입, 특수 도구)로 어렵게 성공한 세션이 있다면, 그걸 그대로 두지 말고 **일반 환경에서 재현 가능한 runbook으로 정제**해 두세요. 아래 오픈소스 메모리 도구들과 정확히 맞물리는 지점입니다.
- **한계**: 터미널 과제 중심이며, critic의 유출 필터링이 불완전하면 벤치 점수가 부풀 수 있습니다.

# 🛠 오픈소스 스포트라이트

이번 주 에이전트 메모리 도구 두 개가 정반대 설계로 나란히 주목받았습니다. 둘 다 직접 클론해 코드·커밋을 확인했고, 스타 수는 세션의 GitHub API 제한으로 확인하지 못했습니다.

**[vshulcz/deja-vu](https://github.com/vshulcz/deja-vu)** — Go, MIT

- Claude Code·Codex·Cursor 등 38개 에이전트가 **이미 디스크에 남긴 세션 로그**를 통째로 인덱싱하는 로컬 메모리. LLM도 임베딩도 안 쓰는 Go 바이너리 하나라, 설치 전 몇 달치 기록까지 설치 직후부터 검색됩니다.
- `deja sync ssh laptop`으로 기기 간 동기화(클라우드 없음), `deja handoff --to codex`로 에이전트 간 컨텍스트 인계. 레포 자체 벤치 기준 LongMemEval-S R@5 97.2%, 19,195개 세션 인덱싱 17.6초(자기 보고치).
- **활용**: "지난달에 이 커넥션 풀 버그 어떻게 고쳤더라"를 에이전트가 먼저 회수하게 만드는 용도. HN 프런트페이지에 오르며 포크가 우후죽순 생겼는데, 원본은 vshulcz입니다.

**[huggingface/funes](https://github.com/huggingface/funes)** — Rust, Apache-2.0

- Hugging Face 공식 메모리 레이어. 세션 트레이스를 고정 로컬 임베딩 모델로 인덱싱하고, 벡터 + BM25 + 크로스인코더 리랭킹의 하이브리드 검색으로 회수합니다. Claude Code·Codex·pi·Hermes 지원, `funes add claude` 한 줄이면 훅과 recall/get 도구까지 설치.
- 차별점은 **메모리를 Hugging Face 데이터셋으로 퍼블리시**할 수 있다는 것 — 팀원이나 다른 기기가 플래그 하나로 같은 메모리에서 recall합니다. 시크릿은 퍼블리시 전에 레다크션.
- **활용**: 개인용이면 deja-vu가 가볍고, 팀 공유·시맨틱 검색 품질이 필요하면 funes가 맞습니다.

![deja-vu와 funes 설계 비교](/images/ai-news-2026-10-06/memory-duo.svg)

*같은 재료(세션 로그), 반대 설계: 임베딩 없는 즉시 인덱싱 vs 임베딩 파이프라인 + 데이터셋 공유. (자체 제작)*

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — 환경별 필수 스킬 강제 (`skills.required`)**

- 카테고리: Workflow / 출처: [커밋 42312d4](https://github.com/openai/codex/commit/42312d4ff4e258c1dfa43db9a9c59eed943c98de) (10/5, 직접 클론으로 확인)
- 💡 환경(environment)마다 "이 스킬 없이는 턴을 시작하지 말라"는 목록을 선언할 수 있게 됐습니다. 누락 시 **모델 호출 전에** 턴이 실패합니다 — 환경 셋업이 실패한 경우에도요.
- 📝 `environments.toml`의 환경 정의에 필수 스킬 목록을 추가합니다:

```toml
# environments.toml
[environments.deploy]
# ...기존 환경 설정...
[environments.deploy.skills]
required = ["deploy-checklist", "rollback-procedure"]
```

- 🎯 "배포 스킬이 로드 안 된 채로 배포 작업을 시작해버리는" 류의 사고를 구조적으로 차단할 때. 셋업 스크립트가 조용히 실패하는 CI·샌드박스 환경에서 특히 유용합니다.
- ⚠️ 스킬 이름은 카탈로그의 정확한 이름이어야 하고, 환경을 해제하면 요구도 함께 풀립니다.
- ⭐ 추천도: ★★★★☆ — 에이전트를 fail-fast로 만드는 가드레일.

**🟦 Claude Code — 플러그인 전용 서브에이전트: `$.agent.register` + `$.agent.spawn`**

- 카테고리: Subagent / 출처: [mods 타입 정의](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) (2.1.289에서 확장, 직접 클론으로 확인)
- 💡 mods(플러그인)가 자기만의 에이전트 타입을 등록하고, 모델을 거치지 않고 훅에서 직접 스폰할 수 있습니다. `agent.offer`로 모델에게는 숨기면 "내 도구가 호출될 때만 도는 전용 러너"가 됩니다.
- 📝 타입 정의 문서의 패턴 요약:

```js
await $.agent.register({
  name: "runner", description: "Runs a spec",
  prompt: RUNNER_PROMPT, tools: ["Read", "Bash"], omitClaudeMd: true
})
// 모델에게는 숨기고, 내 훅에서만 스폰
on("agent.offer", { agent: "lab:runner" }, () => ({ isOffered: false }))
on("tool.call", { tool: "mcp__lab__run" }, async ($, e) => {
  const { agentId } = await $.agent.spawn({
    subagentType: "lab:runner", prompt: e.spec, description: "run" })
})
```

- 🎯 검증 러너, 리포트 생성기처럼 **결정적 트리거로 돌아야 하는 서브에이전트**를 모델의 재량에 맡기지 않고 싶을 때. `$.agent.list()`가 idle/waiting 상태까지 주므로 간단한 디스패처도 만들 수 있습니다.
- ⚠️ mods API는 빠르게 바뀌는 중이라 버전 업그레이드 시 타입 정의를 다시 확인하세요.
- ⭐ 추천도: ★★★★☆ — 플러그인이 '오케스트레이터'가 되는 첫 단추.

**🟪 공통 — best-of-N에서 다수결·단일 judge를 치우기**

- 카테고리: Eval / 출처: [VeriHarness, arXiv 2610.00972](https://arxiv.org/abs/2610.00972)
- 💡 여러 롤아웃 중 하나를 고를 때 "N개 중 다수 의견"이나 "judge 점수 최고"는 둘 다 같은 함정에 빠집니다 — 모두가 공유하는 오류는 아무도 지적하지 않습니다.
- 📝 오늘 적용 가능한 최소 버전: 후보 산출물에서 **서로 다른 주장만 추려** 검증 단계에 넘기고, 검증자는 자연어 판단 대신 테스트 실행·파일 대조 같은 도구 호출로 판정하게 하세요. 전부 일치하는 핵심 주장 1~2개는 일부러 반증을 시도하게 합니다.
- 🎯 코드 생성 best-of-N, 리서치 에이전트의 보고서 선택, PR 자동 리뷰의 중복 판정.
- ⚠️ 검증 비용이 롤아웃 1회분쯤 추가되므로, 저부가 작업엔 과합니다.
- ⭐ 추천도: ★★★★★ — 하니스 구조 하나로 +6점대는 드뭅니다.
