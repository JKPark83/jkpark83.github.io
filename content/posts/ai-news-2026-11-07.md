# 📚 주목 논문

## 1. Harness-S — 실패한 궤적만 '형제 하네스'로 구제해 학습

- **저자**: Kangning Zhang, Wenxiang Jiao, Weinan Zhang 외 (총 11인)
- **arXiv**: [2611.04277](https://arxiv.org/abs/2611.04277) (cs.AI) — HF Daily Papers 상위권
- **핵심 기여**: 에이전트 RL에서 "최고의 하네스 하나"를 찾는 대신, 베이스 하네스로 전부 실패한 과제만 **수리 방향이 다른 형제 하네스들**로 다시 굴려 성공 궤적을 얻고, 그 능력을 베이스 하네스에서도 통하는 단일 정책으로 이전한다.
- **방법**: 수리 방향별로 특화시킨 하네스 풀을 고정해 두고, 전원 실패 그룹에만 투입한다. 어떤 하네스를 쓸지는 행동 프로파일과 복수 LLM 투표로 Top-k를 고르는 라우터가 정하고, 정책이 배우면서 프로파일도 갱신한다.
- **결과**: AppWorld, SWE-Gym, DBBench에서 정책 단독 훈련 대비 상당한 향상을 보고한다(세부 수치는 본문 참조).
- 🛠 **시사점**: 하네스(프롬프트·도구 구성)를 A/B로 갈아끼우며 "뭐가 제일 낫나"를 찾고 있다면, 발상을 뒤집어 볼 것 — 변형 하네스는 **실패 케이스 구제용 훈련 데이터 생성기**로 쓰고, 배포는 베이스 하나로 가는 구조다.
- **한계**: 하네스 풀 설계와 라우팅에 LLM 투표가 들어가 훈련 파이프라인이 무겁다. RL 훈련을 직접 하는 팀에게 해당하는 이야기.

## 2. EvoMemState — '사실 더미'에서 '상태 있는 메모리'로

- **저자**: Zhishang Xiang, Jinsong Su 외
- **arXiv**: [2611.03743](https://arxiv.org/abs/2611.03743) (cs.IR, cs.AI)
- **핵심 기여**: 기존 개인화 메모리는 사실을 독립적으로 쌓는다. 그래서 새 사실이 옛 사실을 **갱신·제약·충돌**시키는 관계가 날아간다. EvoMemState는 사실에 두 가지 상태를 붙인다 — 사실들의 유효성·관계를 추적하는 Relational State, 지금 요청에 사실을 어떻게 적용할지 정하는 Reasoning State.
- **방법**: 온톨로지 기반으로 영속 사실과 관계 상태를 만들고, 메모리 사용 경험을 RL로 정책에 내재화해 요청별 추론 상태를 생성한다.
- 🛠 **시사점**: 에이전트 메모리를 벡터 검색 + 사실 추출로만 운영 중이라면, 최소한 "이 사실이 아직 유효한가, 다른 사실과 충돌하나"를 적는 필드부터 추가해 보자. 시간이 지날수록 메모리 품질 차이가 벌어지는 지점이다.
- **한계**: 온톨로지 설계가 선행되어야 하고, 개인 비서형 워크로드 중심의 평가다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟦 Claude Code — 권한 프롬프트에서 멈추는 대신 거부하고 계속

- **카테고리**: Workflow / **소스**: [v2.1.319 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.319) (클론으로 확인)
- 💡 `permissions.denyInsteadOfPrompting` 설정이 추가됐다. 켜면 권한 프롬프트를 띄우고 기다릴 상황에서 해당 툴 호출만 거부되고 **턴은 계속 진행**된다. 터미널 세션·서브에이전트·팀메이트에 적용.
- 📝 settings.json에:

```json
{ "permissions": { "denyInsteadOfPrompting": true } }
```

- 🎯 자리를 비우는 긴 자율 작업, 또는 서브에이전트를 여럿 띄울 때 — 프롬프트 하나에 전체 파이프라인이 멈춰 있는 사태를 막는다. 거부당한 호출은 Claude가 우회하거나 보고로 남긴다.
- ⚠️ 거부가 조용히 쌓이면 결과물이 "허락 못 받아 생략" 투성이가 될 수 있다. 허용 규칙(allowlist)을 먼저 다듬고, 이 설정은 마지막 안전판으로.
- ⭐ 추천도: 야간 배치·CI처럼 사람이 없는 실행 환경이라면 바로 적용할 가치.

### 🟩 Codex — Code Mode 출력 절단이 기본값이 됐다

- **카테고리**: Context / **소스**: [commit 247934c](https://github.com/openai/codex/commit/247934cfe5f57daffe064a7229ab8bfb3feffb49) (11/6, 클론으로 확인)
- 💡 `code_mode_host_grpc`와 `code_mode_host_output_truncation`이 stable로 승격되며 **기본 활성화**됐다. Code Mode의 실행 출력이 Core(모델 컨텍스트)로 가기 전에 호스트 쪽에서 예산에 맞춰 잘리고, 절단 알림이 붙는다.
- 📝 거대한 로그를 뿜는 명령을 Code Mode로 돌려보고, 절단 알림이 붙는지 확인해 보자. 이전 동작이 필요하면 features에서 두 플래그를 명시적으로 꺼서 opt-out 할 수 있다.
- 🎯 테스트 러너·빌드처럼 출력이 수만 줄인 작업에서 컨텍스트 폭주를 플랫폼 레벨에서 막아준다.
- ⚠️ 출력 꼬리에 중요한 정보가 오는 도구(요약을 마지막에 찍는 러너 등)는 절단 경계를 확인할 것.
- ⭐ 추천도: Code Mode 사용자라면 알아만 둬도 디버깅 시간이 줄어든다.

### 🟪 공통 — 에이전트의 예산은 토큰이 아니라 '사람의 주의력'

- **카테고리**: Workflow / **소스**: [dsh-superagent 000-philosophy](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md)
- 💡 DeepSeek 팀이 상주 에이전트 운영에서 뽑아낸 원칙: **"사람의 주의를 최소로 쓰고, 가치를 최대로 줘라."** 메시지·알림·질문·설정 하나하나를 주의력 비용으로 계산하고, 비용보다 가치가 작으면 지운다.
- 📝 구체 규칙이 바로 쓸 만하다: (1) 요청 또는 팀이 쓴 규칙 없이는 행동하지 않는다 — 선제 작업은 '했을 일을 기록만 하는 모드'로 시작. (2) 사람이 행동해야 하거나 결과를 쓸 수 있을 때만 말한다. (3) 질문은 구조화된 형태로 한 번에 하나. (4) 노력이 아니라 영향 기준으로 멈춘다 — 설계 결정이 필요하면 질문으로 정지.
- 🎯 Slack/GitHub에 상주하는 팀 에이전트를 만들고 있다면, 기능 목록보다 이 '말할 권리' 규칙부터 정하는 편이 체감 품질을 더 올린다.
- ⚠️ 침묵이 기본값이면 장애도 조용히 묻힐 수 있다 — "실패는 실패로 보고한다"는 규칙이 세트로 필요하다.
- ⭐ 추천도: 에이전트를 '제품'이 아니라 '동료'로 배포하려는 팀의 필독 문서.
