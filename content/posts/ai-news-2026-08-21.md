# 🔥 오늘의 핵심

# 📚 주목 논문

## 1. FM-Bench — 에이전트에게 축구단을 20시즌 맡겨봤다

- **저자**: Tianyou Wang, Chongyang Gao, Kezhen Chen 외 (코드 조직: Analogy-AI, 초록에 소속 미표기)
- **arXiv**: [2608.18423](https://arxiv.org/abs/2608.18423) (cs.AI, 8/19)
- **핵심 기여**: 단발 태스크가 아니라 **행동의 결과가 누적되고 환경이 반응하는 20년 호라이즌**에서 장기 의사결정을 측정하는 벤치마크.
- **방법**: 에이전트가 툴 26개로 340~400회 결정(이적·계약·시설·유스 투자)을 내리고, LLM 심판 없이 결정론적 엔진이 최종 점수를 누적한다. 15개 프런티어 모델 × 시드 3개, 솔로 트랙과 같은 세계에서 맞붙는 Arena 트랙.
- **결과**: 규모·가격·벤더 어느 것도 순위를 예측하지 못했고, **토큰 지출량은 점수와 무상관**이었다. 고득점 모델을 가른 건 "경영 행동" — 호라이즌 후반엔 회수가 느린 투자를 줄이고, 현금을 놀리지 않고, 재계약을 마감 전에 미리 시작하는 패턴.
- 🛠 **에이전트 빌더 시사점**: 자기관리 메모리가 **정확히 두 가지 모드로 실패**한다 — 쌓이기만 하는 아카이브, 또는 시즌마다 갈아엎는 계획 재작성. 장기 실행 에이전트의 메모리에는 "정리(eviction)와 안정성" 둘 다 설계해야 한다는 구체적 증거다.
- ⚠️ **한계**: 게임화된 단일 도메인이고, 어떤 모델도 수백 번 거절당한 입찰에서 시장의 숨은 가격을 학습하지 못했다는 것 자체가 현재 세대의 벽이다.
- **코드**: [Analogy-AI/fm-bench](https://github.com/Analogy-AI/fm-bench)

![FM-Bench 20시즌 운영 루프와 주요 발견 요약](/images/ai-news-2026-08-21/fm-bench-loop.svg)
*점수를 가른 것은 연산량이 아니라 경영 행동이었다. 출처: arXiv 2608.18423 초록(자체 작도).*

## 2. SPADE — 훈련 환경을 만드는 것도 학습 가능한 부품이다

- **저자**: Bo Liu, Simon Yu, Yiding Jiang 외 18인 (Luke Zettlemoyer, Yejin Choi, Natasha Jaques 공저)
- **arXiv**: [2608.19197](https://arxiv.org/abs/2608.19197) (cs.CL, 8/19)
- **핵심 기여**: 학습자가 커지는 동안 훈련 환경 풀이 고정돼 있는 병목을 깨는 셀프플레이 RL 프레임워크.
- **방법**: 한 LLM이 두 역할을 맡는다. **환경 설계자**는 reset()/step() 인터페이스의 실행 가능한 멀티턴 환경 코드를 쓰고, **추론 에이전트**는 그 안에서 학습한다. 설계자의 보상은 에이전트의 후회(regret) — 힌트를 줬을 때와 안 줬을 때의 점수 격차로 추정해, "풀 수 있지만 어려운" 경계 난이도를 겨냥하게 만든다.
- **결과**: 30B 스케일에서 최강 고정-환경 베이스라인 대비 8개 홀드아웃 벤치마크 평균 +5.3, **BFCL-v4 멀티턴 +5.7, ACEBench-Agent +13.9**.
- 🛠 **에이전트 빌더 시사점**: 성공의 필수 요소 두 가지가 실무적이다 — 설계자를 사전학습 코퍼스 문서에 **그라운딩**시키는 것, 그리고 **누적 환경 메모리**를 주는 것. 합성 태스크 생성 파이프라인을 만들 때 그대로 가져갈 체크리스트다.
- ⚠️ **한계**: 게임 설정에서의 이득은 모델 스케일에 의존하고, 30B 이상 스케일 검증은 남아 있다.
- **링크**: [arXiv 2608.19197](https://arxiv.org/abs/2608.19197)

![SPADE 셀프플레이 구조와 벤치마크 향상폭](/images/ai-news-2026-08-21/spade-selfplay.svg)
*환경 설계자는 에이전트의 후회 신호로 난이도를 조준한다. 출처: arXiv 2608.19197 초록 수치(자체 작도).*

# 🛠 오픈소스 스포트라이트

이번 실행 환경에서 GitHub API가 차단돼 스타 수·언어 통계는 확인하지 못했다. 아래 정보는 각 논문 초록(1차 출처) 기준이다.

**1. [Analogy-AI/fm-bench](https://github.com/Analogy-AI/fm-bench)**
위 FM-Bench의 공식 구현. 결정론적 엔진 + 툴 26개 환경이 통째로 공개돼 있어, **내 모델·하네스를 끼워 장기 운영 능력을 직접 돌려볼 수 있는** 드문 벤치마크다. LLM 심판이 없어서 재현 논쟁에서 자유롭다는 게 실무적 장점.

**2. [midea-ai/SemaPLC](https://github.com/midea-ai/SemaPLC)**
가전기업 Midea가 공개한 PLC 코드 생성 에이전트 하네스([arXiv 2608.18565](https://arxiv.org/abs/2608.18565)). 도메인은 산업 제어지만 구조가 일반적이다 — **모델이 "다 했다"고 해도 무시하고, 명세·컴파일·라이브 런타임 체크가 로그로 통과해야만 완료로 인정**한다. 정적 점수로는 베이스라인과 10점 차이도 안 나던 것이 실행 트레이스 비교(동적 점수)에서는 22.4~31.4 대 52.2로 벌어졌다. "실행이 유일하게 정직한 테스트"라는 걸 숫자로 보여준다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — 세션 포크로 "되돌릴 수 있는 실험" 만들기
- **카테고리**: Workflow
- **출처**: [Codex CLI 0.148.0 릴리즈 노트](https://github.com/openai/codex/releases/tag/rust-v0.148.0)
- 💡 긴 세션에서 위험한 리팩터링을 시도하기 전에 세션을 분기해두면, 실패해도 원래 맥락으로 돌아올 수 있다.
- 📝 방법:

```bash
# 기존 세션을 분기해 실험용 세션 생성
codex exec fork
# 결과가 좋으면 그 세션을 계속, 아니면 resume 피커에서 원본 복원
# 실험 기록은 /export 로 Markdown으로 남긴다
```

- 🎯 대규모 리팩터링·의존성 업그레이드처럼 "반쯤 가보고 판단"하는 작업.
- ⚠️ stable 승격 직후이므로 프로덕션 파이프라인은 패치 릴리즈 하나 정도 기다렸다 올려도 늦지 않다.
- ⭐ 추천도: ★★★★☆

### 🟦 Claude Code — 기본 모델을 환경변수로 고정하기
- **카테고리**: Context / Workflow
- **출처**: [v2.1.236 릴리즈 노트](https://github.com/anthropics/claude-code/releases/tag/v2.1.236)
- 💡 새 세션이 시작하는 모델을 `ANTHROPIC_DEFAULT_MODEL`로 지정할 수 있다. 팀 공용 머신·CI에서 "기본은 저렴한 모델, 필요할 때만 상위 모델"을 강제하기 좋다.
- 📝 방법:

```bash
# CI나 공용 개발 환경의 기본 모델을 지정
export ANTHROPIC_DEFAULT_MODEL="claude-sonnet-5"
claude   # 새 세션은 Sonnet으로 시작
# 세션 안에서 /model 로 고르면 그 선택이 우선하고 재시작 후에도 유지된다
```

- 🎯 비용 가드레일이 필요한 팀 환경, 야간 배치로 도는 에이전트 세션.
- ⚠️ `/model`로 한 번 고른 선택이 환경변수보다 우선하므로, 강제 정책이 아니라 "기본값" 장치다.
- ⭐ 추천도: ★★★★☆

### 🟪 공통 — 완료 선언을 모델에게 맡기지 말 것 (검증 게이트)
- **카테고리**: Eval / Workflow
- **출처**: [SemaPLC, arXiv 2608.18565](https://arxiv.org/abs/2608.18565)
- 💡 SemaPLC가 7개 모델 전부에서 최고 검증 통과율(평균 72.6%)을 낸 비결은 새 모델이 아니라 **완료 규칙**이다: 로그로 남는 외부 체크(명세·컴파일·실행)가 통과해야만 태스크 종료.
- 📝 방법 (Claude Code라면 Stop hook으로):

```json
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "./verify.sh || echo '{\"decision\": \"block\", \"reason\": \"테스트/빌드 체크 실패 - 통과할 때까지 계속 작업\"}'"
      }]
    }]
  }
}
```

  Codex 0.148.0은 Hook이 비동기 실행과 MCP 툴 호출을 지원하므로 같은 패턴을 Hook으로 옮길 수 있다.
- 🎯 "됐다고 해서 봤더니 안 돌아가는" 일이 반복되는 모든 에이전트 파이프라인.
- ⚠️ 체크 스크립트가 느리면 루프 비용이 커진다. 빠른 정적 체크 → 느린 실행 체크 순으로 계단식 배치.
- ⭐ 추천도: ★★★★★

# 📌 지속 이슈 / 📅 내일 주목 / 🔗 보너스 링크

- 📌 **지속 이슈**: 어제 다룬 자기개선 취약성(측정 분산) 논쟁에 오늘 FM-Bench가 "메모리 실패 2모드"라는 구체적 실패 분류를 보탰다 — 장기 실행 에이전트의 메모리 설계가 이번 주의 실질적 화두.
- 📅 **내일 주목**: **OpenAI Assistants API가 8/26(5일 뒤) 완전 종료**된다. `/v1/assistants`·`/v1/threads` 호출이 에러를 반환하게 되므로 아직 남아 있다면 Responses API 마이그레이션이 이번 주 안 과제다. ([공지 스레드](https://community.openai.com/t/assistants-api-beta-deprecation-august-26-2026-sunset/1354666))
- 🔗 **보너스 링크**: 정답 라벨 없이 이질적 모델 코호트가 서로를 보상해 추론을 학습시키는 Co-RL ([arXiv 2608.17253](https://arxiv.org/abs/2608.17253)) — 텍스트 벤치마크 7종에서 평균 3.0~8.6% 향상. *(한국어 자료 아님)*
