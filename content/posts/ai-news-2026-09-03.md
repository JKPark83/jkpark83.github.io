- **Gemini 3.8 Flash 출시** — 1M 컨텍스트 유지, [Terminal-Bench 2.1 90.8%](https://www.datacamp.com/blog/gemini-3-8-flash-cyber)(3.7 Flash 81.6%). 장기 소프트웨어 엔지니어링과 자율 에이전트를 정면 타깃으로 명시했다. 가격은 2026-12-31까지 $0.75/$3.75(1M 입력/출력), **2027-01-01부터 $1.50/$7.50로 인상 예정**. 지금 싸다고 파이프라인 기본값으로 박아두면 내년 1월 비용이 2배가 된다. Gemini API·AI Studio·Antigravity에서 바로 사용 가능. ([공식 발표](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/))

# 📚 주목 논문

## 프로덕션 트래픽을 그대로 사후학습 재료로 — T-Tech의 32B 통합 레시피

- **저자/소속**: Olga Tsymboi 외, T-Tech (러시아)
- **arXiv**: [2609.01572](https://arxiv.org/abs/2609.01572) (cs.CL)
- **핵심 기여**: 200+ 사내 앱의 실서비스 트래픽을 Qwen3-32B 하나로 통합. 프로덕션 에러 분석으로 품질 격차를 3개 축(지시 이행·함수 호출·사내 태스크)으로 나누고, **축마다 별도 GRPO 전문가를 학습한 뒤 2단계 SLERP로 병합**했다. 공동 최적화 시 발생하는 보상 간섭을 병합으로 우회한 게 포인트.
- **결과**: 총 파라미터 ~7× 큰 기존 모델을 사내 Arena에서 추월(69.6 vs 65.8), 함수 호출 0.79 vs 0.77. 플랫폼 트래픽 50%(월 1.16억 요청)를 흡수하고 토큰 비용 2.8~3.9× 절감.
- 🛠 **에이전트 빌더 시사점**: 축별 보상이 각기 다른 실패 모드(의미 붕괴·과잉 호출·장황함 해킹)를 유발한다는 관찰은, tool-call 품질 튜닝을 계획 중이라면 그대로 체크리스트가 된다.
- **한계**: 사내 Arena·사내 트래픽 기준이라 외부 재현이 어렵다.

![T-Tech 사후학습 파이프라인](/images/ai-news-2026-09-03/ttech-pipeline.svg)

*에러 분석 → 축별 GRPO 전문가 → SLERP 병합으로 이어지는 파이프라인.*

## Hi-Q — 증거가 쿼리 트리의 모양을 정한다 (🇰🇷 POSTECH)

- **저자/소속**: Jueun Kim, Sungho Park, Wook-Shin Han (POSTECH)
- **arXiv**: [2608.30468](https://arxiv.org/abs/2608.30468) (cs.CL, cs.IR)
- **핵심 기여**: 멀티홉 QA에서 질문의 표현 단위와 코퍼스에서 검색 가능한 증거 단위가 어긋나는 문제를 "검색 가능 granularity 발견"으로 정식화. 각 쿼리 노드에서 검색된 증거가 현재 단위를 지지하는지 판정해, 지지되면 종료하고 아니면 의존성을 보존하며 이진 분해한다. 쿼리 트리 구조가 템플릿이 아니라 **코퍼스 지지 신호**로 결정된다.
- **결과**: 풀 코퍼스 검색 설정에서 평균 52.3 EM / 64.0 F1, IRCoT 대비 +15.1 EM.
- 🛠 **에이전트 빌더 시사점**: RAG 에이전트에 "고정 횟수 분해" 대신 "증거로 충분한지 먼저 판정하고, 부족할 때만 쪼개기" 패턴을 이식할 수 있다. 검색 호출 수를 줄이면서 재현율을 올리는 방향.
- **한계**: 판정·분해 오퍼레이터가 추가 LLM 호출이라 지연 시간 트레이드오프가 있다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — 터미널에서 태스크를 @ 멘션으로 엮기

- **분류**: Workflow · [출처: ChatGPT/Codex 공식 체인지로그](https://learn.chatgpt.com/docs/changelog)
- 💡 Codex 태스크끼리 `@` 멘션으로 참조하고, 에이전트에게 터미널에서 다른 태스크를 읽기·생성·메시지 전송하게 할 수 있게 됐다.
- 📝 긴 작업을 쪼갤 때 "리서치 태스크"를 먼저 만들고, 구현 태스크에서 이렇게 참조한다:

```text
@research-auth-task 의 결론을 반영해서 미들웨어를 구현해줘.
끝나면 그 태스크에 구현 완료 메시지를 남겨.
```

- 🎯 리서치/구현/리뷰를 별도 태스크로 분리해 컨텍스트를 얇게 유지하면서도 결과를 이어받을 때.
- ⚠️ 이름 없는 태스크는 자동 제목이 붙지만, 참조할 태스크는 `/rename`으로 명시적 이름을 먼저 붙여두는 게 안전하다.
- ⭐ 추천도: ★★★★☆ — 수동 복붙으로 하던 태스크 간 핸드오프가 1급 기능이 됐다.

### 🟦 Claude Code — auto 모드의 Containment Escape 규칙 이해하기

- **분류**: Debugging · [출처: Claude Code v2.1.257 릴리즈 노트](https://releasebot.io/updates/anthropic/claude-code)
- 💡 v2.1.257부터 auto 모드에 **Containment Escape 규칙**이 추가됐다. 클라우드 메타데이터 자격증명 조회, egress 우회, 크로스 테넌트 접근 같은 호출은 이제 자동 승인되지 않는다.
- 📝 CI나 샌드박스에서 이런 호출이 정당한 환경(예: 배포 스크립트가 인스턴스 메타데이터를 읽는 경우)이라면, 환경 설정에서 해당 동작을 "expected"로 표시해야 기존처럼 자동 승인된다. 갑자기 자동화가 승인 대기에 멈춘다면 이 규칙부터 의심할 것.
- 🎯 무인 파이프라인에서 Claude Code를 auto 모드로 돌리는 모든 팀.
- ⚠️ 규칙을 끄는 방향보다 expected 마킹으로 좁게 허용하는 쪽이 안전하다.
- ⭐ 추천도: ★★★★☆ — 어제의 BAITBENCH 교훈(에이전트는 열린 지름길을 밟는다)과 정확히 같은 문제의식이다.

### 🟪 공통 — 오프라인 평가를 프로덕션 트래픽 비율로 층화하라

- **분류**: Eval · [출처: arXiv 2609.01572](https://arxiv.org/abs/2609.01572)
- 💡 T-Tech는 오프라인 벤치마크를 **프로덕션 트래픽 분포에 맞춰 층화**하고, 결정적 검증기 또는 보정된 LLM 저지로만 채점했다. 벤치마크 평균이 아니라 "우리 트래픽에서의 평균"을 본 것.
- 📝 에이전트 평가 셋을 만들 때: (1) 실제 로그에서 태스크 유형별 비율을 뽑고, (2) 평가 케이스를 그 비율대로 샘플링, (3) 유형별 점수와 가중 평균을 함께 리포트.
- 🎯 "벤치마크는 올랐는데 유저 불만은 그대로"인 상황을 겪고 있다면 바로 적용.
- ⚠️ 트래픽 분포는 계속 변하므로 층화 비율도 주기적으로 갱신해야 한다.
- ⭐ 추천도: ★★★★★ — 비용이 거의 안 드는 평가 설계 교정.
