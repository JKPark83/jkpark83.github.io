# 🔥 오늘의 핵심

# 🤖 모델 & 릴리즈 레이더

- **TypeSafe AI, System One Models와 Jev 공개 (9/15)** — ChatGPT의 지시 이행 연구에 참여했던 Diogo Almeida가 2년 스텔스 끝에 내놓은 첫 모델. 스키마를 미리 정의하면 비구조화 입력에 대해 **타입이 있는 값 + 보정된 확률**만 돌려준다. 토큰 단위 자기회귀가 아닌 병렬 샘플러 아키텍처에 RLCD(보정 결정 강화학습)를 얹었다고 한다. 회사 발표 기준 지연 70~500ms, 입력 $0.042/M에 **출력 과금 없음**. 현재 웨이트리스트 얼리 액세스, DCVC 리드 $40M 시드. 다만 공개된 비교 평가가 자체 실시라는 지적이 이미 나왔다 — 독립 검증 전까지 수치는 참고만. [발표 블로그](https://typesafe.ai/blog/introducing-system-one-models-and-jev) · [GIGAZINE 정리](https://gigazine.net/gsc_news/en/20260916-system-one-jev/)
- **Google, Gemini 3.8 Live · Live Extended Thinking (9/15)** — Live API용 audio-to-audio 모델 2종. 핵심은 **대화 흐름을 멈추지 않는 백그라운드 툴·API 실행**과, Extended Thinking 변형의 "말하는 중 백그라운드 추론"이다. 문장 중간 전환까지 지원하는 97개 언어, 근실시간 시각 입력 처리. 가격은 오디오 입력 $0.005/분, 출력 $0.018/분(발표 기준). 음성 에이전트를 데모가 아니라 프로덕션으로 옮길 때 걸리던 "툴 호출 중 침묵" 문제를 정면으로 다뤘다. [공식 발표](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-8-live-gemini-3-8-live-extended-thinking/)
- **코딩 CLI는 이틀째 조용** — Codex CLI는 0.154.0, Claude Code는 2.1.273에 머물러 있다(이 세션에서 태그 목록·클론으로 확인). 릴리즈 공백은 아래 팁 섹션의 "묵혀둔 기능 발굴"로 채웠다.

# 📚 주목 논문

## 파인튜닝 기반 장기 기억, 단일 기법으론 안 된다 (arXiv 2609.06986, cs.LG)

- **저자**: Zheyuan Zhang, Alvin Zhang, Daniel Khashabi, Tianmin Shu — 존스홉킨스대 (9/7 v1, 오늘 HF Daily 1위 · 287 upvotes)
- **핵심 기여**: 100개 QA 태스크를 순차 SFT로 학습시키며 이전 예제 재사용도, 태스크 ID도 주지 않는 **long-horizon memorization** 세팅을 정의. 단일 continual learning 기법은 전부 이 지평에서 무너진다는 것을 보이고, 기법 "조합"의 설계 공간을 체계적으로 탐색했다.
- **방법**: 무엇을 보존할지(데이터·함수·가중치 앵커 3종)와 어디에 갱신을 쌓을지(low-rank 할당 규칙)를 축으로 조합을 구성. task-level successive halving으로 조합 공간을 탐색하고 요인 실험으로 상호작용 효과를 측정했다.
- **검증된 결과**: 순진한 순차 파인튜닝의 최종 보존율 1.2% → 앵커 3종 + merged LoRA 조합으로 **34.9% (28배)**. 데이터 앵커와 merged LoRA는 세 데이터셋 모두에서 초가산적(super-additive) 상승효과.
- 🛠 **에이전트 빌더 시사점**: "에이전트 기억을 가중치에 심겠다"면 기법 하나 고르는 문제가 아니라 조합 설계 문제다. RAG를 걷어내고 싶은 팀에게 좋은 출발 지도이고, 반대로 읽으면 — 최선의 조합도 34.9%라서 당분간 외부 메모리를 못 버린다는 근거이기도 하다.
- **한계**: QA 형태 암기 태스크 한정. 절차적 스킬이나 장문 문서 기억으로 일반화되는지는 미검증.
- [arXiv 링크](https://arxiv.org/abs/2609.06986)

## StepAudio 3 Realtime: 말하면서 생각하는 음성 에이전트 (arXiv 2609.14005)

- **저자**: StepFun 팀 90인 (9/12 공개, 오늘 HF Daily 3위 · 89 upvotes)
- **핵심 기여**: listen–converse–think–act 루프로 조직된 실시간 audio-language 파운데이션 모델. 깊은 추론과 응답 지연의 긴장을 **Think-While-Speaking** — 말로 전달하는 동안 비공개 추론을 병렬 실행 — 으로 푼다.
- **방법**: 억양·간투사 같은 음향 단서까지 읽는 Deep Perception, 끼어들기·맞장구를 자연 처리하는 Seamless Duplex 스트림 모델링, 그리고 대화 흐름을 끊지 않는 **비동기 툴 실행 Voice Agent**를 통합.
- **결과(초록 기준)**: MMSU 90.6, Artificial Analysis Full-Duplex Bench Overall 98.9, τ-Voice 매크로 태스크 성공률 56.0%.
- 🛠 **에이전트 빌더 시사점**: Gemini 3.8 Live와 같은 날 화제가 된 같은 설계 사상 — "툴 실행과 추론을 발화 뒤로 숨긴다"가 음성 에이전트의 표준 패턴으로 굳는 중. τ-Voice 56%라는 숫자는 음성 툴 에이전트가 아직 절반짜리라는 냉정한 기준선으로 기억해둘 것.
- **한계**: 이 글 작성 시점 기준 가중치는 미공개(HF에는 기술 리포트와 데모 Space만). 재현 검증 불가.
- [arXiv 링크](https://arxiv.org/abs/2609.14005)

# 🛠 오픈소스 스포트라이트

두 저장소 모두 이 세션에서 클론으로 검증했다(마지막 커밋 각각 9/15, 9/16). star 수는 GitHub API 접근 제한으로 미확인.

- **[JustVugg/colibri](https://github.com/JustVugg/colibri)** (C) — "작은 엔진, 거대한 모델." SSD·RAM·VRAM을 하나의 추론 계층으로 묶는 멀티티어링으로 **744B~2.8T 프론티어 MoE를 소비자·이기종 하드웨어에서** 돌리는 pure C 엔진. GLM-5.2/5.3, Kimi K3(2.8T), DeepSeek V4/V4.1 Flash, Qwen3.8-Flash-Next 등 9개 계열을 모델당 C 파일 하나로 지원하고, `coli chat / serve / web` 프론트엔드가 공통이다. "속도 SLA는 없지만 시맨틱스는 보장(정밀도·라우터 동작을 몰래 안 바꾼다)"는 정책이 인상적. **활용처**: H100 없이 로컬에서 오픈 웨이트 프론티어 모델을 평가하거나 에이전트 백엔드로 서빙할 때.
- **[Edge0-AI/edge0](https://github.com/Edge0-AI/edge0)** (Python/MLX) — 같은 문제를 반대쪽 끝에서. SSD expert 오프로드 + 양자화 손실을 복구하는 Recover-LoRA + 다음 라우팅을 예측해 미리 올리는 prerouter로, **35B-A3B MoE를 활성 메모리 약 3GiB**(모델 카드 기준)에 굴린다. Apple Silicon 전용(CUDA는 로드맵), 체크포인트 2종(35B-A3B·8B-A1B)이 LoRA·prerouter까지 한 세트로 Apache 2.0 공개. **활용처**: MacBook 로컬 에이전트 백엔드 후보 — 단, 모델 카드 스스로 "툴 사용·장기 자율성은 아직 약함"이라 밝히고 있으니 판단 계층보단 생성 보조부터.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — `codex cloud`: 터미널에서 클라우드로 태스크 던지고 diff만 회수

- **분류**: Workflow · **출처**: [codex-rs/cloud-tasks 소스](https://github.com/openai/codex/blob/main/codex-rs/cloud-tasks/src/cli.rs) (클론으로 확인)
- 💡 **핵심 아이디어**: 로컬 세션을 점유하지 않고 Codex Cloud에 태스크를 제출한 뒤, 결과를 unified diff로 받아 로컬에 적용하는 서브커맨드 세트가 CLI에 들어 있다(experimental). `--attempts N`으로 **베스트오브N 시도**까지 지원.
- 📝 **방법**:

```bash
codex cloud                      # 환경 ID 탐색용 TUI
codex cloud exec "flaky 테스트 3개 수정" --env <ENV_ID> --attempts 3
codex cloud list                 # 태스크 상태 확인
codex cloud diff <TASK_ID>       # 결과 diff 검토
codex cloud apply <TASK_ID>      # 마음에 들면 로컬 적용
```

- 🎯 **언제**: 랩탑을 잠글 밤 시간대에 병렬로 여러 시도를 걸어두고, 아침에 diff만 골라 담고 싶을 때.
- ⚠️ **주의**: experimental 표기 상태라 인터페이스가 바뀔 수 있고, Cloud 환경 설정(`--env`)이 선행돼야 한다. diff를 읽지 않고 `apply`부터 하지 말 것.
- ⭐ **추천도**: `/worktree`로 로컬 병렬화를 쓰는 팀이라면 클라우드 쪽 반쪽도 붙여볼 가치가 충분하다.

## 🟦 Claude Code — security-guidance: AI가 쓴 코드를 3계층으로 검사

- **분류**: Review · **출처**: [plugins/security-guidance](https://github.com/anthropics/claude-code/blob/main/plugins/security-guidance/README.md) (클론으로 확인)
- 💡 **핵심 아이디어**: 공식 저장소 번들 플러그인. ① `Edit`/`Write` 훅에서 위험 패턴 ~25종(`yaml.load`, `pickle.load`, raw `innerHTML`, 하드코딩 시크릿 등) 즉시 경고 → ② 턴 종료 시 diff를 경량 LLM 리뷰에 보내 고위험 발견을 응답 전에 수정 → ③ `git commit` 시점에 관련 파일을 따라 읽는 에이전트 리뷰로 IDOR·인증 우회 같은 **다중 파일 취약점**까지 추적한다.
- 📝 **방법**:

```text
/plugin install security-guidance@claude-plugins-official
```

  기본값으로 바로 동작. Python 3.8+ 필요, 리뷰 모델 등은 환경 변수로 조정.
- 🎯 **언제**: 생성 코드 비중이 커져 사람 리뷰가 병목이 된 팀. 규제·보안 민감 코드베이스라면 특히.
- ⚠️ **주의**: 턴마다 LLM 리뷰 호출이 붙으므로 토큰 비용이 늘고, 패턴 경고에는 오탐도 있다. 커밋 리뷰는 게이트가 아니라 보조 — CI의 정적 분석을 대체하지 않는다.
- ⭐ **추천도**: Anthropic 스스로 "머지 코드의 80%를 AI가 작성"하는 SDLC를 지키는 방식(아래 보너스 링크)과 세트로 읽으면 도입 근거가 선다.

## 🟪 공통 — 판단을 생성에서 분리하라

- **분류**: Workflow · **출처**: [GIGAZINE의 Jev 분석](https://gigazine.net/gsc_news/en/20260916-system-one-jev/)
- 💡 **핵심 아이디어**: 에이전트 루프의 LLM 호출 중 상당수는 텍스트가 아니라 **결정**(어느 서브에이전트로? 승인 필요? 관련성 점수는? 완료인가?)을 원한다. 이런 호출을 스키마 기반 판단 계층으로 분리하면 지연과 비용이 계단식으로 떨어진다 — Jev는 이 계층의 전용 모델이라는 베팅이고, 지금도 소형 분류기나 구조화 출력 모드로 같은 분리를 시작할 수 있다.
- 📝 **방법**: 루프의 각 LLM 호출에 "출력이 enum/bool/score로 표현 가능한가?"를 물어 태깅 → 가능한 호출부터 소형 모델 + 구조화 출력(또는 로짓 기반 룰)으로 교체 → 프론티어 LLM과의 일치율을 오프라인 평가로 확인 후 전환.
- 🎯 **언제**: 턴당 LLM 호출이 5회를 넘고 그중 절반이 판단성 호출일 때. 특히 가드레일·라우팅처럼 지연이 UX를 직접 깎는 지점.
- ⚠️ **주의**: 판단 계층의 확률이 "보정"돼 있는지는 자체 평가셋으로 확인해야 한다. Jev의 속도·가격 수치는 자체 발표 기준이며 아직 웨이트리스트라 지금 당장의 실전 대안은 소형 분류기 쪽이다.
- ⭐ **추천도**: 9/9에 다룬 "싼 모델 우선 캐스케이드"의 자매 패턴 — 그쪽이 세로(품질 단계) 분리라면 이번엔 가로(역할) 분리다.
