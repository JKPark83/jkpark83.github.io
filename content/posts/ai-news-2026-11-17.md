# 🔥 오늘의 핵심

NeurIPS 2026 벤치마크 논문 WebArena-Pro의 결론이 선명하다 — **웹 자동화에서 Codex·Claude Code 같은 코딩 하네스(62.3%)가 전용 웹 에이전트 스캐폴드(30.3%)를 2배 차이로 이긴다**. 브라우저 자동화 에이전트를 새로 만들 거라면, 전용 스캐폴드부터 짜지 말고 코딩 하네스 위에 올려서 베이스라인을 재보자. 한편 Alibaba는 Qwen4-Max를 정식 출시하며 1M 컨텍스트를 $1.50/$4.50에 풀었다.

*오늘의 AI 변화 지도. 미국 랩들이 조용한 주말, 중국발 릴리즈와 에이전트 인프라 레이어가 지면을 채웠다.*

# 🤖 모델 & 릴리즈 레이더

- **Qwen4-Max GA (11/16, 보도 기준)**: 11/11 제한 프리뷰로 시작한 Alibaba의 플래그십이 정식 출시됐다. 외신 종합으로 2.4T 파라미터 MoE, **1M 토큰 컨텍스트, $1.50/M 입력 · $4.50/M 출력**(국제 표준 요율, 캐시 입력 약 $0.075). 레포 전체를 통째로 넣는 장기 컨텍스트 에이전트 워크로드에서 미국 플래그십 대비 가격 공세가 세다. 단, **API 전용·클로즈드**이고 소형 Qwen4 오픈 웨이트는 "추후"라고만 한다. 이 항목은 1차 소스(qwen.ai) 접근이 막혀 외신·리스팅 교차 확인 기준이다. [Digital Trends](https://www.digitaltrends.com/computing/qwen-4-max-aliababas-latest-flagship-ai-model-announced/) · [OpenRouter 리스팅](https://openrouter.ai/qwen/qwen4-max)
- **InternLM Sage-S2.1-Flash (11/15)**: 상하이 AI랩이 **약 321B 과학 특화 멀티모달 에이전트 모델을 MIT 라이선스**(코드+가중치)로 공개. 분자 그래프·결정 구조·단백질 서열 등 10종 이상의 과학 입력을 받고, 검색·프로그래밍·툴 사용이 포함된 다회차 분석·검증 루프용으로 설계됐다. 모델 카드 자체 보고로 15개 벤치마크 중 4개 1위·7개 2위, MLE-bench Lite 90.3. 라이선스 마찰 없이 연구 자동화 에이전트의 플래너로 쓸 수 있는 급의 모델이다. [HF 모델 카드](https://huggingface.co/internlm/Sage-S2.1-Flash)
- **Haru-4B (11/12)**: 전화 통화처럼 **듣면서 동시에 말하는 풀듀플렉스 음성 대화 모델**(약 5B, Apache 2.0)이 HF 트렌딩 상위에 올랐다. 133ms 오디오 프레임, 캐릭터는 텍스트 카드로·목소리는 짧은 레퍼런스 클립으로 지정하고, **지원 9개 언어에 한국어가 포함**된다. instruct 튜닝 전의 리서치 베이스 모델이고 작성 조직의 실적이 얇다는 점은 감안할 것. 끼어들기(barge-in) 되는 한국어 음성 에이전트 실험 재료로는 드문 물건. # 📚 주목 논문

## 1. WebArena-Pro — 웹 에이전트 벤치마크의 승자는 코딩 하네스

- **저자**: Imene Kerboua, Fatemeh Pesaran Zadeh, Xing Han Lù 외 22인 (McGill/Mila 중심, NeurIPS 2026 D&B 채택)
- **arXiv**: [2611.17955](https://arxiv.org/abs/2611.17955) (cs.AI, 11/13)
- **핵심 기여**: 셀프호스팅 웹 앱 20종·6개 도메인에 걸친 300개 태스크. 라이브 웹 드리프트 없이 재현 가능하고, **웹페이지에 포함된 오디오·비디오를 핵심 관찰 대상으로 다루는 첫 웹 벤치마크**.
- **결과**: Codex+GPT 6.1 Sol과 Claude Code+Opus 5.5가 공동 1위 **62.3%**, OpenCode+Kimi 3.1 Pro 60.7%. 전용 GenericAgent 스캐폴드 최고 구성은 **30.3%**에 그쳤다.
- 🛠 **시사점**: 파일·셸·코드 실행이 되는 코딩 하네스가 현재 브라우저 자동화의 더 나은 기반이라는 정량 근거. 웹 에이전트를 만들고 있다면 "코딩 하네스 + 브라우저 툴" 베이스라인부터 깔고 시작하자.
- **한계**: 셀프호스팅 환경이라 로그인·안티봇·실서비스 드리프트는 못 잡는다. 최고점이 이미 62.3%라 포화도 빠를 수 있다.

![WebArena-Pro 성공률 비교: 코딩 하네스 62.3% 대 전용 웹 에이전트 스캐폴드 30.3%](/images/ai-news-2026-11-17/webarena-pro.svg)

*코딩 하네스 3종이 60%대, 전용 웹 에이전트 스캐폴드는 30%대. 수치는 논문 초록 기재값.*

## 2. MixUA — 공유 에이전트 메모리에 누가 접근해도 되는가

- **저자**: Yunzhe Wang 외 (AWS Agentic AI·USC, 인턴십 연구)
- **arXiv**: [2611.10439](https://arxiv.org/abs/2611.10439) (cs.CL, 11/7 제출 · 11/14 HF Daily 피처)
- **핵심 기여**: 멀티유저·멀티에이전트 환경에서 학습된 교훈(lesson)마다 **user-agent pair / user / agent / global 4단계 스코프**를 부여하는 첫 메모리 시스템. 누출 검증용 privacy probe가 포함된 CrossLearnBench도 함께 공개.
- **방법**: 궤적에서 교훈을 추출한 뒤, "누가 득을 보고 무엇이 노출되는가"에 맞는 **가장 좁은 스코프로 라우팅**. 에이전트는 허용 스코프 안의 메모리만 읽는다.
- **결과**(초록 기준): 5 유저·7 에이전트 실험에서 무메모리 대비 +16%p, **글로벌 단일 메모리 대비 +5%p**. 심어둔 사적 사실이 금지 스코프에서 발견된 비율은 최대 0.02%.
- 🛠 **시사점**: 멀티테넌트 에이전트 플랫폼에서 "전부 하나의 공유 메모리"는 프라이버시만이 아니라 **성능도 손해**라는 증거. 4단계 스코프 분류는 메모리 ACL 설계로 바로 베낄 수 있다.
- **한계**: 5 유저·7 에이전트의 소규모 실험이고, 프라이버시 보장은 probe 기반 경험적 수치다. 코드 미공개.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code / Subagent·Hook** — [mods/types/claude-code.d.ts](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) (11/14 커밋 [37291c9](https://github.com/anthropics/claude-code/commit/37291c90c88badf7e7a92796ec1e6515fff25efe), 클론으로 확인)

- 💡 플러그인(모드) 훅 API에 `$.agent.call()`과 `$.agent.limits()`가 추가됐다. 플러그인이 **특정 서브에이전트의 컨텍스트로** 툴을 실행할 수 있다 — 그 에이전트의 툴 셋·작업 폴더·권한 모드·룰을 그대로 물려받고, 모델이 직접 호출한 것처럼 훅·권한 체크를 전부 통과한다.
- 📝 플러그인 훅 모듈에서:

```ts
// 특정 에이전트의 컨텍스트로 Bash 실행 (agentId 생략 시 메인 대화)
const { text, deny } = await $.agent.call({
  tool: "Bash",
  input: { command: "git status" },
  agentId: e.agentId,
})

// 세션의 에이전트 동시 실행 한도 조회
const { concurrent, isBackgroundEnabled } = await $.agent.limits()
```

- 🎯 서브에이전트의 작업 폴더 상태를 점검하거나, 쉬고 있는 에이전트를 훅에서 움직이는 관찰·오케스트레이션 모드를 만들 때. 지금까지는 플러그인의 전역 `$.tool.call`밖에 없었다.
- ⚠️ 특권 호출이 아니다 — 권한 훅·auto 모드 분류기를 똑같이 거쳐 `deny`로 끝날 수 있고, `Workflow` 툴은 거부되며, 에이전트가 아직 로드하지 않은 툴도 거부된다.
- ⭐ `$.agent.limits()`의 `concurrent`는 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 환경변수를 반영한다(기본 20). 멀티에이전트 모드 만들 때 하드코딩하지 말 것.

**🟩 Codex / Workflow** — [커밋 e51c551](https://github.com/openai/codex/commit/e51c551fb406486afb7ef5c3d43387f1be3c09e8) (11/15 머지, 클론으로 확인)

- 💡 `codex exec`가 자기 에이전트를 띄우는 대신 **이미 떠 있는 `codex app-server`에 비대화형 턴을 실행**할 수 있게 됐다. 서버의 설정·크리덴셜을 그대로 쓰므로, CI나 다른 머신의 스크립트가 중앙에서 구성된 Codex 하나를 공유한다.
- 📝 서버와 클라이언트:

```bash
# 1) 설정·인증을 가진 app-server를 소켓/포트로 리슨
codex app-server --listen ws://127.0.0.1:4500

# 2) 어디서든 그 서버로 비대화형 턴 실행
codex exec --remote ws://127.0.0.1:4500 "fix the failing test"

# 베어러 토큰 인증(+JSON 출력), 스레드 재개도 가능
codex exec --remote wss://host:443 --remote-auth-token-env MY_TOKEN --json "prompt"
codex exec --remote unix:// resume THREAD_UUID "continue"
```

- 🎯 크리덴셜·config를 CI 러너마다 복사하지 않고, 인증된 Codex 서버 하나를 여러 잡이 공유하는 구성.
- ⚠️ `--remote`에서는 `--model`, `--sandbox`, `-c` 오버라이드, `--cwd`, 이미지 첨부가 전부 거부된다("서버에서 구성하라"). 재개는 스레드 UUID로만 되고, 턴 중간에 서버가 끊기면 에러로 끝난다.
- ⭐ 어제 소개한 rollout 예산 기능과 조합하면 "중앙 서버 + 잡별 토큰 상한" 구성이 된다.

**🟪 공통 / Review** — [codex 커밋 375a6b1](https://github.com/openai/codex/commit/375a6b1653ed7007354c2f44d2d4dcfb5f4d150f) (11/15, 클론으로 확인)

- 💡 OpenAI가 자사 리뷰 에이전트용 **디렉터리별 리스크 가이드 파일을 레포에 커밋하기 시작**했다. `codex-rs/tui/OWNERS`가 평가 전용 모드를 선언하고, `TEMPEST_REVIEW` 파일(YAML)이 "자동 승인해도 되는 변경 클래스"와 "사람에게 에스컬레이션할 변경 클래스"(제출·취소·포커스 로직, 재연결 순서 의존 상태 등), 리뷰 전 필독 경로를 명시한다.
- 📝 베낄 패턴: 리뷰 에이전트에게 전역 프롬프트 하나 대신, **디렉터리별로 "자동 통과 기준 / 에스컬레이션 기준 / 필독 문서"를 기계가 읽는 파일로** 깔아줘라. 리스크가 다른 코드에 같은 잣대를 대지 않게 된다.
- 🎯 모노레포에서 AI 코드 리뷰를 돌리는 팀. 렌더링 코드와 결제 코드의 리뷰 기준이 같을 리 없다.
- ⚠️ Tempest 자체는 OpenAI 내부 도구다 — 재사용할 것은 파일 이름이 아니라 패턴이다.
- ⭐ 리뷰 기준이 파일로 명문화되면 사람 리뷰어의 온보딩 문서로도 겸용된다.
