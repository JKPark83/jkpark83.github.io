# 🔥 오늘의 핵심

오늘의 중심은 "에이전트가 자기 스킬을 스스로 관리한다"는 아이디어다. R²Orch는 실패에서 증류한 스킬을 파라미터로 흡수한 뒤 **그 스킬을 회수(withdraw)해도 성능이 유지되는지**를 외부 루프가 검사하는 재귀 구조를 제안했다. 도구 쪽에서는 Anthropic이 자사 저장소의 이슈 트리아지 워크플로 설계를 그대로 공개 저장소에서 갱신해, 운영형 에이전트의 권한·인증 설계 교본을 하나 더 보여줬다.

# 🤖 모델 & 릴리즈 레이더

- **Apriel Voice 27B Preview (ServiceNow, MIT)** — 음성 인식·번역·구어 QA에 추론과 구조화된 툴 콜까지 한 백본에서 처리하는 오픈 모델. Gemma 4 26B-A4B 위에 Whisper large-v3-turbo 인코더를 프로젝터로 연결했고, 별도 대화 모델 없이 음성 입력에서 바로 툴 콜을 생성한다. 음성 에이전트에 ASR→LLM→툴 3단 파이프라인을 쓰고 있다면 단일 모델로 줄일 수 있는지 실험해 볼 만하다. 출력은 텍스트/툴 콜이라 TTS는 따로 필요. 모델 카드 기준 LibriSpeech WER 2.23%(test-clean), τ-Voice pass@1 65.51%(자체 보고). [HF 모델 카드](https://huggingface.co/ServiceNow-AI/Apriel-Voice-27B-preview) · [arXiv 2610.40738](https://arxiv.org/abs/2610.40738)
- 그 외 큰 모델 발표는 없음. 내일(11/4)로 예고된 **Kimi K3.1 Pro 오픈 웨이트** 공개가 이번 주 최대 이벤트다.

# 📚 주목 논문

## 1. R²Orch: 스킬을 회수하며 성장하는 오케스트레이터

- **저자**: Mingda Zhang, Yun Huang, Qiang Huang 외 (초록에 소속 미표기)
- **arXiv**: [2610.22740](https://arxiv.org/abs/2610.22740) (cs.AI) · [코드](https://github.com/beita6969/R2Orch) · HF Daily 2위
- **핵심 기여**: 셀프플레이로 오케스트레이터를 개선하는 내부 루프와, "그 개선 방식 자체"를 개선하는 외부 루프의 2중 재귀 구조.
- **방법**: Proposer는 "스킬을 빼면 결과가 갈리는" 태스크를 고르도록 보상받고(Recursive Learnability), 외부 루프는 통제 평가에서 스킬 없이도 성능이 같으면 그 스킬을 회수한다. 실패→스킬→파라미터→회수→새 실패의 순환.
- **결과**: QA·수학·코드·인터랙티브 12개 데이터셋에서 베이스라인 일관 상회(논문 보고치).
- 🛠 **에이전트 빌더 시사점**: 스킬/프롬프트 라이브러리가 계속 불어나기만 하는 시스템이라면, "졸업한 스킬을 제거하는" 명시적 경로가 설계에 있는지 점검해 볼 것.
- **한계**: 스킬 내재화는 파인튜닝 가능한 모델 전제라, API 모델 위에 스킬 파일을 쌓는 구성에는 회수 아이디어만 부분 이식된다.

![R²Orch의 2중 루프 구조](/images/ai-news-2026-11-03/r2orch-loop.svg)

*실패가 스킬이 되고, 스킬이 파라미터로 흡수되면 회수되는 순환. 종착점은 "스킬 0개 배포"다.*

## 2. SimpleLoRIF: 파인튜닝 데이터 속 '안전 저하 범인' 추적

- **저자**: Saket Reddy, Amro Abbas, Anshuman Suri, Ari Morcos, David Schwab, Pratyush Maini
- **arXiv**: [2610.37481](https://arxiv.org/abs/2610.37481) (cs.LG)
- **핵심 기여**: 겉보기엔 무해한데 모델 안전성을 갉아먹는 파인튜닝 예제를 그래디언트 정렬로 찾아내는, 백만 건 규모까지 도는 필터.
- **방법**: 저랭크 그래디언트 어트리뷰션을 단순화하고 역전파를 마지막 4개 블록으로 제한해 임베딩 비용을 낮췄다. Tulu 3에서 위험 정렬 상위 20%를 제거한 SafeTulu를 공개.
- **결과**: SafeTulu 학습 시 GCG 공격 성공률 최대 22% 감소(Qwen·Llama·Olmo), 능력치는 대체로 유지(논문 보고치).
- 🛠 **에이전트 빌더 시사점**: 흥미로운 발견 — **툴 실행 실패 로그**가 과소평가된 안전 저하 원인으로 지목됐다. 에이전트 궤적으로 파인튜닝한다면 실패 트레이스를 무심코 섞는 게 공짜가 아니라는 뜻.
- **한계**: 그래디언트 기준 필터라 "왜 그 예제가 위험한가"에 대한 해석은 사후 분석에 의존한다.

# 🛠 오픈소스 스포트라이트

> 두 저장소 모두 클론해 README·라이선스를 확인했다. 스타 수는 GitHub 검색 API 기준 근사치.

- **[heydamir/unslop](https://github.com/heydamir/unslop)** — JavaScript, CC BY 4.0, ~6,100★ (10/29 공개). 바이브코딩된 "AI 티 나는" UI(보라 그라데이션, 글로우, 이모지 라벨, 들쭉날쭉한 간격)를 찾아내 디자이너의 레드라인 리뷰처럼 패스 단위로 고치는 스킬. Claude Code(`/unslop`)와 Codex(`$unslop`)를 모두 지원하고, React·Vue·Svelte·Tailwind·순수 CSS 어디서든 돌며 라이브 사이트 링크만으로도 작동한다. **용도**: 데모 전 화면 마감 공정으로 파이프라인 끝에 끼워 넣기.
- **[storytold/craft-anything](https://github.com/storytold/craft-anything)** — Rust, MIT/Apache-2.0, ~3,800★ (10/31 공개, 얼리 알파). 웹사이트·앱·게임을 검사 도구로 분석한 뒤 코딩 에이전트가 클린룸 방식으로 "내 버전"을 빌드하고, 원본과 대조 검사해 어긋난 부분만 다시 고치는 데스크톱 엔진. 규칙 밖 명령은 승인 카드로 사람에게 묻는다. **용도**: 검사→빌드→대조→수정 루프의 참조 구현으로. 클린룸을 표방하지만 타깃에 따라 저작권·약관 문제는 사용자 몫이다.

[커밋 08165a3](https://github.com/anthropics/claude-code/commit/08165a35240d82200b7e22a5f235e79fe2945dd4) (11/1, Sonnet 5.5로 이동)

- 💡 Anthropic이 claude-code 저장소의 이슈 트리아지·중복 정리·`@claude` 멘션 워크플로를 Sonnet 5.5로 옮기면서, 운영형 에이전트 설계가 담긴 `.github/workflows/claude-issue-triage.yml`이 다시 주목할 만해졌다.

**🟪 공통 — 스킬에도 '졸업 시험'을 (Eval / Context)**

- ⚠️ 태스크 분포가 좁으면 "지금은 안 쓰는 스킬"과 "영원히 불필요한 스킬"을 혼동하기 쉽다.
