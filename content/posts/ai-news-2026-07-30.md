# 🔥 오늘의 핵심

오늘은 새 프런티어 모델보다 **에이전트가 실제로 움직이는 '실행 계층'** 에 신호가 모인다. (1) 논문 한 편은 에이전트가 **자기 다음 툴콜을 스스로 예측·선실행**해 대기시간을 회수한다(Hit@1 44.1→61.2). (2) 다른 한 편은 컴퓨터유즈 에이전트가 **"방금 그 액션이 뭘 바꿨는지"를 이해하는지** 따로 측정하는 벤치(DDB)를 내놨다. (3) NVIDIA는 **agentic RL 학습 스택 Molt**를 열었다. 오늘 할 일: 에이전트 루프의 지연을 **툴콜 예측·프롬프트 캐싱**으로 줄이고, 컴퓨터유즈는 **성공 여부와 별개로 '상태 전이'를 검증**하라.

# 📚 주목 논문

오늘은 **에이전트 실행의 두 축** — 속도(툴콜 대기시간)와 신뢰성(컴퓨터유즈 검증).

## 1) Speculate While You Reason — 에이전트가 자기 다음 툴콜을 미리 친다

- **저자**: Jiabao Ji, Yujian Liu, Li An 외 (arXiv `2607.25816`, cs.AI, 2026-07-28)
- **핵심 기여**: 툴콜 speculation의 별도 draft 모델·캐시 트레이스는 **배포된 에이전트의 실제 행동과 어긋난다(speculator-agent gap)**. 저자들은 **에이전트 자신이 최고의 speculator**임을 보이고, 하나의 모델에 두 모드를 합쳤다.
- **방법(3줄)**: 단일 모델이 `agent 모드`(과제 풀이·툴 호출)와 `speculator 모드`(부분 궤적으로 다음 툴콜 예측)를 겸한다. **prefix KV 캐시를 그대로 재사용**해 예측 비용을 낮춘다. agent·speculator를 **번갈아 RL** 업데이트한다.
- **결과(검증)**: next tool-call **Hit@1 — Qwen3-4B 44.1→61.2, Qwen3.5-4B 48.9→66.3**, 과제 성공률은 유지.
- 🛠 **에이전트 빌더 시사점**: 툴콜 대기시간이 지배적인 워크로드(검색 QA, 대화형 툴사용)라면, **다음 호출을 예측해 선실행**하는 것만으로 체감 지연을 크게 줄일 수 있다. 별도 draft 모델을 붙이기 전에 **"내 에이전트 자신"을 speculator로** 써보라.
- ⚠️ **한계**: 검증은 4B급 오픈모델·특정 태스크군 중심. 예측이 빗나가면 선실행한 툴 부작용(쓰기·결제 등)을 어떻게 롤백할지는 별도 설계가 필요하다.
- 링크: [arxiv.org/abs/2607.25816](https://arxiv.org/abs/2607.25816)

![Self-Speculating Agent 방법도. 왼쪽: 단일 모델이 agent 모드와 speculator 모드를 겸하며 prefix KV 캐시를 공유하고, ① 툴 결과 대기 중 다음 호출을 미리 실행 ② 예측이 일치하면 대기시간 회수 ③ agent·speculator 교차 RL. 오른쪽: Hit@1 막대그래프 Qwen3-4B 44.1→61.2, Qwen3.5-4B 48.9→66.3](/images/ai-news-2026-07-30/speculation-flow.svg)
*단일 모델이 스스로 speculator가 되어 다음 툴콜을 미리 실행 → 대기시간을 숨긴다. 수치는 논문 보고값. (자체 제작 SVG)*

## 2) Desktop-Delta Bench — 컴퓨터유즈는 "방금 뭘 바꿨는지" 아는가

- **저자**: Abhishek Pillai, Samir Kumar Nayak, Yuan Chen 외 (arXiv `2607.26041`, cs.AI, 2026-07-28)
- **문제**: 기존 컴퓨터유즈 벤치는 **최종 성공률이나 단일 프레임 grounding**만 잰다. 정작 중요한 건 **한 액션이 만든 인과적 상태 전이를 재구성하는 능력** — 낡은 관측을 걸러내고, 진행을 검증하고, 실패에서 복구하는 데 필수다. 추론·렌더링·스크린샷이 비동기라 다음 관측이 지연·가려짐·엉뚱함으로 오면 "진행됐다"고 오독한다.
- **벤치**: **2,013개 사람 검증 인스턴스**, Linux 멀티앱 궤적, ~15개 앱·50개 도메인. 상태검증·소스추적·문맥제어 3축을 **temporal-ordering(463개, 105개는 교차궤적 decoy 포함)** 과 **before-after 쌍(1,550개)** 로 측정. 폐·오픈 8개 모델군 평가.
- **결과(검증)**: ordering은 아직 미포화 — 최고 exact-match **non-decoy 65.1% / decoy 65.7%**. 액션 인식에서 **위치 찾기(click F1 0.96)보다 '어떤 동작인지' 판별(drag F1 0.76)이 더 어렵다.**
- 🛠 **에이전트 빌더 시사점**: 컴퓨터유즈 루프에 **"이 액션이 실제로 기대한 전이를 일으켰는가"를 판정하는 검증 단계**를 명시적으로 넣어라. 스크린샷 하나로 "됐다"고 넘기지 말고, **before/after 델타**를 근거로 진행을 확정하라.
- ⚠️ **한계**: 오프라인 step 단위 진단 벤치라 end-to-end 성공률과는 별개 층위. 데스크톱(Linux) 중심.
- 링크: [arxiv.org/abs/2607.26041](https://arxiv.org/abs/2607.26041)

# 🛠 오픈소스 스포트라이트

오늘의 축과 맞물리는 **학습 스택(Molt)** 과 **실행 스택(ScaleCUA)** 하나씩.

> 별점은 표기하지 않는다 — 이 세션에서는 GitHub API 접근이 스코프로 막혀 있어 스타 수를 검증할 수 없다. 검증 가능한 속성만 비교한다.

## Molt — agentic RL 학습을 "머릿속에 들어오는" 크기로

- **repo**: [github.com/NVIDIA-NeMo/labs-molt](https://github.com/NVIDIA-NeMo/labs-molt) · Python/PyTorch
- 무엇: **PyTorch-native agentic RL 학습 프레임워크.** RL 코어가 약 **9.2K LOC**로 작아서 연구자(그리고 코딩 에이전트)가 코드 전체를 읽고 추론할 수 있게 설계됐다. 에이전트는 평범한 프로그램이고, 하나의 비동기 루프가 멀티모달·MoE 정책을 학습하되 **자기가 생성하지 않은 토큰으로는 절대 학습하지 않는다(on-policy).**
- 스택: **vLLM**(롤아웃) + **FSDP2/AutoModel**(학습) + **Ray**(배치·비동기 큐)로 **1T-class MoE**까지 스케일.
- 개발자 활용: 검색·코딩 에이전트의 **정책을 직접 RL로 튜닝**하려는데 Megatron 기반 대형 스택이 부담이라면, 읽고 고칠 수 있는 출발점.
- 출처: [arXiv 2607.21653](https://arxiv.org/abs/2607.21653)

## ScaleCUA — 크로스플랫폼 컴퓨터유즈 에이전트의 오픈 베이스

- **repo**: [github.com/OpenGVLab/ScaleCUA](https://github.com/OpenGVLab/ScaleCUA) · Python
- 무엇: **Windows/macOS/Ubuntu/Android를 아우르는 오픈 컴퓨터유즈 에이전트.** 모델 체크포인트 + SFT 코드베이스 + 크로스플랫폼 데이터셋 + 온라인 평가 스위트를 함께 공개(ICLR 2026 Oral).
- 성능(보고값): OSWorld-G **60.6%**, WebArena-Lite-v2 **47.4%**, MMBench-GUI L1-Hard **94.4%**.
- 개발자 활용: 위 DDB 논문이 지적한 **"상태 전이 검증"** 을 직접 실험하고 싶을 때, 데이터·평가까지 갖춘 베이스로 붙여 쓰기 좋다.
- 출처: [huggingface.co/papers/2509.15221](https://huggingface.co/papers/2509.15221)

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — MCP: `config.toml`에 툴 서버를 선언해 붙이기

- 출처: [developers.openai.com/codex/mcp](https://developers.openai.com/codex/mcp)
- 💡 **핵심**: Codex CLI는 `~/.codex/config.toml`(프로젝트 신뢰 시 `.codex/config.toml`)의 `[mcp_servers.<name>]` 블록으로 MCP 서버를 stdio 기동한다. 툴을 코드로 심지 말고 **설정으로 붙여라.**
- 📝 **How-to**:
```toml
# ~/.codex/config.toml
[mcp_servers.docs]
command = "node"
args = ["./mcp/docs-server.mjs"]
env_vars = ["DOCS_TOKEN"]
startup_timeout_sec = 10
tool_timeout_sec = 60
```
```bash
# CLI로 등록도 가능 (stdio 서버는 -- 뒤에 command)
codex mcp add docs -- node ./mcp/docs-server.mjs
```
- 🎯 **언제**: 여러 프로젝트에서 같은 사내 툴(문서·DB·이슈트래커)을 재사용할 때.
- ⚠️ **주의**: `env_vars`는 토큰 값을 파일에 박지 말고 **환경변수 이름만** 넘긴다. `tool_timeout_sec`을 넉넉히 주지 않으면 느린 툴이 끊긴다.
- ⭐ **추천**: 툴을 config로 분리 → 에이전트 코드는 그대로 두고 툴만 갈아끼운다.

## 🟦 Claude Code — Subagent: 곁가지 작업을 병렬 서브에이전트로 내보내기

- 출처: [code.claude.com/docs/en/sub-agents](https://code.claude.com/docs/en/sub-agents)
- 💡 **핵심**: 검색·로그·파일 덤프처럼 **다시 안 볼 컨텍스트**로 메인 대화가 오염될 작업은 서브에이전트에 넘겨라. 각 서브에이전트는 **자기 컨텍스트 창 + 제한된 툴**로 일하고 **요약만** 돌려준다.
- 📝 **How-to** (`.claude/agents/explorer.md`):
```markdown
---
name: explorer
description: 코드베이스를 탐색해 관련 파일과 심볼만 요약 반환. 읽기 전용 조사에 사용.
tools: Read, Grep, Glob
model: haiku
---
당신은 조사 전담이다. 파일을 수정하지 말고,
핵심 파일 경로와 근거 라인만 간결히 보고하라.
```
- 🎯 **언제**: 넓은 코드베이스에서 "어디에 뭐가 있나"를 여러 갈래로 동시에 훑어야 할 때. 저비용 모델(Haiku)로 라우팅하면 비용도 준다.
- ⚠️ **주의**: 실행 중이던 세션은 새로 만든 `~/.claude/agents/` 디렉터리를 못 잡는다. 없던 디렉터리를 만들었으면 **재시작**하라.
- ⭐ **추천**: 오늘의 논문 1과 같은 발상 — **곁가지 지연을 병렬로 숨겨** 메인 루프를 빠르게.

## 🟪 공통 — Context: prefix를 고정하고 프롬프트 캐싱으로 지연·비용 회수

- 출처: [docs.anthropic.com — Prompt caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)
- 💡 **핵심**: 오늘 논문 1이 **prefix KV 캐시 재사용**으로 이득을 봤듯, 실서비스 에이전트도 **툴 정의·시스템 프롬프트·장문 컨텍스트를 프롬프트 앞쪽에 고정**하고 `cache_control`을 걸면 반복 호출의 지연·비용을 크게 줄인다.
- 📝 **How-to**: 변하지 않는 블록(시스템 지침, 툴 스키마, 참고 문서)을 **맨 앞**에 두고 캐시 브레이크포인트를 지정 → 매 스텝 바뀌는 부분(직전 관측·툴 결과)만 뒤에 이어붙인다. 순서를 바꾸면 캐시가 깨진다.
- 🎯 **언제**: 동일한 대형 컨텍스트로 툴콜을 여러 번 도는 모든 에이전트 루프.
- ⚠️ **주의**: 앞쪽 블록을 한 토큰이라도 바꾸면 그 뒤 캐시가 전부 무효화된다. **동적 요소를 앞에 섞지 마라.**
- ⭐ **추천**: "speculation(예측)"과 "caching(재사용)"은 같은 목표 — **에이전트 대기시간을 없애는** 두 손잡이다.

# 📌 지속 이슈 / 📅 내일 주목 / 🔗 보너스 링크
