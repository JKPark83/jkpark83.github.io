# 🔥 오늘의 핵심

오늘 축은 **"값싼 결정적(deterministic) 체크로 에이전트 신뢰성 올리기"**. 프런티어 모델 소식은 조용하지만, 신규 논문 두 편이 실무에 바로 꽂힌다. 핵심은 하나 — **모든 스텝을 LLM 심판에게 맡기지 말 것**. 실패는 μs급 모니터로 1차 알람하고, 메모리는 검색·저장을 폐루프로 함께 굴려라.

# 📚 주목 논문

## ① 정상 실행만으로 에이전트 실패를 잡는다

- **저자/소속**: Sunny Dubey (독립 저자, preprint)
- **arXiv**: [2608.02464](https://arxiv.org/abs/2608.02464) · cs.AI · 2026-08-03
- **핵심 기여**: LLM 에이전트는 루프·툴 에러 폭주·목표 이탈·환각·오염 흡수로 실패하는데, 표준 처방(매 스텝을 2차 LLM으로 판정)은 에이전트 본체보다 비싸다. 이 논문은 **관측 가능한 스텝 텔레메트리만으로, 정상 실행만 학습한 μs급 모니터**가 실패를 얼마나 잡는지 측정한다.
- **방법 (2–3줄)**: 원클래스 **echo-state-network 앙상블 + CUSUM 알람**. 건강한 실행 분포만 학습해 이상 스텝에서 경보. 스텝당 비용은 마이크로초 수준.
- **검증된 결과**: 2,823개 에피소드(3개 프레임워크, 로컬 qwen2.5 7b/3b·llama3.1 8b + gemini-2.5-flash)에서 **오탐 5% 예산에 실패 탐지율 0.71, AUROC 0.872**.
- 🛠 **에이전트 빌더 시사점**: judge-every-step을 버리고, **툴 에러 연속·동일 호출 반복(루프)·지연·목표 이탈** 같은 값싼 신호로 1차 알람 → 플래그된 스텝만 LLM 심판/복구로 에스컬레이션.
- **한계**: "정상 대비 이상"으로 잡히는 실패 클래스에 강하고, 복구(repair) 파트는 상대적으로 덜 성숙. 단독 저자 preprint라 재현 확인 권장.

![arXiv 2608.02464 실패 탐지 파이프라인과 검증 수치](/images/ai-news-2026-08-05/failure-monitor.svg)
*정상 실행만 학습한 모니터가 이상 스텝을 알람하고, 의심 스텝만 LLM 심판/복구로 넘긴다. 수치는 논문 abstract 기준.*

## ② CoEvo-Mem — 검색과 메모리를 폐루프로 함께 굴린다

- **저자**: Bowen Ye, Yongchao Xu, Zhijian Li, Xiang Yin, Junkai Ma 외
- **arXiv**: [2608.01739](https://arxiv.org/abs/2608.01739) · cs.AI · 2026-08-03
- **핵심 기여**: 장기 에이전트 성능은 **질의별 검색**과 **메모리의 지속적 정제**에 함께 달렸는데, 기존 방법은 둘 중 하나만 최적화한다. 이 논문은 **검색이 어떤 메모리에 사용 신호를 주고, 갱신된 메모리가 다시 검색을 바꾸는** 피드백 루프에 주목한다.
- **방법 (2–3줄)**: 각 질의마다 frozen LLM이 경로별 질의 재작성을 만들고, 검색 정책과 메모리 뱅크를 **폐루프(CoEvo)**로 공진화. 사용된·유용했던 메모리 신호를 검색·정제 양쪽에 되먹인다.
- 🛠 **에이전트 빌더 시사점**: 메모리 스토어를 고정하지 말 것. **어떤 메모리가 검색됐고 실제로 쓸모 있었는지**를 로깅해 검색 랭킹과 메모리 통합(consolidation) 양쪽 업데이트에 반영.
- **한계**: 폐루프가 늘리는 시스템 복잡도·지연은 별도 관리 필요. 정량 지표는 원문 본문 확인 권장.

# 🛠 오픈소스 스포트라이트

- **AgentOps** — `AgentOps-AI/agentops` · Python · ⭐ ~5.5k
  - AI 에이전트 모니터링/비용 추적/세션 리플레이/실패 탐지 SDK. CrewAI·OpenAI Agents SDK·LangChain·AutoGen 등과 연동, `agentops.init()` 2줄로 대시보드 관측.
  - **쓸 곳**: 논문 ①의 아이디어를 실제로 굴리려면 먼저 스텝 텔레메트리가 필요하다. AgentOps가 그 수집·리플레이 레이어.
- **Cognee** — `topoteretes/cognee` · Python · Apache-2.0 · ⭐ ~28.3k
  - ECL(extract-cognify-load) 파이프라인으로 **그래프+벡터+세션 메모리**를 단일 Postgres에 자가호스팅. MCP·LangGraph 네이티브 연동.
  - **쓸 곳**: 논문 ②의 폐루프 메모리를 붙일 실전 저장소. 검색 로그를 메모리 정제에 되먹이기 좋은 그래프 구조.

### 🟦 Claude Code — Context/Workflow

- **출처**: [Claude Code changelog](https://code.claude.com/docs/en/changelog) (v2.1.221)
- 💡 **핵심**: 긴 에이전트 실행에서 툴 활동이 화면을 뒤덮으면 판단이 흐려진다. `Focus view`는 툴 활동을 **턴별 요약**으로 접고 실행 중 툴 표시만 남긴다.
- 📝 **How-to**: 채팅 메뉴 토글 또는 단축키.

```text
Ctrl+Alt+F          # Focus view 토글
"Claude Code: Toggle Focus view"   # 커맨드 팔레트에서도 동일

# 폭주 방지용 세션 상한(v2.1.212~)도 같이 걸어두면 좋다
export CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=200
export CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION=200
```

- 🎯 **언제**: 서브에이전트·툴 호출이 많은 장기 작업에서 로그 스크롤에 지칠 때.
- ⚠️ **주의**: 요약 뒤로 접힐 뿐 실행은 그대로. 디버깅 중 세부 툴 출력이 필요하면 다시 펼쳐야 한다.
- ⭐ **추천**: 장기 에이전트 실행이 일상이면 기본으로 켜둘 만하다.

### 🟪 공통 — Eval/Debugging (오늘 논문 ①에서)

- **출처**: [arXiv 2608.02464](https://arxiv.org/abs/2608.02464)
- 💡 **핵심**: 신뢰성 게이트를 **값싼 결정적 신호**로 먼저 세워라. LLM 심판은 그 다음.
- 📝 **How-to**: 프레임워크와 무관하게 스텝 훅에서 아래를 계측한다.

```python
# 정상 실행 로그로 임계치를 먼저 잡고, 이탈 시 알람
signals = {
    "tool_error_streak": consecutive_tool_errors,   # 연속 툴 실패
    "loop": identical_call_count(last_n=5),          # 동일 호출 반복 = 루프
    "latency_spike": step_latency / baseline_p95,    # 지연 급증
}
if any_over_threshold(signals):
    escalate_to_llm_judge(step)   # 플래그된 스텝만 심판/복구
```

- 🎯 **언제**: 장기·다단계 툴 사용 에이전트를 프로덕션에 올릴 때.
- ⚠️ **주의**: 임계치는 반드시 **정상 실행 분포**에서 캘리브레이션. 자기보고 confidence로 랭킹하지 말 것(이전 브리핑 참고).
- ⭐ **추천**: judge-every-step으로 비용이 새고 있다면 1순위로.
