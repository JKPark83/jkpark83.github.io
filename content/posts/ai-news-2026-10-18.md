# 🔥 오늘의 핵심

# 📚 주목 논문

## Self-Evolving Agent Harness: 하네스 자가진화의 이론틀

- **저자**: Chuyang Wei, Haoxiang Guan, Yifei Shen 외 (Zhongguancun Academy, Zhongguancun Institute of AI, USTC)
- **arXiv**: [2610.18813](https://arxiv.org/abs/2610.18813) (cs.AI, 10/13 공개, arXiv API 검증)
- **핵심 기여**: 에이전트가 프롬프트·메모리·워크플로·코드 같은 **자기 하네스를 스스로 고치는 과정(Harness RSI)을 처음으로 형식화**한 서베이+이론 논문. 18페이지 본편에 66페이지 풀버전이 따로 있습니다.
- **방법**: "무엇을 고치나(해석되는 상태 vs 실행 코드 vs 제어 로직 vs 플러그인)"와 "어떻게 제안·수용하나"를 분리하고, 진화적 탐색과 continual PAC-learning으로 신뢰성을 분석합니다.
- **핵심 결과**: 일반화 바운드·회귀 예산 조건부 유지 바운드와 함께, **"새 검증 데이터를 통과한 수정만 수용하라"는 고확률 admission rule**을 유도.
- 🛠 **에이전트 빌더 시사점**: 메모리 파일·스킬을 스스로 갱신하는 에이전트를 운영 중이라면, 이 논문의 admission rule이 "자가 수정이 언제 안전한가"에 대한 첫 이론적 기준선입니다.
- **한계**: 이론 중심이라 바운드의 가정(독립 검증 데이터 확보 등)이 실제 운영에선 비쌀 수 있습니다.
- [GitHub(읽기 목록+자료)](https://github.com/zgcagi/Harness-RSI)

## LEASH: 약한 모델의 불확실성이 라우터다

- **저자**: Qingni Wang, Changdae Oh, Sharon Li, Xin Eric Wang 외 (arXiv 페이지에 소속 미표기)
- **arXiv**: [2610.22280](https://arxiv.org/abs/2610.22280) (cs.AI, 10/15 공개, arXiv API 검증)
- **핵심 기여**: 컴퓨터 유즈 에이전트의 weak-to-strong 에스컬레이션에서 **"언제 강한 모델을 부르고, 부른 뒤엔 어떻게 감시하나"**를 학습 없이 푸는 프레임워크.
- **방법**: 약한 모델의 은닉 상태를 과거 성공/실패 궤적과 비교해 불확실성을 추정 — 액션 생성 때 나온 활성값을 재사용하므로 **추가 forward pass가 없습니다**. 이 신호로 ① 초기 라우팅 ② 스텝 단위 에스컬레이션 ③ 핸드오프 후 블랙박스 강한 모델의 섀도 감시까지 3겹을 돌립니다.
- **결과(저자 보고)**: OSWorld에서 Qwen3.5-35B-A3B + LEASH가 성공률 73.66%/태스크당 $0.41 — **상시 Claude Opus 5(72.90%)와 동급, 비용 19.2% 절감**. 같은 에스컬레이션 비율의 무작위 핸드오프 대비 +6.55~11.94pt.
- 🛠 **에이전트 빌더 시사점**: 어제의 SpecAgent가 "강한 모델은 리뷰어"였다면 LEASH는 "강한 모델은 비상 호출" — 로컬 가중치가 있는 약한 모델이라면 은닉 상태가 공짜 라우팅 신호가 됩니다.
- **한계**: 약한 모델의 내부 접근이 전제라 API 전용 모델 조합엔 그대로 못 씁니다. 공개 코드도 아직 없습니다.

![LEASH 워크플로](/images/ai-news-2026-10-18/leash-flow.svg)

*LEASH의 3겹 구조: 초기 라우팅 → 스텝 단위 에스컬레이션 → 섀도 옵저버. (자체 제작, 출처: arXiv 2610.22280)*

- 💡 **핵심**: 10/16 머지로 `multi_env_copy_file` 툴이 들어왔습니다. 연결된 **두 환경(로컬↔원격 executor) 사이에서 파일을 직접 복사**하는데, 파일 내용이 **모델 컨텍스트를 거치지 않습니다**. 지금까지는 에이전트가 파일을 읽어 다른 환경에 다시 써야 해서 토큰과 정확성 양쪽에서 손해였습니다.
- 📝 **방법**: 기본 비활성(Under Development). `~/.codex/config.toml`에서:

```toml

multi_env_copy_file = true
```

- ⚠️ **주의**: 절대 경로만 받고 양 끝의 샌드박스 정책·권한을 그대로 적용합니다. 쓰기 실패 시 대상 파일이 잘린 채 남을 수 있다고 커밋 메시지에 명시돼 있습니다.

- 💡 **핵심**: 어제 다룬 기본값 변경 말고도 2.1.302엔 조용한 운영 변화가 더 있습니다. ① **프롬프트·에이전트 훅은 이벤트당 동시 12개까지만 실행**되고 나머지는 대기 ② auto 모드 서버측 분류기가 너무 긴 대화를 만나면 이제 **툴 콜 전면 거부 대신 컴팩션**을 수행 ③ `/config`에 **Idle compaction** 토글이 생겼습니다.
- 📝 **방법**: 훅을 수십 개 등록한 플러그인 헤비 유저라면 오늘 점검:

```bash
# 훅 실행이 밀리는지 확인 — 같은 이벤트에 12개 초과 등록 시 순차 대기
claude --debug  # hook 실행 타이밍 로그 확인
# 유휴 컴팩션이 싫다면 /config → Idle compaction → off
```

- 🎯 **언제**: PreToolUse 훅에 린트·정책 검사를 줄줄이 달아둔 저장소, 그리고 장시간 무인 세션.
- ⚠️ **주의**: 동시 12개 제한은 끄는 옵션이 없습니다. 지연에 민감한 검사라면 훅 하나로 합치는 편이 안전합니다.
- ⭐ 추천도: ★★★★☆
