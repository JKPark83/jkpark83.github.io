# 🔥 오늘의 핵심

주말이라 릴리즈는 조용하지만 설계에 영향을 주는 신호가 둘 나왔다. **IQuest-Q1 기술 리포트**는 토큰당 활성 15B짜리 MoE가 터미널·보안 에이전트 과제에서 프런티어 5점 안쪽까지 들어왔음을 공개했고(측정 하네스가 Claude Code다), **Raw-RAG 논문**은 "복잡한 agentic memory 시스템이 원문 검색+리랭크보다 못하다"는 결과로 메모리 스택의 기본값을 흔든다. 오늘 해볼 일: 메모리 프레임워크를 걷어내고 베이스라인부터 다시 재는 것.

![2026년 10월 25일 AI 변화 지도 — 모델, 논문, 오픈소스, 바이브코딩 4개 영역 요약](/images/ai-news-2026-10-25/change-map.svg)

*오늘의 AI 변화 지도. "더 작게, 더 단순하게"가 모델과 메모리 양쪽에서 동시에 나왔다.*

# 🤖 모델 & 릴리즈 레이더

- **IQuest-Q1 기술 리포트 공개** — 웨이트는 9/28부터 [HF에 올라와 있었지만](https://huggingface.co/IQuestLab/IQuest-Q1), 10/22 [기술 리포트(arXiv 2610.30949)](https://arxiv.org/abs/2610.30949)가 나오면서 HF Daily Papers 상위권에 올랐다. 320B MoE(활성 15B), 524K 컨텍스트, 3 SWA + 1 FA 하이브리드 어텐션, 추론 시 재귀 MTP. 에이전트 빌더가 볼 포인트 둘. 첫째, 포스트트레이닝이 "multi-scaffold" — 여러 하네스(스캐폴드)에서 RL을 돌리고 모델 머징으로 합쳤다. 둘째, 벤치마크 재현 조건에 Claude Code `2.1.140` / Codex `0.142`를 명시했다. 모델 스펙에 하네스 버전이 들어가는 시대다.
- 그 외 큰 모델 소식 없음. HF 트렌딩은 여전히 DeepSeek-V4.1-Flash와 Flint(어제 다룸)가 상위권.

![IQuest-Q1과 각 벤치마크 1위 모델의 점수 비교 막대 차트](/images/ai-news-2026-10-25/iquest-q1.svg)

*제조사 발표치 기준. Terminal-Bench 2.1에서 83.2(1위 Claude Opus 5는 89.1), CyberGym 84.5. 활성 15B로 낸 숫자라는 게 핵심이고, 전부 자체 측정이라는 게 함정이다.*

# 📚 주목 논문

## Is Complex Agentic Memory Always Needed?

- **저자**: Zhengye Bao, Shengtao Zhang, Muning Wen, Minnan Luo 외 (소속 미표기)
- **arXiv**: [2610.30755](https://arxiv.org/abs/2610.30755) (cs.AI, 10/22, 62쪽)
- **핵심 기여**: 변이(mutation)·그래프화·학습된 검색을 쓰는 agentic memory 시스템들을, 원문 기록에 dense retrieval + 리랭킹만 하는 **Raw-RAG 베이스라인**과 정면 비교했다.
- **방법**: LoCoMo, LongMemEval, MEME, MemoryAgentBench 4개 벤치마크에서 메모리 시스템들과 동일 조건 비교. 증거 커버리지와 활용률을 분리해 원인 분석.
- **결과**: 7개 벤치마크×모델 세팅 중 6개에서 Raw-RAG 1위, 최강 agentic memory 대비 +0.13~5.53점. 가공된 저장소는 전체 접근을 허용해도 원문 대비 정확도 격차가 남았다 — 변환 과정에서 답을 유도하는 관계·의존 경로가 유실되기 때문.
- 🛠 **Agent Builder 시사점**: 메모리 레이어의 원천 데이터는 항상 원문으로 보존하고, 요약·그래프는 파생 캐시로만 다뤄라. 그리고 어떤 메모리 프레임워크든 도입 전에 Raw-RAG 베이스라인 점수부터 찍어라.
- **한계**: 장기 대화 이해 태스크 평가라, 쓰기 빈도가 높은 작업 메모리(코딩 에이전트의 진행 상태 등)에 그대로 일반화하긴 이르다.

![복잡한 agentic memory 파이프라인과 Raw-RAG 파이프라인 비교 다이어그램](/images/ai-news-2026-10-25/memory-baseline.svg)

*두 파이프라인의 차이는 "변환을 언제 하느냐"다. Raw-RAG는 원문을 끝까지 들고 간다.*

## Deep Search in Real-World Web Environments (OpenDS-World)

- **저자**: Xiaomin Yu 외 25인 — HKUST(GZ), Fudan, Stanford, SJTU, Yale, NUS, Microsoft Research 등 14개 기관
- **arXiv**: [2610.30181](https://arxiv.org/abs/2610.30181) (cs.IR, 10/19) · HF Daily Papers 154 업보트
- **핵심 기여**: 정적 검색 세트가 아니라 **라이브 웹**에서 멀티스텝 딥서치를 평가하는 OpenDS 태스크와 200문제 벤치마크 OpenDS-World. 증거 유효성·답 유일성을 사람이 검증했다.
- **결과**: 통일된 툴 환경에서 프런티어 12개 모델 평가 — 최고 모델이 39.0%, 인간은 1,000회 독립 시도에서 21.1%. 에이전트가 이미 사람을 크게 앞서지만, 툴 코디네이션과 장기 탐색 관리가 여전히 병목이라는 실패 분석까지 포함.
- 🛠 **Agent Builder 시사점**: 딥서치 에이전트를 만들고 있다면 정적 QA 세트 점수는 과대평가일 수 있다. 데이터는 [HF 데이터셋](https://huggingface.co/datasets/Yu2020/OpenDS-World)으로 공개돼 있다.
- **한계**: 라이브 웹 특성상 시간이 지나면 증거가 사라져 문제가 낡는다. 200문제로 규모도 작은 편.

# 🛠 오픈소스 스포트라이트

주말 + 이 세션의 GitHub API 제한으로 트렌딩 집계는 못 했다. 대신 클론으로 직접 검증한 2개만 간다(스타 수 미확인).

- **[datalab-to/indra](https://github.com/datalab-to/indra)** (Python) — 총 7.3M 파라미터, 다운로드 약 76MB짜리 OCR 모델. GPU도 PyTorch도 없이 CPU + ONNX로 PDF·이미지를 마크다운/JSON(바운딩 박스 포함)으로 바꾼다. 한국어 포함 80개 이상 언어, 레이아웃·읽기 순서 복원, 자체 측정 4코어 기준 페이지당 약 210ms. 코드는 Apache 2.0, 웨이트는 OpenRAIL-M 변형(연구·개인·소규모 스타트업 무료). 에이전트의 문서 인제스천을 외부 API 호출 없이 로컬 전처리로 돌리고 싶을 때 바로 쓸 수 있다. 약점은 복잡한 표와 저품질 스캔. 마지막 커밋 10/22 확인.
- **[IQuestLab/IQuest-Q1](https://github.com/IQuestLab/IQuest-Q1)** (Markdown/Docker) — 위 모델의 공식 배포 저장소. SGLang/vLLM용 cu130 도커 이미지, tp=8 실행 커맨드, 전용 `--tool-call-parser iquest_q1` 플래그, 재귀 MTP 스펙큘레이티브 디코딩 옵션까지 서빙 레시피가 통째로 들어 있다. 320B급 MoE 셀프호스팅이 어떤 모양인지 보는 레퍼런스로도 가치. 8×GPU 노드가 전제라는 점은 유의.

![indra와 IQuest-Q1 저장소 비교 카드 — 7.3M CPU OCR vs 320B 서빙 킷](/images/ai-news-2026-10-25/repo-compare.svg)

*에이전트 스택의 양 끝. 인제스천은 7.3M으로 충분해지고 있고, 두뇌는 여전히 8×GPU를 요구한다.*

- 📝 Codex TUI에서 임포트 플로우를 열면 "Choose an import source" 화면에서 Claude Code / Cursor를 고를 수 있다. Claude Code 홈의 `projects` 아래 메모리 파일이 감지 대상이다.

- ⭐ 추천도: 병행 사용자라면 지금 체험해볼 가치, 프로덕션 의존은 아직.

**🟦 Claude Code — 카테고리: Workflow(대기/폴링)**

- 소스: [claude-code CHANGELOG 2.1.310](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 조건 충족까지 지켜보는 **Monitor 툴**이 Bedrock·Vertex·Foundry와 텔레메트리 차단 환경에서도 열렸고, 같은 환경에서 긴 포그라운드 `sleep`은 이제 차단된다. "sleep 루프로 CI 기다리기" 패턴을 공식적으로 밀어내는 변화다.
- 📝 에이전트에게 대기를 시킬 때 이렇게 지시하라:

```text
sleep 루프 대신 Monitor를 써서 'gh run watch가 끝나면' 결과를 요약해줘
```

- 🎯 엔터프라이즈 게이트웨이(Bedrock/Vertex/Foundry) 뒤에서 Claude Code를 돌리는 팀. 그동안 이 환경에서만 안 되던 기능이었다.
- ⚠️ 긴 sleep에 의존하던 기존 스크립트·훅은 2.1.310 이후 해당 환경에서 깨질 수 있으니 먼저 점검.
- ⭐ 추천도: 게이트웨이 사용자 필수 체크.

**🟪 공통 — 카테고리: Context/Memory**

- 소스: [arXiv 2610.30755](https://arxiv.org/abs/2610.30755)
- 💡 메모리 프레임워크를 붙이기 전에 **Raw-RAG 베이스라인**(원문 로그 + dense retrieval + 리랭크)을 먼저 깔아라. 이걸 못 이기는 메모리 시스템은 복잡도 비용만 낸다.
- 📝 체크리스트: ① 세션 로그를 변형 없이 저장 ② 임베딩 검색 + 리랭커로 상위 k 원문 청크 주입 ③ 자체 태스크 20~30개로 점수화 ④ 그 다음에야 요약·그래프 메모리를 후보로 검토.
- 🎯 장기 대화·히스토리 참조가 많은 에이전트의 메모리 설계 초기.
- ⚠️ 쓰기 중심 작업 메모리(진행 상태 추적)는 이 논문 범위 밖이다.
- ⭐ 추천도: 메모리 도입 전 필수 절차로 삼을 만.
