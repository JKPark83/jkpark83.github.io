# 🔥 오늘의 핵심

신규 모델 발표가 없는 조용한 날이다. 대신 오늘의 실은 분명하다: **모델은 빌려 쓰더라도, 데이터는 내 것에서 가치가 나온다.** 내 코딩 세션을 학습 데이터로 바꾸는 스킬(tinker-ai-skill), 내 문서·DB를 검증 가능한 지식 계층으로 바꾸는 MCP 서버(auto-ontology-mcp), 그리고 "Python 밖에서도 그 실력이 나오나"를 묻는 벤치마크(Longtail-SWE)까지 — 전부 오늘 바로 만져볼 수 있는 것들이다.

# 📚 주목 논문

## 1. Longtail-SWE — 코딩 에이전트, Python 밖에서도 그 실력인가

- **저자**: Vladimir Dobrovolskii, Ibragim Badertdinov, Alexander Golubev (소속 미표기)
- **arXiv**: [2611.10304](https://arxiv.org/abs/2611.10304) (cs.SE)
- **핵심 기여**: SWE-bench류 벤치마크가 비워 둔 13개 언어 — Clojure, Dart, Elixir, Erlang, F#, Haskell, Julia, Kotlin, Lua, OCaml, R, Scala, Swift — 에서 실제 이슈 해결 과제 **202개**를 구축했다.
- **방법**: **solver–judge–repairer** 파이프라인. solver가 후보 과제를 실제로 풀고, judge가 풀이 궤적과 테스트 결과를 보고 과제 품질을 심사하고, 설명이 모호하거나 테스트가 불량인 과제는 버리는 대신 repairer가 고친다. 희소한 후보를 최대한 살리는 설계다.
- **결과**: 프런티어 모델 포함 9개 구성을 평가. 벤치마크 인스턴스, 실행 환경, 구축·평가 도구 전체를 공개한다고 밝혔다.
- 🛠 **시사점**: 에이전트의 언어별 성능 격차를 처음으로 넓게 잴 수 있게 됐다. 그리고 solver–judge–repairer 레시피 자체가 사내 코드베이스용 **프라이빗 벤치마크 제작법**으로 그대로 쓸 만하다. 아래 공통 팁에서 구체화한다.
- **한계**: 202개 과제를 13개 언어로 나누면 언어당 과제 수는 많지 않다. 언어별 순위보다는 "격차가 존재하는가"를 읽는 용도로 적합하다.

![Longtail-SWE의 solver-judge-repairer 구축 파이프라인과 13개 대상 언어](/images/ai-news-2026-11-11/longtail-swe.svg)

*과제를 '거르는' 게 아니라 '고쳐서 살리는' 파이프라인. 희소 언어 벤치마크의 현실적인 해법이다.*

## 2. Sage-Taiyi — 메타인지를 단 AI 공동 과학자

- **저자**: Weida Wang 외 90인 공동 저술 (소속 미표기, [프로젝트 페이지](https://alpha-innovator.github.io/Sage-Taiyi/))
- **arXiv**: [2611.12762](https://arxiv.org/abs/2611.12762) (cs.AI), 38쪽 18개 그림
- **핵심 기여**: "무엇을 다음에 조사할지, 어떻게 조사할지"를 축적된 과학적 이해로 결정하는 **메타인지 아키텍처**. 증거·가정·미해결 질문에 대한 자기 평가를 명시적으로 유지하고, 그 평가로 연구 타깃과 추론 방법을 갈아끼운다.
- **방법**: 모니터링(내가 뭘 알고 뭘 모르나)과 컨트롤(그래서 다음에 뭘 하나)을 분리한 전형적 메타인지 구조를 에이전트 루프에 얹었다.
- **결과**: 10개 분야 50개 논문에서 뽑은 265개 과제 벤치마크 **Taiyi-Bench**에서 8개 지표 전부 1위, Overall **54.0** (최강 베이스라인 AI Scientist-v2는 47.9). 제안이 실제 습식 실험으로도 이어졌다 — 코발트 촉매 카보닐화 수율 trace→**84%**, 광촉매 알릴 아민화 **13%→69%**.
- 🛠 **시사점**: "unresolved questions를 명시적 상태로 유지하고, 그걸로 다음 액션을 고른다"는 패턴은 과학이 아니라도 유효하다. 장기 리서치 에이전트의 메모리에 '결론'만 쌓지 말고 '미해결 질문 목록'을 1급 객체로 두는 설계를 시험해 볼 것.
- **한계**: 90인 저술의 대형 시스템 — 재현 비용이 높고, 벤치마크(Taiyi-Bench)도 같은 팀이 만들었다.

# 🛠 오픈소스 스포트라이트

![tinker-ai-skill, auto-ontology-mcp, cinecode 세 리포지토리 비교 카드](/images/ai-news-2026-11-11/repo-cards.svg)

*세 리포의 공통점: 모델 API가 아니라 '내가 이미 가진 것'에서 가치를 뽑는다.*

**1. [drost-ai/tinker-ai-skill](https://github.com/drost-ai/tinker-ai-skill)** — Python · MIT · 약 300★

내 Claude Code 세션을 수집→익명화→슬라이스해서 SFT 데이터셋을 만들고, [Tinker](https://thinkingmachines.ai/tinker)로 LoRA를 학습해 llama.cpp용 GGUF까지 뽑는 전체 파이프라인을 Agent Skill 하나로 포장했다. 오픈 가중치 모델 Tess-4/4.5-27B를 실제로 만든 레시피의 공개판. 설치 후 "지난 3개월 세션으로 Qwen3.6-35B-A3B를 파인튜닝해"라고 말하면 에이전트가 과금 직전 단계까지 알아서 진행한다. 익명화 단계(크리덴셜 치환, 세션별 랜덤 신원 부여, 누출 시 실패)가 특히 잘 만들어져 있어서, 파인튜닝 안 하더라도 **세션 데이터 정제 파이프라인**으로만 봐도 배울 게 많다.

**2. [gogoymh/auto-ontology-mcp](https://github.com/gogoymh/auto-ontology-mcp)** — Python · Apache-2.0 · 약 300★

NVIDIA Auto Ontology의 시맨틱 레이어를 MCP 서버로 옮겼다. DB를 가리키면 에이전트가 비즈니스 용어와 조인 관계를 정리하고, 이후의 text-to-SQL은 온톨로지에 대해 **검증**된다 — 틀린 조인 거부, 저장 값 포맷 안내, 일대다 조인의 팬아웃 경고 등 "조용히 틀리는 SQL"을 막는 데 집중한다. 영수증·논문·메모를 먹이면 개인 지식베이스로도 쓰고 Obsidian vault로 내보낸다. 원본과 달리 별도 LLM 엔드포인트가 필요 없다는 게 포인트: 언어 작업은 전부 내 MCP 클라이언트(Claude Code, Codex 등)의 모델이 한다.

**3. [sarpstar/cinecode](https://github.com/sarpstar/cinecode)** — Python · MIT · 약 2,000★

"코드로 만든 영화." 아이디어 한 문장을 주면 에이전트가 각본을 쓰고, three.js로 매 장면을 코딩하고, headless Chrome으로 렌더링해 ffmpeg로 완성 MP4를 뱉는다. Claude Code·Cursor에서 로컬로 돌고 유료 영상 생성 API가 필요 없다. 광고·설명 영상·뮤직비디오까지 지원. 에이전트 개발자 입장에서는 "렌더링을 코드 실행으로 환원하면 영상 생성도 에이전트 루프가 된다"는 아키텍처 샘플로 읽을 만하다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**1. 🟩 Codex — readOnlyHint가 승인 판정 1순위가 됐다** (카테고리: MCP)

- 소스: [openai/codex#60638 커밋](https://github.com/openai/codex/commit/057d9140a8b356a4b1eb71f01c8e981f2aeef20f) (11/10)
- 💡 핵심: automatic 승인 모드에서 MCP 툴 어노테이션 충돌 시 이제 `readOnlyHint`가 `destructiveHint`·`openWorldHint`보다 우선한다. 전에는 `readOnlyHint: true`여도 `destructiveHint: true`가 같이 있으면 승인 프롬프트가 떴다.
- 📝 방법: MCP 서버를 만든다면 읽기 전용 툴에 어노테이션을 정확히 달 것.

```json
{
  "name": "list_events",
  "annotations": { "readOnlyHint": true }
}
```

- 🎯 언제: 읽기 전용 조회 툴이 많은 MCP 서버(모니터링, 검색, DB 조회)를 codex automatic 모드에서 쓸 때. 불필요한 승인 클릭이 사라진다.
- ⚠️ 주의: 거꾸로 말하면 **서버가 readOnlyHint를 거짓으로 달면 codex가 그 툴을 묻지 않고 실행한다.** 힌트는 신뢰 선언이다 — 외부 MCP 서버를 붙일 땐 그 서버의 어노테이션을 믿을 수 있는지가 곧 보안 경계가 된다. explicit prompt 모드와 strict automatic review는 여전히 각자의 확인을 거친다.
- ⭐ 추천도: MCP 서버 작성자라면 오늘 반영할 것.

**2. 🟦 Claude Code — Vertex AI에서도 /fast** (카테고리: Workflow)

- 소스: [v2.1.322 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.322) (11/10)
- 💡 핵심: fast mode가 Vertex AI의 global·us·eu 리전에서 동작한다. Vertex가 fast 서빙을 거부하면 같은 모델의 표준 속도로 자동 폴백한다.
- 📝 방법: Vertex 경유 세션에서 `/fast`로 토글하면 끝. CI 등 비대화형에서는 업데이트(`claude update`) 후 버전을 2.1.322 이상으로 맞춘다.
- 🎯 언제: 회사 정책상 GCP 경유로만 Claude를 쓰는 팀. 그동안 1st-party API 사용자만 누리던 속도 옵션이 열렸다.
- ⚠️ 주의: 리전이 global/us/eu 밖이면 해당 없음. 폴백이 조용히 일어나므로 벤치마크할 땐 실제 서빙 속도를 따로 확인할 것.
- ⭐ 추천도: Vertex 사용자라면 바로 켜볼 것.

**3. 🟪 공통 — 코딩 에이전트 평가에 롱테일 언어 1개를 추가하라** (카테고리: Eval)

- 소스: [Longtail-SWE (arXiv 2611.10304)](https://arxiv.org/abs/2611.10304)
- 💡 핵심: 에이전트 평가 대부분이 Python·JS·TS에 몰려 있다. 모델 교체·프롬프트 변경의 효과가 주류 언어에서만 측정되면, Kotlin·Swift·Scala가 섞인 실제 모노레포에서의 회귀를 놓친다.
- 📝 방법: 팀 스택에 있는 비주류 언어 하나를 골라 Longtail-SWE에서 해당 언어 과제를 평가 셋에 편입. 자체 과제를 만들 땐 논문의 solver–judge–repairer 패턴을 쓴다 — 후보 과제를 에이전트가 먼저 풀게 하고, 궤적을 보고 과제 설명과 테스트를 고친 뒤 셋에 넣는다.
- 🎯 언제: 모델 업그레이드(예: 이번 주 Fable 5.2 전환) 전후 비교 평가를 돌릴 때.
- ⚠️ 주의: 언어당 표본이 작으면 점수 등락에 과민해진다. 합격/불합격보다 실패 유형(빌드 도구 혼동, 표준 라이브러리 오용)을 읽을 것.
- ⭐ 추천도: 다언어 코드베이스 팀이라면 이번 주 안에.
