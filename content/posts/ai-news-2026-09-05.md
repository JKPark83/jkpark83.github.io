# 🔥 오늘의 핵심

OpenAI가 9/3 [GPT-6 Astra](https://openai.com/index/gpt-6-astra/)를 정식 출시했다. 컴퓨터 유즈·호스티드 셸·MCP를 기본 탑재한 "컴퓨터를 쓰는 모델"이 드디어 GA다. 같은 주 Qwen의 [Terminal-Universe](https://arxiv.org/abs/2609.04148)는 이미 쌓인 에이전트 궤적을 실행 가능한 환경 37.3k개로 되살려 학습에 재투입했다. 오늘의 실행 포인트: Codex CLI 0.153+ 사용자는 `model = "gpt-6-astra"` 한 줄로 미리 갈아탈 준비를 하고, 팀에 쌓인 에이전트 로그를 "버리는 데이터"가 아니라 평가·학습 자산으로 다시 보자.

*오늘의 변화 지도 — 모델은 컴퓨터를 쓰기 시작했고, 궤적은 환경으로 되살아난다.*

# 🤖 모델 & 릴리즈 레이더

OpenAI [Preparedness Framework의 "Critical" 사이버 임계선을 처음 넘은 모델](https://www.ghacks.net/2026/09/04/openai-launches-gpt-6-astra-claiming-a-new-frontier-in-computer-use-coding-and-science/)이라 Trusted Access 기업부터 단계적으로 풀린다. API·Plus/Pro는 "수일 내". 272K 초과 입력엔 2배 요금이 붙으니 롱 컨텍스트 에이전트는 비용 모델을 다시 짜야 한다. ([공식 발표](https://openai.com/index/gpt-6-astra/), [벤치마크 분석](https://www.vellum.ai/blog/gpt-6-astra-benchmarks-explained))

# 📚 주목 논문

## Terminal-Universe — 궤적은 한 번 쓰고 버리기엔 아깝다

- **저자/소속**: Jie Wu, Zhenru Zhang 외, Qwen (Alibaba)
- **arXiv**: [2609.04148](https://arxiv.org/abs/2609.04148) (cs.AI)
- **핵심 기여**: 에이전트 포스트 트레이닝에 정말 필요한 건 일회성 시연(궤적)이 아니라 재질의·실행 피드백이 가능한 **환경**이라는 관점 전환. 궤적의 툴 실행 이력에 환경 구조가 남아 있다는 관찰에서 출발해, 환경을 처음부터 만드는 대신 궤적에서 복원한다.
- **방법**: 궤적에 기록된 파일 연산을 리플레이해 수정 전 워크스페이스를 복원 → 완성 에이전트가 누락 파일·의존성 보충 → 원래 태스크 재구성 + 신규 태스크 합성. 크로스-워크스페이스 질의(넓이)와 유저 에이전트 피드백 멀티턴(깊이)으로 확장.
- **결과**: 공개 터미널 에이전트 궤적에서 환경 37.3k개 생산. 이 코퍼스로 Qwen3.5-27B를 SFT하면 Terminal-Bench 2.1 +11.9p, EvoCode-Bench v2 MT@4 +13.8p.
- 🛠 **에이전트 빌더 시사점**: 프로덕션 에이전트 로그가 곧 평가·학습 환경의 원료라는 뜻. 툴 콜 이력을 리플레이 가능한 형태로 남기는 로깅 설계부터가 자산이 된다.
- **한계**: 터미널·파일 조작 중심 도메인에서 검증됐고, 외부 API 상태까지 얽힌 환경 복원은 다루지 않는다.

![Terminal-Universe 파이프라인](/images/ai-news-2026-09-05/tu-pipeline.svg)

*궤적 리플레이 → 워크스페이스 복원 → 태스크 합성으로 이어지는 4단계.*

## DRACO — 루브릭 점수를 스텝 단위 크레딧으로 쪼개기

- **저자/소속**: Shubham Gandhi, Kiran Kate, Yara Rizk 외, IBM Research
- **arXiv**: [2609.04094](https://arxiv.org/abs/2609.04094) (cs.AI)
- **핵심 기여**: 프로그래밍 가능한 채점기가 없는(outcome-blind) 장기 에이전트 태스크에서, 궤적당 1회 채점되는 루브릭 점수를 **책임 있는 스텝들로 재분배**해 GRPO의 스텝별 advantage를 만든다.
- **방법**: 학습 중 정책 수준에 맞춰 루브릭을 동적으로 생성 → 완료된 궤적에 한 번 채점 → 닫힌 형식(closed-form) 재분배로 스텝별 크레딧 산출. 별도 어트리뷰션 모듈 학습이 없다.
- **결과**: AppWorld에서 베이스 대비 +15.9p, 정답 보상으로 학습한 GRPO 대비도 +5.3p. 도메인 밖 Tau-Bench에서도 +5.3p.
- 🛠 **에이전트 빌더 시사점**: "검증기 없는 업무 도메인이라 RL은 무리"라던 영역에서 루브릭 기반 학습이 정답 보상을 이길 수 있다는 실증. 사내 에이전트 파인튜닝의 보상 설계 옵션이 하나 늘었다.
- **한계**: 루브릭 채점 자체가 LLM 저지 품질에 묶이고, 벤치마크 2종 검증이라 일반화는 더 봐야 한다.

GitHub API가 이 세션에서 막혀 있어 스타 수는 API로 검증하지 못했다. 두 리포 모두 클론으로 존재·내용·최신 커밋(9/4)을 직접 확인했다.

## deepseek-ai/deepseek-harness — DeepSeek의 공식 에이전트 하네스

- [github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) · TypeScript · v0.1.3-alpha.1 · 최신 커밋 9/4
- DeepSeek이 직접 만드는 오픈소스 하네스 `dsh`. **"모든 것이 플러그인"** 아키텍처(Cordis 프레임워크 기반)로, `npx @deepseek-ai/dsh web` 한 줄이면 로컬 Web UI가 뜬다. [OSSInsight 집계](https://ossinsight.io/trending/ai)로는 8일간 스타 +11k의 최상위 급상승 리포다.
- **활용**: 하네스 내부 구조(플러그인 경계, 세션 관리)를 뜯어보는 교보재로 좋고, DeepSeek 모델 중심 스택이라면 기본 하네스 후보. 단 developer preview라 호환성 파괴 변경이 예고돼 있다.

## stablyai/orca — 병렬 에이전트 플릿의 조종석

- [github.com/stablyai/orca](https://github.com/stablyai/orca) · TypeScript(Electron) · MIT · v1.4.197 · 최신 커밋 9/4
- Codex, Claude Code, OpenCode, Pi를 **각자 격리된 git worktree에서 나란히** 돌리고 한 화면에서 추적하는 데스크톱 오케스트레이터(macOS/Windows/Linux). 프롬프트 하나를 에이전트 5개에 팬아웃하고 결과를 비교해 승자를 머지하는 워크플로를 지원한다.
- **활용**: 터미널 탭 4개 띄워놓고 에이전트를 수동 관리하고 있다면, worktree 격리 + 결과 비교 + 머지까지 이걸로 일원화할 수 있다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex · 카테고리: Workflow** — [openai/codex 저장소](https://github.com/openai/codex) (클론으로 확인)

- 💡 Codex CLI 소스에 `gpt-6-astra` 지원이 들어가 있다. 접근 권한이 풀리는 대로 config 한 줄로 전환 가능.
- 📝 설정:

```toml
# ~/.codex/config.toml
model = "gpt-6-astra"   # Codex CLI 0.153.0 이상 필요
```

- 🎯 컴퓨터 유즈·긴 터미널 태스크 비중이 큰 워크로드에서 Sol 대비 개선 폭이 가장 크다(OpenAI 발표 기준).
- ⚠️ 단계적 롤아웃 중이라 계정에 아직 안 풀렸을 수 있고, Enterprise는 관리자가 콘솔에서 켜야 한다. 소스 코드상 Astra에는 Daybreak(사이버 접근 프로그램)가 적용되지 않아 일부 보안 관련 요청이 제한된다는 안내문이 내장돼 있다.
- ⭐ 지금 config만 준비해 두고, 풀리면 기존 태스크 몇 개로 Sol과 A/B 해볼 것.

**🟦 Claude Code · 카테고리: Context** — [v2.1.261 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.261)

- 💡 스킬을 많이 깔수록 시스템 프롬프트가 무거워진다. 2.1.261의 `/skill-doctor`는 로드된 스킬 중 뭐가 안 쓰이는지, 각각 컨텍스트를 얼마나 먹는지 보여준다.
- 📝 사용:

```text
/skill-doctor        # 미사용 스킬과 컨텍스트 비용 리포트
```

리포트에서 사용률 낮은 스킬을 확인하고, 프로젝트 `.claude/skills/`나 플러그인에서 제거·비활성화한다.

- 🎯 스킬·플러그인을 5개 이상 쓰는 프로젝트, 또는 프롬프트 캐시 미스가 잦아졌을 때.
- ⚠️ "지금까지 안 썼다"가 "앞으로 안 쓴다"는 아니다. 온보딩 직후처럼 이력이 짧을 땐 판단을 보류하자.
- ⭐ 월 1회 스킬 다이어트 루틴으로 넣어두면 컨텍스트 예산이 눈에 띄게 돌아온다.

**🟪 공통 · 카테고리: Eval** — [Terminal-Universe (arXiv 2609.04148)](https://arxiv.org/abs/2609.04148)

- 💡 에이전트 궤적을 "일회성 로그"가 아니라 **복원 가능한 환경의 씨앗**으로 저장하자.
- 📝 오늘 할 수 있는 최소 버전: 에이전트의 파일 쓰기 툴에 수정 전 원본을 함께 남기는 훅을 추가한다.

```text
로깅 체크리스트
- [ ] 툴 콜 인자·결과 전문 저장
- [ ] 파일 수정 전 스냅샷(diff가 아닌 원본)
- [ ] 작업 디렉터리 파일 트리 기록
```

- 🎯 회귀 평가 세트가 부족한 팀. 실패 궤적을 그대로 재현 환경으로 만들면 최고의 회귀 테스트가 된다.
- ⚠️ 궤적에 시크릿·고객 데이터가 섞이기 쉬우니 스냅샷 단계에서 마스킹을 강제할 것.
- ⭐ 논문처럼 3.7만 개는 필요 없다. 실패 케이스 10개만 환경화해도 체감된다.
