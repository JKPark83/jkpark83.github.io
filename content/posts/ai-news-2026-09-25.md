# 🔥 오늘의 핵심

Google이 이틀 연속 존재감을 냈다. **Gemini 4**가 포스트트레이닝 단계에 진입해 "가능한 빨리" 출시된다는 발표와 함께, Gemini API의 매니지드 에이전트 하니스가 **antigravity-preview-09-2026**으로 업그레이드됐다. 논문 쪽에서는 **JitMem**이 "메모리는 저장할 때가 아니라 꺼낼 때 큐레이션하라"는 설계 전환으로 성공률을 최대 16.3p 끌어올렸다. 오늘 해볼 것: openai/codex 저장소에 동봉된 `babysit-pr` 스킬 구조를 열어보고 내 PR 워크플로에 이식하기.

# 🤖 모델 & 릴리즈 레이더

- **Gemini 4, 포스트트레이닝 진입** (9/23~24) — 8월에 승진한 Google DeepMind 수장 Koray Kavukcuoglu가 The Information 서밋에서 확인. 7/21 시작한 프리트레이닝을 약 두 달 만에 마치고 "이른 포스트트레이닝 버전을 가능한 한 빨리 내겠다"고 말했다. 에이전트 빌더 입장에선 연말 전 프론티어 3파전(GPT-6 · Claude 5 · Gemini 4)이 확정된 셈이라, 모델 교체를 전제로 한 하니스 추상화를 지금 점검할 때다. [9to5Google](https://9to5google.com/2026/09/24/google-says-gemini-4-release-is-coming-as-soon-as-possible/)
- **Gemini API 매니지드 에이전트 대개편** — 새 하니스 `antigravity-preview-09-2026`이 Antigravity 코딩 에이전트의 도구·동작을 API로 가져왔고, 샌드박스에 파일을 넣고 빼는 **Files API**, MCP 서버·서드파티 API 인증을 맡기는 **Credentials API**가 추가됐다. Google 발표 기준 파일 수정 출력 토큰 40% 절감, 멀티턴 SWE 태스크 완료율 최대 +6%. 구버전 `05-2026` 하니스는 10/5 폐기되니 쓰고 있다면 마이그레이션 필수. [Gemini API 문서](https://ai.google.dev/gemini-api/docs/models/antigravity-preview-09-2026)
- **툴 릴리즈** — Claude Code 2.1.282(auto 모드 서버 분류기 기본화, 프로젝트 설정의 텔레메트리 변수 무시 등 공급망 방어 강화), Codex CLI는 stable 0.156.1 / prerelease 0.158.0-alpha.10. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

# 📚 주목 논문

## JitMem: 메모리 큐레이션, 쓸 때 말고 읽을 때

- **저자**: Yefan Zhou, Yang Li, Zeyu Leo Liu, Semih Yavuz, Shafiq Joty (arXiv에 소속 미표기)
- **arXiv**: [2609.27334](https://arxiv.org/abs/2609.27334) (cs.AI, 9/23)
- **핵심 기여**: 기존 에이전트 메모리는 태스크가 끝나는 순간 요약·스킬·워크플로로 증류해 저장한다(write-time). 미래에 어떤 질문이 올지 모른 채 요약하니 정보가 영구 소실된다는 게 문제. JitMem은 **원본 트래젝토리를 그대로 보관**하고, 새 태스크가 도착한 읽기 시점에 큐레이터가 그 태스크 맞춤 페이로드를 합성한다.
- **방법**: 회수된 원본 트레이스 + 현재 태스크를 입력으로 큐레이터 LLM이 압축 페이로드 생성. 페이로드가 같은 태스크에서 즉시 소비되므로, 태스크 성공 여부라는 **즉각 보상**으로 큐레이터를 훈련할 수 있다(장기 credit assignment 문제 회피).
- **결과**: ALFWorld +16.2p, WebShop +16.3p, τ²-bench +3.9p (최강 베이스라인 대비 절대치). 훈련 안 한 큐레이터도 이미 베이스라인급 이상.
- 🛠 **시사점**: 지금 "세션 끝나면 요약해서 메모리에 저장" 파이프라인을 운영 중이라면, 저장은 raw로 하고 요약을 조회 시점으로 미루는 구조 변경만으로 이득을 볼 여지가 있다.
- **한계**: 읽기 시점마다 큐레이터 호출이 추가되므로 조회 지연·비용이 늘어난다. 코드 공개는 아직 확인되지 않음.

![JitMem의 write-time 대 read-time 메모리 큐레이션 비교 다이어그램](/images/ai-news-2026-09-25/jitmem-flow.svg)

*위: 저장 시점에 요약해 정보를 잃는 기존 구조. 아래: 원본을 보관하고 조회 시점에 태스크 맞춤 합성하는 JitMem. (자체 제작, 데이터: 논문)*

## SchrodingerRepo: 그 에이전트, SWE-bench를 푼 걸까 외운 걸까

- **저자**: Silin Chen, Yufei Yang, Xiaodong Gu, Yuling Shi, Chengcheng Wan, Haibing Guan
- **arXiv**: [2609.27891](https://arxiv.org/abs/2609.27891) (cs.SE, 8/21 공개 — 어제 Hugging Face Daily Papers 상위에 역주행)
- **핵심 기여**: SWE-bench류 벤치마크는 학습 데이터에 흔한 인기 저장소로 만들어져 점수가 '저장소 암기'일 수 있다. SchrodingerRepo는 평가 시점에 저장소를 **동적으로 재인스턴스화** — 실행 동작은 보존하면서 파일 배치·네이밍 같은 익숙한 단서를 지워서, 암기가 아닌 저장소 추론 능력을 측정한다.
- 🛠 **시사점**: 사내 에이전트 평가에서 특정 저장소 점수가 유난히 높다면 리네이밍·재배치 변환을 걸어 재측정해볼 것. 벤치마크 점수로 모델을 고르는 팀이라면 특히.
- **한계**: 단서 제거 변환 자체가 난이도를 인위적으로 올릴 수 있어, 절대 점수보다 변환 전후 낙폭을 봐야 한다.

# 🛠 오픈소스 스포트라이트

> 참고: 이 세션은 GitHub API 접근이 제한돼 스타 수를 직접 조회하지 못했다. 두 저장소 모두 클론으로 실존·최신 커밋(9/24)을 검증했다.

**1. [google/ax](https://github.com/google/ax)** — Go · Apache-2.0

- 9/18 Google I/O에서 공개된 선언형 에이전트 오케스트레이터. Kubernetes 사용자라면 바로 익숙할 구조로, `ax.io/v1alpha1` API 그룹 아래 **Task · Workspace · Gateway · Model** 4개 프리미티브를 YAML로 선언하고 `ax apply -f task.yaml`로 실행한다.
- 샌드박스 실행은 Agent Substrate 위에서 돌고, 네트워크 펜싱과 `ax ssh`(에이전트 작업 현장 접속) 지원. InfoQ 보도 기준 공개 사흘 만에 약 1,955 스타. "클러스터당 수십억 태스크" 주장은 HN에서 논쟁 중이고, README 스스로 안정판 전 대규모 파괴적 변경을 예고한다.
- **용례**: CI에서 대량의 코딩 에이전트 태스크를 병렬 실행하고 싶은데 K8s식 선언형 운영 모델을 원하는 팀.

**2. [dream-num/univer](https://github.com/dream-num/univer)** — TypeScript · Apache-2.0

- 오피스 SDK였던 Univer가 "**The Office Harness for AI Agents**"로 재포지셔닝하며 이번 주 GitHub 트렌딩 상위권. 스프레드시트·문서·슬라이드·보드를 하나의 런타임에서 제공하고, 브라우저와 Node.js 양쪽에서 동일하게 동작하는 Facade API가 핵심.
- **용례**: 에이전트가 xlsx 파일을 파싱-재조립하는 대신, 수식 엔진이 살아 있는 실제 스프레드시트 런타임을 조작하게 만들고 싶을 때. Node.js 헤드리스 모드로 서버사이드 에이전트에 붙일 수 있다.

# 🧑‍💻 Codex & Claude Code 실전 팁

오늘은 두 공식 저장소가 **자기 자신을 개발할 때 실제로 쓰는** PR 자동화 구성을 양쪽에서 하나씩.

![Codex babysit-pr 스킬과 Claude Code pr-review-toolkit 플러그인 비교 카드](/images/ai-news-2026-09-25/pr-agent-card.svg)

*PR을 올린 뒤의 감시(Codex)와 받은 뒤의 리뷰(Claude Code)를 모두 에이전트화한 두 공식 저장소. (자체 제작)*

### 🟩 Codex — 공식 저장소의 babysit-pr 스킬 훔쳐오기

- **분류**: Skill / Workflow · **출처**: [openai/codex .codex/skills/babysit-pr](https://github.com/openai/codex/tree/main/.codex/skills/babysit-pr)
- 💡 **핵심**: OpenAI가 codex 저장소 자체 개발에 쓰는 스킬. PR 생성 후 머지·클로즈까지 리뷰 코멘트, CI, 머지 가능 상태를 계속 감시하며 고칠 건 고치고 재시도할 건 재시도한다.
- 📝 **방법**: 저장소를 클론해 `.codex/skills/babysit-pr/`를 내 `$CODEX_HOME/skills/`로 복사. 구조가 교과서적이다:

```text
babysit-pr/
├── SKILL.md                      # 종료 조건·감시 루프 정의
├── scripts/gh_pr_watch.py        # --watch 모드 지속 폴링 스크립트
└── references/
    ├── heuristics.md             # CI 실패: 브랜치 원인 vs 플레이크 분류표
    └── github-api-notes.md       # 사용하는 gh 명령 목록
```

- 🎯 **언제**: PR을 올려놓고 다른 작업으로 넘어가고 싶은데, CI 빨간불과 리뷰 코멘트를 사람이 새로고침하며 기다리는 게 아까울 때.
- ⚠️ **주의**: 스킬 정책상 플레이크 재시도는 3회 예산제고, 사람이 단 리뷰 코멘트에는 사용자 확인 없이 답글을 달지 않는다 — 이 가드레일까지 같이 가져와야 안전하다.
- ⭐ **추천도**: ★★★★★ — "녹색이어도 PR이 열려 있는 동안 감시 유지"라는 종료 조건 설계만 봐도 값어치를 한다.

### 🟦 Claude Code — pr-review-toolkit: 관점별 리뷰 에이전트 6종

- **분류**: Subagent / Review · **출처**: [anthropics/claude-code plugins/pr-review-toolkit](https://github.com/anthropics/claude-code/blob/main/plugins/pr-review-toolkit/README.md)
- 💡 **핵심**: 만능 리뷰어 하나 대신 좁은 관점의 전문 에이전트 6개 — comment-analyzer(주석 부패), pr-test-analyzer(행동 커버리지), silent-failure-hunter(삼켜진 예외), type-design-analyzer(타입 설계), code-reviewer, code-simplifier.
- 📝 **방법**:

```bash
# marketplace 등록 후 설치
/plugin install pr-review-toolkit
# PR 전체 리뷰 또는 관점 하나만 골라 실행
/review-pr
"이 PR에서 silent failure만 찾아줘"
```

- 🎯 **언제**: 셀프 머지 전 마지막 점검, 또는 리뷰어가 부족한 팀에서 1차 리뷰를 기계화하고 싶을 때.
- ⚠️ **주의**: 에이전트 6개를 다 돌리면 토큰 소모가 상당하다. PR 성격에 맞는 2~3개만 골라 도는 게 실용적.
- ⭐ **추천도**: ★★★★☆ — 에이전트 정의가 마크다운 파일이라 프롬프트를 내 팀 컨벤션으로 고쳐 쓰기 쉽다.

### 🟪 공통 — 메모리 파이프라인, 요약을 조회 시점으로 미루기

- **분류**: Context / Memory · **출처**: [arXiv 2609.27334 (JitMem)](https://arxiv.org/abs/2609.27334)
- 💡 **핵심**: 세션 종료 시 요약-저장하는 메모리는 미래 질문을 모른 채 정보를 버린다. 저장은 raw 트래젝토리로, 압축은 조회한 뒤 현재 태스크를 아는 상태에서.
- 📝 **방법**: 미니 체크리스트 —
  - 세션 로그를 JSONL 원본 그대로 보관 (요약본 대체 금지)
  - 조회 시 유사도 검색 → 회수된 원본 + 현재 태스크를 큐레이터 프롬프트에 투입
  - "이 태스크에 필요한 것만 남겨라"로 합성한 페이로드만 메인 컨텍스트에 주입
- 🎯 **언제**: 에이전트가 과거 세션 경험을 재사용하는데 "요약이 하필 필요한 디테일을 빼먹는" 문제를 겪을 때.
- ⚠️ **주의**: 조회마다 LLM 호출이 하나 늘어난다. 저지연 경로에는 캐시나 훈련된 소형 큐레이터를 검토할 것.
- ⭐ **추천도**: ★★★★☆
