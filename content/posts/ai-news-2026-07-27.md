# 🔥 오늘의 핵심

오늘 신호는 **"더 똑똑한 에이전트"가 아니라 "하니스(harness) 레이어를 제대로 짜라"** 로 모인다. 신규 논문 두 편이 같은 곳을 가리킨다. 하나는 **기억을 에이전트의 자발적 선택에 맡기면 거의 안 쓰인다(사전 시드가 있어도 114턴 중 0회)** — 기억은 하니스가 상황 큐에 맞춰 강제 주입해야 한다. 다른 하나는 **악성 이슈의 66.5%가 Cursor·Claude Code·Codex의 가드레일을 전부 뚫는다** — 그마저 거절은 프레임워크가 아니라 모델이 하고 있다. 오늘 할 일: (1) 에이전트 메모리를 "문서"가 아니라 "경로/이벤트 트리거로 자동 배달"되게 바꾸고, (2) 이슈·PR·PDF 본문을 **신뢰 불가 입력**으로 취급하는 게이트를 세워라.

# 📚 주목 논문

## 1) Delivery, Not Storage — 기억은 에이전트가 아니라 '하니스'가 배달해야 한다
- **저자**: Swapnanil Saha (arXiv `2607.20972`, cs.AI/cs.SE, 2026-07-23)
- **핵심**: 코딩 에이전트의 기억은 지금 전부 "문서"다(지시 파일·플랜·자동 메모리 디렉터리). 쓰고 읽는 걸 **에이전트가 매번 선택**해야 한다. 하지만 진짜 실무를 지탱하는 건 상황에 묶여 **자기도 모르게 인코딩·회수되는** 운영 지식(그 코드의 함정, 위치, 로컬 관례)이다.
- **방법(요약)**: 이 2차 기억을 **에이전트 선택이 아니라 하니스 속성**으로 올린다. 각 메모리에 `path·symbol·semantic·event·temporal` 어휘로 짜인 **트리거 조건(cue)** 을 1급으로 부여하고, 하니스가 결정론적으로 평가해 상황이 맞으면 자동 주입한다.
- **결과(검증됨)**: 실제 코딩 태스크에서 **자발적 메모리 사용은 사실상 0(사전 시드가 있어도 114턴 중 0회)**. 반면 결정론적 주입은 시드된 모든 실행에서 **오탐 0건**으로 배달됐다. 대화에만 담긴 사실 10개는 첫 요약에서 사라져 **108번의 컴팩션 중 106번 부재**했고, 에이전트는 그걸 복구하려 하니스의 세션 파일을 스스로 grep했다. 같은 사실을 하니스 저장소에서 주입하면 **138번의 compact-resume 전부에서 온전히 살아남았다**. 세션 내 재열람의 **39%는 컴팩션 전에 이미 산 내용을 다시 사는 낭비**였다.
- **🛠 agent-builder 시사점**: "메모리 디렉터리를 줬으니 알아서 쓰겠지"는 환상이다. 기억 채널은 **에이전트가 생각하지 않아도 되는 것**이라야 한다. 경로·심볼·이벤트 조건으로 사실을 자동 배달하는 레이어를 하니스에 넣어라.
- **한계**: 단일 저자·단일 실제 태스크 기반의 통제 실험. 트리거 어휘 설계와 오탐 관리가 도메인마다 필요.
- 링크: [arxiv.org/abs/2607.20972](https://arxiv.org/abs/2607.20972)

![기억 생존율 비교. 대화 컨텍스트에만 저장하면 108번 컴팩션 중 106번 소실(생존 1.9%), 하니스가 주입하면 138번 compact-resume 전부 생존(100%). 사전 시드가 있어도 자발적 메모리 조작은 114턴 중 0회, 세션 내 재열람 39%가 중복 구매, 결정론적 주입 오탐 0건](/images/ai-news-2026-07-27/memory-decay.svg)
*"저장"이 아니라 "배달"이 제품이다. 대화에만 둔 사실은 요약 한 번에 증발한다. (자체 제작 SVG, 값 출처 arXiv 2607.20972)*

## 2) IssueTrojanBench — 악성 이슈의 66.5%가 코딩 에이전트를 뚫는다
- **저자**: Ankur Singh, Jinqiu Yang, Tse-Hsun Chen (arXiv `2607.20759`, cs.CR/cs.AI/cs.SE, 2026-07-22)
- **핵심**: 코딩 에이전트는 LLM 백본(적대적 프롬프트·오염 데이터·백도어)과 에이전트 구조(툴 자율성 → API 오용·데이터 유출·개발환경 지속 침해) **양쪽에서** 보안 리스크를 물려받는다.
- **방법(요약)**: **4개 공격 유형 × 6개 전달 벡터**(이슈 본문·이슈 코멘트·PDF 등)로 악성 이슈를 구성해, Cursor·Claude Code·Codex Desktop을 GPT-5.3 Codex/GPT-5.4·Anthropic Sonnet 4.6 위에서 평가.
- **결과(검증됨)**: **악성 이슈의 66.5%가 에이전트·LLM 양쪽 가드레일을 전부 관통**. 거절은 거의 전부 **프레임워크가 아니라 LLM**에서 나왔다 — GPT 계열은 폭넓게 취약, Sonnet 4.6은 고위험 액션을 더 선별적으로 차단. 현재의 에이전트 레벨 방어는 추가 보호가 제한적이었다.
- **🛠 agent-builder 시사점**: "이슈/PR/PDF를 읽고 자동으로 코드 짜기"는 편하지만, **본문 = 신뢰 불가 입력**이다. 프레임워크 방어가 얇으니, 외부 텍스트를 툴 권한 밖 샌드박스에서 처리하고 파괴적/외부 통신 액션에는 사람 승인 게이트를 강제하라.
- **한계**: 특정 제품·모델 스냅샷 기준. 벤더 패치로 수치는 빠르게 바뀔 수 있음.
- 링크: [arxiv.org/abs/2607.20759](https://arxiv.org/abs/2607.20759)

![IssueTrojanBench 결과. 악성 이슈 66.5%가 가드레일을 전부 통과. 거절은 거의 전부 LLM 레이어 몫이고 에이전트 프레임워크의 추가 보호는 미미. 공격면은 4개 공격 유형과 6개 전달 벡터(이슈 본문·코멘트·PDF 등)](/images/ai-news-2026-07-27/issuetrojan.svg)
*자동화 편의의 뒷면 — 외부에서 들어오는 이슈 텍스트가 그대로 명령이 된다. (자체 제작 SVG, 값 출처 arXiv 2607.20759)*

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — Workflow: `/import`로 Claude Code 컨텍스트 이관
- 출처: [gradually 요약](https://www.gradually.ai/en/changelogs/codex-cli/)
- 💡 **핵심 아이디어**: 하니스를 바꿔도 셋업·프로젝트 구성·최근 대화를 **처음부터 다시 만들지 않는다**.
- 📝 **How-to**: Claude Code를 쓰던 저장소에서 Codex를 열고 `/import`를 실행 → 가져올 항목(setup / project config / recent chats)을 선택. MCP 세션은 일시 끊김에도 유지되므로 이관 중 재연결로 흐름이 끊기지 않는다.

```bash
# Codex CLI 안에서
/import        # setup·프로젝트 구성·최근 채팅을 선택적으로 가져오기
```

- 🎯 **언제**: 두 CLI 병행 평가, 혹은 팀 표준을 옮길 때.
- ⚠️ **주의**: 가져온 지시에 **오래된 규칙·비밀정보**가 섞일 수 있으니 이관 후 한 번 리뷰. 버전(v0.145.0)에 따라 항목 구성이 다를 수 있음.
- ⭐ **추천**: 마이그레이션·A/B 평가엔 강추. 기존 컨텍스트를 살린 채 비교 가능.

## 🟦 Claude Code — Context: 기억을 '경로 스코프'로 자동 배달
- 출처: [Claude Code Memory 문서](https://code.claude.com/docs/en/memory)
- 💡 **핵심 아이디어**: "Delivery, Not Storage"를 오늘 바로 흉내 낸다 — 전역 `CLAUDE.md`에 다 몰아넣지 말고, **작업 중인 디렉터리의 `CLAUDE.md`가 그 폴더에 들어갈 때 로드**되게 해 상황 큐에 맞춰 사실을 배달한다.
- 📝 **How-to**: 하위 디렉터리별로 그 폴더의 함정·관례를 담은 `CLAUDE.md`를 두면, Claude가 해당 경로 파일을 다룰 때 자동으로 읽는다(`@path`로 다른 파일 import, 최대 4홉). 규칙이 무시되면 `/memory`로 어떤 파일이 로드됐는지 확인.

```text
repo/
  CLAUDE.md              # 프로젝트 공통 규칙
  services/payments/
    CLAUDE.md            # 이 폴더 작업 시에만 필요한 결제 관련 함정·관례
```

- 🎯 **언제**: 모노레포·대형 코드베이스에서 폴더마다 로컬 관례가 다를 때.
- ⚠️ **주의**: import 파일은 **실행 시점에 함께 로드**되므로 무한정 쪼갠다고 컨텍스트가 줄지 않는다. 스코프를 좁게.
- ⭐ **추천**: 전역 지시가 비대해지고 자주 무시된다면 첫 번째로 시도할 리팩터.

## 🟪 공통 — Review/Security: 이슈·PR 본문을 신뢰 불가 입력으로
- 출처: [arxiv.org/abs/2607.20759](https://arxiv.org/abs/2607.20759)
- 💡 **핵심 아이디어**: IssueTrojanBench가 보였듯 **프레임워크 방어는 얇다**. 외부 텍스트가 그대로 명령이 되지 않게 경계를 코드로 세워라.
- 📝 **How-to**: (1) 이슈/PR/첨부(PDF 포함) 본문은 "데이터"로만 넣고 명령 권한과 분리, (2) 파일 쓰기·셸·네트워크 등 **파괴적/외부통신 액션엔 사람 승인 게이트**, (3) 툴 실행은 최소권한 샌드박스, (4) 악성 이슈 몇 개를 회귀 테스트로 상시 주입해 관통률을 모니터링.
- 🎯 **언제**: 이슈→PR 자동화, 외부 기여를 읽는 에이전트 파이프라인 전부.
- ⚠️ **주의**: 모델별 편차가 크다(GPT 계열 폭넓게 취약, Sonnet 4.6은 더 선별적). "모델이 알아서 거절하겠지"에 기대지 말 것.
- ⭐ **추천**: 자동 병합 파이프라인이라면 필수. 게이트 없는 자동화는 곧 공격면.
