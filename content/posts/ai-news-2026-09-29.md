# 📚 주목 논문

## AgentWorld: 멀티에이전트 '협업'은 아직 절반짜리 (arXiv:2609.31590)

- **저자**: Raphael Shu, Yusen Zhang 외 10명 (UPenn·Penn State·Columbia 계열) · cs.MA · 9/25 제출 · **COLM 2026 채택**
- **핵심 기여**: 기존 멀티에이전트 벤치가 20스텝 미만·경쟁 위주였다면, AgentWorld는 **50라운드 이상·3~20개 에이전트**가 비대칭 역할로 협업해야 하는 100개 태스크(+100 변형)를 MMORPG 샌드박스에서 평가.
- **방법**: 각 에이전트는 서로의 내부 상태를 못 보는 블랙박스 조건에서 소통·공동 계획·자원 공유로만 협업. 성공/실패 이분법 대신 **CCE**(Causal Collaboration Effectiveness) — 행동 간 인과 그래프를 추적해 "팀 노력 중 실제로 결과에 기여한 비율"을 측정.
- **결과**: Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, DeepSeek R1-70B 중 최고 모델도 태스크 성공률 **52.0%**. 실패 유형은 소통 단절, 역할 혼동, 공유 계획 유지 실패로 수렴.
- 🛠 **시사점**: 서브에이전트 오케스트레이션에서 "성공했는가"만 보면 낭비를 못 잡습니다. 각 에이전트 행동이 결과에 기여했는지 추적하는 CCE식 지표를 eval에 넣어볼 것.
- **한계**: 게임 샌드박스 기반이라 업무 도메인 일반화는 검증 필요. 전부 오픈소스.
- [arXiv](https://arxiv.org/abs/2609.31590) · [프로젝트](https://agentworld.io)

## SLCA-GRPO: 툴콜 토큰과 요약 토큰의 보상을 분리 (arXiv:2609.29050)

- **저자**: Yan Zhan 외 10명 (arXiv에 소속 미표기) · cs.AI (cs.LG 교차) · 9/24 제출, 41쪽
- **핵심 기여**: 툴콜 에이전트의 출력은 "구조화된 툴 호출 + 자연어 요약"의 혼합인데, GRPO는 궤적 하나에 스칼라 어드밴티지 하나를 모든 토큰에 뿌립니다. 요약 품질의 노이즈가 툴 결정 토큰에 새는 **교차 세그먼트 credit 오귀속**이 문제라는 진단.
- **방법**: 같은 롤아웃 그룹 안에서 세그먼트별로 어드밴티지를 분리 정규화(SLCA), 실행 보상은 툴 토큰에, 선호 보상은 요약 토큰에만 라우팅(HierR). 추가 롤아웃 비용 없음. 실 API 대신 스키마 기반 LLM 시뮬레이터(**SGLS**)로 학습.
- **결과**: 7B 기준 GRPO·ToolPO·RLTR 대비 인도메인 +2.53pp, BFCL +1.36pp, **τ²-Bench +9.15pp** (동일 학습 예산).
- 🛠 **시사점**: 툴콜 모델을 직접 튜닝한다면 "보상을 어느 토큰에 주는가"가 알고리즘 교체보다 싼 개선 지점. SGLS 방식은 학습 안 해도 eval용 목(mock) 툴 환경 설계에 참고할 만합니다.
- **한계**: 시뮬레이터 기반 학습이라 실 API 분포와의 간극은 남은 숙제.
- [arXiv](https://arxiv.org/abs/2609.29050) · [코드](https://github.com/SLCA-GRPO/SLCA-GRPO)

# 🛠 오픈소스 스포트라이트

**agentproto/ts** — [github.com/agentproto/ts](https://github.com/agentproto/ts) · TypeScript · Apache-2.0 · 스타 수 미확인(이 세션의 API 제한)

"코딩 에이전트를 지켜보지 말고 돌려놔라"가 콘셉트인 백그라운드 에이전트 런타임입니다(현재 0.20.0, 어제도 커밋). Claude Code·Codex·opencode·Mastra 등 **14개 에이전트를 동일한 수명주기 명령**(start/message/watch/stop)으로 다루고, 핵심은 **정책 게이트**: 에이전트가 턴을 마칠 때마다 내 테스트나 리뷰어 모델이 검증을 돌리고, 커밋은 검증+사람의 승인 뒤에만 진행됩니다. MCP 서버 임포트, 워크플로/크론, 데몬 자체의 MCP 노출(~175개 도구)까지 포함. README가 "실제 동작(Tier 1) vs 스펙 로드맵(Tier 2)"을 정직하게 갈라놓은 점도 인상적. **활용처**: 퇴근 후에도 돌아가는 에이전트 작업 큐에 "검증 없인 커밋 없음" 규칙을 강제하고 싶은 팀.

**SLCA-GRPO** — [github.com/SLCA-GRPO/SLCA-GRPO](https://github.com/SLCA-GRPO/SLCA-GRPO) · Python · Apache-2.0 · 스타 수 미확인

위 논문의 레퍼런스 구현(9/25 공개). verl 기반 RL 파이프라인에 SFT·베이스라인·ablation·eval 스크립트, 그리고 **실 API 호출 없이 툴콜 학습을 돌리는 SGLS 시뮬레이터**가 통째로 들어 있습니다. 가공된 데이터 4종은 Hugging Face에 공개. **활용처**: 사내 툴 스키마로 소형 툴콜 모델을 튜닝하려는 팀, 또는 툴 환경 목킹 설계 참고.
