# 📚 주목 논문

## FDE-Gym: The Last Mile of AI Delivery

- **저자/소속**: Dongxu Yang, Hongda Yan 외 24인 (DeepLethe, 산업 전문가 협업)
- **arXiv**: [2610.22350](https://arxiv.org/abs/2610.22350) (cs.AI)
- **핵심 기여**: 이슈 티켓이 아니라 **실제 고객 납품 프로젝트**에서 각색한 95개 과제·20개 시나리오·18개 산업 벤치마크. 스크립트된 이해관계자에게 질문하고, 수정 가능한 고객 시스템에서 작업한다.
- **방법**: 납품 결과를 **고객 자신의 성공 지표 개선도**(0~1)로 채점. 질문·시험 실행·대기 시간은 감점, 제출은 1회.
- **결과**: 7개 프로바이더 13개 구성 평가. 최고 구성도 평균 0.56, "해결"(0.8↑ 무사고)은 14/95. 핵심 정보를 전부 확보한 23개 과제에서도 10개만 성공.
- 🛠 **Agent builder 시사점**: 병목은 코드가 아니라 **"안 적혀 있는 제약 발견"**. 에이전트에 "작업 전 이해관계자 확인 질문" 단계를 설계하는 것이 벤치마크 점수로 정당화되기 시작했다.
- **한계**: 이해관계자가 스크립트라 실제 사내 정치·커뮤니케이션 변수는 단순화됨.

![FDE-Gym 구조와 결과 — 모호한 요구사항부터 숨겨진 트래픽 평가까지, 최고 구성 0.56점·14/95 해결](/images/ai-news-2026-10-19/fde-gym.svg)

*FDE-Gym의 채점 파이프라인과 주요 결과. 정보 수집 능력과 납품 능력은 별개라는 것이 핵심 발견.*

## Scalable Weak-to-Strong Verifier Hardening for Agent Environments

- **저자/소속**: Chong Zeng, Ziqian Zhong, Aditi Raghunathan(CMU) 외
- **arXiv**: [2610.15924](https://arxiv.org/abs/2610.15924) (cs.CR)
- **핵심 기여**: 에이전트 환경의 채점용 검증기(verifier)는 **리워드 해킹으로 뚫린다**는 전제에서, 약한 현재 모델로 미래의 강한 모델을 막는 자동 보강 방법 제시.
- **방법**: ① 에이전트가 손댈 수 없는 **격리된 검증기 샌드박스** 구성 → ② "해커" 에이전트가 익스플로잇을 찾고 "수리공" 에이전트가 고치는 **hacker-fixer 루프** 반복.
- **결과**: Terminal Bench, KernelBench, SETA에 적용해 공격 성공률 대폭 감소. 루프 반복 횟수에 따라 방어력이 계속 올라감. 이 루프의 초기 버전은 **Terminal Bench 공식 리포에 채택**됐다.
- 🛠 **Agent builder 시사점**: 사내 에이전트 평가 파이프라인의 검증기도 공격 대상이다. 아래 공통 팁 참고.
- **한계**: 보강 비용이 반복 횟수에 비례, 완전 방어 보장은 없음.

# 🧑‍💻 Codex & Claude Code 실전 팁

![Codex wake_on_agent_messages와 Claude Code decider person 설정 비교 카드](/images/ai-news-2026-10-19/tips-cards.svg)

*오늘의 두 팁 요약 카드. 왼쪽은 Codex의 세션 깨우기, 오른쪽은 Claude Code의 사람 승인 강제.*

### 🟩 Codex — 에이전트 메일로 쉬는 세션 깨우기 (Workflow)

- **출처**: [openai/codex 커밋 8c07694](https://github.com/openai/codex/commit/8c076942cb70fba8e5c4732c23f1faabc4aed484) (10/18)
- 💡 **핵심**: 지금까지는 부모 세션이 최종 답변을 끝낸 뒤 도착한 워커 메시지는 durable sleep이 걸려 있어야만 처리됐다. 새 `wake_on_agent_messages` 기능을 켜면 에이전트 메일 도착 자체가 새 루트 턴을 시작한다.
- 📝 **방법**:

```toml
# ~/.codex/config.toml
[features]
wake_on_agent_messages = true
```

- 🎯 **언제**: 오래 걸리는 워커를 여럿 띄워 두고 부모가 결과를 취합하는 오케스트레이션. 폴링용 sleep 루프를 없앨 수 있다.
- ⚠️ **주의**: 기본 비활성. 중단된 세션·Plan 모드·자식 에이전트는 자동으로 깨어나지 않게 경계가 잡혀 있다.
- ⭐ **추천도**: 멀티 에이전트 Codex 사용자라면 바로 실험해 볼 가치 있음.

### 🟦 Claude Code — 훅으로 '사람 승인' 강제하기 (Hook)

- **출처**: [anthropics/claude-code 커밋 8a8dff6](https://github.com/anthropics/claude-code/commit/8a8dff6af07514630d2d4843c7005129633a66f5) (10/17, sec-default mod 업데이트)
- 💡 **핵심**: `tool.check` 훅이 `decision: 'ask'`에 `decider: 'person'`을 달면, 그 호출은 **사람이 직접 답할 때까지** 멈춘다. 자동 분류기의 allow나 다른 플러그인이 이 ask를 무르지 못한다.
- 📝 **방법**: 훅 판정에서 위험 도구를 골라 사람에게 넘긴다.

```ts
// tool.check 훅
if (toolName === 'Bash' && /drop table|terraform apply/i.test(input.command)) {
  return { decision: 'ask', decider: 'person', reason: '파괴적 명령 — 사람 확인 필요' }
}
```

- 🎯 **언제**: 프로덕션 배포, DB 마이그레이션, 과금이 걸린 API 호출 등 "자동 allow가 더 무서운" 도구 호출.
- ⚠️ **주의**: 플러그인이 host의 ask를 건드릴 수 있는 건 `decider`를 person으로 **좁히는 방향뿐** — 완화는 sec-default가 막는다. 도구 전체 allow 규칙 저장도 이 ask에는 적용되지 않는다.
- ⭐ **추천도**: 팀 공용 훅에 한 줄 넣어둘 가치가 충분한 안전장치.

### 🟪 공통 — 평가 검증기도 레드팀하라 (Eval)

- **출처**: [arXiv:2610.15924](https://arxiv.org/abs/2610.15924)
- 💡 **핵심**: 에이전트 평가의 검증기는 "에이전트가 과제를 안 풀고 채점기만 속이는" 공격에 취약하다. 검증기를 에이전트 파일시스템에서 격리하고, 해커 역할 에이전트로 익스플로잇을 찾은 뒤 고치는 루프를 돌려라.
- 📝 **방법**: ① 검증 스크립트·정답 데이터를 에이전트가 쓰기 불가능한 경로(별도 컨테이너/볼륨)로 분리 → ② 강한 모델에 "채점만 통과시켜 봐"라는 과제를 주고 성공 사례를 수집 → ③ 발견된 구멍을 수리하고 반복.
- 🎯 **언제**: RL 리워드나 CI 게이트로 쓰는 자동 채점기를 운영 중일 때. Terminal Bench도 이 방식을 공식 채택했다.
- ⚠️ **주의**: 1회성 점검이 아니라 반복 루프여야 효과가 쌓인다.
- ⭐ **추천도**: 자체 에이전트 벤치마크를 가진 팀이라면 필수 점검 항목.
