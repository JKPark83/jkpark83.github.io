# 📚 주목 논문

## Prime Agent: A Self-Improving RLM Harness

- **저자**: Seth Karten, Alex L. Zhang, Kevin Thomas 외 11명 (Prime Intellect)
- **arXiv**: [2608.23552](https://arxiv.org/abs/2608.23552) (cs.AI, 8/24 공개)
- **핵심 기여**: "하네스 실패가 모델 실패로 측정되는 것"을 막는 오픈소스 장기 태스크 하네스.
- **방법**: 영속 IPython REPL로 Recursive Language Model(RLM) 방식의 컨텍스트 처리를 수행하고, Continual Harness가 히스토리·메모리·스킬·프롬프트·서브에이전트 사양을 트라젝토리 간에 보존한다. 서브에이전트끼리는 직접 통신하고, Agents View로 데몬 세션을 사람이 관리한다.
- **결과**: 동일 모델에서 하네스만 교체해 ARC-AGI-3 RHAE Best@1 30% → 95.5%. 장문 코딩, GPU 커널 생성, nanoGPT 스피드런 등에서도 기존 하네스와 대등하거나 우위.
- 🛠 **에이전트 빌더 시사점**: 벤치마크 점수의 상당 부분이 모델이 아니라 하네스 설계에서 나온다. 모델 업그레이드 전에 실행·복구·검증·자원 회계부터 표준화할 것.
- **한계**: 자기 개선·서브에이전트 병렬화 효과는 Factorio 등 특정 환경 관찰이 중심이라 일반화는 더 검증이 필요하다.
- **코드**: [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

## One Success Isn't Reliability: Thinkingbox

- **저자**: Zhuochun Li, Youngmin Ko, Mirco Milletari 외 12명 (Microsoft)
- **arXiv**: [2608.19741](https://arxiv.org/abs/2608.19741) (cs.CL, 8/20 공개)
- **핵심 기여**: 상태를 가진 업무 워크플로에서 "끝까지 정확한 상태 전이"를 코드로 채점하는 샌드박스 + 507개 태스크 벤치마크.
- **방법**: 리테일·호텔·자동차보험·네오뱅크 IT·컨설팅 IT/HR 시나리오에서 MCP 호환 도구 세션을 격리 실행하고, 태스크별 실행 가능한 체크가 누락·초과 효과까지 검증한다.
- **결과**: 최상위 모델도 pass@1 65.36% 대비 pass^20(20회 전부 성공)은 25.25%. 실패한 시행 다수가 "깨끗한 종료 + 유효한 툴콜" 형태였다.
- 🛠 **에이전트 빌더 시사점**: 응답이 멀쩡하고 툴콜이 성공했다는 신호로는 업무 완료를 판정할 수 없다. 최종 상태를 검증하는 체크를 만들고, 반복 실행으로 신뢰성을 재야 한다.
- **한계**: 시나리오가 사무·고객지원 업무 중심이라 다른 도메인 일반화는 미검증.

![Thinkingbox pass@1 대 pass^20 격차](/images/ai-news-2026-08-26/thinkingbox-passk.svg)

*한 번이라도 성공(65.36%)과 20번 전부 성공(25.25%)의 격차. 수치는 논문 초록의 최상위 모델 기준. (자체 제작)*

# 🛠 오픈소스 스포트라이트

- **[deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)** — TypeScript/Node 기반, MIT. 8/13 개발자 프리뷰 공개 후 이틀 만에 스타 약 10만을 넘겼고, 8/25 기준 약 19.4만(주간 +3.4만, [OSSInsight 집계](https://ossinsight.io/trending/ai) — 이번 실행 환경에서 GitHub API 직접 확인 불가). 모델·도구·스킬·세션·샌드박스·루프·UI까지 전부 Cordis 커널 위의 플러그인으로 교체하는 구조다. `npx @deepseek-ai/dsh web`로 로컬 Web UI가 뜨므로, 자체 에이전트 제품의 런타임 뼈대나 사내 도구 통합 실험대로 쓰기 좋다. 프리뷰 단계라 호환성 깨지는 변경이 예고돼 있으니 프로덕션 고정은 아직 이르다.
- **[PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)** — 위 논문의 공식 구현(스타 수 미확인, 동일 사유). dsh가 "제품 런타임"이라면 이쪽은 "측정 장비"에 가깝다. 자기 하네스로 돌리던 장기 태스크를 Prime Agent로 다시 돌려 점수 차이를 보면, 내 하네스가 모델 능력을 얼마나 깎아먹는지 정량화할 수 있다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟦 Claude Code — 캐시 TTL을 메인/서브에이전트로 분리

- **분류**: Context / [출처](https://blog.serverworks.co.jp/claude-code-subagent-prompt-cache-ttl)
- 💡 v2.1.243부터 API 키·Bedrock·Vertex 사용자는 프롬프트 캐시 수명을 메인 대화와 서브에이전트에 따로 지정할 수 있다.
- 📝 settings.json에 지정한다:

```json
{
  "promptCacheTtl": "1h",
  "subagentPromptCacheTtl": "5m"
}
```

- 🎯 오래 이어지는 메인 세션은 1시간 캐시로 재사용률을 높이고, 수명이 짧은 서브에이전트는 5분으로 두면 캐시 쓰기 비용 낭비를 줄인다.
- ⚠️ 1시간 캐시는 쓰기 단가가 더 비싸다. 서브에이전트까지 1h로 올리는 건 장수 서브에이전트를 쓸 때만.
- ⭐ 추천도: 종량제(API 키)로 Claude Code를 쓰는 팀이라면 바로 적용 가치 있음.

## 🟩 Codex — `codex queue`로 돌아가는 세션에 작업 밀어넣기

- **분류**: Workflow / [출처](https://releasebot.io/updates/openai/codex)
- 💡 0.149.0 정식판의 `codex queue`는 이미 실행 중인 로컬·원격 세션에 메시지를 보낸다. 세션을 끊고 다시 프롬프트를 쓰는 대신, 밖에서 할 일을 적재하는 방식이다.
- 📝 긴 리팩토링 세션을 띄워두고, 리뷰 중 발견한 추가 수정 사항을 다른 터미널에서 `codex queue`로 보내 쌓아두면 세션 컨텍스트를 유지한 채 순서대로 처리된다. `codex agents` 대시보드로 어떤 세션이 무엇을 하는지 한눈에 확인.
- 🎯 에이전트를 여러 개 병렬로 굴리면서 사람이 감독자 역할을 할 때.
- ⚠️ 큐에 쌓인 지시가 서로 충돌하면 뒤 지시가 앞 작업을 덮을 수 있다 — 독립적인 작업 단위로 쪼개서 보낼 것.
- ⭐ 추천도: 멀티 세션 사용자라면 이번 주 최고의 삶의 질 개선.

## 🟪 공통 — 데모 성공 말고 pass^k를 재라

- **분류**: Eval / [출처](https://arxiv.org/abs/2608.19741)
- 💡 Thinkingbox의 교훈: 한 번 성공한 워크플로도 20번 반복하면 4분의 1만 전부 성공한다. "깨끗한 종료"는 완료의 증거가 아니다.
- 📝 핵심 워크플로마다 최종 상태를 검증하는 체크 스크립트를 만들고, 같은 태스크를 k회(최소 5회) 반복 실행해 전원 통과율을 기록하자:

```bash
for i in $(seq 1 5); do
  ./run_agent_task.sh && ./verify_state.sh || echo "FAIL run $i"
done
```

- 🎯 에이전트를 실제 업무(주문 변경, 티켓 처리, 데이터 수정)에 붙이기 전 게이트로.
- ⚠️ 검증 스크립트가 "응답에 특정 문자열 포함" 수준이면 논문이 지적한 함정을 그대로 밟는다 — 반드시 백엔드 상태를 확인할 것.
- ⭐ 추천도: 상태를 바꾸는 에이전트를 운영 중이라면 필수.
