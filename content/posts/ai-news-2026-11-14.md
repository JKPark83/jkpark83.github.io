# 📚 주목 논문

## 1. Actor, Judge, or Teacher? — 못 하는 배우도 좋은 심판이 된다

- **저자**: Haochen Liu, Qianhao Zhu, Zixuan Wang 외 (저장대·Baidu)
- **arXiv**: [2611.17167](https://arxiv.org/abs/2611.17167) (cs.AI, 11/12 공개 — HF Daily Papers 상위)
- **핵심 기여**: 결정 모델(선택지+확률을 typed 출력으로 내는 모델)의 세 용도 — 행동 선택(actor), 사후 평가(judge), RL 보상(teacher) — 를 분리해서 측정했다. 결론: **행동은 못 해도 심판과 교사는 잘할 수 있다.**
- **방법**: ALFWorld에서 결정 모델 3종 + 일반 LLM 3종을 배우·심판으로 비교. 배우로는 6개 모델 전부 "먼저 해야 하는 하위 목표"를 두고 더 쉬운 목표에 끌려갔다. 반면 전체 궤적을 보고 **행동마다 "이게 도움됐나"를 묻는 심판**은 유용한 행동을 정확히 가려냈다.
- **결과**: JEV를 교사로 쓴 GRPO 학습으로 Qwen2.5-1.5B가 ALFWorld 72.8%→**82.9%**, WebShop 56.8%→**71.4%**. 코드: [ZJU-REAL/decision-agents](https://github.com/ZJU-REAL/decision-agents)
- 🛠 **시사점**: 평가·보상 신호 설계의 질문을 바꾸라는 것. 아래 공통 팁에서 구체화한다.
- **한계**: 환경이 ALFWorld·WebShop 2종으로 좁고, 사후 심판은 에피소드가 끝나야 쓸 수 있다(실시간 가드레일용은 아님).

![결정 모델의 배우·심판·교사 세 역할과 각 역할의 결과를 정리한 다이어그램](/images/ai-news-2026-11-14/actor-judge-teacher.svg)

*행동 선택은 결과를 '예측'해야 하지만, 사후 심판은 결과를 '보고' 판단한다 — 이 비대칭이 논문의 핵심.*

## 2. Evidence-Guided Recovery — 도구가 타임아웃으로 죽었을 때, 에이전트는 뭘 믿어야 하나

- **저자**: Genliang Zhu, Xiaobo Chen 외 (Accentrust, Duke, Georgia Tech, UIUC, UMass Amherst)
- **arXiv**: [2610.41453](https://arxiv.org/abs/2610.41453) (cs.AI — 오늘 HF Daily Papers에 부상)
- **핵심 기여**: 도구 호출이 타임아웃되면 그 액션은 실패했을 수도, 커밋됐을 수도, 아직 진행 중일 수도 있다. 이 **모호한 상태에서의 복구**를 "공개된 증거와 모순되지 않는 상태들" 위의 계획 문제로 정식화했다.
- **방법**: 키 만료·인가 시점·의존성·잔여 효과를 검사하는 공용 admissibility 체크 + 실제 목표 달성과 "증거상 안전한 완료"를 구분하는 terminal certificate. 여기에 효과 이력을 판정하는 adjudicator를 결합.
- **결과**: 19개 과제 패밀리 58쌍 비교에서 복구 계획 조언이 완료 인증 **30 vs 9** (+36.2%p, p=0.0078), 제안 횟수는 272 vs 399로 더 적었다.
- 🛠 **시사점**: 결제·배포·DB 쓰기처럼 부수효과 있는 도구를 에이전트에 물릴 때, "타임아웃 = 실패로 간주하고 재시도"는 이중 실행 사고의 지름길이다. 재시도 전에 **증거 조회(조회 API, 멱등성 키 확인)** 단계를 강제하는 설계가 답.
- **한계**: 평가 규모가 작고(58쌍), admissibility 체크는 도메인별로 직접 정의해야 한다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code — AGENTS.md를 드디어 공식으로 읽는다** (카테고리: Context)

- 출처: [claude-code mods/agents-md](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/README.md)
- 💡 빌트인 플러그인 `agents-md`가 AGENTS.md를 CLAUDE.md와 같은 위치·같은 방식으로 로드한다. 옵션은 `instructionFiles` 하나, 4개 모드: `claude-md` / `claude-md-or-agents-md`(기본: CLAUDE.md 없는 프로젝트만 AGENTS.md 사용) / `claude-md-and-agents-md`(둘 다) / `managed-only`.
- 📝 `/config`의 "Project instructions" 행에서 고르거나, 유저 설정에 직접:

```json
{
  "pluginConfigs": {
    "agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}
```

- 🎯 Codex·Cursor와 저장소를 공유하는 팀이라면 `claude-md-and-agents-md`로 바꾸고, CLAUDE.md에서 AGENTS.md를 `@`-import하던 브리지를 걷어낼 수 있다 (중복 로드는 경로·내용 기준으로 자동 제거).
- ⚠️ 프로젝트의 `.claude/settings.json`은 플러그인 옵션을 읽지 않는다 — 유저 설정이나 managed 설정에 넣어야 한다.
- ⭐ 추천도: ★★★★★ (AGENTS.md 표준 수렴의 마지막 조각)

**🟩 Codex — 샌드박스 안 네이티브 TCP도 관리 프록시로** (카테고리: Workflow)

- 출처: [openai/codex 커밋 7194b21 (11/13)](https://github.com/openai/codex/commit/7194b2177643f3c639cfc5b29f6398c545b0e7e2)
- 💡 리눅스 샌드박스에 `--transparent-tcp` 옵트인이 추가됐다. 프록시 설정을 모르는 네이티브 TCP 클라이언트(DB 드라이버, gRPC 등)의 IPv4/IPv6 연결을 내장 TUN 인터페이스 + DNS 스텁으로 가로채 관리형 SOCKS 프록시로 라우팅한다. 원래 호스트네임이 보존돼 프록시 정책 검사도 그대로 작동.
- 📝 `codex exec-server`에는 `--linux-sandbox-transparent-tcp`와 `--tcp-upstream-proxy`(직접 연결 폴백 없는 HTTP CONNECT 넥스트홉)가 노출된다.
- 🎯 "HTTP는 프록시로 되는데 psql·redis-cli가 샌드박스에서 안 나간다"는 상황이 정확히 이 플래그의 용도.
- ⚠️ 프라이빗 네트워크·PID 네임스페이스, 시스템 `bwrap`, `/dev/net/tun` 접근이 필요하고, 방금 main에 머지된 기능이라 릴리스 반영 버전을 확인할 것.
- ⭐ 추천도: ★★★☆☆ (해당 상황이면 ★5, 아니면 몰라도 됨)

**🟪 공통 — 평가 질문을 "성공할까?"에서 "이 행동이 도움됐나?"로** (카테고리: Eval)

- 출처: [arXiv 2611.17167](https://arxiv.org/abs/2611.17167)
- 💡 위 논문의 실전 요약. 궤적 평가 LLM 저지에게 "이 과제는 성공하겠는가"를 묻는 것보다, 에피소드 종료 후 **행동 단위로 "이 행동이 목표에 기여했는가"**를 묻는 쪽이 유용한 행동과 낭비 행동을 훨씬 잘 가른다.
- 📝 기존 LLM-judge 평가 루프가 있다면 프롬프트 한 줄 교체로 실험 가능: 궤적 전체 + 행동 인덱스를 주고 행동별 기여 판정을 받아 집계한다.
- 🎯 에이전트 리그레션 테스트에서 "성공했지만 15턴 낭비"와 "실패했지만 방향은 맞음"을 구분하고 싶을 때.
- ⚠️ 사후 판정이므로 실행 중 가드레일로는 못 쓴다. 심판 모델의 편향은 소량 수동 라벨로 교차 검증할 것.
- ⭐ 추천도: ★★★★☆
