# 🔥 오늘의 핵심

주말이라 새 모델 출시는 없지만, 방향성 있는 신호가 둘 나왔습니다. Anthropic의 Opus 5.5 공식 프롬프팅 가이드는 11개 섹션 중 **"뭔가를 지우거나 재테스트하라"는 섹션(5개)이 "추가하라"(4개)보다 많습니다.** 그리고 NVIDIA의 PivotOPD 논문은 실패한 에이전트 롤아웃의 절반 이상이 초반의 '결정적 실수(pivotal mistake)' 하나에서 시작된다는 걸 측정으로 보여줬습니다. 오늘의 공통 교훈은 '빼기': 낡은 워크어라운드, 낡은 지시, 눈덩이가 되기 전의 첫 실수를 찾아 지우는 쪽이 이깁니다.

# 🤖 모델 & 릴리즈 레이더

- **Anthropic, Claude Opus 5.5 공식 프롬프팅 가이드 공개** — [플랫폼 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)에 증상별로 정리된 11개 섹션. 핵심은 이전 모델용 설정을 그대로 들고 오지 말라는 것: effort를 재스윕하고(코딩·지식 작업에서 Opus 5.5 medium이 Opus 5 high와 비슷하거나 더 낫다고 명시), 커스텀 OCR·차트 파싱 우회는 지우고 네이티브 비전을 테스트하고, thinking은 끌 수 없으니(끄려 하면 에러) 전제에서 빼라는 내용입니다. 외부 분석들도 '삭제 우선' 구성이라는 점에 주목했습니다([Towards AI 분석](https://pub.towardsai.net/anthropics-opus-5-5-prompting-guide-has-11-sections-and-more-of-them-say-delete-than-add-b241dcc1500e)).
- **OpenAI 안전 투명성 리드 David Robinson 사임** — 10/3 The Atlantic에 "문화가 망가졌다"는 에세이를 직접 기고. 약 1주 사이 네 번째 안전 조직 이탈로, GPT-6.1 Astra 출시 취소(내부 안전 기준 미달, 지난주 커버) 직후의 흐름이라는 점이 포인트입니다. API로 OpenAI 모델을 쓰는 입장에서는 모델 릴리즈 일정의 변동성이 당분간 크다는 신호로 읽는 게 실용적입니다. — [보도 정리](https://www.yahoo.com/news/us/articles/meet-david-robinson-openai-safety-193656593.html)
- 그 외 큰 모델 소식 없음 (일요일 기준).

# 📚 주목 논문

## PivotOPD: 실패의 절반은 '첫 실수'에서 시작된다

- **저자**: Yinghui He, Yapei Chang, Khushi Bhardwaj, Jan Kautz, Ali Hatamizadeh 외 (NVIDIA 연구진)
- **arXiv**: [2609.40285](https://arxiv.org/abs/2609.40285) (cs.AI, 9/30 공개)
- **핵심 기여**: 멀티턴 에이전트의 실패 롤아웃을 분석해 **절반 이상이 초반의 pivotal mistake 하나에서 비롯**되고, 그 시점엔 아직 짧은 개입으로 복구 가능하다는 것을 보인 뒤, 이를 겨냥한 증류 기법을 제안.
- **방법**: 이중 증류. 실수 직전 상태에서 교사의 올바른 행동을 배우는 **예방 증류(reverse KL)** + 실수가 난 뒤의 상태에서 교사의 복구 행동을 배우는 **복구 증류(forward KL)**.
- **결과(논문 보고치)**: ALFWorld에서 Qwen3-1.7B 학생 모델 기준 최강 베이스라인 대비 +5.5%, SWE-Bench Verified에서 Nemotron-3.5 학생 기준 해결률 +3.2%.
- 🛠 **에이전트 빌더 시사점**: 훈련을 안 하더라도 진단 프레임은 바로 쓸 수 있습니다. 실패 트레이스를 리뷰할 때 "어느 턴이 첫 결정적 실수였나"를 라벨링하면, 프롬프트/가드레일을 고칠 지점이 마지막 턴이 아니라 **초반**이라는 걸 자주 발견하게 됩니다.
- **한계**: 교사 모델이 필요한 증류 기반이고, 보고된 수치는 소형 학생 모델 중심입니다.

![PivotOPD 이중 증류 구조](/images/ai-news-2026-10-05/pivotopd-loop.svg)

*PivotOPD의 구조: 초반 결정적 실수를 기준으로 '예방'과 '복구'를 따로 증류한다. (논문 내용 기반 자체 제작)*

## IntentFlux: 사용자가 말을 바꾸면 에이전트는 못 따라온다

- **저자**: Yanjie Zhang, Bowen Cao, Zixin Chen, Yushi Sun (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2609.32520](https://arxiv.org/abs/2609.32520) (cs.CL, 9/26 공개, HF Daily 노출)
- **핵심 기여**: 멀티턴 대화 중 사용자가 요구를 바꿨을 때 **철회된 옛 지시가 계속 출력에 영향을 주는 'intent drift'**를 측정하는 벤치마크 IntentFlux 구축. 8개 모델 전부에서 동일 과제를 단일 턴으로 줬을 때보다 성능이 크게 하락.
- **방법**: 과제를 '중간에 의도가 바뀌는 대화'로 변환해 통제된 비교. 완화책으로 생성 직전에 '현재 유효한 요구사항' 목록을 유지·갱신하는 StateForge를 제안 — 개선되지만 단일 턴과의 갭을 다 닫지는 못함.
- 🛠 **에이전트 빌더 시사점**: 어제 다룬 belief state(PoS)와 같은 계보입니다. 긴 세션에서는 대화 로그를 그대로 믿지 말고, **"지금 유효한 요구사항" 블록을 별도로 유지하고 사용자가 번복하면 그 블록에서 명시적으로 삭제**하세요. 컨텍스트에 남은 옛 지시가 곧 버그입니다.
- **한계**: 완화책이 갭을 못 닫았고, 공개 코드 여부는 미확인입니다.

# 🛠 오픈소스 스포트라이트

이번 주말 눈에 띈 두 레포는 방향이 반대라 같이 보면 좋습니다. 하나는 '에이전트에게 일 시키는 프로세스'를, 하나는 '에이전트가 도는 인프라'를 셀프호스팅합니다. (스타 수는 세션의 GitHub API 제한으로 미확인 — 두 레포 모두 직접 클론해 코드·커밋을 확인했습니다.)

**[mattpocock/skills](https://github.com/mattpocock/skills)** — TypeScript/Markdown, MIT

- Total TypeScript의 Matt Pocock이 매일 실무에 쓰는 Agent Skills 모음. "GSD·BMAD·Spec-Kit처럼 프로세스를 통째로 소유하는 방식 대신, 작고 수정하기 쉽고 조합 가능한 스킬"이 설계 철학입니다.
- 배포가 두 갈래인 게 재밌는 지점: Claude Code 공식 마켓플레이스 플러그인(`claude plugins install mattpocock-skills`, 자동 업데이트되는 구독형)과 `npx skills@latest add mattpocock/skills`(프로젝트에 파일을 복사해 내 것으로 고치는 포크형, Codex 등 다른 에이전트 지원).
- **활용**: 스킬을 직접 쓰는 것 못지않게, 잘 짜인 스킬 레포의 구조(카테고리, CHANGELOG, ADR)를 팀 스킬 레포의 레퍼런스로 삼기 좋습니다. 10/4에도 커밋이 이어지는 활발한 레포입니다.

**[pi-pod/pipod](https://github.com/pi-pod/pipod)** — TypeScript + Swift/Kotlin, AGPL-3.0

- Mario Zechner(badlogic)의 pi 코딩 에이전트 세션을 **내가 운영하는 서버의 격리 샌드박스("pod")에서 실행**하는 풀스택: CLI, REST 컨트롤 플레인, 네이티브 샌드박스 서비스, iOS/Android 앱까지. 인증은 Zitadel(OIDC), 설치는 Compose 프로젝트 하나.
- 10/4 하루에만 CLI 0.1.8→0.1.9 릴리즈. 특히 "pod에서 크리덴셜 제거, 로그에서 티켓 차단" 같은 보안 커밋이 눈에 띕니다.
- **활용**: 클라우드 에이전트 실행 환경(Claude Code on the web 같은)을 데이터 주권 이슈로 못 쓰는 팀이, 8GB RAM Linux 호스트 하나로 비슷한 경험(폰에서 세션 접속 포함)을 자체 구축하는 출발점. AGPL이라 사내 SaaS화 시 라이선스 검토는 필수입니다.

## 🟩 Codex — strict Code Mode로 툴 프리픽스 고정 (Context)

- **소스**: [openai/codex 커밋 58ae3ba](https://github.com/openai/codex/commit/58ae3ba61186c39b849a6ebe60e60f4b11690373) (10/3 머지)
- 💡 **핵심**: 새로 추가된 `code_mode_only_strict_3p_tools` 기능 플래그(기본 off)는 Code Mode Only에서 서드파티 MCP·앱 툴을 전부 deferred 상태로 유지합니다. 툴은 `exec` 경유로 여전히 발견·호출 가능하지만, **모델에게 먼저 주입되는 eager tool prefix가 고정**됩니다.
- 📝 **어떻게**: 커밋 메시지가 명시하듯 포인트는 "MCP 카탈로그가 턴 사이에 바뀌어도 프롬프트 프리픽스가 안 바뀐다"는 것. MCP 서버를 자주 붙였다 떼는 워크플로라면 이 플래그가 프롬프트 캐시 히트율을 지켜줍니다.
- 🎯 **언제**: MCP 서버 수가 많고 카탈로그가 동적으로 변하는 세션, 캐시 비용에 민감한 장기 세션.
- ⚠️ **주의**: 10/3에 막 머지된 기본 꺼짐 실험 기능입니다. built-in 툴 노출은 바뀌지 않고, disabled/policy-denied 제한은 그대로 유지됩니다.
- ⭐ **추천도**: 캐시 비용이 보이는 팀이라면 추적할 가치 충분.

## 🟦 Claude Code — v2.1.289, 권한 규칙 재검증 타이밍 (Review)

- **소스**: [v2.1.289 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.289)
- 💡 **핵심**: 이번 버전은 deny/ask 권한 규칙이 새던 에지케이스를 여럿 막았습니다 — 심링크를 경유한 `Read`, `TZ="$HOME" rm -rf build`처럼 환경변수 프리픽스가 붙은 명령, 복합 셸 명령의 중첩 부분 등.
- 📝 **어떻게**: 업그레이드 후, 믿고 있던 규칙이 실제로 막히는지 우회 경로로 재검증하세요.

```bash
# 예: .env를 deny로 막아뒀다면 심링크 우회도 막히는지 확인
ln -s .env /tmp/not-an-env && claude -p "Read /tmp/not-an-env"
# 예: env 프리픽스 뒤의 위험 명령이 ask에 걸리는지 확인
claude -p "run: FOO=bar rm -rf build"
```

- 🎯 **언제**: 비밀 파일·파괴적 명령을 permission rule로 막아둔 모든 프로젝트. mods를 만드는 쪽이라면 `agent.spawn`과 `$.agent.list()`의 idle/waiting 상태 추가도 이번 버전입니다.
- ⚠️ **주의**: 규칙이 막아주는 건 해당 버전의 매칭 로직까지입니다. 진짜 비밀은 애초에 세션이 닿는 경로 밖에 두는 게 원칙.
- ⭐ **추천도**: deny 규칙 쓰는 팀은 필수 점검.

## 🟪 공통 — 모델 마이그레이션은 '삭제 체크리스트'부터 (Workflow)

- **소스**: [Opus 5.5 프롬프팅 가이드](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- 💡 **핵심**: 새 모델로 갈아탈 때 프롬프트에 뭘 더할지부터 고민하지 말 것. 이번 가이드의 구성 자체가 증거입니다 — 삭제·재테스트 권고가 추가 권고보다 많습니다.
- 📝 **어떻게**: 마이그레이션 PR에 세 줄짜리 체크리스트를 넣으세요. (1) effort·thinking 예산 재스윕 — 상위 모델의 medium이 이전 모델의 high를 대체하는지 측정, (2) 전처리 워크어라운드(OCR, 차트→텍스트 변환, 수동 청킹) 제거 후 네이티브 성능 비교, (3) 이전 모델의 버릇을 고치려 넣었던 지시("반드시 단계별로", "절대 요약하지 마" 류) 하나씩 빼며 회귀 테스트.
- 🎯 **언제**: 모든 모델 업그레이드. 특히 프롬프트가 6개월 이상 누적된 프로덕션 에이전트.
- ⚠️ **주의**: 가이드의 수치는 Opus 5.5 기준입니다. 다른 모델로 일반화하지 말고 자기 eval로 확인하세요.
- ⭐ **추천도**: 비용 절감이 바로 나오는 습관이라 강력 추천.
