# 🔥 오늘의 핵심

주말이라 새 모델 발표는 없지만 방향 신호는 또렷하다. Google이 Android Studio 안정 버전에서 Claude Agent·Codex 같은 외부 에이전트를 ACP(Agent Client Protocol)로 직접 연결하게 열었다. "에이전트는 IDE에 종속되지 않는다"가 플랫폼 공식 입장이 된 셈이다. 논문 쪽에서는 실사용자 요청 기반 코딩 에이전트 벤치마크 Co-Design Bench가 나왔다 — 기준 하나하나는 70% 가까이 맞추면서 요청을 완전히 끝내는 비율은 26.4%에 그친다.

*오늘의 변화를 모델 / 논문 / 오픈소스 / 도구 네 축으로 정리한 지도.*

# 🤖 모델 & 릴리즈 레이더

- **Android Studio Rabbit 2 안정화 — BYOA(Bring Your Own Agent) (10/28)** — Claude Agent, OpenAI Codex, Google Antigravity, Junie 등 40개 이상의 코딩 에이전트를 ACP로 IDE에 연결할 수 있다. 연결된 에이전트는 에뮬레이터·빌드 시스템·Logcat 같은 Android Studio 도구에 접근하고, 개인/기업 구독으로 인증한다. 에이전트 빌더 관점에서는 ACP가 JetBrains 계열 밖에서도 "에이전트 이식성 표준"으로 자리 잡는 신호다. [Google 발표](https://developer.android.com/blog/posts/ai-agents-android-studio-integration)
- **Claude Code 2.1.316 (10/31)** — 서브에이전트 effort 기본값을 정하는 `CLAUDE_CODE_SUBAGENT_EFFORT` 추가(아래 팁 참고), `ultrathink` 키워드를 끄는 `CLAUDE_CODE_DISABLE_ULTRATHINK` 추가. Opus 4.8 fast mode는 10/30부로 deprecated, 11/30 제거 예정이니 Opus 5.5로 옮겨야 한다. [릴리즈 노트](https://github.com/anthropics/claude-code/releases/tag/v2.1.316)
- 그 외 큰 모델 소식 없음. Moonshot이 예고한 **Kimi K3.1 Pro 오픈 웨이트(11/4)**가 다음 이벤트다.

# 📚 주목 논문

## 1. Co-Design Bench: 멀티모달 협업 코딩 평가

- **저자**: Xilin Wei, Shengyuan Ding, Xinyu Fang 외 (Shanghai AI Lab 계열 공동 연구)
- **arXiv**: [2610.35138](https://arxiv.org/abs/2610.35138) (cs.AI, 10/26 공개)
- **핵심 기여**: 실제 코딩 세션 26,314개에서 추린 사용자 요청으로 만든, 정답 코드 없는(reference-free) 코딩 에이전트 벤치마크. 273개 태스크, 숨겨진 전문가 작성 수용 기준 2,331개.
- **방법**: 이미지·오디오·영상·문서가 섞인 국소 수정(ME)과 저장소 단위 수정(RE) 두 트랙. 채점은 judge-then-refute — LLM judge가 소스·브라우저 증거로 기준별 채점하고, 별도 verifier가 "통과" 판정만 골라 반증을 시도해 거짓 통과를 걸러낸다.
- **결과**: 10개 엔드포인트 중 최강 모델도 태스크당 기준 통과율 평균 69.9%, 모든 기준 충족은 26.4%. 수정 범위가 3~4개 파일로 커지면 전 모델이 더 떨어진다.
- 🛠 **에이전트 빌더 시사점**: "부분 점수는 높은데 완수율이 낮다"는 패턴은 내부 제품 평가에서도 흔하다. 기준별 통과율과 완전 충족률을 분리해서 추적할 것.
- **한계**: 채점이 LLM judge 체인에 의존하므로 judge 모델 교체 시 수치가 흔들릴 수 있다.

![Co-Design Bench 수치와 채점 프로토콜](/images/ai-news-2026-11-01/codesign-bench.svg)

*기준 통과율(69.9%)과 완전 충족률(26.4%)의 격차, 그리고 judge-then-refute 채점 파이프라인.*

## 2. WorkFactory: 직업 의도를 실행 가능한 에이전트 학습 태스크로

- **저자**: Ziyang Zeng, Tingyang Chen, Jia Deng 외 (Kuaishou·RUC 계열)
- **arXiv**: [2610.37161](https://arxiv.org/abs/2610.37161) (cs.AI, 10/27 공개, HF Daily 상위)
- **핵심 기여**: "직업적 의도"에서 출발해 교사 모델이 실제로 실행·시연할 수 있는 업무 태스크를 대량 합성하는 프레임워크. 612개 직군에서 112,686개 태스크를 구축.
- **방법**: 산출물에 필요한 정보의 위치·의존성을 그래프(information support graph)로 먼저 설계하고, probe 실행으로 "정보가 모자라 교사가 못 푸는" 태스크를 찾아 수리한다.
- **결과**: 이 데이터로 파인튜닝한 WorkPilot 계열(4B/27B/35B-A3B)이 4개 업무 벤치마크에서 베이스 대비 전부 상승. 35B-A3B는 GDPval-AA v2.1 Elo 879 → 1565 (논문 보고치).
- 🛠 **에이전트 빌더 시사점**: 태스크 합성의 병목은 "그럴듯한 지시문"이 아니라 "교사가 실행 가능한 정보 지원"이라는 관점. 사내 SFT 데이터 만들 때 정보 의존성 점검을 파이프라인 앞단에 둘 것.
- **한계**: 스케일링 수익이 모델에 따라 꺾이는 지점이 다르고, 교사 품질에 상한이 묶인다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — TUI에서 백엔드를 넘나드는 세션 전환

- **카테고리**: Workflow · **출처**: [commit 1da2aef](https://github.com/openai/codex/commit/1da2aefe001b333340fe8b012b18b072c49cc743) (10/30)
- 💡 **핵심**: 세션 피커에 여러 백엔드(예: 로컬/다른 계정·제공자)의 대화가 떠도 지금까지는 다른 백엔드 소유 대화를 선택하면 거부됐다. 이제 소유 백엔드를 통해 그대로 재개된다.
- 📝 **방법**: 업그레이드 후 평소처럼 세션 피커(`codex resume`)에서 고르면 된다. 작성 중 드래프트는 보존되고, 대상 백엔드의 설정·계정 상태·모델 카탈로그·워크스페이스 서비스로 전환된다.
- 🎯 **언제**: 회사 계정과 개인 계정, 또는 서로 다른 제공자 백엔드를 오가며 작업하는 멀티 계정 셋업.
- ⚠️ **주의**: 턴이 진행 중일 때는 전환이 차단되고, 대상 준비에 실패하면 현재 대화가 유지된다. 백그라운드 백엔드의 이벤트는 표시 중 대화와 격리된다.
- ⭐ **추천도**: 멀티 백엔드 사용자에겐 체감 큰 편의 기능. 단일 계정 사용자는 해당 없음.

### 🟦 Claude Code — 서브에이전트 effort를 메인 세션과 분리

- **카테고리**: Subagent / Context · **출처**: [v2.1.316 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.316) (10/31)
- 💡 **핵심**: 지금까지 effort 지정이 없는 서브에이전트는 세션의 effort를 상속했다. 새 환경 변수로 "지정 없는 서브에이전트"의 기본 effort를 따로 정할 수 있다.
- 📝 **방법**:

```bash
# 메인 세션은 high로 돌리더라도, 탐색용 서브에이전트는 medium으로
export CLAUDE_CODE_SUBAGENT_EFFORT=medium
claude
```

- 🎯 **언제**: 메인 턴은 `ultrathink`/high effort로 쓰면서, Explore 같은 fan-out 서브에이전트가 같은 effort를 상속해 토큰을 태우는 게 아까울 때.
- ⚠️ **주의**: 에이전트 정의나 호출에서 effort를 명시한 경우에는 그 값이 우선이다. 어디까지나 "아무도 지정 안 했을 때"의 기본값.
- ⭐ **추천도**: 서브에이전트를 자주 쓰는 셋업이라면 비용 대비 효과가 바로 보인다.

### 🟪 공통 — judge만 믿지 말고 refuter를 붙여라

- **카테고리**: Eval · **출처**: [Co-Design Bench (arXiv 2610.35138)](https://arxiv.org/abs/2610.35138)
- 💡 **핵심**: LLM judge는 "통과" 쪽으로 관대해지기 쉽다. Co-Design Bench는 judge 판정 후 별도 LLM이 통과 판정만 골라 반증을 시도하는 2단계 프로토콜로 거짓 통과를 걸러낸다.
- 📝 **방법**: 에이전트 산출물 평가 파이프라인에 단계를 하나 추가한다 — (1) judge가 기준별로 증거(코드 diff, 실행 로그, 스크린샷)를 인용하며 채점 → (2) refuter가 "이 기준이 사실은 충족되지 않았다는 반례"를 찾게 시킨다 → (3) 반례가 성립하면 통과를 취소.
- 🎯 **언제**: gold 정답이 없는 자유 형식 태스크(UI 수정, 리팩터링)의 자동 평가. 통과율이 체감보다 후하게 나올 때 특히.
- ⚠️ **주의**: refuter도 LLM이므로 과도하게 공격적이면 거짓 불통과가 생긴다. 소량 수동 라벨로 양방향 오류율을 먼저 측정할 것.
- ⭐ **추천도**: judge 기반 eval을 운영 중이라면 가장 싸게 신뢰도를 올리는 패턴.
