# 📚 주목 논문

## 1. SparseRead — 에이전트의 '과식 읽기'를 끊는 제어 레이어

- **저자**: Zedong Liu, Jiaan Wu, Xinyang Ma, Le Xu, Kai Wang, Yuanchao Hu, Dingwen Tao, Guangming Tan
- **arXiv**: [2608.22237](https://arxiv.org/abs/2608.22237) (cs.AI, v2 — 오늘 HF Daily Papers 상위)
- **핵심 기여**: 웹·문서·저장소·도구 응답을 객체 통째로 노출하는 기존 읽기 인터페이스가 토큰·지연을 키우고 증거를 희석시킨다는 문제를, **모델 수정 없이** 재사용 가능한 읽기 제어 레이어로 푼다.
- **방법**: ① Read Intent Protocol이 "지금 뭘 찾는지"와 소스 커버리지를 추적하고 ② Adaptive Reader Backends가 소스별 증거 탐색 방식을 고르고 ③ Budgeted Read Gate가 에피소드당 원문 노출 총량에 상한을 건다. 부족하면 전체 보기로 폴백해 충실성을 지킨다.
- **결과**: Claude Opus 5 포함 6개 모델 × 5개 시나리오에서 전체 토큰 최대 **-92.9%**, 소요 시간 최대 **-89.0%**, 품질은 97% 설정에서 유지 또는 개선. 웹 딥서치 과제에선 토큰 -31~43%.
- 🛠 **시사점**: 읽기 통제를 프롬프트("필요한 부분만 읽어")가 아니라 **인터페이스 계층**에 두는 설계. 아래 공통 팁에서 구체화한다.
- **한계**: 게이트·백엔드 자체가 새 구성 요소라 튜닝 포인트가 늘고, 상한이 너무 낮으면 폴백이 잦아져 이득이 줄어든다.

![SparseRead의 3개 구성 요소와 토큰 절감 결과를 보여주는 구조도](/images/ai-news-2026-11-13/sparseread.svg)

*에이전트와 외부 콘텐츠 사이에 읽기 제어 레이어를 끼운다. 모델과 프레임워크는 그대로.*

## 2. SteerDistill — 양자화로 망가진 에이전트를 교사가 고쳐준다

- **저자**: Genming Cui, Xiangyu Li, Zixu Hao, Xin Ding, Yunxin Liu, Ting Cao
- **arXiv**: [2611.13410](https://arxiv.org/abs/2611.13410) (cs.AI)
- **핵심 기여**: 저비트 양자화된 에이전트가 과제 요구사항이나 환경 조건을 놓치는 **행동 편차**를 실패 원인으로 짚고, 이를 교정하는 양자화 인지 증류를 제안.
- **방법**: 풀정밀 교사가 학생(양자화 모델)의 실패 응답을 고치도록 유도하고, 학생의 실행 피드백으로 그 가이드를 반복 정제한다. 교정된 턴은 "교사 도움 받은 학생"을, 나머지 턴은 교사를 따라 하도록 학생을 학습시켜, 추론 시엔 도움 없이 돌아가게 만든다.
- **결과**: 5개 에이전트 벤치마크 × 3개 모델에서 W4A16 기준 최강 양자화 베이스라인을 1.67~2.18점 상회, **BF16 대비 1점 이내**.
- 🛠 **시사점**: 로컬·엣지에서 에이전트를 돌리려는 팀에게 "양자화 후 벤치만 돌리고 포기"가 아닌 복구 레시피가 생겼다. 일반 증류와 달리 **학생의 실패 맥락에서 데이터를 만든다**는 점이 포인트.
- **한계**: 교사 모델과 환경 롤아웃이 필요해 학습 파이프라인 비용이 있다. 평가는 벤치마크 환경 기준.

# 🛠 오픈소스 스포트라이트

- **[expo/exact](https://github.com/expo/exact)** (Rust, MIT, 약 3,300 스타): Expo가 공개한 "에이전트 우선" 크로스플랫폼 프레임워크. 한 번 작성한 앱이 웹·macOS·iOS·리눅스에서 네이티브로 돌고, 에이전트가 `scripts/agent.mjs`로 **빌드→실행→화면 확인→테스트**까지 전부 수행할 수 있게 설계됐다. README에는 Claude Code에 던지는 프롬프트 예시와 실측 소요 시간(초회 약 57분, 이후 빌드 1~2분)까지 적혀 있다. 바이브 코딩으로 데스크톱/모바일 앱을 찍어내고 싶은 팀의 실험 재료.
- **[agentes-chat/agentes-chat](https://github.com/agentes-chat/agentes-chat)** (TypeScript, AGPL-3.0, 약 1,100 스타): 사람과 에이전트가 같은 채널에서 일하는 셀프호스트 Slack 대안. 에이전트는 **역할·소유자·예산**을 달고 채널에 참여하고, 민감한 작업 전에 승인을 묻는다. Claude·Codex·Gemini·Grok·OpenRouter 모델과 MCP 도구를 지원. "에이전트를 팀 채팅의 1급 시민으로" 패턴을 직접 뜯어볼 수 있는 레퍼런스.
- **[shanselman/gputaskman](https://github.com/shanselman/gputaskman)** (Python, MIT, 약 2,700 스타): "GPU 안쪽을 보는 htop". 프로세스별 VRAM과 엔진 활동을 로드된 런타임·모델 파일과 연결하고, LLM이면 **가중치/KV 캐시/컴퓨트 버퍼**까지 추정해 보여준다. `uv tool install gputaskman` 한 줄로 설치. 로컬 추론·파인튜닝 중 "15GB가 대체 뭐에 쓰이는 거지"를 끝내준다. 분류는 추정치라는 점은 README가 스스로 명시한다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code — sec-default 모드 업데이트: 조직 정책의 '티어' 모델 이해하기**

- 카테고리: Hook / 정책
- 소스: [mods/sec-default 11/11 업데이트](https://github.com/anthropics/claude-code/commit/927b66497b89542dc1242e26d5735dbf880c829e)
- 💡 Claude Code의 function hook은 **조직 prepend 티어 → 유저 티어 → 조직 append 티어** 순서로 체인을 탄다. 이번 업데이트는 `managed-tools-restored` 정책을 추가했다: 조직이 관리 설정에서 내린(제거한) MCP 도구를 유저 티어 플러그인이 목록 조작으로 되살리는 경로를 막는다.
- 📝 내 플러그인이 조직 관리 설정과 어떻게 상호작용하는지 보려면 소스를 직접 읽는 게 가장 빠르다:

```bash
git clone --depth 1 https://github.com/anthropics/claude-code
# 티어 모델과 정책 행렬: mods/sec-default/README.md
# 내 플러그인 로컬 테스트:
claude --plugin-dir ./my-plugin
```

- 🎯 회사 관리 설정이 깔린 환경에서 "내 훅이 왜 안 먹지"를 디버깅할 때, 또는 팀 자체 정책 훅을 설계할 때.
- ⚠️ 정책 읽기는 fail-closed다 — 관리 설정을 읽지 못하면 "정책 있음"으로 간주되니, 읽기 실패를 우회 수단으로 기대하지 말 것.
- ⭐ 추천: sec-default는 Anthropic이 직접 쓰는 정책 훅의 레퍼런스 구현이다. 자체 가드레일 플러그인을 만들 때 베끼기 좋은 출발점.

- 카테고리: Review

- 💡 같은 스레드에서 `thread/guardianReview`를 연속 호출하면 이제 **재사용되는 Guardian 세션**을 타고, 직접 리뷰가 라이브 승인과 리뷰 히스토리를 공유한다. 리뷰어 대화는 actor와 분리 유지되고, 재시도는 현재 정책 기준으로 마지막 호출을 재평가한다.
- 📝 Codex에서 명령 승인 플로우를 쓰는 중이라면 별도 설정은 없다 — 다만 "같은 스레드에서 리뷰를 쪼개 여러 번 요청"하는 패턴이 이제 맥락을 잃지 않으므로, 큰 diff를 나눠 리뷰시키는 게 전보다 손해가 아니다.
- 🎯 자체 하네스를 만드는 사람에게 더 중요한 패턴: **리뷰어는 actor와 세션을 분리하되, 리뷰어끼리는 히스토리를 공유**시켜라. 같은 코드에 대해 매번 백지 리뷰를 시키면 일관성이 떨어지고 토큰도 샌다.
- ⚠️ 리뷰어 히스토리는 부모 스레드 단위로 격리된다 — 스레드가 다르면 공유되지 않는 게 의도된 동작.
- ⭐ 추천: 11/4 브리핑의 Guardian 재고(reconsideration)와 묶어 보면 Codex 리뷰 서브시스템의 방향이 보인다: 리뷰어를 1회용 함수가 아니라 **상태 있는 동료**로 만드는 것.

**🟪 공통 — 읽기 예산 게이트: 프롬프트가 아니라 인터페이스에 상한을**

- 카테고리: Context
- 소스: [SparseRead, arXiv 2608.22237](https://arxiv.org/abs/2608.22237)
- 💡 "필요한 부분만 읽어라"는 프롬프트는 모델이 무시하면 끝이다. SparseRead의 Budgeted Read Gate는 **에피소드당 원문 노출 총량**을 도구 계층에서 세고, 상한 초과분은 검색/발췌 모드로 강제 전환한다.
- 📝 자체 에이전트에 최소 구현: 도구 래퍼에 `raw_chars_exposed` 카운터를 두고, 임계 초과 시 전문 반환 대신 "검색어를 달라"는 에러를 반환하게 바꾼다. 단, 막다른 길 방지를 위해 명시적 `force_full_view` 탈출구는 남겨둘 것 — 논문도 충실성 폴백을 핵심 설계로 꼽는다.
- 🎯 웹 리서치·저장소 탐색처럼 에이전트가 긴 외부 콘텐츠를 반복해서 끌어오는 워크로드.
- ⚠️ 상한을 너무 낮게 잡으면 폴백 왕복이 늘어 오히려 느려진다. 논문의 수치는 자체 백엔드 포함 기준이니 그대로 기대하진 말 것.
- ⭐ 추천: 토큰 비용이 아픈 팀이라면 이번 주에 카운터부터 달아보자. 측정만 해도 어디서 새는지 보인다.
