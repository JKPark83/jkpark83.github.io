# 📚 주목 논문

## 1. WikiTrace — 메모리가 에이전트를 망칠 때

- **저자**: Yukyeong Lee, Yumin Choi, Jinheon Baek, Sung Ju Hwang (소속 미표기)
- **arXiv**: [2611.14320](https://arxiv.org/abs/2611.14320) (cs.AI)
- **핵심 기여**: 외부 메모리의 역효과를 정면으로 다룬다. **메모리가 없었으면 풀었을 과제를 메모리 때문에 틀리는** 현상(memory-induced degradation)의 원인을 "lesson이 출처 궤적 없이 주입되어 에이전트가 검증할 수단이 없기 때문"으로 짚었다.
- **방법**: lesson을 3층으로 저장한다 — ① 간결한 insight ② 그 궤적이 왜 성공/실패했는지 요약 ③ 원본 궤적. 평소엔 insight만 쓰고, 디테일이 부족하거나 insight끼리 충돌하거나 실패 과제에서 나온 것일 때만 링크를 타고 내려가 확인 후 행동한다.
- **결과**: 5개 에이전트 벤치마크에서 기존 메모리 방식과 "같은 insight만 제공" 베이스라인을 일관되게 상회하고, degradation 자체도 줄였다. [코드 공개](https://github.com/yukyeongleee/wikitrace).
- 🛠 **시사점**: lesson 추출형 메모리를 쓰고 있다면, 압축 후 궤적을 버리는 설계는 실패 모드를 내장한 셈이다. 아래 공통 팁에서 구체화한다.
- **한계**: 원본 궤적을 보관해야 하므로 저장·토큰 비용이 늘고, "언제 내려가서 확인할지" 판단 자체를 모델에 맡긴다.

![기존 lesson 주입 방식과 WikiTrace의 3층 근거 링크 구조 비교](/images/ai-news-2026-11-12/wikitrace.svg)

*lesson만 남기면 에이전트는 틀린 교훈을 검증할 수 없다. WikiTrace는 의심스러울 때만 증거로 내려간다.*

## 2. MMDM — System-1 결정 모델의 실력을 재다

- **저자**: Junhao Shen, Qing Zong, Yue Guo, Zhanqiu Zhang, Yiwen Guo, Hong Cheng (소속 미표기)
- **arXiv**: [2611.14309](https://arxiv.org/abs/2611.14309) (cs.LG)
- **핵심 기여**: 추론 텍스트 생성 없이 한 번의 forward pass로 선택지에 확률을 찍는 **System-1 결정 모델** 전용 벤치마크. 16개 과제 유형, 5,448문항, 선택지 2~1,024개, 입력 최대 64,817 토큰으로 기존 벤치마크가 못 잡던 장문 맥락·대형 선택 공간·논리 의존성을 한꺼번에 측정한다.
- **결과**: 28개 결정 모델 평가. 최상위권인 Perplexity Decider-V1.2도 세계 지식 Hard Single-select **78.75%** 대비 옵션 간 논리 **53.95%**, 제약 계획 **47.95%**로 급락. Hard Multi-select는 전 모델 최고치가 **36.81%**에 그쳤다.
- 🛠 **시사점**: 라우팅·툴 선택·가드레일 판정을 싸고 빠른 결정 모델로 뽑는 설계가 늘고 있는데, 이 결과는 그 적용 범위를 알려준다 — "아는 것 고르기"는 맡겨도 되지만, 선택지끼리 얽힌 제약 판단은 아직 추론 모델 몫이다.
- **한계**: System-1 결정 모델 생태계 자체가 초기라 평가 대상의 대표성이 금방 바뀔 수 있다.

*결정 모델에 라우팅을 맡길 수 있는 영역과 아직 못 맡기는 영역이 수치로 갈렸다.*

**1. 🟩 Codex — MCP OAuth 자격증명 경합이 수정됐다** (카테고리: MCP)

- 소스: [openai/codex#60849 커밋](https://github.com/openai/codex/commit/392ced7d3a9160fd35d40c606359869215f50522) (11/11)
- 💡 핵심: 진행 중이던 토큰 갱신이 **그 사이에 일어난 새 로그인을 덮어쓰거나, 로그아웃한 자격증명을 되살리는** 경합이 있었다. 이제 저장 전에 잠그고 재검증하며, 저장소가 바뀌었으면 재인증을 요구한다.
- 📝 방법: `codex`를 최신으로 올리면 끝. OAuth MCP 서버에서 "분명히 재로그인했는데 옛 계정으로 돌아가 있다" 같은 증상을 겪었다면 이 버그였을 가능성이 높다.
- 🎯 언제: OAuth 인증 MCP 서버(사내 API, SaaS 커넥터)를 장시간 세션·병렬 세션에서 쓸 때.
- ⚠️ 주의: 같은 패턴이 **내가 만드는 에이전트 하네스**에도 있다. 갱신된 토큰을 저장하기 전에 저장소의 현재 값이 갱신 시작 시점 값과 같은지 비교하는 compare-and-swap 없이 쓰면 똑같은 경합이 난다.
- ⭐ 추천도: MCP OAuth 사용자라면 오늘 업데이트.

**2. 🟦 Claude Code — /diff 패널, 이제 소스까지 읽을 수 있다** (카테고리: Workflow)

- 소스: [mods/diff README](https://github.com/anthropics/claude-code/blob/main/mods/diff/README.md) (11/11 갱신)
- 💡 핵심: 세션의 미커밋 변경을 트랜스크립트 옆에 띄우는 diff 패널이 **플러그인 하나로 구현되어 공개돼 있다**. 동작 규칙(첫 편집 성공 시 자동 오픈, 터미널 144칼럼 이상 + 파일 체크포인팅 켜짐 조건, 외부 커밋 감지용 HEAD 폴링)이 README에 전부 문서화됐다.
- 📝 방법: 쓰는 법은 `/diff` 토글, `ctrl+x b`로 비교 기준 이동이 전부. 진짜 가치는 읽는 데 있다 — 패널·스크롤·버튼이 있는 UI 플러그인을 function hooks로 어떻게 짜는지 보여주는 공식 레퍼런스다.
- 🎯 언제: 에이전트가 고치는 걸 실시간으로 훑으며 승인하고 싶을 때, 그리고 Claude Code용 커스텀 패널 플러그인을 만들려 할 때.
- ⚠️ 주의: 자동 오픈은 서브에이전트 편집이나 셸 명령으로는 트리거되지 않는다. 좁은 터미널에서는 직접 `/diff`를 쳐야 한다.
- ⭐ 추천도: 플러그인 만들 계획이 있다면 정독 가치 높음.

**3. 🟪 공통 — 메모리의 lesson에 근거 링크를 달아라** (카테고리: Context)

- 소스: [WikiTrace (arXiv 2611.14320)](https://arxiv.org/abs/2611.14320)
- 💡 핵심: 에이전트 메모리에서 lesson만 남기고 궤적을 버리면, 틀린 lesson을 에이전트가 영원히 검증할 수 없다. 저장할 때 출처를 같이 남기는 것만으로 degradation이 줄어든다.
- 📝 방법: 메모리 항목 스키마에 두 필드를 추가한다.

```json
{
  "insight": "배포 전 migration dry-run을 먼저 돌린다",
  "why": "10/03 배포 실패: dry-run 생략 → 스키마 충돌로 롤백",
  "trace_ref": "sessions/2026-10-03-deploy.jsonl"
}
```

  에이전트 프롬프트에는 "insight가 서로 충돌하거나 실패 사례에서 나왔으면 trace_ref를 읽고 확인 후 행동" 규칙을 넣는다.
- 🎯 언제: CLAUDE.md·메모리 파일에 자동으로 교훈을 축적하는 장기 운영 에이전트. 특히 실패 경험에서 lesson을 뽑는 경우.
- ⚠️ 주의: 궤적 전문을 매번 읽게 하면 토큰이 폭발한다. 핵심은 "항상"이 아니라 **"의심스러울 때만"** 내려가는 조건부 설계다.
- ⭐ 추천도: 메모리 기능 운영 중이라면 이번 주에 스키마부터.
