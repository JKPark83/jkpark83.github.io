# 🔥 오늘의 핵심

Codex의 비동기 보안 리뷰어 **Guardian v2**의 정책·분류기 프롬프트 전문이 저장소에서 그대로 읽히고, Claude Code는 내장 플러그인 4종의 소스를 **mods/** 폴더로 공개하고 있습니다. 두 CLI 모두 "바이너리에 밀봉돼 있던 코어 계층"을 소스로 열어 둔 셈이라, 자체 에이전트에 보안 게이트나 훅 시스템을 넣으려는 개발자에게는 1차 교재가 생겼습니다. 오늘 해볼 것: 두 폴더를 클론해서 정책 문서와 훅 구조를 훑어보기.

# 📚 주목 논문

## AgentKernel: 에이전트 아래에 'OS'를 깔자 (arXiv:2609.29647)

- **저자**: Zhenhua Zou, Sheng Guo, Qiuyang Zhan, Zhuotao Liu 외 (총 6명, arXiv에 소속 미표기) · cs.CR (cs.AI 교차) · v1 8/29 제출, 최근 공개되어 HF Daily Papers 9/25자에 등재
- **핵심 기여**: 에이전트 보안을 앱 레벨 미들웨어(필터, 가드레일)로 덧대는 대신, 오케스트레이션 프레임워크·런타임·샌드박스 **아래**에 강제 집행 경계를 두자는 38쪽 분량의 설계 제안.
- **방법**: Identity(조직 간 신원) / Perception(단일 필터 대신 단계적 입력 필터링) / Cognition(메모리 오염 방지용 정보 흐름 제어) / Execution(도구 호출 전 의미 검증) 4개 축으로 커널 계층을 정의.
- 🛠 **시사점**: 아래 Guardian v2가 실제 제품에서 하는 일과 겹칩니다. "프롬프트에 부탁"이 아니라 "레이어에서 강제"로 가는 흐름을 설계 어휘로 정리해 둔 문서로 읽으면 유용.
- **한계**: 포지션 성격이 강해 초록 기준 정량 평가가 없음.
- [arXiv](https://arxiv.org/abs/2609.29647)

## Qwen-Planner-Agent: 에이전트 개발 루프 자체를 AI에게 (arXiv:2609.29892)

- **저자**: Tingyu Qu 외 (총 26명) · cs.AI · 9/24 제출 · 프로젝트 페이지는 Tongyi(알리바바) 계열
- **핵심 기여**: 모바일 플래너 에이전트를 대상으로, 태스크 구축·궤적 수집(데이터 생산) → 지도학습 + 하이브리드 RL(**CARE**: 역량 인지형 보상·어드밴티지 설계) → 실행 피드백 기반 모델·도구 공진화까지를 닫힌 루프로 돌리는 "AI-for-AI" 프레임워크.
- **결과**: MobilePA-Bench에서 베이스라인 대비 우위 보고(세부 수치는 본문 확인 필요), 비모바일 벤치마크 성능은 유지.
- 🛠 **시사점**: "에이전트가 실패한 지점에서 새 학습 태스크를 만들어내는" 실패 분석 루프는 학습 없이도 흉내 낼 수 있는 패턴 — 실패 궤적을 eval 케이스로 자동 적재하는 파이프라인부터.
- **한계**: 실기기 상호작용 비용이 커서 재현 장벽이 높음.
- [arXiv](https://arxiv.org/abs/2609.29892) · [프로젝트 페이지](https://tongyi-mai.github.io/Qwen-Planner-Agent/)

# 🛠 오픈소스 스포트라이트

| 레포 | 언어 | 라이선스 | 한 줄 요약 |
|---|---|---|---|
| [Recurse-Labs/recurse](https://github.com/Recurse-Labs/recurse) | Rust·TS | Apache-2.0 | 리버스 엔지니어링용 AI 네이티브 IDE |
| [Parcha-ai/agentrun](https://github.com/Parcha-ai/agentrun) | TypeScript | Apache-2.0 | 에이전트 위에 얹는 워크플로 DSL |

**Recurse** — "리버스 엔지니어링계의 Cursor"를 표방하는 Tauri 2 데스크톱 앱입니다. 순수 Rust 네이티브 분석 엔진(ELF/PE/Mach-O 파싱, 10여 개 아키텍처 디스어셈블리, 자체 디컴파일러)이 기본이고 radare2·IDA Pro를 백엔드로 갈아끼울 수 있습니다. 개발자 관점의 백미는 **recurse-mcp**: 동일한 분석 엔진을 stdio MCP 서버로 노출해 Claude Code나 Cursor가 바이너리 분석·xref·디컴파일을 도구로 호출할 수 있습니다. 함수 리네임·노트가 SQLite(FTS5 검색)에 남아 세션을 넘어 유지되는 "그라운디드 메모리" 설계도 참고할 만합니다. 어제(9/27)도 커밋이 이어질 만큼 활발하고, HN AI 다이제스트 9/26자에 언급됐습니다(스타 수는 이 세션의 API 제한으로 미확인). **활용처**: 악성코드 분석·CTF·바이너리 감사에 에이전트를 붙이려는 보안 개발자.

**AgentRun** — "이미 굴리고 있는 에이전트"에 반복 가능한 워크플로를 얹는 DSL입니다(9/26 `0.1.0-beta.5`). 검색·도구 호출은 `call` 노드로, 애매한 판단은 신뢰도가 보정된 판정 모델(Jev)을 쓰는 `judge` 노드로, 조사가 필요할 때만 에이전트를 호출하는 구조라서 "전부 에이전트에게"보다 비용과 분산이 줄어듭니다. Zod 스키마 계약, 병렬 map, 유한 루프, 에스컬레이션 경로까지 스펙에 포함. API 키 없이 `npx agentrun demo`로 스크립티드 데모가 돌아갑니다. **활용처**: 고객 지원·티켓 라우팅처럼 "대부분 정형 + 가끔 조사"인 업무의 에이전트화.

# 🧑‍💻 Codex & Claude Code 실전 팁

![Codex Guardian v2 비동기 보안 리뷰 루프](/images/ai-news-2026-09-28/guardian-v2-flow.svg)

*Guardian v2의 논블로킹 분류 → 블로킹 리뷰 승격 구조와 4대 위험 분류. (자체 제작, 출처: openai/codex 저장소 policy.md·classifier_instructions.md)*

**1. 🟩 Codex — Guardian v2 정책을 소스에서 읽고 조율하기**

- **카테고리**: Review / Debugging
- **출처**: [codex-rs/prompts/templates/guardian](https://github.com/openai/codex/tree/main/codex-rs/prompts/templates/guardian)
- 💡 **핵심**: Codex의 보안 리뷰어 Guardian이 v2로 진화하면서 정책 전문(`policy.md`)과 분류기 지침(`classifier_instructions.md`)이 저장소에 공개돼 있고, `config.toml`로 세부 조율이 가능합니다. 최근 커밋(9/26~27)으로 컴팩션 후에도 Guardian 히스토리가 독립 유지되고, 서킷브레이커 중단이 구조화 에러로 노출됩니다.
- 📝 **방법**:

```toml
[features.guardianv2]
enabled = true
review_threshold = 0.7          # 블로킹 리뷰 승격 임계값
persist_scores = true            # 리뷰된 액션·위험 점수를 롤아웃 파일로 (디버깅용)

[features.guardianv2.review_scope]
sandboxed_exec_commands = true   # 샌드박스 셸 명령까지 분류 대상에 포함

[features.guardianv2.transcript]
sources = ["tool_calls", "tool_outputs"]
```

- 🎯 **언제**: 자율성 높은 장시간 세션을 돌리는데 "어떤 액션이 왜 막혔는지" 추적이 필요할 때. `persist_scores`로 판정 로그를 남겨 두면 원인 분석이 쉬워집니다.
- ⚠️ **주의**: 필드 구성은 알파 채널에서 계속 바뀌는 중입니다(`thread_context`는 이미 deprecated). 클론한 소스의 `features/src/feature_configs.rs`가 가장 정확한 스키마입니다.
- ⭐ **추천도**: ★★★★☆

**2. 🟦 Claude Code — 내장 플러그인 'mods'를 예제로 쓰기**

- **카테고리**: Hook / Workflow
- **출처**: [anthropics/claude-code mods/](https://github.com/anthropics/claude-code/tree/main/mods)
- 💡 **핵심**: Claude Code에 내장돼 배포되는 플러그인 4종(sec-default, diff, telemetry, agents-md)의 소스가 `mods/` 폴더에 공개돼 있습니다. `register(on, options)` 진입점 하나로 엔진 이벤트를 `($, e, next)` 미들웨어처럼 후킹하는 구조라, 커스텀 플러그인을 만들 때 베낄 수 있는 공식 레퍼런스입니다. `agents-md` 모드는 `CLAUDE.md`가 없는 프로젝트에서 `AGENTS.md`를 프로젝트 지침으로 읽는 동작(기본값 `claude-md-or-agents-md`)의 구현체이기도 합니다.
- 📝 **방법**:

```bash
git clone --depth 1 https://github.com/anthropics/claude-code.git
claude --plugin-dir claude-code/mods/diff   # 소스에서 바로 실행
claude plugin test claude-code/mods/diff    # 모드 테스트 러너
```

- 🎯 **언제**: 훅 기반 플러그인을 처음 만들 때, 또는 `/diff` 패널·AGENTS.md 로딩이 정확히 어떻게 동작하는지 소스로 확인하고 싶을 때.
- ⚠️ **주의**: 테스트 API(`claude-code/testing`의 `tier`, mock)는 문서화가 얇아 `tests/` 폴더의 실제 코드를 함께 읽어야 합니다.
- ⭐ **추천도**: ★★★★☆

**3. 🟪 공통 — "판정 게이트 + 임계값 + 에스컬레이션" 패턴**

- **카테고리**: Eval / Workflow
- **출처**: [AgentRun support-answer 예제](https://github.com/Parcha-ai/agentrun/blob/main/examples/support-answer.mjs)
- 💡 **핵심**: 에이전트 출력을 그대로 내보내지 말고, ① 보정된 판정 호출로 yes/no/uncertain + 신뢰도를 받고 ② 임계값(예: 0.8) 미달이면 **딱 1회** 에이전트 재시도 ③ 그래도 미달이면 사람에게 에스컬레이션 — 하는 3단 게이트를 워크플로 레벨에 두는 패턴입니다. Guardian v2가 위험도에 쓰는 구조와 동형입니다.
- 📝 **방법**: 판정 스키마에 yes/no/uncertain 기준을 명시하고, 재시도 횟수와 임계값을 코드(설정)로 고정하세요. 프롬프트 안의 "신중하게 판단해"는 게이트가 아닙니다.
- 🎯 **언제**: 답변 품질 편차가 크고 오답 비용이 높은 고객 대면 에이전트.
- ⚠️ **주의**: 판정 모델의 신뢰도가 실제로 보정돼 있는지 라벨된 케이스로 먼저 검증할 것.
- ⭐ **추천도**: ★★★★★
