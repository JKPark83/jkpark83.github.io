# 🤖 모델 & 릴리즈 레이더

- **Claude Opus 5 (Anthropic, 7/24) — Fable 5급 성능을 절반 값에.** 가격 **입력 $5 / 출력 $25 per 1M**(Opus 4.8과 동일), Fable 5($10/$50)의 절반. **1M 컨텍스트**, `claude.ai`·API·Claude Code·Cowork에 즉시 배포되며 Claude Max 기본 모델이 됐다. SWE-bench Verified **최상위권(출처별 96~97%)**, Frontier-Bench·GDPval-AA에서 새 SOTA(사이버보안은 Mythos 5에 뒤짐). **Fast 모드**는 기본 대비 약 2.5배 속도에 2배 단가. → **에이전트 빌더 시사점**: 코딩·롱호라이즌 툴콜 루프의 **기본 모델 교체 1순위**. 같은 토큰 예산에서 성능이 올라가므로, 프런티어를 이유로 Fable/외부 모델에 붙여둔 워크로드를 다시 측정할 값어치가 크다. 출처: [venturebeat](https://venturebeat.com/orchestration/anthropic-launches-claude-opus-5-a-cheaper-ai-model-for-coding-agents-and-enterprise-workflows) · [morphllm 벤치](https://www.morphllm.com/claude-benchmarks)
- **Claude Code v2.1.219 (7/24) — Opus 5 기본화 + 중첩 서브에이전트 depth 3.** `claude-opus-5`가 새 기본 Opus(1M 컨텍스트, `/fast`는 Opus 5·4.8에 적용). **서브에이전트가 서브에이전트를 최대 depth 3까지** 스폰(기존 1), `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`로 차단. `sandbox.network.strictAllowlist`, `DirectoryAdded` 훅, MCP 실패 가시성 개선도 포함. → **시사점**: 다단계 분해가 필요한 작업을 한 세션에서 재귀적으로 위임할 수 있게 됐다 — 다만 깊이만큼 토큰·지연이 붙으니 상한을 정하고 써라. 출처: [code.claude.com/changelog](https://code.claude.com/docs/en/changelog)

# 📚 주목 논문

## 1) Agentic Context Management — 에이전트 실패는 '추론'이 아니라 '컨텍스트' 문제
- **저자**: Gaurav Dadhich (arXiv `2607.21503`, cs.AI, 2026-07-23)
- **핵심**: 프로덕션 에이전트는 추론력이 부족해서가 아니라 **컨텍스트 관리 실패**로 무너진다 — 누적되는 대화 이력, 비대한 프롬프트, 툴 정의, 팽창하는 툴 출력.
- **방법(요약)**: 컨텍스트를 **수명주기**로 취급 — 기억 여부 결정·추출·구조화·저장 선택·통합·(출처 보존하며) 망각·관련성 판단·미래 예측·compaction. 이를 **5개 프리미티브**(architecting / ingesting / scoping / anticipating / compacting & consolidation)로 분해한다.
- **결과(검증됨)**: 순진한 컨텍스트 누적은 **대화 길이에 대해 토큰 비용이 2차로** 증가하지만, 검증된 compaction은 **선형 비용에 충실도를 유지**. LongMemEval **92%**, LoCoMo **93.2%**(명시된 설정 하). 레퍼런스 구현은 멀티테넌트 서비스 `Maximem Synap`.
- **🛠 agent-builder 시사점**: 메모리를 "벡터DB 하나 붙이기"로 끝내지 말고, **넣고·좁히고·압축하는 수명주기 규율**로 다뤄라. 특히 롱세션 에이전트의 비용 폭발은 대개 여기서 온다.
- **한계**: 단일 저자·단일 레퍼런스 구현 중심 — 벤치 수치는 "명시된 설정" 조건부이니 자기 워크로드에서 재측정 필요.
- 링크: [arxiv.org/abs/2607.21503](https://arxiv.org/abs/2607.21503)

## 2) Euclid-MCP — MCP 서버로 '결정론적 논리 추론' 붙이기
- **저자**: Bartolomeo Bogliolo (arXiv `2607.21412`, cs.AI, 2026-07-23)
- **핵심**: LLM의 다단계 논리 추론 약점을 **뉴로-심볼릭**으로 보완. 오픈소스 MCP 서버가 **SWI-Prolog** 기반 결정론적 추론을 툴로 제공한다.
- **방법(요약)**: Horn-clause 논리를 위한 엔진-독립 중간표현 `Euclid-IR`(사람·LLM 가독)을 도입하고, **translate → run → inspect → repair** 사이클로 클라이언트에 증명 트레이스·유도 로그를 돌려준다.
- **결과(검증됨)**: IT 보안·컴플라이언스 과제에서 LLM-only 대비 **정확한 답·낮은 지연·간결한 출력**. 저자는 "semantic RAG는 규칙 강제에 근본적으로 부적합"하며 LLM은 큰 문제에서 "체계적으로 환각"한다고 지적.
- **🛠 agent-builder 시사점**: 정책·권한·컴플라이언스처럼 **규칙이 곧 정답**인 도메인은 RAG로 우기지 말고 **결정론적 추론 툴을 MCP로 꽂아라**. 증명 트레이스가 나오니 감사·디버깅에도 유리.
- **한계**: 규칙을 Horn-clause로 옮기는 모델링 비용이 든다 — 자유서술형·모호한 과제엔 부적합.
- 링크: [arxiv.org/abs/2607.21412](https://arxiv.org/abs/2607.21412)

**🟦 Claude Code · category: Subagent**
- 출처: [code.claude.com/docs/en/changelog](https://code.claude.com/docs/en/changelog) (v2.1.219)
- 💡 **핵심**: 서브에이전트가 다시 서브에이전트를 **기본 depth 3**까지 스폰한다(기존 1). 재귀적 분해가 한 세션에서 가능.
- 📝 **how-to**:
```bash
# 깊이 폭주가 걱정되면 상한을 1로 고정(중첩 차단)
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1
# 새 기본 모델은 claude-opus-5, /fast는 Opus 5·4.8에 적용
/model            # "Opus (1M context)" 확인
```
- 🎯 **언제**: "리서치→설계→구현→리뷰"처럼 단계가 뚜렷한 큰 작업을 한 번에 위임할 때.
- ⚠️ **주의**: 깊이만큼 토큰·지연·관측성 부담이 붙는다 — 깊게 열기 전에 로깅/상한부터.
- ⭐ **추천**: 기본 depth를 그대로 쓰되, 비용 민감 파이프라인은 `=1`로 명시 고정.

**🟩 Codex · category: Subagent**
- 출처: [developers.openai.com/codex/changelog](https://developers.openai.com/codex/changelog)
- 💡 **핵심**: Codex는 **반대로** 서브에이전트의 중첩 스폰을 **기본 차단**하고, 필요 시 `subagent_depth`로 올린다. 또 실행 중 서브에이전트를 **백그라운드로** 보낼 수 있다.
- 📝 **how-to**: 서브에이전트를 백그라운드로 보내고 메인 작업 계속 → 필요할 때만 `subagent_depth` 상향. 부모 에이전트가 이제 **터미널 서브에이전트 에러를 그대로 수신**(빈 성공 대신)하니, 실패를 조용히 삼키지 않는다.
- 🎯 **언제**: 비용·예측가능성을 우선하고, 깊은 자동 위임보다 사람이 깊이를 통제하고 싶을 때.
- ⚠️ **주의**: 기본이 얕으므로, 다단계 분해를 기대했다면 `subagent_depth`를 명시적으로 올려야 함.
- ⭐ **추천**: "기본 얕게 + 필요 시 상향"을 팀 규칙으로. Claude Code와 정반대 기본값이라 툴 전환 시 헷갈리지 않게 문서화.

**🟪 공통 · category: Context**
- 출처: [arxiv.org/abs/2607.21503](https://arxiv.org/abs/2607.21503) (Agentic Context Management)
- 💡 **핵심**: 롱세션 에이전트의 비용 폭발은 대개 **컨텍스트 누적**에서 온다 — 순진한 누적은 대화 길이에 대해 **토큰이 2차로** 증가한다.
- 📝 **how-to**: (1) 무엇을 기억할지 결정(architecting) → (2) 필요한 것만 넣기(ingesting) → (3) 관련 범위로 좁히기(scoping) → (4) 다음에 쓸 것 예측(anticipating) → (5) 주기적 **compaction & consolidation**으로 이력을 압축. 출처는 보존하되 원문을 통째로 끌고 다니지 말 것.
- 🎯 **언제**: 멀티턴·장시간 에이전트가 후반부에 느려지고 비용이 튈 때.
- ⚠️ **주의**: 과도한 망각은 정확도를 깎는다 — 압축 전후를 자기 워크로드에서 A/B로 검증(논문 수치는 조건부).
- ⭐ **추천**: 대화 이력에 "compaction 임계 길이"를 하나 정해 루프에 넣어라.
