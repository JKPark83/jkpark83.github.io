# 📚 주목 논문

## Option-Channel Attack: 가드레일 결정 모델은 문이 아니라 커튼이다

- **저자**: Seyedarmin Azizi, Erfan Baghaei Potraghloo, Massoud Pedram (USC)
- **arXiv**: [2610.12292](https://arxiv.org/abs/2610.12292) (cs.AI, 10/8 공개)
- **핵심 기여**: 에이전트 툴콜을 허용/차단하는 **타입드 결정 모델(텍스트를 읽고 호출자가 정의한 옵션에 확률만 매기는 모델)** 7종을 공격자 관점에서 체계 평가. 위험한 쪽으로 열리는 fail-open(취약점)과 안전한 쪽으로 닫히는 fail-closed(비용)를 분리해 측정했습니다.
- **방법**: 프롬프트 인젝션·탈옥·유해성 스크리닝으로 기본 성능을 재고, 합성 에이전트 툴콜 스위트에서 입력 교란·옵션 라벨 조작 공격을 수행.
- **결과**: 기본 스크리닝 정확도가 **36–72%**(찍기 50% 기준)로 이미 흔들립니다. 모델이 원래 맞게 처리하던 정책에서 **무관한 서버 로그 6줄을 끼워 넣자 fail-open이 0%에서 63%로**, 허용 옵션의 **라벨 이름만 오해되게 바꾸자 93–100%**(라벨을 입력에 쓰는 4개 모델)로 뛰었습니다. 테스트한 방어는 전부 우회됐고, 저신뢰 결정 에스컬레이션도 실패 — 뒤집힌 결정이 원래 결정만큼 자신만만했기 때문입니다.
- 🛠 **에이전트 빌더 시사점**: 정책 필드를 타입 있는 값으로 파싱하면 공격 하나는 막히는데, 그 값 위의 **결정적 규칙만으로 6개 정책 전부 100% 정확도**가 나왔습니다. 즉 규칙으로 환원되는 정책이라면 모델이 필요 없고, 환원 안 되는 정책이라면 모델을 최종 결정자로 두면 안 됩니다.
- **한계**: 오픈웨이트 모델 평가라 상용 API 결정 모델(Decision-1 등)에 그대로 적용된다는 보장은 없습니다. 다만 공격 채널(옵션 라벨·입력 텍스트) 자체는 구조적으로 동일합니다.

## OnTrack: 에이전트 궤적을 스텝당 1ms로 실시간 감시

- **저자**: Babak Barazandeh 외 4인 (소속은 초록 미표기)
- **arXiv**: [2610.12375](https://arxiv.org/abs/2610.12375) (cs.AI, 10/8 공개)
- **핵심 기여**: 가드 에이전트는 매 스텝 지연을 더하고(비싸고), 사후 로그 리뷰는 손해가 난 뒤에 옵니다(늦고). OnTrack은 **성공 레퍼런스 런과의 구조 인식 최적수송(OT) 거리를 스트리밍으로 계산**해, 스텝당 약 1ms로 이탈 궤적을 경고·차단합니다.
- **방법**: 과거 성공 런·툴 스키마·스텝 로그라는 3단계 접근 수준별로 탐지 능력을 측정. 접근이 줄면 계획 위반 탐지에서 루프·정체·반복 호출 탐지로 능력이 줄어듭니다.
- **결과**: SWE-bench에서 **첫 8스텝만으로** 실패 궤적 랭킹이 콘텐츠 유사도 대비 AUROC +0.057. 이탈 궤적 중단 정책으로 **실패 런이 소모할 연산의 약 18% 절약**, 중단된 런의 83%가 실제로 실패로 가던 중이었습니다.
- 🛠 **에이전트 빌더 시사점**: 대량 배치로 에이전트를 돌린다면 '끝까지 돌리고 채점'이 아니라 **초반 몇 스텝에서 가망 없는 런을 쳐내는** 레이어가 연산비를 직접 줄여 줍니다. 성공 런 아카이브가 곧 자산이 됩니다.
- **한계**: 레퍼런스 런이 없는 새 과제 유형에는 탐지력이 루프·정체 수준으로 제한됩니다.

# 🛠 오픈소스 스포트라이트

- **[addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)** (Markdown/Skills, MIT) — Chrome 팀의 Addy Osmani가 만든 **개발 수명주기 전체(스펙→계획→빌드→테스트→리뷰→배포)를 덮는 프로덕션 지향 스킬·플러그인 세트**입니다. `/spec`, `/plan`, `/build`, `/ship` 등 9개 슬래시 커맨드가 단계별 스킬을 자동 활성화하고, `/build auto`는 계획 승인 한 번으로 태스크 전체를 테스트 주도 방식으로 자동 구현합니다. 10/10 당일 커밋까지 활발히 머지 중(클론 확인), 스타는 제3자 집계 약 10만+(미검증). **활용**: 어제 다룬 '스킬 공급망' 논문의 교훈대로, 복사 대신 **플러그인으로 설치해 버전 추적**이 되는 드문 스킬 세트라는 점이 포인트.
- **[Danau5tin/ai-trains-ai](https://github.com/Danau5tin/ai-trains-ai)** (Python, MIT) — "RL로, RL 훈련 잡을 짜는 에이전트를 훈련한다." 에이전트가 과제를 받아 **prime-rl 훈련 잡(환경·리워드·데이터셋·하이퍼파라미터)을 작성**해 실제 GPU에 제출하고, 그 결과로 작아진 모델의 히든 평가 상승분이 에이전트의 리워드가 되는 이중 RL 루프입니다. 총비용 약 $1.3K로 리워드 0.0→0.63(54스텝), 미학습 과제군으로 전이까지 보고(저자 보고). 7월 공개 프로젝트인데 지금 Hacker News 프런트페이지에 올라 재조명 중입니다(클론 확인, 가중치·리워드 코드·실패 회고까지 전부 공개). **활용**: 에이전트에게 '훈련 파이프라인 작성'을 시키는 설계의 레퍼런스. 회고 문서만 읽어도 값집니다.

**🟩 Codex — retain 마킹한 도구 출력, 컴팩션에서도 살리기** (Context)

- 출처: [openai/codex #52937 커밋](https://github.com/openai/codex/commit/6c0c6759d0617d7670826b61aca0a931bbb6db1f) (10/10 머지, 클론 확인)
- 💡 Codex를 앱 백엔드로 쓸 때 클라이언트가 주입하는 도구 출력(태스크 지시문 포함)이 컴팩션 전에 잘려 사라지는 문제가 있었습니다. 새 `retain_client_tool_outputs` 기능을 켜면 **`retain: true`로 마킹된 출력이 컴팩션과 새 컨텍스트 윈도 전환에서 역할 그대로 보존**됩니다.
- 📝 config.toml에서:

```toml
[features]
retain_client_tool_outputs = true
```

클라이언트 쪽에서는 보존할 `function_call_output` 아이템에 `retain: true`를 마킹하면 됩니다(`call_id` 없는 명명 출력 대상).

- 🎯 Codex 위에 자체 앱을 얹고, 긴 세션에서 클라이언트 주입 지시문이 증발하는 경우.
- ⚠️ 기본 꺼짐. 기존 64K 토큰 유지 예산을 공유하며, 예산 초과 시 출력을 자르지 않고 통째로 드롭합니다. 과하게 마킹하면 다른 보존 대상이 밀려납니다.
- ⭐ 추천도: Codex 임베딩 사용자에겐 필수 점검 항목.

**🟦 Claude Code — 공식 settings 베이스라인에서 시작하기** (Workflow)

- 출처: [anthropics/claude-code examples/settings](https://github.com/anthropics/claude-code/tree/main/examples/settings) (이번 주 HIPAA 세트 추가, 클론 확인)
- 💡 리포지토리에 **공식 설정 예제 모음**이 있습니다: `settings-lax.json`(마켓플레이스 차단 수준), `settings-strict.json`(웹 도구 차단 + Bash 승인 필수), `settings-bash-sandbox.json`(Bash 샌드박스 강제). 이번 주 샌드박스·네트워크 허용목록·로컬 보존 기간까지 묶은 HIPAA 세트가 추가됐습니다.
- 📝 무인으로 도는 에이전트 세션이라면:

```bash
curl -O https://raw.githubusercontent.com/anthropics/claude-code/main/examples/settings/settings-bash-sandbox.json
# 내용 검토 후 managed-settings.json 또는 settings.json에 병합
```

`sandbox.network.allowedDomains`를 자기 Git 호스트·패키지 레지스트리로 채우는 게 첫 커스터마이즈 포인트입니다.

- 🎯 개인 노트북 기본값 그대로 CI·cron에서 에이전트를 돌리고 있을 때.
- ⚠️ README가 명시하듯 community-maintained 스니펫이라 자기 환경 검증은 본인 몫입니다. `sandbox`는 Bash 도구에만 적용되고 Read/Write/MCP에는 적용되지 않습니다.
- ⭐ 추천도: 빈 파일에서 시작하는 것보다 항상 낫습니다.

**🟪 공통 — 결정 모델은 신호, 결정은 규칙으로** (Review/Eval)

- 출처: [Option-Channel Attack, arXiv 2610.12292](https://arxiv.org/abs/2610.12292)
- 💡 위 논문의 결론: 가드레일 자리의 결정 모델은 옵션 라벨과 입력 텍스트라는 공격 채널을 그대로 노출합니다. **허용/차단의 최종 결정은 타입 필드 위의 결정적 규칙**이 내리고, 모델 출력은 로깅·에스컬레이션 신호로만 쓰세요.
- 📝 지금 바로 할 수 있는 점검: 내 가드레일 평가 세트에 (1) 무관한 로그 텍스트를 끼운 변형, (2) 옵션 라벨 이름을 바꾼 변형을 추가해 fail-open 비율을 재 보세요. 신뢰도 기반 에스컬레이션은 이 공격에 방어가 안 된다는 것도 논문의 실측입니다.
- 🎯 툴콜 허용/차단, 수신 메시지 필터링에 LLM 저지를 쓰는 모든 곳.
- ⚠️ 규칙으로 환원이 안 되는 정책 영역은 남습니다. 그 영역은 모델 판단 + 사람 리뷰 큐로 이원화하는 게 현실적입니다.
- ⭐ 추천도: 가드레일을 운영 중이라면 오늘 평가부터.
