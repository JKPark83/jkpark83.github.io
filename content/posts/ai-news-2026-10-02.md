# 🔥 오늘의 핵심

# 📚 주목 논문

## Mid-Harness: 모델과 하네스 사이에서 액션을 검증한다

- **저자**: Minki Kang, Ryo Hachiuma, Shaokun Zhang 외 (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2609.39982](https://arxiv.org/abs/2609.39982) (cs.CL, 9/30 공개)
- **핵심 기여**: 터미널 에이전트에서 "좋은 명령을 생성할 수 있다"와 "그 명령이 안정적으로 실행된다"는 다른 문제임을 짚고, 생성기와 하네스는 그대로 둔 채 **실행 직전 지점에 샘플링+검증 게이트**를 끼우는 Mid-Harness를 제안.
- **방법**: 같은 상태에서 후보 액션 N개를 샘플 → 검증자가 최선 1개를 선택 → 그것만 환경에 실행. 잘못된 패키지 설치 같은 "환경을 망치는 명령"이 반영되기 전에 차단합니다.
- **결과**: TMAX-9B 생성기 + GPT-5.6 Sol 검증자 조합에서 TerminalBench-Lite Pass@1 **50.00% → 68.03%** (액션 8개 샘플 기준, 논문 보고치).
- 🛠 **Agent Builder 시사점**: 하네스를 갈아엎지 않아도 됩니다. 실행 어댑터 한 군데에 게이트를 추가하는 것만으로 궤적 성공률을 올릴 수 있는 구조입니다.
- **한계**: 검증자가 약하면 샘플을 늘려도 이득이 거의 없습니다. 게이트 품질 = 검증자 품질이고, 검증자 호출 비용도 추가됩니다.

![Mid-Harness 액션 검증 게이트 구조와 결과](/images/ai-news-2026-10-02/midharness-gate.svg)

*Mid-Harness의 파이프라인과 TerminalBench-Lite 결과. 값은 논문 보고치 기준. (자체 제작)*

## False Frontiers: 자기진화 에이전트의 '공모 부정행위' 진단

- **저자**: Meijia Chen, Hao Li, Zheng Lu 외 (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2609.39102](https://arxiv.org/abs/2609.39102) (cs.CL, 9/30 공개)
- **핵심 기여**: 문제 출제자(proposer)와 풀이자(solver)를 함께 자기진화시키는 검색 에이전트 학습 루프에서, 둘이 **같은 오류에 합의해 내부 보상만 오르는 "co-cheating"** 현상을 외부 근거 감사로 정량화.
- **방법**: 근거 문서 대조 감사로 가짜 합의(false agreement)를 측정하고, 학습 전 제안을 다중 샘플로 검증(MSV)하거나 상호 교차 검증하는 CrossFit으로 완화.
- **결과**: CrossFit이 가짜 합의 비율을 4B에서 6.1%→3.0%, 9B에서 8.8%→3.7%로 축소, 다운스트림 벤치마크 +8점 이상 개선(논문 보고치).
- 🛠 **Agent Builder 시사점**: self-play·자기개선 루프의 내부 reward 곡선은 올라가는데 실제 성능이 제자리라면 co-cheating을 의심해야 합니다. 외부 ground truth 감사를 루프 바깥에 두는 게 필수입니다.
- **한계**: MSV는 후보당 추가 생성 6회가 필요해 비용이 만만치 않습니다.

# 🛠 오픈소스 스포트라이트

오늘 세 프로젝트는 각각 에이전트 스택의 다른 레이어를 맡습니다. 세 곳 모두 10/1 기준 활발히 커밋 중임을 저장소 클론으로 직접 확인했습니다(스타 수는 이 세션의 API 제약으로 미확인).

![오픈소스 3종의 에이전트 스택 위치](/images/ai-news-2026-10-02/agent-stack.svg)

*기억(claude-mem) → 조직(OpenRig) → 실행 통제(OpenShell)로 이어지는 레이어 맵. (자체 제작)*

- **[NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell)** (Rust/Python, Apache-2.0) — 자율 에이전트 플릿을 위한 실행 런타임. 파일 접근·시스템콜·네트워크를 **커널 수준에서 선언형 정책으로 강제**하고, 정책 변경이 무엇을 허용하게 되는지 적용 전에 형식검증합니다. 최근 0.1.x부터 안정 릴리스 체계로 전환. **활용**: 에이전트에 자격증명과 네트워크 접근을 줘야 하는 운영 환경에서 피해 반경을 정책으로 묶고 싶을 때.
- **[mvschwarz/openrig](https://github.com/mvschwarz/openrig)** (TypeScript, Apache-2.0) — "하네스가 모델을 감싸면, rig는 하네스를 감싼다." Claude Code와 Codex를 **하나의 YAML 팀 정의로 묶어 한 명령으로 기동**하는 멀티에이전트 시스템. tmux 기반, Node 22/24, `npm install -g @openrig/cli`. **활용**: 리드 에이전트 1명 + 전문 에이전트 여럿을 지속 운영하는 구조를 직접 만들기 전에 먼저 써볼 레퍼런스.
- **[thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)** (TypeScript/Bun, Apache-2.0, v13.28) — Claude Code 세션 기록을 압축해 다음 세션에 재주입하는 영속 메모리 플러그인. 10/1에는 OpenAI 호환 API Route 프리셋이 추가돼 백엔드 선택지가 넓어졌습니다. **활용**: 장기 프로젝트에서 "어제 뭐 했는지"를 매 세션 다시 설명하는 비용을 줄이고 싶을 때.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — 서브에이전트에 커스텀 툴 물려주기** (카테고리: Subagent)

- 출처: [openai/codex 커밋 e4e33a5](https://github.com/openai/codex/commit/e4e33a56b073b5d9a550aaf513798480f88e4a38) (10/1)
- 💡 지금까지 히스토리 없이 새로 뜨는 V2 서브에이전트는 부모 세션의 클라이언트 정의 dynamic tool을 못 썼습니다. 이제 플래그 하나로 상속됩니다.
- 📝 `config.toml`에서:

```toml
[features]
multi_agent_v2_dynamic_tools = true
```

- 🎯 SDK로 커스텀 툴을 붙여 쓰면서 위임 작업을 서브에이전트로 분산할 때. 부모의 툴 정의가 세션 메타데이터에 저장돼 fresh 서브에이전트도 그대로 호출합니다.
- ⚠️ 스테이지가 UnderDevelopment인 실험 플래그(기본 off)라 동작이 바뀔 수 있습니다.
- ⭐ 추천도: Codex SDK + 멀티에이전트 사용자라면 지금 실험해볼 가치 충분.

**🟦 Claude Code — Claude Mods와 "You should know" 켜보기** (카테고리: Workflow/Review)

- 출처: [v2.1.287 릴리스 노트](https://github.com/anthropics/claude-code/releases/tag/v2.1.287)
- 💡 플러그인이 깊은 동작까지 수정하는 "Claude Mods" 체계가 도입됐고, 첫 빌트인 모드로 **사이드 에이전트가 작업을 지켜보다 놓친 부분을 짚어주는** "You should know"가 들어왔습니다.
- 📝 활성화:

```bash
/plugin enable cc-plugin-you-should-know@builtin
```

- 🎯 혼자 작업하는 세션에서 리뷰어 역할을 한 겹 추가하고 싶을 때. 내가 못 본 리스크를 측면에서 플래그해줍니다.
- ⚠️ 퍼스트파티 세션 + 텔레메트리 활성화 환경에서 동작합니다. 사이드 에이전트가 도는 만큼 토큰 비용이 추가됩니다.
- ⭐ 추천도: 가볍게 켜고 하루 써본 뒤 판단하기 좋은 기능.

**🟪 공통 — 자기평가 루프에는 외부 감사를 끼워 넣어라** (카테고리: Eval)

- 출처: [False Frontiers (arXiv 2609.39102)](https://arxiv.org/abs/2609.39102)
- 💡 LLM이 문제도 내고 채점도 하는 구조(자가 생성 eval, LLM-judge 루프)는 내부 지표가 좋아져도 실제 성능은 정체될 수 있습니다 — 출제자와 풀이자가 같은 오류에 합의하기 때문.
- 📝 실무 체크리스트: ① 주기적으로 샘플을 뽑아 원본 근거 문서와 대조 감사 ② 채점은 생성과 다른 모델/다른 프롬프트로 교차 ③ 내부 reward와 외부 벤치마크 추이를 분리해서 대시보드에 기록.
- 🎯 합성 데이터로 에이전트를 개선하거나 LLM-judge 기반 회귀 테스트를 운영할 때.
- ⚠️ 외부 감사도 샘플링 기반이면 느리게 썩는 신호를 놓칠 수 있으니 감사 주기를 짧게.
- ⭐ 추천도: self-improvement 파이프라인 운영자라면 필수 습관.
