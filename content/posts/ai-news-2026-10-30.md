# 🔥 오늘의 핵심

GitHub Universe 2026(10/28~29)에서 에이전트 인프라가 한꺼번에 GA로 풀렸다. **Copilot Fusion**(모델 대신 effort를 고르는 라우팅)과 **Agentic Workflows**(마크다운으로 정의하는 Actions 에이전트)가 핵심. 오늘 해볼 것: `gh aw`로 이슈 트리아지 워크플로 하나 올려보고, safe-outputs 권한 분리 패턴을 자기 파이프라인에 훔쳐오기.

# 🤖 모델 & 릴리즈 레이더

- **Google DeepMind Genie 4 (10/27, 리서치 프리뷰)** — 실시간 인터랙티브 월드 모델. 네이티브 오디오(환경음·대사) 생성, 장면 일관성 약 2분(Genie 3의 2배), 자연어로 카메라·날씨·캐릭터를 실시간 조종. 에이전트 빌더에게 의미 있는 건 배포 경로다: **Gemini API·AI Studio 얼리 액세스 파트너**에게 열린다고 명시해, 컴퓨터 사용·로보틱스 에이전트의 합성 학습·평가 환경으로 쓸 길이 생겼다. 가격·일정은 미공개. [DeepMind 블로그](https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/) · [TechCrunch](https://techcrunch.com/2026/10/27/googles-genie-4-world-model-adds-audio-more-realistic-worlds-and-real-time-steering/)
- **Copilot Fusion GA (10/28, Universe)** — 9월에 "HydraFusion"으로 다뤘던 그 모델 라우팅이 전 플랜 GA가 됐다. 모델명 대신 **Standard/High/Max effort**를 고르면 Cascade(저렴한 모델 먼저 → 품질 게이트 통과 못 하면 상위 모델)나 Critique(초안 → 타 모델 리뷰 → 수정)로 알아서 조합한다. 자체 보고 기준 AA Coding Agent Index 60으로 Claude Code+Opus 5.5 Max와 2점 차, 태스크당 평균 API 비용은 절반. Fusion 자체 요금은 없고 사용 모델 요금만 과금, 11/30까지 모델 비용 30% 할인. [VentureBeat](https://venturebeat.com/orchestration/github-copilot-fusion-mixes-models-to-achieve-near-opus-5-5-coding-performance-at-half-the-per-task-cost)
- **Copilot 클라우드 세션 영속화 (10/28)** — 클라우드 에이전트 세션이 GitHub 인프라에서 돌아가므로 노트북을 덮어도 계속 실행되고, 같은 세션을 VS Code·웹·모바일·CLI 어디서든 이어받는다. Copilot Projects(멀티 레포 병렬 세션)는 퍼블릭 프리뷰. [GitHub Changelog](https://github.blog/changelog/2026-10-28-github-copilot-in-vs-code-universe-releases/)

# 📚 주목 논문

**1. RealCLI: 인간-에이전트 협업까지 재는 CLI 벤치마크** — [arXiv 2610.22507](https://arxiv.org/abs/2610.22507) (cs.CL, 10/15 제출, HF 데일리 10/29 등재)

- 저자: Yunqi Liu, Peiyu Wang 외 24인 (소속은 arXiv 피드에 미표기)
- 기여: 같은 태스크를 두 모드로 짝지어 평가 — **EXEC**(완전한 명세를 처음에 다 줌) vs **COLLAB**(스크립트화된 가상 사용자가 정보를 점진 제공하고, 중간에 정정·제약 변경·승인 결정을 끼워 넣음). 협업 품질을 5개 차원, 22개 세부 차원, 51개 시나리오 템플릿으로 계측
- 결과: 프런티어 에이전트 최고 구성도 평균 49.2%, 협업 통합 점수(J_collab)는 최고 37.6%. **태스크를 잘 푸는 능력과 협업 품질이 뚜렷이 갈라진다** — 조종 가능성(steerability), 신뢰 보정, 안전 경계 관리에서 일관되게 약함
- 🛠 시사점: 내 에이전트 eval이 "완성된 프롬프트 → 결과 채점"만 한다면 실사용의 절반만 재는 것. 아래 공통 팁 참고
- 한계: 가상 사용자가 스크립트 기반이라 실제 사용자의 비일관성까지는 못 담음

**2. TAO: 툴 호출까지 보고 스케줄링하는 에이전트 서빙** — [arXiv 2610.37230](https://arxiv.org/abs/2610.37230) (cs.DC, 10/27 제출)

- 저자: Shuhuai Li, Shengdong Ye, Dongdong Ge, Yinyu Ye, Jianghao Lin
- 기여: 에이전트 서빙은 GPU 추론과 CPU 툴 실행이 교대로 일어나는데, 기존 서빙은 **툴이 언제 돌아올지**를 무시하고 GPU 자리를 배정한다. TAO는 툴 리턴 임박도 + 노드별 캐시 크레딧(시간 감쇠) + 토큰 풋프린트를 묶은 가치 함수로 admission과 배치를 동적 프로그래밍으로 함께 결정
- 결과: 12개 모델-워크로드-동시성 설정에서 최고 베이스라인 대비 지연 최대 -26.8%, TTFT 최대 -36.3%, 디코드 처리량 최대 +29.5%
- 🛠 시사점: 자체 GPU로 에이전트를 서빙하는 팀이라면 "툴 대기 중 세션이 KV 캐시를 점유"하는 문제의 해법 설계도로 읽을 만하다
- 한계: 코드 링크 아직 없음, 논문 보고치

# 🛠 오픈소스 스포트라이트

둘 다 클론으로 활동 검증(스타 수는 세션 API 제한으로 미확인).

- **[github/gh-aw](https://github.com/github/gh-aw)** (Go, MIT, v0.89.22) — GitHub Agentic Workflows의 CLI 확장. 마크다운 + YAML frontmatter로 에이전트 워크플로를 쓰면 표준 Actions 워크플로로 컴파일된다. 10/28 [GA 선언](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available). 엔진으로 Copilot·Claude Code·Codex·Gemini·Pi를 지원하고, 에이전트 잡은 기본 읽기 전용·샌드박스, GitHub 쓰기는 별도 **safe-outputs 잡**이 검증 후 스코프 제한 권한으로 적용. 이슈 트리아지, CI 실패 조사, 문서 유지보수 같은 "판단이 필요한 반복 작업"을 레포에 상주시키는 용도. 참고: 0.83.3~0.85.4 버전은 보안 취약점으로 회수됐으니 최신으로 설치할 것
- **[ruvnet/metaharness](https://github.com/ruvnet/metaharness)** (Rust + TypeScript, MIT, v0.4.19) — "에이전트 프레임워크가 아니라 **프레임워크 공장**". `npx metaharness`에 레포 URL을 주면 그 레포 전용 CLI, 로컬 MCP 서버, 레포 구조에서 생성한 스킬, 프로젝트 스코프 메모리, 거버넌스 정책을 묶은 하네스를 npm 패키지로 찍어낸다. 산출물은 Claude Code·Codex 등에 바로 장착. Universe 시기에 맞춰 발표됐고 커밋은 10/27까지 활발. 단, "2,254개 테스트 통과" 등은 자체 주장이고 문서의 과장 톤은 감안하고 볼 것

![gh-aw 보안 모델 파이프라인](/images/ai-news-2026-10-30/gh-aw-pipeline.svg)

*Agent Builder 시사점: 추론과 쓰기의 권한 분리. 에이전트는 쓰기 요청을 버퍼에 쌓기만 하고, 검증·적용은 권한이 분리된 별도 단계가 맡는다.*

# 🧑‍💻 Codex & Claude Code 실전 팁

**1. 🟩 Codex / Review·Workflow** — [커밋 #58045](https://github.com/openai/codex/commit/9cc14e79882ff8885cd5d33b4adadae014045aef) (10/29)

- 💡 관리 정책(managed `requirements.toml`)의 명령 prefix 룰에 `decision = "prompt-user"`가 생겼다. 매칭되는 명령은 **자동 리뷰·훅 허용·저장된 승인을 전부 무시하고** 매번 새로 사람의 1회성 결정(accept/decline/cancel)을 요구한다.
- 📝 조직 관리 설정에서:

```toml
[[rules]]
prefix = ["kubectl", "delete"]
decision = "prompt-user"
```

- 🎯 "자동화는 풀되 프로덕션 파괴 명령만은 반드시 사람 손을 거치게" 하고 싶은 팀. 에이전트에게 광범위 권한을 준 뒤 특정 명령만 체크포인트로 묶는 설계
- ⚠️ 클라이언트가 `requiredHumanApproval` 능력을 광고해야 동작하고(TUI는 지원), 받을 수 있는 클라이언트가 없으면 해당 명령은 거부된다
- ⭐ 추천도: 조직 단위 Codex 운영 팀이면 즉시 검토

**2. 🟦 Claude Code / Hook** — [v2.1.312 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.312) (10/27)

- 💡 프롬프트·에이전트 훅의 동시 실행이 세션당 **최대 24개**(서브에이전트 포함) + 이벤트 타임아웃을 넘긴 것 **12개까지**로 제한됐다. 1초 미만 `timeout`은 1초로 올림.
- 📝 훅을 많이 깐 세션(플러그인 다수 + 서브에이전트 팬아웃)이라면: (1) `/hooks`로 등록된 훅 개수를 세어 보고 (2) 오래 걸리는 훅에 명시적 `timeout`을 달고 (3) 서브에이전트가 상속할 필요 없는 훅은 스코프를 좁힐 것. 상한에 걸리면 훅이 큐잉되면서 눈에 안 보이는 지연이 생긴다.
- 🎯 SubagentStop·PostToolUse 훅을 로깅·알림용으로 대량 운용하는 setup
- ⚠️ 상한은 조정 옵션이 없다 — 훅 수 자체를 줄이는 게 답
- ⭐ 추천도: 훅 10개 이상 깔린 환경이면 오늘 점검

**3. 🟪 공통 / Eval** — [arXiv 2610.22507](https://arxiv.org/abs/2610.22507)

- 💡 RealCLI의 설계를 내 eval에 이식: **태스크 성공률과 협업 품질을 별도 축으로** 재라. 완성된 명세만 주는 eval은 실사용(중간 정정, 제약 변경, 승인 요청)을 전혀 커버하지 못한다.
- 📝 최소 버전: 기존 eval 태스크 몇 개를 골라 (1) 명세의 절반만 주고 나머지는 스크립트화된 가상 사용자가 2~3턴에 걸쳐 제공 (2) 중간에 한 번 요구사항을 뒤집고 (3) 위험한 행동 직전에 승인을 요구하게 만든 변형을 추가. 두 점수의 격차를 추적
- 🎯 장기 실행 에이전트, 특히 사용자 개입이 잦은 CLI·코딩 에이전트
- ⚠️ 가상 사용자 스크립트 품질이 낮으면 노이즈만 는다 — 시나리오 템플릿을 소수 정예로
- ⭐ 추천도: eval 파이프라인이 이미 있는 팀이라면 가성비 높은 확장
