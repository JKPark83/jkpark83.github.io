1. 도입 — 다들 직접 짜던 그 코드가 API가 됐다

에이전트를 하나라도 프로덕션에 올려 본 사람은 압니다. 모델 호출은 쉽고, 그 주변이 어렵습니다. 컨텍스트가 한도에 닿기 전에 요약해 넣는 컴팩션 코드, 몇 시간짜리 작업이 중간에 죽었을 때 이어 가는 복구 코드, 큰 일을 쪼개 서브에이전트에 나눠 주는 오케스트레이션 코드, 그리고 에이전트가 명령을 실행할 샌드박스 배선까지. 이 주변 시스템을 하네스(harness)라고 부르는데, 지난주까지는 전부 각자 짜서 각자 유지보수하는 물건이었습니다.

9월 10일, OpenAI가 이 판을 흔들었습니다. Codex와 ChatGPT를 굴리던 자사 관리형 하네스를 Agents API 퍼블릭 베타로 공개한 겁니다. 세션 유지, 컨텍스트 컴팩션, 병렬 툴 실행, 서브에이전트 위임, 크래시 복구 — 직접 짜던 코드가 API 호출 하나 뒤로 들어갔습니다. 발표 직후 Hacker News 스레드에 댓글 178개가 달리며 "드디어"와 "또 속을 순 없다"가 정면으로 부딪혔고, 이번 주 에이전트 엔지니어링 최대 talking point가 됐습니다.

중요한 건 이게 OpenAI 혼자만의 방향이 아니라는 점입니다. Anthropic은 이미 4월에 같은 모양의 Claude Managed Agents를 내놨습니다. 두 회사가 각자의 코딩 에이전트를 굴리며 다듬은 하네스를 상품으로 파는 것 — 업계에서는 이 흐름을 하네스의 상품화(commoditization)라고 부르기 시작했습니다. 이 글에서는 Agents API를 해부해 보고, "사서 쓸 것인가, 계속 만들 것인가"를 판단할 기준까지 정리합니다.

2. 배경 — 하네스에서 가장 아픈 세 조각

하네스가 무엇인지는 6월의 하네스 엔지니어링 편에서 기초부터 다뤘으니, 여기서는 이번 발표를 이해하는 데 필요한 부분만 짚습니다. 직접 하네스를 운영해 본 팀들이 공통으로 아파하는 조각은 대략 셋입니다.

  • 컨텍스트 컴팩션(compaction) — 몇 시간짜리 작업이면 대화 이력이 컨텍스트 한도를 넘습니다. 언제, 무엇을, 어떻게 요약해 넣을지 정하는 코드는 짜기도 어렵고, 잘못 짜면 에이전트가 방금 한 일을 잊습니다. 컴팩션 편에서 다뤘듯 정답이 없는 트레이드오프 덩어리입니다.
  • 장기 세션의 저장과 복구 — 프로세스가 재시작되면 에이전트의 "지금까지의 상태"는 어디에 있어야 할까요? 대화 이력, 작업 중이던 파일, 진행 상황을 내구성 있게 저장하고 이어 가는 코드는 사실상 작은 분산 시스템입니다.
  • 서브에이전트 오케스트레이션 — 큰 작업을 쪼개 병렬로 위임하고, 결과를 모으고, 실패한 가지만 다시 돌리는 로직. 멀티에이전트 편에서 봤듯 여기서부터는 프레임워크 없이는 버겁습니다.

Codex 같은 상용 코딩 에이전트가 잘 도는 이유의 절반은 모델이 아니라 이 하네스가 잘 만들어져 있기 때문이라는 게 업계의 중론이었습니다. 그 하네스가 이제 분리되어 팔리기 시작한 겁니다.

3. Agents API 해부 — 프리미티브 4개와 하네스가 대신 해 주는 일

공식 문서 기준으로 Agents API는 프리미티브 4개로 조립됩니다.

프리미티브무엇인가
Agent모델 + instructions + 툴 + MCP 서버. "이 에이전트가 무엇을 할 수 있는가"의 선언
Environment에이전트가 파일을 만지고 명령을 실행할 샌드박스(선택 사항). 어디서 실행할지 고른다
Session에이전트의 내구성 있는(durable) 실행 인스턴스. 턴을 넘어 상태가 유지된다
Events · Items세션에 넣는 입력과, 세션이 뿜는 출력 스트림(툴 호출, 진행 상황, 결과물)

코드로 보면 감이 빠릅니다. 세션을 만들면서 에이전트 정의와 실행 환경을 넘기고, 이벤트 스트림을 받아 읽는 게 전부입니다.

{{< highlight python >}} from openai import OpenAI with OpenAI() as client: with client.beta.agents.sessions.create( agent={ "model": "gpt-6-astra", "instructions": "코드를 깔끔하게 쓰고, 실행해 보고, 실제 출력을 보고해라.", }, environment={"type": "openai_hosted"}, # 샌드박스는 OpenAI가 띄운다 input="tree.py를 만들어서 디렉터리 트리를 출력하게 해줘", stream=True, ) as events: for event in events: # 툴 호출·진행 상황·결과가 이벤트로 흘러온다 print(event.to_json(indent=None), flush=True) {{< /highlight >}}

겉보기엔 평범한 API인데, 핵심은 이 session 뒤에서 하네스가 대신 해 주는 일들입니다.

  • 자동 컨텍스트 컴팩션 — 세션이 컨텍스트 한도에 다가가면 이전 이력을 알아서 요약·압축합니다. 애플리케이션 쪽에서 상태 관리 코드를 짤 필요가 없습니다.
  • tool search — 툴 수십 개를 전부 컨텍스트에 넣는 대신, 필요할 때 관련 툴 정의만 로드합니다. 토큰과 프롬프트 캐시를 아끼는, 툴 검색 편에서 다룬 바로 그 패턴이 기본값이 된 겁니다.
  • 서브에이전트 병렬 위임 — 복잡한 작업을 독립 조각으로 쪼개, 각자 컨텍스트를 가진 서브에이전트들에 나눠 돌립니다.
  • 내구성과 복구 — 세션 상태가 OpenAI 인프라에 durable하게 저장됩니다. 수 시간~수 일짜리 작업을 이어 가고, 끊긴 지점에서 재개합니다.

한 줄로 요약하면 이렇습니다. "모델을 파는 API"에서 "에이전트 런타임을 파는 API"로. 발표를 분석한 한 글의 제목처럼, "개발자들이 만들기 싫어하던 오케스트레이션 레이어"가 통째로 상품이 된 셈입니다.

4. 실행 환경 스펙트럼 — 호스팅, 파트너 샌드박스, 셀프호스트

하네스는 OpenAI가 관리하지만, 에이전트가 실제로 파일을 만지고 명령을 실행하는 곳은 세 갈래 중에서 고를 수 있습니다.

첫째, OpenAI 호스팅 샌드박스. 위 코드의 {"type": "openai_hosted"}가 이겁니다. 제일 편하지만 컨테이너 요금이 붙습니다(다음 절). 둘째, 파트너 샌드박스. 발표와 함께 Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop, Vercel — 9개 파트너 연동이 공개됐습니다. 하네스는 OpenAI, 실행 환경은 이미 쓰던 클라우드에 두는 조합입니다. 셋째, 자체 인프라(셀프호스트). 규제나 데이터 요건 때문에 코드가 회사 밖으로 못 나가는 팀의 선택지입니다.

흥미로운 건 관리형 API로 가지 않아도 같은 패턴을 라이브러리로 조립할 수 있게 해 뒀다는 점입니다. openai-agents-js(v0.18)의 베타 기능 SandboxAgent가 그 물건인데, 워크스페이스를 Manifest로 선언하고 capability를 붙이는 방식입니다.

{{< highlight typescript >}} import { run } from '@openai/agents'; import { Capabilities, Manifest, SandboxAgent, localDir } from '@openai/agents/sandbox'; import { UnixLocalSandboxClient } from '@openai/agents/sandbox/local'; // 워크스페이스 선언: 이 디렉터리를 샌드박스에 스테이징한다 const manifest = new Manifest({ entries: { repo: localDir({ src: './repo' }) }, }); const agent = new SandboxAgent({ name: 'Sandbox engineer', model: 'gpt-5.6-sol', instructions: 'repo/task.md를 읽고 문제를 고친 뒤, 돌린 검증 명령을 보고해라.', defaultManifest: manifest, capabilities: [...Capabilities.default()], // 파일시스템·셸·스킬·메모리·컴팩션 }); // 클라이언트만 바꾸면 로컬 → Docker → E2B·Modal·Vercel·Cloudflare 호스팅으로 이동 const result = await run(agent, 'repo/task.md의 이슈를 해결해줘', { sandbox: { client: new UnixLocalSandboxClient() }, }); {{< /highlight >}}

주목할 설계는 두 가지입니다. capability 목록에 파일시스템·셸과 나란히 메모리와 컴팩션이 "장착하는 부품"으로 들어가 있다는 것, 그리고 sandbox.session·sandbox.snapshot으로 이전 작업 상태를 저장하고 재개할 수 있다는 것. 관리형 세션의 축소판을 셀프호스트로 먼저 검증해 보고, 맞으면 Agents API로 올라가는 경로가 의도적으로 깔려 있습니다.

파트너 쪽 생태계도 따로 볼 만합니다. 예컨대 cloudflare/agents는 Durable Objects 위에 에이전트를 "영속 상태를 가진 실행 환경"으로 올리는 프레임워크로, 에이전트마다 독립 상태·스토리지를 갖고 유휴 시 동면(hibernate)해서 수백만 개를 띄워도 비활성 비용이 없습니다. 사용자별로 오래 사는 개인 비서 같은 아키텍처라면 이쪽 모델이 더 자연스럽습니다.

그리고 이 그림에서 빼놓을 수 없는 게 Anthropic입니다. 4월에 나온 Claude Managed Agents는 샌드박스 코드 실행, 체크포인팅, credential scoping, 트레이싱을 REST 엔드포인트 3개로 제공합니다 — 애플리케이션이 세션에 이벤트를 넣고, 하네스와 샌드박스는 Anthropic 인프라에서 돌고, 이벤트 스트림을 돌려받는 구조. 어디서 많이 본 모양이죠? 두 벤더가 "durable session + 이벤트 스트림 + 관리형 샌드박스"라는 같은 형태로 수렴하고 있습니다.

5. 요금 산수 — 수수료는 없지만 미터기는 3개

Agents API 자체에는 추가 수수료가 없습니다. 대신 청구서에는 미터기가 3개 돕니다.

미터기과금 대상비고
① 모델 토큰세션이 소비한 입력·출력 토큰장기 세션에선 이게 지배 항목. 컴팩션·tool search가 여길 줄여 준다
② 툴 사용료웹 검색 등 OpenAI 제공 툴내가 가져온 함수·MCP 툴은 해당 없음
③ 컨테이너OpenAI 호스팅 샌드박스20분 세션-컨테이너당 1GB $0.03 · 4GB $0.12 · 16GB $0.48 · 64GB $1.92, 분 단위 과금(최소 5분)

봉투 뒷면 계산을 해 보면, 4GB 컨테이너로 1시간 돌리면 컨테이너 요금은 $0.36 — 사실상 무시할 수준입니다. 진짜 비용은 언제나 ①번, 토큰입니다. 토큰 이코노믹스 편에서 봤듯 에이전트 루프는 매 턴 이력을 재전송하는 O(N²) 구조라, 몇 시간짜리 세션의 토큰 청구서는 컨테이너 요금의 수백 배가 될 수 있습니다. 관리형 하네스의 컴팩션·tool search·프롬프트 캐시 관리가 얼마나 잘 동작하느냐가 곧 비용 성능인 셈이고, 그래서 "관리형이 더 싸다"는 벤더 주장은 자기 워크로드로 검증해 봐야 합니다.

실제로 OpenAI가 공개한 초기 사례 수치도 이 방향입니다 — SafetyKit은 케이스 리뷰 워크플로를 이전해 케이스당 비용을 60% 줄였고, Hypha는 하네스와 샌드박스를 분리해 실패 응답을 86% 줄였으며, Cirridae는 지연을 4배 개선했다고 합니다. 단, 셋 다 벤더가 고른 성공 사례의 자체 보고 수치라는 점은 감안하고 읽어야 합니다.

6. 사서 쓸까, 만들까 — 락인 논쟁과 Assistants API의 기억

발표 직후 Hacker News 스레드(338포인트, 댓글 178개)에서 벌어진 논쟁이 이 주제의 실무 쟁점을 잘 보여 줍니다. 진영은 크게 셋이었습니다.

"살 수밖에 없다" 진영은 이렇게 말합니다. 하네스의 진짜 어려움은 API 모양이 아니라 "상태가 어디에 지속되는가" 같은 근본 문제인데, 이걸 개별 팀이 OpenAI·Anthropic 엔지니어링 조직과 경쟁하며 풀 수는 없다는 겁니다. Codex를 수백만 세션 굴리며 다듬은 하네스를 API로 받는 건 공짜 점심에 가깝다는 논리입니다.

"또 속을 순 없다" 진영의 근거는 역사입니다. OpenAI의 이전 관리형 에이전트 인프라였던 Assistants API는 2026년 8월 26일에 완전히 꺼졌습니다 — Agents API 발표 불과 2주 전입니다. 자동 마이그레이션 도구도 없어서, Threads에 쌓인 상태는 각자 알아서 옮겨야 했습니다. "Assistants에 데인 뒤로는 직접 만든다"는 댓글이 괜히 나온 게 아닙니다. 관리형 하네스에 상태를 맡긴다는 건, 벤더의 제품 로드맵에 내 아키텍처를 거는 일입니다.

"애초에 종속을 설계로 피하자" 진영도 있습니다. 툴이 MCP 서버이고 instructions가 마크다운 파일이면, 밑의 모델·하네스를 바꾸는 건 재작성이 아니라 설정 변경이라는 겁니다. 두 벤더의 관리형 하네스가 같은 모양으로 수렴한 지금은 이 전략의 실행 비용이 오히려 낮아졌습니다.

덧붙이면, 이 상품화 흐름은 하네스에 그치지 않습니다. 같은 주에 GitHub는 여러 모델을 캐스케이드·교차 검토로 조립하는 HydraFusion을 리서치 프리뷰로 열었고, Sakana AI는 모델 풀 라우팅 자체를 학습한 Fugu Ultra v2를 냈습니다. 라우팅도, 오케스트레이션도, 하네스도 — 에이전트 스택의 중간층이 통째로 플랫폼 기능이 되는 중입니다.

7. 실전 — 가장 아픈 조각 하나만 옮겨 보는 실험 설계

"전면 이전"은 베타 API에 걸기엔 큰 판돈입니다. 추천하는 건 어댑터 한 층을 깔고, 가장 아픈 조각 하나만 옮겨서 숫자로 비교하는 것입니다. 먼저 자기 루프와 관리형 세션을 같은 인터페이스 뒤에 세웁니다.

{{< highlight python >}} from typing import Protocol, Iterator class AgentRuntime(Protocol): """우리 앱이 하네스에 기대하는 것만 정의한다 — 벤더 타입을 앱에 새지 않게.""" def start(self, task: str) -> str: ... # 세션(또는 자체 루프) 시작 → session_id def events(self, session_id: str) -> Iterator[dict]: ... # 진행 이벤트 스트림 def resume(self, session_id: str) -> None: ... # 끊긴 작업 재개 class SelfHostedRuntime: """지금 쓰는 자체 루프를 이 인터페이스로 감싼다.""" ... class AgentsAPIRuntime: """같은 인터페이스의 Agents API 구현. 앱 코드는 이 교체를 모른다.""" def start(self, task: str) -> str: session = self.client.beta.agents.sessions.create( agent={"model": "gpt-6-astra", "instructions": self.instructions}, environment={"type": "openai_hosted"}, input=task, ) return session.id {{< /highlight >}}

그다음 평가를 겁니다. 에이전트 평가 편에서 만든 것 같은 대표 태스크 셋(20~50개면 충분합니다)을 양쪽 런타임에서 돌리고, 세 숫자를 나란히 놓습니다.

  • 태스크 성공률 — 관리형 컴팩션이 우리 컴팩션보다 긴 작업에서 덜 잊는가?
  • 태스크당 비용 — usage 필드로 토큰을, 대시보드로 컨테이너 요금을 집계. "60% 절감" 같은 벤더 수치를 우리 워크로드로 재현해 본다
  • p95 소요 시간 — 서브에이전트 병렬화가 실제로 벽시계 시간을 줄이는가?

이 비교표가 있으면 "사서 쓸까"는 감이 아니라 데이터의 문제가 됩니다. 그리고 어댑터 덕에, 결과가 나쁘거나 훗날 일몰 공지가 와도 되돌리는 비용이 통제됩니다.

8. 흔한 실수 · 팁

  • 베타 API를 애플리케이션 코어에 직결하기. Agents API는 퍼블릭 베타라 형태가 바뀔 수 있습니다. 위의 어댑터 없이 client.beta.agents...가 코드베이스 곳곳에 박히면, API 변경이 전면 수리가 됩니다. Assistants → Responses 마이그레이션이 "엔드포인트 교체가 아니라 아키텍처 변경"이 됐던 이유가 정확히 이겁니다.
  • 세션을 켜 두고 잊기. durable 세션은 편한 만큼 놓아 주는 걸 잊기 쉽습니다. 컨테이너는 분 단위 과금이고, 장기 세션의 토큰 소비는 O(N²)로 큽니다. 세션 수명 상한과 유휴 타임아웃, 태스크당 예산 가드를 처음부터 정하세요.
  • 관측성을 벤더에 통째로 맡기기. 하네스가 관리형이 되면 내부가 블랙박스가 됩니다. 이벤트 스트림을 그냥 소비하고 버리지 말고, 자체 트레이싱(관측성 편)에 남기세요. 장애가 났을 때 "우리 쪽 로그"가 없으면 디버깅도 벤더 티켓 대기열입니다.
  • 벤더 사례 수치를 그대로 옮겨 말하기. "비용 60% 절감"은 벤더가 고른 성공 사례의 자체 보고입니다. 우리 팀 기획서에 쓸 숫자는 7절의 실험에서 나와야 합니다.
  • "관리형이니까 보안도 해결"이라고 믿기. 관리형 샌드박스는 격리 기본값을 올려 주지만, 프롬프트 인젝션이나 이번 주 화제였던 GitSpawn(악성 .git/config로 에이전트가 레포를 여는 순간 코드 실행) 같은 입력 쪽 공격면은 그대로 남습니다. 에이전트에 물리는 레포·데이터 검증은 여전히 우리 몫입니다.
  • 상태의 출구를 확인하지 않고 쌓기. 세션에 쌓이는 이력·작업 상태를 주기적으로 내보내 우리 저장소에 복제할 수 있는지 도입 첫 주에 확인하세요. 출구 없는 durable 상태는, 일몰 공지 하나로 인질이 됩니다.

9. 마무리 (TL;DR)

  • 9월 10일 OpenAI가 Codex를 굴리던 관리형 하네스를 Agents API 퍼블릭 베타로 공개했습니다. 세션·컨텍스트 컴팩션·tool search·서브에이전트·복구가 API 호출 하나 뒤로 들어갔고, 프리미티브는 Agent / Environment / Session / Events 4개입니다.
  • 실행 환경은 스펙트럼입니다 — OpenAI 호스팅 샌드박스, 파트너 9곳(Cloudflare·Vercel·E2B·Modal·Oracle 등), 자체 인프라. 셀프호스트 쪽엔 openai-agents-js의 SandboxAgent(Manifest + capability + snapshot)와 cloudflare/agents(Durable Objects, 동면) 같은 선택지가 있습니다.
  • API 수수료는 없지만 미터기는 3개(토큰·툴·컨테이너)이고, 지배 항목은 언제나 토큰입니다. 컨테이너는 4GB 기준 시간당 $0.36 수준. SafetyKit −60% 비용, Hypha −86% 실패 같은 사례 수치는 벤더 자체 보고로 읽으세요.
  • Anthropic도 4월부터 같은 모양의 Claude Managed Agents를 팔고 있습니다 — "durable session + 이벤트 스트림 + 관리형 샌드박스"로 벤더들이 수렴 중이고, 그래서 어댑터 한 층의 가치가 커졌습니다.
  • 락인 우려는 근거가 있습니다. 직전 관리형 인프라였던 Assistants API가 발표 2주 전인 8월 26일에 자동 마이그레이션 도구 없이 완전히 꺼졌습니다. 상태의 출구와 어댑터 없이 관리형에 직결하지 마세요.
  • 추천 경로: 하네스에서 가장 아픈 조각(컴팩션·복구·서브에이전트 중 하나)만 어댑터 뒤에서 관리형으로 옮기고, 같은 태스크 셋으로 성공률·비용·p95를 자기 워크로드에서 비교해 결정하세요.
