# 🔥 오늘의 핵심

오늘의 주제는 **"여는 순간이 공격면"**이다. 악성 `.git/config` 하나로 Claude Code·Codex·Cursor 등 7개 코딩 에이전트에서 코드가 실행되는 GitSpawn 결함군이 후속 보도로 다시 달아올랐고, 8건 중 4건은 아직 미패치라는 보도도 나왔다. 오늘 할 일은 둘: 에이전트를 최신 버전으로 올리고, 아래 공통 팁의 체크리스트를 팀 온보딩 문서에 붙여넣기. 모델 쪽에서는 Cognition이 Kimi K3 기반 SWE-2로 "프론티어 성능을 64% 싸게"를 들고 나왔다.

# 🤖 모델 & 릴리즈 레이더

- **Cognition SWE-2 (9/10)** — Moonshot Kimi K3(2.8T 파라미터)를 베이스로 RL 포스트트레이닝한 코딩 모델. medium/high/max 3단계 reasoning effort를 레벨별 비용 페널티를 걸어 **한 번의 RL 런으로** 학습한 게 기술적 포인트다. 자체 발표 기준 FrontierCode 1.1 Main에서 Fable 5.1 대비 64% 저렴. 현재 Devin Desktop·CLI에서 쓸 수 있고 Web·Fusion으로 롤아웃 중. 단독 API·가격표·가중치는 미공개라 "Devin 안에서만"이라는 제약이 크다. [Cognition 발표](https://cognition.com/blog/swe-2)
- **Codex CLI 0.154.0 (9/9)** — 실험 기능으로 **워크트리 세션**(`--worktree` / `/worktree`)이 들어왔다. 새 세션·포크 세션을 격리된 체크아웃에서 돌리고 나중에 찾아 재개할 수 있다. Codex가 작업 중일 때 메인 초안을 잃지 않고 인라인으로 질문에 답하는 기능, GPT-6-Astra 모델 피커 추가도 포함. 보안 쪽으로는 "신뢰가 확립되기 전에 워크스페이스가 제어하는 헬퍼를 실행하지 않도록" 시작 동작을 고쳤다 — 아래 GitSpawn 이슈와 정확히 같은 결의 수정이다(저장소 태그로 확인). [릴리즈 노트](https://github.com/openai/codex/releases/tag/rust-v0.154.0)
- **Claude Code 2.1.270** — 세션이 오래 지속되면 읽기 전용 git 명령이 불필요하게 권한을 묻던 2.1.269 회귀 수정 1건짜리 마이너 릴리즈(저장소 클론으로 확인). 큰 모델 소식은 오늘 이게 전부다.

# 📚 주목 논문

## An Open Recipe for IMO Gold (arXiv 2609.10712, cs.AI)

- **저자**: Ivan Moshkov, Stephen Ge, Igor Gitman 외 — NVIDIA Nemotron 팀 (9/9 공개, HF Daily 22 upvotes)
- **핵심 기여**: IMO 2026에서 금메달 기준선(30/42점)을 넘긴 시스템을 **레시피 전체 공개** — 포스트트레이닝된 체크포인트 2개, 학습 데이터, 학습·추론 코드, 신규 벤치마크 Nemotron-IMO-Bench(200문제)까지.
- **방법**: Nemotron 3 Ultra에서 SFT+RL로 스페셜리스트 체크포인트 2개를 만들고, 체크포인트 3개가 후보 증명을 **생성→검증→수정**하는 반복 탐색을 돌린 뒤, 별도의 고연산 스테이지가 최종 제출을 선택한다. 형식 증명기·외부 도구·인터넷 없이 전부 자연어로 동작.
- 🛠 **에이전트 빌더 시사점**: "생성기·검증기·수정기를 다른 체크포인트로 분리하고 마지막에 선택 스테이지를 두는" 구조는 수학이 아니어도 그대로 이식 가능한 test-time 파이프라인 템플릿이다. 코드까지 있으니 베낄 수 있다.
- **한계**: 고연산 test-time 탐색이라 비용이 크고, 검증도 자연어 기반이라 형식 검증 수준의 보장은 아니다.
- [arXiv 링크](https://arxiv.org/abs/2609.10712)

## MetroLLM-Bench: 키오스크 런타임으로서의 LM 평가 (arXiv 2609.10016, cs.LG)

- **저자**: Remco Hendriks (단독 저자, 9/9 공개, HF Daily 19 upvotes)
- **핵심 기여**: 실제 지하철 6개 노선망을 배경으로, LM이 구조화된 툴을 호출해 발권 키오스크의 정책 레이어 역할을 하는 955케이스 벤치마크. 14개 결정론적 채점(Tier 1) + 8개 의미 품질 채점(Tier 2)으로 나눈 채점 설계가 볼거리다.
- **검증된 결과**: PEFT로 튜닝한 **4B Qwen 3.5 학생 모델이 Tier 1에서 GPT-5.6 두 티어를 추월**(91.3 vs 90.6/90.0). Q4_K_M 양자화로 2.6GB. 9B·27B로 키워도 Tier 1은 더 안 올랐다.
- 🛠 **에이전트 빌더 시사점**: 좁은 도메인 에이전트라면 "프론티어 API 호출" 대신 "결정론적 채점 하니스 + 소형 튜닝 모델"이 비용·지연·오프라인 모두에서 이길 수 있다는 실측 사례.
- **한계**: 단독 저자 벤치마크이고 Tier 2는 LLM 저지 의존이라 재현·검증 커뮤니티가 아직 없다.
- [arXiv 링크](https://arxiv.org/abs/2609.10016)

# 🛠 오픈소스 스포트라이트

두 저장소 모두 이 세션에서 클론으로 검증했다. star 수는 GitHub API 차단으로 미확인.

- **[GoPlusSecurity/agentguard](https://github.com/GoPlusSecurity/agentguard)** (TypeScript, MIT, 마지막 커밋 9/10) — 에이전트용 실시간 보안 가드. ① 훅 기반 자동 가드(`rm -rf`, `curl | bash`, `.env`·`.ssh` 접근, 웹훅 유출 차단), ② 24개 룰 기반 스킬 딥스캔(세션 시작 시 신규 스킬 자동 스캔), ③ 일일 보안 패트롤의 3층 구조. `npm install -g @goplus/agentguard && agentguard init`이면 Claude Code·Codex 등 지원 에이전트를 자동 감지해 훅을 설치한다. **활용처**: GitSpawn류가 뚫고 들어와도 "실행 직전" 한 층을 더 두고 싶을 때. 어떤 스킬이 어떤 행동을 유발했는지 추적하는 감사 로그가 특히 유용하다.
- **[ProofAgent-ai/proofagent-harness](https://github.com/ProofAgent-ai/proofagent-harness)** (Python, Apache 2.0) — 배포 전 에이전트를 상대로 멀티턴 레드팀 대화를 돌리고, 완성 산출물은 정답 기준으로 채점하는 평가 하니스. `--upload` 플래그 하나로 CI의 pass/review/block 릴리즈 게이트가 되고, `proof watch`는 지금 내 레포에서 일하는 코딩 에이전트 세션에 붙어 실시간으로 위험을 스크리닝한다. **활용처**: agentguard가 "실행 차단"이라면 이쪽은 "배포 전 검증 + 세션 관찰" — 위 방어 레이어 도식의 ④번 자리다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟪 공통 — GitSpawn 방어 체크리스트

- **분류**: Workflow · **출처**: [The Hacker News 보도](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html) · [Manifold Security 원문](https://www.manifold.security/blog/ai-coding-agents-git-hijack)
- 💡 **핵심 아이디어**: 에이전트는 폴더를 열자마자 컨텍스트 수집용 `git status`를 돌린다. 레포의 `core.fsmonitor` 설정은 이때 git이 실행하는 "프로그램"이 될 수 있다 — 프롬프트를 치기 전, 승인 클릭 전에 발동한다.
- 📝 **방법**: 클론이 아니라 압축파일·복사본으로 받은 레포는 에이전트로 열기 전에 검사한다.

```bash
# 값이 나오면 git이 대신 실행할 프로그램이라는 뜻 — 열지 말 것
git config --get core.fsmonitor
# 의심되면 .git/config 전체를 눈으로 확인
cat .git/config
```

- 🎯 **언제**: 이슈 재현용 첨부 레포, 채용 과제, 튜토리얼 zip 등 "남이 만든 폴더"를 열 때마다.
- ⚠️ **주의**: 벤더 패치가 진행 중이지만(예: goose 1.44.0의 CVE-2026-72718) 변종 8건 중 4건 미패치 보도가 있다. 에이전트 최신 버전 유지가 전제다.
- ⭐ **추천도**: 필수. 팀 온보딩 문서에 넣자.

## 🟩 Codex — `/worktree`로 세션을 격리 체크아웃에서

- **분류**: Workflow · **출처**: [Codex 0.154.0 릴리즈 노트](https://github.com/openai/codex/releases/tag/rust-v0.154.0)
- 💡 **핵심 아이디어**: 새 세션이나 포크 세션을 메인 체크아웃이 아닌 관리형 워크트리에서 돌리면, 병렬 실험이 서로의 작업 트리를 밟지 않는다.
- 📝 **방법**: 시작할 때 `codex --worktree`, 또는 세션 안에서 `/worktree`("start or continue a conversation in a new worktree" — TUI 소스로 확인). 만들어진 워크트리는 목록에서 찾아 이어서 작업할 수 있다.
- 🎯 **언제**: 같은 레포에서 리팩터링과 버그픽스를 동시에 굴릴 때, 실패해도 되는 실험 브랜치를 던질 때.
- ⚠️ **주의**: 실험(experimental) 딱지가 붙어 있다. 워크트리 정리는 아직 수동 몫이라 디스크를 주기적으로 확인할 것.
- ⭐ **추천도**: 병렬 에이전트 워크플로우를 쓴다면 바로 시도할 가치.

## 🟦 Claude Code — pr-review-toolkit의 6개 리뷰 서브에이전트

- **분류**: Subagent · **출처**: [plugins/pr-review-toolkit](https://github.com/anthropics/claude-code/blob/main/plugins/pr-review-toolkit/README.md)
- 💡 **핵심 아이디어**: 공식 저장소에 번들된 이 플러그인은 리뷰를 6개 전문 서브에이전트로 쪼갠다 — comment-analyzer(주석 정확성), pr-test-analyzer(테스트 커버리지), silent-failure-hunter(조용한 실패), type-design-analyzer(타입 설계), code-reviewer, code-simplifier.
- 📝 **방법**: `/plugins`에서 pr-review-toolkit을 설치한 뒤, PR을 만들기 전에 한 번에 시킨다.

```text
PR 만들 준비 됐어. 다음을 순서대로:
1) 테스트 커버리지 리뷰  2) 조용한 실패 탐지
3) 주석 정확성 확인      4) 새 타입 설계 리뷰  5) 일반 코드 리뷰
```

- 🎯 **언제**: 리뷰어가 한 명뿐인 팀, 혹은 에이전트가 쓴 코드를 사람이 리뷰하기 전 1차 필터로.
- ⚠️ **주의**: 에이전트 6개를 다 돌리면 토큰이 꽤 든다. 평소엔 diff 성격에 맞는 1–2개만 지목하자.
- ⭐ **추천도**: silent-failure-hunter 하나만 써도 본전은 뽑는다.
