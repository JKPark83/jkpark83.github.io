# 📚 주목 논문

## 1) TurnSight — turn 단위 hindsight로 tool-integrated RL 조이기

- 저자: Changle Qu, Sunhao Dai, Hengyi Cai 외 (arXiv, 2026-08-04)
- arXiv: **2608.04007** (cs.CL / cs.AI)
- 핵심 기여: Tool-Integrated Reasoning(TIR)을 RL로 학습할 때 흔한 **trajectory-level 보상의 credit 배분 한계**를 turn 단위로 해소.
- 방법(3줄): ① 정답이 아니라 **실제 방문한 실행 상태에서** hindsight를 뽑는다. ② lookahead 길이가 다른 여러 hindsight 뷰를 만들고 **방향이 일치하는 신호만** 채택한다. ③ sibling rollout끼리 정규화해 **RL advantage를 조절**하되 원래 최적화 방향은 보존.
- 결과: 3개 벤치마크에서 효과 확인(세부 수치는 원문).
- 🛠 agent-builder 시사점: 에이전트 학습·평가를 **trajectory 단위가 아니라 turn 단위로** 보라는 신호. 로그·리워드·회귀 테스트를 "이 한 번의 tool call이 상태를 개선했나"로 쪼개면 긴 호흡 작업의 디버깅이 쉬워진다.
- 한계: RL 파이프라인 전제(rollout·teacher 브랜치)라 인퍼런스만 하는 팀엔 바로 적용 어려움.
- 링크: <https://arxiv.org/abs/2608.04007> · 코드 <https://github.com/quchangle1/TurnSight>

![TurnSight 방법 다이어그램: 기존 trajectory-level 보상은 최종 정답 1개로 turn별 credit 배분이 불가능하지만, TurnSight는 여러 lookahead 시야의 방향이 일치할 때만 채택해 turn 단위 신호로 RL advantage를 조절한다](/images/ai-news-2026-08-06/turnsight-flow.svg)
*TurnSight 핵심 — "최종 정답 1개"의 보상을 turn별 hindsight로 분해. (출처: arXiv 2608.04007, 수치는 논문 요약 기준)*

## 2) Video-DeepResearch — 단계별 tool unlocking으로 modality bias 깨기

- 저자: Zhen Fang, Yu Zeng, Wenxuan Huang 외 (arXiv, 2026-08-04)
- arXiv: **2608.03979**
- 문제 진단: 멀티모달 에이전트의 두 병목 — (1) **modality bias**(비주얼 툴을 건너뛰고 텍스트 검색부터), (2) **파라메트릭 지식 누수**(툴 실행 대신 내부 기억에 의존).
- 방법: perception과 exploration을 분리한 파이프라인 + **stage-wise tool unlocking**(웹 검색 전에 프레임 간 비주얼 그라운딩을 강제). 학습은 SFT → GRPO 2단계.
- 결과(검증): Video-DR-Bench(200개 multi-hop VQA)에서 **35B-A3B가 평균 64.0%**로 SOTA. Claude-4.5-Sonnet 59.0%, GPT-5 52.5%, Gemini 2.5 Pro 57.5%를 상회. 30B-A3B도 59.3%.
- 🛠 agent-builder 시사점: "툴이 있는데 안 쓴다"는 문제는 프롬프트가 아니라 **툴 게이팅 설계**로 잡는다. 특정 툴을 특정 단계까지 잠가두면 에이전트가 지름길(내부 기억·텍스트 검색)로 새는 걸 구조적으로 막을 수 있다.
- 한계: 비디오 딥리서치 도메인 특화 + RL 학습 비용.
- 링크: <https://arxiv.org/abs/2608.03979> · 코드 <https://github.com/Osilly/Vision-DeepResearch>

# 🛠 오픈소스 스포트라이트

오늘 두 저장소는 위 논문의 **공식 코드**다. (참고: 이번 세션은 GitHub API 이그레스가 정책상 차단돼 **별점은 확인하지 못했다** — 수치를 지어내지 않고 생략한다.)

- **quchangle1/TurnSight** — Python. TIR용 turn-level hindsight self-distillation 구현. → RL로 tool-use 에이전트를 학습 중이라면 credit assignment 부분을 이 방식으로 교체 실험해볼 만하다.
- **Osilly/Vision-DeepResearch** — Python. 멀티모달 딥리서치 에이전트 + 단계별 tool unlocking. → 멀티모달 에이전트가 비주얼 툴을 안 쓰는 문제를 겪는다면 게이팅 파이프라인 설계 레퍼런스로.

두 저장소의 공통 메시지: **툴 사용은 "붙이는" 게 아니라 "학습·게이팅으로 강제하는" 문제**라는 것. 하나는 학습 신호(TurnSight), 하나는 실행 파이프라인(Video-DR) 쪽에서 같은 곳을 찌른다.

# 🧑‍💻 Codex & Claude Code 실전 팁

![Codex exec와 Claude Code 커스텀 subagent를 나란히 비교한 카드: 왼쪽은 헤드리스 CI 실행, 오른쪽은 별도 컨텍스트 창의 도구 화이트리스트](/images/ai-news-2026-08-06/tips-card.svg)
*둘 다 "메인 컨텍스트를 지키는 격리 실행" 패턴 — Codex는 프로세스 격리, Claude Code는 컨텍스트 격리. (출처: OpenAI Codex 공식 문서 · code.claude.com/docs)*

**🟩 Codex — Workflow / `codex exec`를 CI 게이트로**
- 💡 핵심: `codex exec`는 TUI·승인 프롬프트 없이 **1회 실행 후 종료**한다. stdout에 최종 메시지, 종료 코드에 의미가 실려 CI/크론에 그대로 물릴 수 있다.
- 📝 How-to: 인터랙티브 설정과 섞이지 않게 `.codex/config.toml`에 `ci` 프로파일을 분리한다.
```toml
[profiles.ci]
sandbox_mode = "read-only"
approval_policy = "never"
model_reasoning_effort = "medium"
```
```bash
codex exec --profile ci "run the test suite and summarize failures"
echo "exit=$?"
```
- 🎯 언제: PR pre-merge 체크, 나이트리 회귀 요약처럼 **사람 개입 없이 한 번 돌고 끝나는** 작업.
- ⚠️ caveat: 프롬프트 인젝션 blast radius는 `sandbox_mode`로만 통제된다. CI에선 `read-only`부터 시작하고 필요할 때만 권한을 넓혀라.
- ⭐ 추천: 로컬 인터랙티브 세션의 습관을 그대로 파이프라인에 넣지 말 것. CI는 별도 프로파일이 정석.
- 출처: [OpenAI Codex 공식 문서 — non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)

**🟦 Claude Code — Subagent / 반복 작업은 `.claude/agents/*.md`로 고정**
- 💡 핵심: 같은 종류의 곁가지 작업(리뷰·탐색·리서치)을 계속 시킨다면 **커스텀 subagent**로 박제하라. 별도 컨텍스트 창 + 좁힌 도구·권한으로 메인 대화가 로그에 잠기지 않는다.
- 📝 How-to: 프로젝트 스코프는 `.claude/agents/`에 파일 하나. `tools`로 도구를 화이트리스트하고 `model: haiku`로 저비용 라우팅.
```markdown
---
description: PR diff만 읽고 리뷰. 코드 수정 후 사용.
tools: Read, Grep, Glob
model: sonnet
---
너는 리뷰 전용 에이전트다. diff만 보고 버그·회귀 위험만 보고하라.
```
- 🎯 언제: 검색 결과·로그가 메인 컨텍스트를 오염시키는 반복 작업. 팀 공유가 필요하면 repo에 커밋.
- ⚠️ caveat: v2.1.198부터 `/agents`는 생성 마법사를 열지 않는다 — Claude에게 작성을 부탁하거나 파일을 직접 만들면 된다. 세션 시작 뒤 `agents/` 폴더를 새로 만들면 재시작 전엔 인식 안 될 수 있다.
- ⭐ 추천: `tools`를 최소로 좁혀 subagent가 실수로 파일을 건드리지 못하게. 읽기 전용 작업엔 `Read, Grep, Glob`만.
- 출처: [code.claude.com/docs/en/sub-agents](https://code.claude.com/docs/en/sub-agents)

**🟪 공통 — Eval / 리워드·회귀를 turn 단위로**
- 💡 핵심: TurnSight의 교훈은 학습만이 아니라 평가에도 적용된다. "이 실행 전체가 성공/실패"가 아니라 **"이 한 번의 tool call이 상태를 개선했나"**를 별도로 로깅·판정하라.
- 📝 How-to: tool call마다 `(before_state → after_state)` 델타를 남기고, 실패 궤적에서 **어느 turn부터 어긋났는지**를 리그레션 지표로 삼는다.
- 🎯 언제: 긴 호흡(멀티턴) 에이전트의 성공률이 "가끔 무너지는데 원인을 못 잡을 때".
- ⚠️ caveat: turn 단위 정답 라벨은 비싸다 — 전량이 아니라 실패 궤적 위주로 샘플링.
- 출처: [arXiv 2608.04007](https://arxiv.org/abs/2608.04007)
