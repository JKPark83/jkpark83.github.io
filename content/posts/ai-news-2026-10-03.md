# 📚 주목 논문

## VISTA: 하네스만 바꿔서 ARC-AGI-3 만점

- **저자**: Qiushi Han, Keya Hu, Linlu Qiu, Cathy Wu, Kaiming He (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2610.02200](https://arxiv.org/abs/2610.02200) (cs.AI, 10/1 공개)
- **핵심 기여**: 멀티모달 모델의 추론 능력은 이미 충분하고, 병목은 하네스라는 주장. 과거 시각 관측을 **원본 그대로 보존하는 무손실 시각 메모리**를 주고, 모델이 필요할 때 능동적으로 꺼내 시각 입력을 재구성하게 합니다.
- **방법**: 관측을 요약(텍스트화)하지 않고 이미지 그대로 저장 → 모델이 추론 중 직접 조회·재배열. 하네스 설계가 단순해 다양한 환경에 거의 수정 없이 이식됩니다.
- **결과**: Claude Opus 5.0의 ARC-AGI-3 행동 효율(RHAE) 점수 **40.68 → 100.00 (만점)**. 공개 25게임 전부 완료, 첫 도전 인간 대비 행동 수 57.4% 절감(논문 보고치).
- 🛠 **Agent Builder 시사점**: 시각 환경 에이전트에서 스크린샷을 텍스트 요약으로 바꿔 쌓고 있다면, 그 요약 단계가 성능을 깎고 있을 수 있습니다. "원본 보존 + 선택적 재조회" 구조를 검토해볼 것.
- **한계**: 시각 메모리를 원본으로 유지하는 만큼 토큰·저장 비용이 커질 수 있고, 수치는 공개 게임 기준입니다.

## AutoCompact: 컴팩션 타이밍을 학습한다

- **저자**: Xuan Zhang, Longtao Zheng, Cunxiao Du, Bo An, Xin Dong (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2610.02163](https://arxiv.org/abs/2610.02163) (cs.CL, 10/1 공개)
- **핵심 기여**: 장기 코딩 에이전트의 컨텍스트 컴팩션을 하네스의 고정 규칙이 아니라 **모델 정책의 일부로 학습**. "언제 압축할지, 어떤 작업 상태를 보존할지, 압축 후 어떻게 이어갈지"를 모델이 결정합니다.
- **방법**: 베이스 에이전트의 컴팩션 결정·요약·후속 행동을 판정자가 검수해 잘못된 결정은 교정본으로 바꿔 궤적을 이어감 → 그 궤적으로 SFT → 과제 성공 보상으로 코딩+컴팩션 공동 RL.
- **결과**: SWE-bench Verified **+9.2%p**, SWE-PolyBench Verified **+5.0%p** (절대치, 논문 보고치). 모든 추론 예산 구간에서 개선이 유지되고 256K 컨텍스트에서 오버플로가 없습니다.
- 🛠 **Agent Builder 시사점**: "80% 차면 자동 컴팩션" 같은 고정 임계값은 과제 상태를 무시합니다. 학습까지는 안 가더라도, 컴팩션 요약에 보존할 작업 상태를 명시하는 것만으로 방향이 같습니다(아래 공통 팁).
- **한계**: 판정자 기반 데이터 수집 비용이 들고, 학습 파이프라인이 있는 팀에만 직접 적용 가능합니다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — 에이전트가 직접 worktree를 만든다** (카테고리: Workflow)

- 출처: [openai/codex 커밋 e7ea5f4](https://github.com/openai/codex/commit/e7ea5f4a8658ebe49e879be933effed2340fa276) (10/2)
- 💡 TUI에서 `create_worktree`, `list_worktrees`, `get_worktree_creation_status` 도구가 MCP로 노출됩니다. "이 작업은 분리해서 해줘"라고 하면 에이전트가 스스로 worktree를 만들어 작업을 격리할 수 있는 구조.
- 📝 worktrees 기능을 켜고 시작:

```bash
codex --enable worktrees
```

- 🎯 리팩터링과 핫픽스를 같은 레포에서 병렬로 진행할 때. worktree는 비동기로 생성돼 작업(task)에 붙고, 재시작해도 소유권과 첨부가 유지됩니다. 기본 분기점은 원격 기본 브랜치.
- ⚠️ 신뢰된(trusted) 로컬 프로젝트에서만 동작하고, 임시 사이드 대화에서는 생성이 거부됩니다. 아직 신선한 기능이라 동작이 바뀔 수 있습니다.
- ⭐ 추천도: 병렬 작업이 많은 모노레포 사용자라면 바로 실험해볼 가치 있음.

**🟦 Claude Code — 코드리뷰 findings 개수 직접 제어** (카테고리: Review)

- 출처: [v2.1.288 릴리스](https://github.com/anthropics/claude-code/releases/tag/v2.1.288)
- 💡 `/code-review`가 보고하는 findings 수를 직접 지정할 수 있게 됐습니다. 한 번 지정하면 다음 호출에도 유지됩니다.
- 📝 사용 예:

```text
/code-review --max-findings 3        # 상위 3개만
/code-review --max-findings all      # 전부 보고
/code-review --max-findings default  # 기본값 복귀
```

- 🎯 머지 직전엔 `3`으로 치명 이슈만 빠르게, 릴리스 전 정밀 점검엔 `all`로 전수 확인하는 식의 2단 운용.
- ⚠️ `all`은 사소한 지적까지 쏟아져 리뷰 피로가 커질 수 있습니다. 평소엔 기본값 권장.
- ⭐ 추천도: CI에서 `/code-review`를 돌리는 팀이라면 설정할 가치 충분.

**🟪 공통 — 컴팩션 요약에 "작업 상태 보존 목록"을 명시하라** (카테고리: Context)

- 출처: [AutoCompact (arXiv 2610.02163)](https://arxiv.org/abs/2610.02163)
- 💡 AutoCompact의 판정자가 교정한 핵심 실수는 "압축하면서 작업 상태를 잃는 것"이었습니다. 학습 없이도, 컴팩션 프롬프트에 보존 항목을 고정하면 같은 방향의 효과를 노릴 수 있습니다.
- 📝 컴팩션 지시문(또는 CLAUDE.md/AGENTS.md)에 추가:

```text
컨텍스트를 압축할 때 반드시 보존:
1) 현재 목표와 완료 조건  2) 수정 중인 파일 목록과 변경 요지
3) 마지막 실패 테스트와 에러 메시지  4) 시도했다가 버린 접근과 그 이유
탐색 과정의 중간 출력(파일 덤프, 검색 결과)은 과감히 버릴 것.
```

- 🎯 장기 코딩 세션에서 컴팩션 직후 에이전트가 "방금 뭐 하고 있었지" 상태로 리셋되는 문제를 겪고 있다면.
- ⚠️ 보존 목록이 길어지면 압축 효과 자체가 줄어듭니다. 4~5항목 이내로.
- ⭐ 추천도: 비용 제로. 오늘 바로 적용 가능.
