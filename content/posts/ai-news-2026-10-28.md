# 🔥 오늘의 핵심

에이전트 추론 원가가 양쪽에서 내려갔다. OpenAI **GPT-6.1 Terra**는 컴퓨터 유즈 작업을 GPT-6.1 Sol 절반 가격($1/$5)에 돌리라고 나온 모델이고, Liquid AI **LFM3**는 툴콜링 특화 1.7B를 4bit 기준 약 1GB 메모리에 올린다. 오늘 해볼 일: 브라우저 자동화나 컴퓨터 유즈 파이프라인이 있다면 모델명만 `gpt-6.1-terra`로 바꿔 비용·성공률 A/B를 돌려보는 것.

# 🤖 모델 & 릴리즈 레이더

- **GPT-6.1 Terra (OpenAI, 10/26)** — 컴퓨터 유즈·비주얼 추론 특화 모델. API 단가 $1/1M 입력, $5/1M 출력, 캐시 입력 $0.05로 [GPT-6.1 Sol($2/$10)의 절반](https://www.marktechpost.com/2026/10/26/openai-gpt-6-1-terra/)이다. OSWorld 2.1에서 max effort 기준 74.2%로 Sol보다는 낮지만, OpenAI는 태스크당 비용이 훨씬 싸다는 점을 전면에 세웠다 — [보도 기준](https://www.infoworld.com/article/4241006/openai-bets-on-ai-economics-with-lower-cost-gpt-6-1-terra.html) 구세대 GPT-5.6 Terra 대비 태스크당 $4.76 → $1.19. 컨텍스트 약 1M, ChatGPT·Codex에도 투입. 왜 중요한가: 컴퓨터 유즈는 스크린샷 루프 때문에 토큰을 많이 태우는 대표 워크로드라, 단가 반값은 곧 "돌릴 수 있는 자동화의 범위"가 넓어진다는 뜻이다. ⚠️ 이 세션은 openai.com 접근이 막혀 있어 복수 보도를 교차 확인했는데, OSWorld 비교 수치가 보도마다 달라(74.2% vs 60.0%) effort 설정 조건은 공식 문서로 재확인을 권한다.
- **LFM3 패밀리 (Liquid AI, 10/27)** — [LFM3-1.7B](https://huggingface.co/LiquidAI/LFM3-1.7B)(텍스트)에 VL-2B·Audio-2B·Omni-2B까지 멀티모달 동반 공개. 게이티드 컨볼루션 13 + 슬라이딩 윈도 어텐션 5 + 글로벌 어텐션 6의 트라이하이브리드 24층, 256K 컨텍스트, 한국어 포함 16개 언어. 모델 카드가 명시한 용도가 "로컬 에이전트, 툴콜링, 구조화 출력"이고 Hermes Agent·Pi 같은 에이전트 하네스 대상 포스트트레이닝을 거쳤다. 벤더 보고치로 BFCL V4 71.4, ToolSandbox 80.4 — 종합 평균 49.4로 Qwen3.5-9B(47.2)를 넘는다고 주장한다. 라이선스는 LFM Open License v1.0(상용 조건 확인 필요). [릴리즈 블로그](https://www.liquid.ai/blog/lfm3)

# 📚 주목 논문

## Trial by Trace: 하네스도 벤치마크가 필요하다

- **저자**: Zhiyong Cao, Hengjie Zhu, Yongxin Wang 외 23인 (소속 미표기)
- **arXiv**: [2610.32285](https://arxiv.org/abs/2610.32285) (cs.AI, 10/23) — HF Daily Papers 10/27 3위 (업보트 208)
- **핵심 기여**: 모델이 아니라 **하네스(에이전트 실행기)의 신뢰성**을 재는 벤치마크 TraceTrial-Bench. 컨텍스트·실행·거버넌스·라이프사이클·관측성·툴·검증 7개 축으로 채점한다.
- **방법**: 실행 가능한 정답 기준을 가진 전문가급 태스크 95개 + 궤적 추적 모듈 + 런 단위로 실패 원인을 귀속하는 Failure Attribution 모듈. 하네스 4종 × 모델 9종 × 3,420런.
- **결과**: 하네스별 매크로 평균 점수 59.8~72.0%. 결정적 수치는 **태스크에 성공한 런의 31.1%가 하네스 기준 하나 이상을 위반**하고 있었다는 것.
- 🛠 **Agent Builder 시사점**: "태스크 성공률"만 보면 하네스가 조용히 저지르는 문제(컨텍스트 유실, 삼켜진 툴 에러, 권한 위반)가 안 보인다. 성공한 런도 궤적을 채점해야 한다.
- **한계**: abs 페이지에 코드·데이터 링크가 아직 없다.

## DynaFlow: 오케스트레이션을 코드로 "생성"하기

- **저자**: Ruhao Liu, Qi Li, Shizun Wang, Xinchao Wang (소속 미표기)
- **arXiv**: [2610.34467](https://arxiv.org/abs/2610.34467) (cs.MA, 10/25) — HF Daily Papers 10/27 4위 (업보트 183)
- **핵심 기여**: 고정 그래프 대신 **메인 에이전트가 태스크마다 실행 가능한 워크플로(순차·병렬·검증 포함)를 직접 생성**해 서브에이전트들을 조율한다.
- **방법**: 학습은 메인 에이전트만 — 증류 궤적으로 SFT 후 필터링된 예제로 정제. 서브에이전트는 고정.
- **결과**: 수학·과학 QA·멀티홉 검색 6개 벤치마크에서 Qwen3.5-27B 기준 종합 88.08%, 최강 베이스라인 대비 +10.9%p.
- 🛠 **Agent Builder 시사점**: LangGraph식 정적 그래프와 자유 대화형 멀티에이전트 사이의 중간 지점. "오케스트레이터만 학습하고 워커는 고정"은 비용 면에서도 현실적인 레시피다.
- **한계**: 코드 미공개, 평가가 추론형 벤치마크 중심이라 장기 실행 에이전트로의 일반화는 미검증.

# 🛠 오픈소스 스포트라이트

GitHub API가 이 세션에서 막혀 있어 스타 수 미확인, 두 저장소 모두 클론으로 직접 검증.

- **[craft-ai-agents/craft-agents-oss](https://github.com/craft-ai-agents/craft-agents-oss)** (TypeScript/Bun, Apache 2.0) — 문서 앱 Craft(craft.do)가 사내용으로 만들어 공개한 **문서 중심 에이전트 워크스페이스**. Claude Agent SDK와 Pi SDK를 나란히 쓰는 드문 구조다. 특징은 "소스" 개념: "Linear를 소스로 추가해줘"라고 하면 에이전트가 공개 API·MCP 문서를 읽고 자격증명 설정까지 스스로 끝낸다. OpenAPI 스펙이나 문서 스크린샷을 붙여도 알아서 연결. Claude Code 스킬·MCP 임포트도 지원하고, 10/11 v0.15.0 이후 2주간 6회 릴리즈(10/23 v0.15.6)로 템포가 빠르다. 자기들 말로는 Craft Agents 개발 자체를 코드 에디터 없이 Craft Agents로만 한다고.
- **[FrigadeHQ/hob](https://github.com/FrigadeHQ/hob)** (TypeScript, MIT) — 10/27 Show HN 상위에 오른 **완전 온디바이스 Claude/ChatGPT 대안 데스크톱 앱**. 설치 시 하드웨어를 보고 맞는 오픈 웨이트 모델을 골라주는 게 핵심인데, 저장소의 `catalog/catalog.json`을 보면 모델별 GGUF 빌드·양자화·요구 메모리·에이전트 적합도 점수를 선언적으로 관리한다(Qwen3, Gemma 4 계열 등). PDF 작성·문서 작업을 오프라인으로 처리하고, 코드 실행은 채팅 폴더로 샌드박싱된다(보도 기준). 10/27 하루에만 0.2.2 릴리즈 포함 커밋 다수. LFM3 같은 소형 모델이 실제 제품으로 배포되는 형태의 참고 사례.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — 카테고리: Context**

- 소스: [openai/codex 커밋 2edc8dc (10/27)](https://github.com/openai/codex/commit/2edc8dcb0c55dd66c866948437b5725241169615)
- 💡 스킬 카탈로그에서 **설명문을 통째로 생략**하는 `omit_skill_descriptions` 기능 플래그가 들어왔다. 모델에게 보이는 카탈로그에 스킬 이름과 위치만 남긴다 — 스킬이 수십 개면 설명문만으로 컨텍스트가 상당히 먹히는데, 그 비용을 끄는 스위치다.
- 📝 config.toml에서:

```toml
# ~/.codex/config.toml
[features]
omit_skill_descriptions = true
```

- 🎯 스킬·플러그인을 많이 설치해서 시스템 프롬프트가 비대해진 팀. 이름만으로 스킬을 고를 수 있을 만큼 네이밍이 잘 돼 있다면 효과적.
- ⚠️ UnderDevelopment 단계(기본 꺼짐)라 동작이 바뀔 수 있다. 켜 두면 설명문만 고친 스킬 변경은 카탈로그 델타에 반영되지 않는다. 스킬 이름이 모호하면 모델이 엉뚱한 스킬을 고를 위험이 커지니, 켜기 전에 이름부터 정리할 것.
- ⭐ 추천도: 스킬 20개 이상이면 측정해볼 가치 충분.

**🟦 Claude Code — 카테고리: Subagent/Context**

- 소스: [anthropics/claude-code 2.1.312 체인지로그 (10/27)](https://github.com/anthropics/claude-code/commit/0e1f4789406477380b267a01f3ddd50b0211e5b3)
- 💡 서브에이전트 프런트매터의 `autoCompactWindow`가 이제 **전역 env 값(`CLAUDE_CODE_AUTO_COMPACT_WINDOW`)보다 낮은 값으로도 동작**한다. 지금까지는 env를 쓰는 환경에서 이 필드가 무시됐는데, 이번 수정으로 "본체는 넉넉하게, 특정 서브에이전트만 일찍 압축"이 실제로 가능해졌다.
- 📝 에이전트 정의(.claude/agents/log-digger.md)에서:

```yaml
---
name: log-digger
description: 대용량 로그·테스트 출력을 뒤지는 전용 서브에이전트
autoCompactWindow: 60000
---
```

- 🎯 grep·테스트 러너처럼 툴 출력이 큰 서브에이전트. 어차피 결론만 보고하면 되는 에이전트는 일찍 압축해도 손해가 없고, 압축 없이 컨텍스트 한도에 부딪혀 죽는 것보단 낫다.
- ⚠️ 이 값은 창을 **낮출 수만** 있고 전역 설정보다 올리지는 못한다. 너무 낮게 잡으면 압축이 잦아져 오히려 느려진다.
- ⭐ 추천도: 서브에이전트가 긴 작업 중 컨텍스트로 죽어본 적 있다면 바로 적용.

**🟪 공통 — 카테고리: Eval**

- 소스: [Trial by Trace (arXiv 2610.32285)](https://arxiv.org/abs/2610.32285)
- 💡 성공한 런의 31.1%가 하네스 기준 위반이었다는 위 논문의 수치를 뒤집으면: **지금 통과 중인 에이전트 평가의 1/3은 운이 좋았을 뿐일 수 있다**. 태스크 성공과 하네스 신뢰성을 분리 계측하자.
- 📝 체크리스트: ① 평가 리포트에 "성공률" 옆에 궤적 기준 위반율(툴 에러 무시, 컨텍스트 절단, 권한 이탈)을 별도 컬럼으로 추가 ② 성공 런에서도 궤적을 샘플링해 LLM 저지로 채점 ③ 실패는 "모델 탓 vs 하네스 탓"을 귀속해서 집계 — 하네스 탓 실패는 모델 업그레이드로 안 고쳐진다.
- 🎯 에이전트 평가 파이프라인을 운영하는 모든 팀. 특히 하네스를 직접 만들거나 갈아탈 계획이 있다면.
- ⚠️ 궤적 채점은 비용이 드니 전수 대신 샘플링으로 시작할 것.
- ⭐ 추천도: 평가 지표 설계에 오늘 반영 권장.
