# 🔥 오늘의 핵심

# 📚 주목 논문

## Atria Dawn: The Dawn of Agentic Superintelligence

- **저자**: Honglin Guo, Tao Gui 외 143인 (소속은 논문 페이지에 명시 없음, Atria 팀)
- **arXiv**: [2609.15818](https://arxiv.org/abs/2609.15818) (cs.AI, v2 9/17)
- **핵심 기여**: 연구·엔지니어링 워크플로 특화 에이전틱 파운데이션 모델 "Atria Dawn Preview"와, 그 모델을 만든 개발 과정 자체의 실측 분석.
- **방법**: 도구 호출을 실행 가능한 환경과 외부 검증된 결과에 연결하는 Verifiable Experience Pipeline로 학습. 즉 "말이 된 경험"이 아니라 "검증에 통과한 경험"만 학습 신호로 쓴다.
- **결과**: 연구·엔지니어링·디지털 업무 16개 벤치마크에서 프런티어급, 그중 5개 최고 기록 보고. 개발 과정의 과제 기록 769건(참여자 56명) 분석에서, 완료된 AI 보조 과제의 약 1/3을 참여자들이 "AI 없이는 불가능했다"고 평가.
- 🛠 **시사점**: 에이전트 학습 데이터를 모을 때 "실행 + 외부 검증"을 통과한 궤적만 남기는 파이프라인 설계가 사실상 표준이 되고 있다. 자체 에이전트의 성공 런을 그냥 쌓지 말고 검증 게이트를 달아두자.
- **한계**: Preview 명칭 그대로 상세 스펙(크기·데이터 구성)이 제한적으로만 공개. [코드 저장소](https://github.com/atria-asi/Atria-Dawn-Preview)는 확인됨.

## Dream-RSI: Recursive Self-Improvement through Evolving Worlds

- **저자**: Tong Zheng, Xidong Wu 외 17인
- **arXiv**: [2609.14858](https://arxiv.org/abs/2609.14858) (cs.CL, 9/14)
- **핵심 기여**: 에이전트의 재귀적 자기 개선에서 병목인 "탐색 전략 개선"을 싸게 만드는 프레임워크.
- **방법**: 코딩 에이전트 본체는 건드리지 않고, 얇은 오케스트레이션 레이어가 탐색을 명시적·프로그래머블하게 만든다. 핵심 통찰은 누적된 발견 히스토리가 이미 실현된 탐색 공간의 리플레이 시뮬레이터 역할을 할 수 있다는 것 — 새 전략을 비싼 실시간 롤아웃 대신 과거 기록 위에서 먼저 평가한다.
- 🛠 **시사점**: 오케스트레이터·프롬프트·탐색 정책을 바꿀 때마다 라이브 에이전트를 돌려 A/B 하고 있다면, 런 히스토리 리플레이로 1차 스크리닝하는 구조가 훨씬 싸다.
- **한계**: 리플레이는 "이미 가본 공간"만 비추므로, 전략이 크게 달라지면 오프라인 평가의 신뢰도가 떨어진다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — 훅 12종 라이프사이클, 핸들러는 command만이 아니다

- **카테고리**: Hook · **출처**: [openai/codex docs/config.md](https://github.com/openai/codex/blob/main/docs/config.md) + 앱서버 프로토콜 스키마 (저장소에서 직접 확인)
- 💡 **핵심**: Codex 훅 체계가 스키마 레벨에서 12개 이벤트로 정리됐다: `preToolUse`, `postToolUse`, `permissionRequest`, `preCompact`, `postCompact`, `sessionStart`, `sessionEnd`, `userPromptSubmit`, `subagentStart`, `subagentStop`, `stop`, `interrupt`. 핸들러도 command 외에 **mcp_tool / prompt / agent** 타입이 있다.
- 📝 **how-to**: 훅이 주입하는 additionalContext는 약 2,500 토큰을 넘으면 자동으로 디스크에 스필되고 복구 메타데이터가 붙는다 — 훅에서 긴 로그를 밀어 넣어도 컨텍스트가 터지지 않게 설계돼 있다. 조직 관리자는 `requirements.toml`에 다음을 넣어 사용자·프로젝트 훅을 무시하고 관리 훅만 허용할 수 있다:

```toml
allow_managed_hooks_only = true
```

- 🎯 **언제**: 규정 준수가 필요한 팀 배포, 또는 컴팩션 전후(`preCompact`/`postCompact`)에 상태를 저장·복원하는 메모리 훅을 만들 때.
- ⚠️ **주의**: `allow_managed_hooks_only`는 `config.toml`에 넣으면 동작하지 않는다. requirements.toml 전용.
- ⭐ **추천도**: 팀 단위 Codex 운영자라면 필수 숙지.

## 🟦 Claude Code — hookify: 자연어 한 줄로 훅 만들기

- **카테고리**: Hook · **출처**: [anthropics/claude-code plugins/hookify](https://github.com/anthropics/claude-code/blob/main/plugins/hookify/README.md) (저장소에서 직접 확인)
- 💡 **핵심**: 공식 hookify 플러그인은 `hooks.json`을 직접 편집하지 않고, 자연어 요청을 YAML frontmatter가 달린 마크다운 규칙 파일로 바꿔준다.
- 📝 **how-to**:

```
/hookify Warn me when I use rm -rf commands
```

이 한 줄이 `.claude/hookify.warn-rm.local.md`를 생성하고, **재시작 없이** 바로 다음 도구 호출부터 정규식 매칭으로 경고를 띄운다. 대화 로그를 분석해 반복되는 "원치 않는 행동"을 자동으로 찾아 규칙화하는 모드도 있다.

- 🎯 **언제**: 어제 브리핑의 과잉 주장(overclaiming) 문제처럼, "에이전트가 자꾸 하는 나쁜 습관"을 발견 즉시 규칙으로 굳히고 싶을 때.
- ⚠️ **주의**: 규칙은 정규식 기반이라 우회 표현까지 막지는 못한다. 강한 차단이 필요하면 정식 훅 스크립트로 승격할 것.
- ⭐ **추천도**: 훅 입문용으로 최적. 오늘부터 쓸 수 있다.

## 🟪 공통 — 런 히스토리를 리플레이 시뮬레이터로

- **카테고리**: Eval · **출처**: [Dream-RSI (arXiv:2609.14858)](https://arxiv.org/abs/2609.14858)
- 💡 **핵심**: 에이전트의 모든 런(도구 호출, 결과, 점수)을 append-only 로그로 남기면, 그 자체가 "이미 탐색한 공간"의 시뮬레이터가 된다.
- 📝 **how-to**: 오케스트레이션 레이어와 에이전트 본체를 분리하고, 새 탐색 전략·프롬프트 변경은 (1) 과거 히스토리 리플레이로 점수 추정 → (2) 통과한 후보만 라이브 롤아웃, 2단계로 평가한다.
- 🎯 **언제**: 라이브 평가 1회가 수 분·수 달러 이상인 장기 에이전트 루프.
- ⚠️ **주의**: 전략이 히스토리 분포에서 크게 벗어나면 리플레이 추정을 믿지 말 것.
- ⭐ **추천도**: 에이전트 평가 비용이 고민이라면 이번 주 실험 감.
