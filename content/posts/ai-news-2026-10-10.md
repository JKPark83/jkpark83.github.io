## Skill Constellations: SKILL.md 복사의 공급망 지도

- **저자**: Fahd Seddik (소속은 초록 미표기, 단독 저자)
- **arXiv**: [2610.11169](https://arxiv.org/abs/2610.11169) (cs.SE, 10/8 공개)
- **핵심 기여**: Claude Code·Codex가 사용자 권한으로 실행하는 SKILL.md가 저장소 간 복사로 퍼지는 과정을, **git 히스토리 기반의 '날짜 있는 복사 네트워크'**로 처음 재구성했습니다. GitHub 전체 **2,193,119건의 스킬 채택**을 커버합니다.
- **방법**: GitSkills에 수집된 모든 SKILL.md의 git 히스토리에서 누가 누구를 복사했는지 시점과 함께 추적. 복사의 원천이 되는 저장소를 예측하는 모델을 학습해 감사 우선순위를 매깁니다. 인터랙티브 뷰어도 공개.
- **결과**: 소수 저장소가 거의 모든 복사의 원천인데 **스타 수로는 그 저장소들을 못 찾습니다**. 복사본은 소스와 함께 갱신되지 않아 소스의 보안 픽스가 복사본에 거의 전파되지 않습니다. 모델이 뽑은 상위 100개 저장소를 감사하면 이후 고위험 스킬 채택의 **14.9%를 사전 차단** — 스타 상위 100개 기준(0.5%)의 약 30배입니다.
- 🛠 **에이전트 빌더 시사점**: 스킬을 복사가 아니라 **버전 있는 참조로 배포·설치**해야 한다는 게 논문의 결론입니다. 팀 내 스킬도 출처 URL과 커밋 해시를 함께 기록해 두면 픽스 추적이 가능해집니다.
- **한계**: GitHub 공개 저장소 기준이라 사내 유통은 안 보입니다.

## Learn2Play Bench: 에이전트는 경험에서 얼마나 배우나

- **저자**: Yibo Li, Jinhang Qiu, Zhi Zheng 외 — Bryan Hooi 포함 7인 (소속은 초록 미표기)
- **arXiv**: [2610.08215](https://arxiv.org/abs/2610.08215) (cs.AI, v2 10/6)
- **핵심 기여**: 기존 '경험 학습' 벤치마크는 규칙이 지시문에 있거나 사전학습으로 아는 과제라서, 학습과 기존 지식 추론이 구분되지 않았습니다. 이 벤치마크는 **규칙이 새롭거나 반직관적인 텍스트 게임**으로 그 구분을 강제합니다.
- **방법**: 재현 가능한 피드백과 자동 채점이 있는 신규 게임들에서 반복 시도에 걸친 학습을 측정. 게임 인스턴스를 바꿔 배운 것의 전이도 테스트합니다. 백본 모델·자기진화 기법·하니스를 각각 바꿔가며 비교.
- **결과**: (1) **행동·피드백 원본 기록을 유지하는 쪽이, 규칙·전략으로 요약하는 쪽보다 학습에 유리.** (2) 상위 인간 플레이어가 피크 점수에서 여전히 우위 — 인간은 더 다양한 전략을 탐색하고 같은 행동을 덜 반복. (3) 백본을 고정해도 **하니스를 바꾸면 추론 비용을 줄이면서 성능이 오르는 경우**가 있음.
- 🛠 **에이전트 빌더 시사점**: 메모리를 설계할 때 '요약된 교훈'만 남기고 원본 로그를 버리면 학습 능력을 깎을 수 있습니다. 하니스 자체가 성능·비용 튜닝 변수라는 것도 재확인.
- **한계**: 텍스트 게임 환경이라 실제 코딩·브라우징 과제로의 일반화는 별도 검증 필요.
- [프로젝트 사이트](https://liushiliushi.github.io/learn2play-bench-website/)

Claude Code·Codex·Cursor용 스킬과 어댑터 플러그인 카탈로그 동봉. 현재 v0.8.4, 공개 레포 커밋은 9월 말이 마지막이고 이번 주 뉴스 브리핑들에 공개 소식이 돌았습니다(클론 확인). **활용**: 같은 사이트를 반복 조작하는 브라우저 에이전트의 토큰·안정성 개선 1차 후보.

- 출처: [v2.1.296 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.296) (CHANGELOG + 태그, 클론 확인)
- 💡 서브에이전트 프런트매터와 `--agents` 정의에 `autoCompactWindow`가 생겨, **서브에이전트가 메인 대화보다 일찍 자동 압축**되게 할 수 있습니다.
- 📝 대용량 도구 출력(테스트 로그, 크롤 결과)을 소화하는 워커 에이전트의 프런트매터에 `autoCompactWindow`를 좁게 지정하세요. 워커는 자주 압축돼도 결과 요약만 반환하므로 본 세션 품질에 영향이 없습니다. 같은 릴리즈의 `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`로 워크플로 에이전트 전체를 한 모델로 고정하는 것도 함께 쓸 만합니다.
- 🎯 긴 로그를 읽는 fanout 워커가 컨텍스트 한도로 죽거나 느려질 때.
- ⚠️ 값 단위·세부 동작은 공식 문서에서 확인 후 적용하세요. 너무 좁히면 워커가 과제 맥락 자체를 잃습니다.
- ⭐ 추천도: 워커 중심 워크플로라면 바로 실험해 볼 가치.

**🟩 Codex — 서브에이전트에 부모 컨텍스트 설정 상속 끊기** (Subagent/Context)

- 출처: [openai/codex #52659 커밋](https://github.com/openai/codex/commit/8a0437ff34c920af41dd83af71bc8474c452fb10) (10/9, 클론 확인)
- 💡 `subagent_default_context_limits` 기능을 켜면 서브에이전트 스폰·재개 시 부모의 `model_context_window`·`model_auto_compact_token_limit` 오버라이드가 **상속되지 않고, 각자 모델 기본값**을 씁니다.
- 📝 config.toml에서:

```toml
[features]
subagent_default_context_limits = true
```

- 🎯 메인 세션 컨텍스트를 일부러 좁혀 쓰는데(비용 절약 등) 서브에이전트까지 좁아져 작업이 잘리는 경우.
- ⚠️ 기본 꺼짐에 스테이지가 `UnderDevelopment`인 실험 플래그입니다(스키마·소스로 확인). 동작이 바뀔 수 있습니다.
- ⭐ 추천도: 컨텍스트 오버라이드를 쓰는 파워유저용.

**🟪 공통 — '요약된 교훈'만 남기지 말 것** (Memory/Context)

- 📝 에이전트 메모리 파이프라인에서 요약본과 별도로 원본 trajectory를 보관하고, 요약은 원본에서 언제든 다시 뽑을 수 있게 하세요. 메모리 파일에는 요약과 함께 원본 로그 경로를 링크.
