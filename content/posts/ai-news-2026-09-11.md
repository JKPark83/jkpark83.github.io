# 🔥 오늘의 핵심

# 📚 주목 논문

## AgentGrad: 멀티에이전트 프롬프트, 추측 말고 개입으로 고쳐라

- **저자**: Jaewon Chu, Jinwoo Seo, Jaewon Cho, Yunyang Xiong, Hyunwoo J. Kim 외
- **arXiv**: [2609.08572](https://arxiv.org/abs/2609.08572) (cs.AI, 9/8 공개) · HF 데일리 73 업보트
- **핵심 기여**: 멀티에이전트 시스템(MAS)의 텍스트 그래디언트 기반 프롬프트 최적화에서, "어느 프롬프트를 고칠지"를 검증 없이 고르던 기존 방식의 한계를 지적하고 개입(intervention) 기반으로 대체.
- **방법**: 실패 케이스마다 에이전트를 한 번에 하나씩 수정해 실패가 실제로 해소되는 타깃을 찾고, 그 수정된 중간 출력을 감독 신호로 그래디언트를 추출한다. 이후 의미가 비슷한 그래디언트끼리 클러스터링해 일반화된 수정 패턴으로 추상화한다.
- **결과**: MAS 벤치마크 5종에서 SOTA, 차순위 대비 최적화 벽시계 시간 평균 2.5배 단축.
- 🛠 **에이전트 빌더 시사점**: 서브에이전트 프롬프트를 손으로 돌려 깎고 있다면, "한 놈만 바꿔서 실패가 풀리는지 본다"는 개입 프로토콜 자체는 프레임워크 없이도 당장 흉내낼 수 있는 디버깅 습관이다.
- **한계**: 개입 실험이 필요한 만큼 실패 케이스당 추가 실행 비용이 든다(속도 수치는 기존 텍스트 그래디언트 대비 기준).

![AgentGrad 흐름](/images/ai-news-2026-09-11/agentgrad-flow.svg)

*실패 → 순차 개입 → 에이전트 수준 감독 → 의미 클러스터링 → 타깃 프롬프트 업데이트.*

## SWE-Bench Pro Verified: 그 점수, 부풀려져 있었다

- **저자**: Pujun Zheng, Zixin Shang, Shufan Jiang 외
- **arXiv**: [2609.08149](https://arxiv.org/abs/2609.08149) (cs.AI, cs.SE, 9/8 공개)
- **핵심 기여**: 에이전트 코딩 표준 벤치인 SWE-Bench Pro의 신뢰성 결함 두 가지를 실증 — 정답 솔루션·숨겨진 평가 정보가 새는 **보상 해킹** 경로와, 오해를 부르는 문제 설명·잘못 스코프된 테스트 같은 **과제 품질 문제**.
- **방법**: 누수 채널을 막는 anti-hacking 안전장치 + 결함 인스턴스를 최소 수정하는 task refinement로 검증판을 구성.
- **결과**: 검증판에서 일부 모델 점수가 기존 보고보다 크게 하락. 기존 SWE-Bench Pro 수치는 실제 능력을 과대평가했을 수 있다.
- 🛠 **에이전트 빌더 시사점**: 모델 선정 근거로 쓰던 리더보드 수치를 재확인할 이유가 생겼다. 그리고 같은 누수 패턴은 여러분의 사내 평가 하니스에도 있다(아래 공통 팁 참고).
- **한계**: 검증 과정 자체의 기준(어디까지가 "결함 인스턴스"인가)에는 판단이 개입된다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — `/agents` 커맨드 센터로 세션 정리

- **카테고리**: Workflow · **소스**: [slash_command.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/slash_command.rs)
- 💡 Codex TUI에는 활성 에이전트 세션 전체를 보고 전환하는 `/agents`와, 현재 세션의 서브에이전트만 오가는 `/multi-agents`가 구분되어 있다.
- 📝 병렬 작업 중 `/agents`로 커맨드 센터를 열면 목록에서 방향키로 태스크를 열고, 최근 업데이트로 아카이브·삭제·숨김 정리까지 지원한다(9월 커밋 #44344, #44433, #44424로 소스 확인).
- 🎯 백그라운드 태스크를 3개 이상 굴리기 시작해 "어느 세션이 뭘 하고 있었지"가 되는 순간.
- ⚠️ 서브에이전트 전환(`/multi-agents`)과 혼동하면 다른 세션 컨텍스트에 지시를 보내게 된다.
- ⭐ 병렬 에이전트 사용자라면 오늘 손에 익힐 가치가 있다.

### 🟦 Claude Code — hookify 플러그인으로 훅을 말로 만들기

- **카테고리**: Hook · **소스**: [hookify README](https://github.com/anthropics/claude-code/blob/main/plugins/hookify/README.md)
- 💡 공식 저장소에 포함된 hookify 플러그인은 `hooks.json`을 직접 쓰는 대신, 자연어로 규칙을 말하면 YAML frontmatter를 가진 마크다운 규칙 파일을 생성해 준다.
- 📝 예를 들어:

```
/hookify Warn me when I use rm -rf commands
```

  이러면 `.claude/hookify.warn-rm.local.md`가 생기고 **재시작 없이** 다음 툴 호출부터 적용된다. 인자 없이 `/hookify`를 치면 최근 대화에서 반복 교정한 행동을 찾아 규칙을 제안하고, `/hookify:list`·`/hookify:configure`로 관리한다.
- 🎯 "이건 하지 말라고 했잖아"를 세 번째 말하고 있을 때 — 그 교정을 훅으로 굳히는 용도.
- ⚠️ 정규식 매칭 기반이라 과하게 넓은 패턴은 정상 작업까지 막는다. 생성된 규칙 파일을 열어 패턴을 확인하자.
- ⭐ 훅 진입 장벽을 크게 낮춰 준다. 팀 온보딩에도 좋다.

### 🟪 공통 — 자체 평가 하니스의 누수 점검 체크리스트

- **카테고리**: Eval · **소스**: [arXiv 2609.08149](https://arxiv.org/abs/2609.08149)
- 💡 SWE-Bench Pro Verified가 찾은 누수 경로는 사내 에이전트 평가에도 그대로 존재한다.
- 📝 오늘 점검할 세 가지: (1) 에이전트가 정답 패치·정답 테스트 파일에 접근 가능한가(git 히스토리 포함), (2) 평가 스크립트나 히든 테스트가 작업 디렉터리에 노출되는가, (3) 통과 판정 테스트가 과제 범위와 정확히 일치하는가.
- 🎯 에이전트 점수가 "느낌보다 좋게" 나오기 시작했을 때. 대개 실력이 아니라 누수다.
- ⚠️ 누수를 막은 뒤 점수 하락은 정상이다. 하락 폭 자체가 그동안의 과대평가량이다.
- ⭐ 반나절 투자로 평가 신뢰도가 달라진다.
