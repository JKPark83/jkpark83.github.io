# 🔥 오늘의 핵심

Reflection이 **Beam 1.0(501B 총 / 23.4B 활성) 가중치를 Apache-2.0으로 공개**하고, 공식 터미널 에이전트 **Mirror**까지 오픈소스로 풀었습니다. 어제 Meta Muse Spark Open에 이어 이틀 연속 프런티어급 에이전트 모델의 오픈 웨이트 릴리즈입니다. 함께 볼 것은 SpecAgent 논문 — **강한 모델을 매 스텝의 저자가 아니라 리뷰어로 돌리면 품질은 1pt 이내로 지키면서 비용이 절반**이라는 데이터. 오늘 해볼 일: **내 에이전트에서 읽기 전용 툴 콜을 작은 모델에 위임할 수 있는 구간 찾아보기.**

# 📚 주목 논문

## OpenGCUA: 컴퓨터 유즈 풀스택을 연다

- **저자**: Hanzhang Zhou, Long Li, Quyu Kong 외 (Alibaba Tongyi-MAI, MAI-UI 팀)
- **arXiv**: [2610.22200](https://arxiv.org/abs/2610.22200) (cs.CV, 10/15 공개, arXiv API 검증)
- **핵심 기여**: GUI만 클릭하는 에이전트를 넘어 **"관찰·행동·작업 조직 방식을 모델이 스스로 고르는" 범용 컴퓨터 유즈 에이전트(GCUA)**를 정의하고, 닫혀 있던 이 스택 전체를 공개하는 프로젝트의 첫 릴리즈입니다.
- **방법**: 핵심은 ① **코드 실행** — GUI 조작을 코드로 써서 루프·조건문과 결합 ② **harness-to-model decision transfer** — 하네스의 고정 규칙이 하던 관찰 선택·작업 상태 판단을 모델 쪽으로 옮기는 설계.
- **결과(저자 보고)**: OSWorld-v2에서 평가한 8개 모델 전부 점수 상승 — 평균 partial score **+19.6pt**, 과제당 스텝 수 **평균 53% 감소**(배치 GUI 전용 실행 대비).
- 🛠 **에이전트 빌더 시사점**: "하네스 규칙을 늘릴까, 모델에게 맡길까" 고민에 대한 실측 답. 8개 모델의 평가 트래젝토리까지 공개라 내 하네스 실패 사례와 비교 디버깅이 가능합니다.
- **한계**: 실기기 평가는 macOS 과제 4개 수준이고, ongoing 프로젝트의 1차 릴리즈입니다.
- [GitHub](https://github.com/Tongyi-MAI/OpenGCUA) · [프로젝트 페이지](https://tongyi-mai.github.io/OpenGCUA/)

## SpecAgent: 트래젝토리 단위 투기 실행

- **저자**: Zilin Wang, Yinhong Liu, Chao Chen, Qun Liu, Zhijiang Guo (arXiv 페이지에 소속 미표기)
- **arXiv**: [2610.21463](https://arxiv.org/abs/2610.21463) (cs.CL, 10/15 공개, arXiv API 검증)
- **핵심 기여**: 투기적 디코딩을 토큰이 아니라 **에이전트 스텝 시퀀스 단위**로 끌어올렸습니다. 강한 모델이 매 스텝을 생성하는 대신, **약한 모델이 초안을 쓰고 강한 모델은 검증만** 합니다.
- **방법**: 약한 모델이 읽기 전용 툴 콜은 실제 실행하며 드래프트(스텝이 실관측에 근거), 환경을 바꾸는 첫 액션은 보류. 강한 모델이 드래프트 구간을 **프리필 1회**로 의미 검증 → 유효한 최장 프리픽스 커밋 → 첫 거부 스텝만 수선.
- **결과(저자 보고)**: τ²-Bench에서 강한 모델 단독 대비 성공률 1pt 이내, 월타임·메모리 트래픽 약 절반. MCP-Atlas 엣지-클라우드 배치에서는 약한↔강한 격차의 53~75% 회복, 강한 모델 생성 토큰은 절반 이하.
- 🛠 **에이전트 빌더 시사점**: 모델 라우팅보다 구현이 단순한 비용 절감 아키텍처. "읽기 전용 vs 쓰기" 툴 분류만 있으면 어느 스택에든 이식 가능한 패턴입니다.
- **한계**: 공개된 코드가 아직 없습니다.

![SpecAgent 워크플로](/images/ai-news-2026-10-17/specagent-flow.svg)

*SpecAgent의 3단계: 약한 모델 드래프트 → 강한 모델 프리필 검증 → 커밋+수선. (자체 제작, 출처: arXiv 2610.21463)*

# 🛠 오픈소스 스포트라이트

모델과 함께 하네스가 세트로 공개되는 날이었습니다.

- **[reflection-oss/mirror](https://github.com/reflection-oss/mirror)** (Rust + Python, Apache-2.0, v1.0.0) — Beam의 **공식 터미널 코딩 에이전트**. `uv tool install reflection-mirror` 한 줄로 설치되고, 저장소 워크트리를 분리해 **병렬 작업**을 돌립니다. 구조가 볼만합니다: `mirror-agent`(Rust 코어) / `mirror-cli` / `mirror-sandbox`·`mirror-sandboxd`(샌드박스 데몬 분리) / `protocols`(프로토콜 정의). 체크포인트 테스트에 git 대신 Jujutsu(`jj`)를 쓰는 점도 특이합니다. 10/14~16 커밋 활발(클론 검증, 스타 수는 세션 API 제한으로 미확인). **활용**: Beam 없이도 다른 프로바이더 연결이 되므로, Claude Code·Codex와 또 다른 하네스 설계 레퍼런스로.
- **[Tongyi-MAI/OpenGCUA](https://github.com/Tongyi-MAI/OpenGCUA)** (Python + TypeScript, Apache-2.0) — 위 논문의 실제 코드. macOS 14+ 실기기 하네스, OSWorld 통합 예제, 크로스 디바이스 SDK(컴퓨터·모바일·브라우저 공통 인터페이스), 그리고 8개 프런티어 모델의 **평가 트래젝토리 원본**이 들어 있습니다. 10/16에도 커밋 중(클론 검증). **활용**: 컴퓨터 유즈 에이전트를 만들기 시작할 때 빈 화면에서 출발하지 않게 해주는 출발점.

# 🧑‍💻 Codex & Claude Code 실전 팁

**1. 🟩 Codex / 카테고리: MCP** — [커밋 #54656](https://github.com/openai/codex/commit/0df4aa67781ae45a3c97befa4db48b734afe46d9) · [#54654](https://github.com/openai/codex/commit/beae473be8564d884a8cfe9704194a5c803d2ac1)

- 💡 **핵심**: 10/16 머지 두 건으로 Codex의 MCP 레이어가 동적으로 변했습니다. `mcp_tool_list_changed` 기능을 켜면 서버가 `tools/list_changed` 알림을 보낼 때 **같은 턴 안에서 툴 카탈로그를 갱신**해 새 툴을 바로 호출하고, 코드 모드의 동적 툴 콜은 이제 `Promise.all`로 **병렬 실행**됩니다.
- 📝 **방법**: `~/.codex/config.toml`에서:

```toml
[features]
mcp_tool_list_changed = true
```

- 🎯 **언제**: 인증 후에야 툴을 늘려주는 MCP 서버, 또는 탐색 결과에 따라 툴을 동적으로 노출하는 게이트웨이를 붙일 때. 이전엔 다음 턴까지 새 툴이 안 보였습니다.
- ⚠️ **주의**: 기본 비활성(Under Development 단계)이고, 갱신 실패 시 직전 카탈로그 유지 + 5초 쿨다운으로 동작합니다. 릴리즈 반영 시점은 확인 필요.
- ⭐ 추천도: ★★★☆☆ (해당 유즈케이스면 ★★★★★)

**2. 🟦 Claude Code / 카테고리: Subagent·헤드리스 운영** — [v2.1.302 체인지로그](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

- 💡 **핵심**: 10/16 릴리즈로 **헤드리스·SDK의 기본값이 여럿 바뀌었습니다.** 체크리스트: ① 포크 서브에이전트(`subagent_type: "fork"`)가 `claude -p`·Agent SDK·데스크톱·VS Code에서도 기본 활성 ② 서드파티 프로바이더에서 권한 모드를 지정하지 않은 `claude -p`/SDK 세션은 이제 `default` 모드로 시작(기존 자동 동작 기대했다면 `--permission-mode auto` 명시) ③ 클라이언트측 auto 모드 분류기의 모델을 `CLAUDE_CODE_AUTO_MODE_MODEL`로 지정 가능.
- 📝 **방법**: CI·cron에서 도는 파이프라인이라면 오늘 점검:

```bash
# 포크 서브에이전트가 부담스러우면 끄기
export CLAUDE_CODE_FORK_SUBAGENT=0
# Bedrock/Vertex 등에서 기존 동작 유지가 필요하면
claude -p "..." --permission-mode auto
```

- 🎯 **언제**: 서드파티 게이트웨이(Bedrock·Vertex) 위에서 무인 실행 중인 모든 자동화.
- ⚠️ **주의**: 디폴트 변경은 조용히 동작을 바꿉니다. 권한 프롬프트 대기로 파이프라인이 멈춰 있는지 로그부터 확인하세요.
- ⭐ 추천도: ★★★★★ (무인 운영자 필수 점검)

**3. 🟪 공통 / 카테고리: Workflow(비용 설계)** — [arXiv 2610.21463](https://arxiv.org/abs/2610.21463)

- 💡 **핵심**: SpecAgent의 교훈은 프레임워크 없이도 적용됩니다 — **툴을 읽기 전용/쓰기로 분류**해 두면, 읽기 전용 구간은 작은 모델이 실제 실행하며 초안을 만들고 큰 모델은 구간 단위로 검증·수선만 하게 만들 수 있습니다.
- 📝 **방법**: 툴 정의에 `readOnlyHint`(MCP annotation) 같은 메타데이터부터 달아두는 것이 1단계. 쓰기 액션 직전을 체크포인트로 삼으면 됩니다.
- 🎯 **언제**: 검색·파일 읽기·조회가 스텝의 대부분인 리서치형·운영형 에이전트.
- ⚠️ **주의**: 검증자(강한 모델)가 놓치는 의미 오류는 그대로 커밋됩니다. 쓰기 액션만큼은 반드시 강한 모델 또는 사람의 게이트를 유지하세요.
- ⭐ 추천도: ★★★★☆
