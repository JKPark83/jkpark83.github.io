# 🔥 오늘의 핵심

프론티어 모델 신작은 없는 조용한 주말. 대신 오늘 눈에 띄는 흐름은 하나다 — **"매번 값비싼 추론으로 다시 계산하지 말고, 환경·메모리를 결정적(deterministic)으로 재사용하라."** 학습 쪽에선 EnvACE가 외부 시뮬레이터 없이 정책이 스스로 환경을 "연기"해 월드 모델을 내재화했고, 컨텍스트 쪽에선 Activity Frames가 화면 로그를 LLM 요약 대신 모델 0개짜리 파이프라인으로 컴파일해 정확도를 끌어올렸다.

# 📚 주목 논문

## 1) EnvACE — 월드 리허설로 환경을 파라미터에 내재화

- **저자/소속:** Zishan Xu, Zhiyuan Yao 외 (Yasheng Wang·Weinan Zhang 등 공동, 산학 협업)
- **arXiv:** [2608.06197](https://arxiv.org/abs/2608.06197) · cs.AI · 2026-08-06
- **핵심 기여:** 장기(long-horizon) 툴 사용 에이전트를 학습할 때 필요한 "실행 가능한 외부 환경/시뮬레이터"를 없앤다. 정책이 **행동(act) ⇄ 리허설(rehearse)** 을 번갈아 수행 — tool call을 만든 뒤, 곧바로 환경 역할을 스스로 연기해 그 응답을 생성하고, 다음 결정을 그 응답에 조건화한다.
- **방법(2–3줄):** 두 역할을 하나의 정책으로 두고 task-success 보상으로 end-to-end 최적화. 행동↔응답 관계가 파라미터에 스며들어 "에이전트 월드 모델"이 생긴다. 테스트 시엔 실제 실행 전 **사설 리허설**로 결과를 미리 시뮬레이션.
- **결과(검증):** BFCL-v4 · tau²-Bench · VitaBench · FinMCP-Bench에서 환경-스케일링 베이스라인 대비 종합 우위. 테스트 시 리허설 예산을 조금 쓰면 외부 호출 0회로 추가 향상.
- 🛠 **에이전트 빌더 시사점:** "커밋 전에 결과를 먼저 예측한다"는 아이디어는 학습 없이도 쓸 수 있다 — 위험/비용 큰 도구는 dry-run 게이트를 붙여 예상 결과를 먼저 뽑고 검증하라.
- ⚠️ **한계:** 리허설 응답의 충실도가 곧 성능 상한. 실제 환경과 편차가 크면 잘못된 월드 모델을 학습할 위험.
- 코드: [github.com/Within-yao/EnvACE](https://github.com/Within-yao/EnvACE)

![EnvACE 월드 리허설 방법 다이어그램: 행동과 리허설을 번갈아 수행하고 테스트 시 사설 리허설로 커밋 전 검증](/images/ai-news-2026-08-09/envace-flow.svg)
*EnvACE 메서드 — 학습 루프에서 정책이 환경을 "연기"하고, 테스트 시엔 실제 실행 전 사설 리허설로 나쁜 호출을 걸러낸다. (직접 생성, 수치는 초록 기준)*

## 2) Activity Frames — 로그를 "요약"하지 말고 "컴파일"하라

- **저자:** Nossa Iyamu (단독)
- **arXiv:** [2608.05784](https://arxiv.org/abs/2608.05784) · cs.AI · 2026-08-06
- **핵심 기여:** 컴퓨터-사용 에이전트의 메모리가 "사용자가 *말한 것*"만 기록하고 "*한 것*"은 놓친다는 문제 제기. 수동 캡처된 화면 활동을 **모델 0개의 결정적 파이프라인**으로 컴파일한다.
- **방법:** 로컬 캡처 스트림을 타입드 activity frame(앱·사이트·타이밍·입력량 + 원시 행 포인터)으로 분절. 출력이 바이트 단위로 동일 → 캐시 가능·기계적 감사 가능.
- **결과(검증):** 128,756 프레임(51일)을 하루치 기준 **86배 축소**, 68ms. 그 블록을 읽은 에이전트는 하루 질의응답 **98.4%**(Wilson 95% CI 91.7–99.7%) — 같은 캡처의 LLM 요약은 66–80%. 중위 모델이 이 블록만 읽어도 프론티어 모델과 대등.
- 🛠 **에이전트 빌더 시사점:** 세션 히스토리/도구 로그를 매번 LLM으로 요약하면 비싸고 비결정적이다. **규칙 기반으로 구조화·캐싱**하면 토큰↓, 재현성↑.
- ⚠️ **한계:** 단일 사용자 코퍼스 결과라 일반화는 추가 검증 필요.

![Activity Frames 결과: 결정적 컴파일 블록 98.4퍼센트 대 LLM 요약 66에서 80퍼센트, 하루치를 86배 축소](/images/ai-news-2026-08-09/activity-frames.svg)
*결정적 컴파일 블록(98.4%) vs 같은 캡처의 LLM 요약(66–80%). 요약보다 컴파일이 이긴다. (직접 생성, 수치는 초록 기준)*

# 🛠 오픈소스 스포트라이트

> ⚠️ 이번 세션은 GitHub API 접근(egress)이 막혀 별 수는 **웹 출처 기준·API 미검증**입니다.

- **[screenpipe/screenpipe](https://github.com/screenpipe/screenpipe)** · Rust/TS · ⭐ 약 20K (웹 출처, API 미검증)
  화면·오디오를 로컬에서 24/7 캡처해 SQLite에 저장하고 MCP/API로 에이전트에 연결하는 "로컬 워크 메모리". 매초가 아니라 앱 전환·클릭·입력 멈춤 같은 의미 있는 이벤트에서만 스냅샷을 잡는다.
  → **활용:** 오늘의 Activity Frames 아이디어를 실제로 붙여볼 캡처 계층. 개인 로컬 컨텍스트를 Claude/Codex에 MCP로 물릴 때 출발점으로 좋다.

- **[Within-yao/EnvACE](https://github.com/Within-yao/EnvACE)** · Python · ⭐ 신규 (API 미검증)
  위 EnvACE 논문의 공식 코드. 월드 리허설 기반 agentic RL 학습 파이프라인.
  → **활용:** 외부 시뮬레이터 없이 툴-사용 정책을 학습/재현해 보려는 연구·실험용.

두 레포는 같은 흐름의 양쪽 끝이다 — screenpipe는 **캡처/메모리 계층**, EnvACE는 **학습 계층**. "환경을 값싸게 재사용한다"는 오늘의 축을 실전(screenpipe)과 연구(EnvACE)에서 각각 구현한다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — Agent Plugins로 팀 워크플로 이식하기
- **카테고리:** Workflow / MCP
- **출처:** [openai/codex releases (rust-v0.147.0)](https://github.com/openai/codex/releases)
- 💡 **핵심:** Codex CLI 0.147.0이 **포터블 Agent Plugins**를 추가했다. local·personal·workspace·remote 카탈로그를 가로질러 플러그인을 검색·설치할 수 있고, MCP 2026-07-28 스펙을 지원한다.
- 📝 **How-to:** 플러그인을 설치하면 팀 공용 도구/프롬프트/서브에이전트를 매 레포마다 다시 세팅할 필요 없이 카탈로그에서 끌어온다. 자동 승인이 필요한 파이프라인은 새 플래그를 조합:

```bash
# 검토된 명령을 자동 승인(비대화형/CI 친화)
codex exec --approve-for-me "run test suite and fix failing unit tests"
```

- 🎯 **언제:** 여러 레포/팀원이 같은 에이전트 셋업을 공유해야 할 때.
- ⚠️ **주의:** `--approve-for-me`는 승인 마찰을 줄이는 만큼 블래스트 반경이 커진다. CI에선 read-only/워크스페이스 한정 샌드박스와 함께만.
- ⭐ **추천:** 팀 표준 에이전트를 굴린다면 지금 카탈로그화해 둘 가치 충분.

## 🟦 Claude Code — 신뢰하지 않는 디렉터리 자동 차단
- **카테고리:** Security / Workflow
- **출처:** [code.claude.com/docs/en/changelog](https://code.claude.com/docs/en/changelog)
- 💡 **핵심:** v2.1.225에서 `claude agents`가 **신뢰되지 않은 디렉터리(untrusted directory)** 진입 시 워크스페이스 신뢰 프롬프트를 띄운다. 낯선 레포를 클론해 바로 에이전트를 돌릴 때의 위험(악성 설정/훅)을 한 단계 막아준다.
- 📝 **How-to:** 최신으로 올린 뒤 새 레포에서 세션을 시작하면 신뢰 여부를 먼저 묻는다. 자동화/헤드리스에선 신뢰 정책을 미리 정해 두자.

```bash
claude --version   # 2.1.225 이상인지 확인, 낮으면 업데이트
```

- 🎯 **언제:** 남의 레포/PR을 로컬에서 에이전트로 검토·실행하기 직전.
- ⚠️ **주의:** 프롬프트를 습관적으로 "신뢰"로 넘기면 방어 의미가 없다. 처음 보는 코드는 한 번 눈으로 훑고.
- ⭐ **추천:** 낮은 버전 사용자는 업데이트 권장(이번 주 릴리즈에 401/키체인 관련 수정도 동반).

## 🟪 공통 — "커밋 전 리허설" 게이트
- **카테고리:** Context / Reliability
- **출처:** [arXiv:2608.06197 (EnvACE)](https://arxiv.org/abs/2608.06197)
- 💡 **핵심:** EnvACE의 테스트-시 사설 리허설을 학습 없이 흉내내기 — 위험/비용 큰 tool call은 **실행 전에 예상 결과를 먼저 뽑아 검증**하고 통과할 때만 커밋.
- 📝 **How-to:**

```text
사용자 요청 → 도구 호출 계획
  ↳ (리허설) "이 호출의 예상 결과/부작용은? 실패 시 신호는?"
  ↳ 검증: 예상과 스키마/전제 불일치면 재계획
  ↳ 통과 시에만 실제 실행(commit)
```

- 🎯 **언제:** 결제·삭제·외부 쓰기 등 되돌리기 어려운 도구.
- ⚠️ **주의:** 리허설이 항상 맞진 않는다 — 게이트일 뿐, 실제 검증(테스트/드라이런 API)을 대체하진 못한다.
- ⭐ **추천:** high-risk 도구부터 선별 적용.
