# 🔥 오늘의 핵심

# 🤖 모델 & 릴리즈 레이더

- **OpenAI Agents API 퍼블릭 베타 (9/10)** — Codex와 ChatGPT for Work를 굴리던 관리형 하니스를 API 호출 하나로 제공한다. 자동 컨텍스트 관리, 병렬 툴 실행, 서브에이전트 위임이 포함되고, 실행 환경은 OpenAI 호스팅 샌드박스 또는 Cloudflare·Vercel·Oracle 같은 파트너 중에서 고른다. 별도 수수료 없이 토큰·툴 사용량 과금. OpenAI가 공개한 초기 사례로는 비용 60% 절감(SafetyKit), 실패율 86% 감소(Hypha)가 있다. [OpenAI 발표](https://openai.com/index/introducing-the-agents-api/)
- **Sakana AI Fugu Ultra v2 · Fugu Max (9/11)** — 단일 모델이 아니라 "오케스트레이션 엔진". 고정된 오픈·특화 모델 풀로 작업을 라우팅하고 자기 자신을 재귀 호출하도록 학습됐다. 풀에 Fable 5.1이나 GPT-6-Astra 같은 독점 프론티어 모델이 없다는 점이 특징. 가격은 입력 $5 / 출력 $30 / 캐시 $0.50 (1M 토큰당), 272K 초과 컨텍스트는 $10/$45. reasoning effort(high/xhigh/max), 구조화 출력, 이미지·PDF 입력, 웹서치를 지원한다. sakana.ai가 이 세션에서 접속 차단이라 수치는 OpenRouter 등록 정보와 다중 보도로 교차 확인했다. [Sakana 발표](https://sakana.ai/fugu-max-release/) · [OpenRouter](https://openrouter.ai/sakana/fugu-ultra-v2)

# 📚 주목 논문

## NCP-ArchPreview: Next Concept Prediction (arXiv 2609.10715, cs.CL)

- **저자**: The Intern-NCP Team — Shanghai AI Lab · 상하이교통대 LUMIA Lab (9/9 공개, HF Daily 170 upvotes 1위)
- **핵심 기여**: 다음 토큰 예측(NTP)에 더해, 여러 토큰에 걸친 이산 "개념"을 예측하는 NCP 목표를 추가한 잠재공간 언어 모델.
- **방법**: 모델의 은닉 상태에서 product-quantized 개념 어휘를 직접 구성하고, 전용 Concept Module이 다음 개념을 예측한다. 예측된 개념은 토큰 레벨로 피드백되어 이후 생성을 가이드하며, NTP와 NCP를 end-to-end로 공동 학습한다.
- **검증된 결과**: 8.9B 파라미터를 Dolma-3 5.73T 토큰으로 학습 — 잠재공간 LM으로는 최대 규모 실증. 가중치와 중간 체크포인트가 Apache 2.0으로 [Hugging Face](https://huggingface.co/ArchSpace-Collection/NCP_ArchPreview_dolma3_8.9B_Stage1_Step1000000)에 공개됐다.
- 🛠 **에이전트 빌더 시사점**: 토큰보다 굵은 단위의 계획 신호가 백본에 들어가는 흐름. 장기 플래닝이 필요한 에이전트 백본 연구 방향으로 주시할 것.
- **한계**: 이름대로 "ArchPreview" — 아키텍처 실증 단계이고, 다운스트림 벤치마크 수치는 이번 요약에서 별도 검증하지 못했다.
- [arXiv 링크](https://arxiv.org/abs/2609.10715)

## EvoSafeHarness: 배포별 안전 하니스 자동 합성 (arXiv 2609.05903, cs.CR)

- **저자**: Nanxi Li, Yingzi Ma, Yulong Cao, Edward Suh, Bo Li, Dawn Song 외 (9/5 공개, HF Daily 36 upvotes)
- **핵심 기여**: "전문가가 한 번 설계해 모든 모델·도메인에 적용"하던 안전 하니스를, 고정된 모델 × 대상 도메인 조합마다 자동으로 합성하는 최적화 프레임워크.
- **방법**: 자연어 정책과 실행 가능한 코드 로직을 함께 탐색하고, fresh-context 적대적 리뷰로 벤치마크에만 특화된 규칙을 걸러낸다.
- **검증된 결과**: DecodingTrust-Agent에서 평균 공격 성공률 45.6% → 10.0% (효용 손실 3.3pt), AgentDojo에서 ASR 0%를 유지하며 효용 82.8% — 같은 지점의 CaMeL 대비 2배. 적응형 PAIR 공격에서도 평균 ASR 20% 미만.
- 🛠 **에이전트 빌더 시사점**: 한 모델에 맞춘 가드레일이 다른 모델에선 과차단이 된다는 걸 정량화했다. 모델 교체 시 하니스 재튜닝을 체크리스트에 넣자.
- **한계**: frozen model 가정이라 모델 업데이트마다 재최적화가 필요하고, 탐색 비용이 든다.
- [arXiv 링크](https://arxiv.org/abs/2609.05903)

# 🛠 오픈소스 스포트라이트

두 저장소 모두 이 세션에서 클론으로 검증했다(마지막 커밋 둘 다 9/11). star 수는 GitHub API 차단으로 미확인.

- **[openai/openai-agents-js](https://github.com/openai/openai-agents-js)** (TypeScript, v0.18.0) — OpenAI Agents SDK의 JS/TS 구현. 이번에 눈여겨볼 것은 베타인 **샌드박스 에이전트**: `Manifest`로 워크스페이스 파일·저장소를 선언하고, capabilities로 파일시스템·셸·스킬·메모리·압축 툴을 붙이면, 로컬(Unix/Docker)부터 E2B·Modal·Vercel·Cloudflare 같은 호스티드 샌드박스까지 클라이언트만 바꿔 실행된다. `sandbox.session`/`snapshot`으로 이전 작업 재개도 지원. **활용처**: Agents API(관리형)로 가기 전, 같은 패턴을 셀프호스트로 검증하는 용도로 정확히 맞다.
- **[cloudflare/agents](https://github.com/cloudflare/agents)** (TypeScript) — Durable Objects 위에 에이전트를 "영속 상태를 가진 실행 환경"으로 올리는 프레임워크. 에이전트마다 자체 상태·스토리지·라이프사이클을 갖고, 유휴 시 동면(hibernate)해서 수백만 개를 띄워도 비활성 비용이 없다. 실시간 동기화, 스케줄링, MCP 내장에 openai-sdk 연동 예제 디렉터리도 있다. **활용처**: 사용자·세션 단위로 오래 사는 에이전트(예: 유저별 개인 비서)를 엣지에 상주시키는 아키텍처.

두 저장소의 역할 구분은 위 "Agents API 스택 비교" 다이어그램 하단에 정리했다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — Codex 하니스를 내 앱에서: Agents API 검토 포인트

- **카테고리**: Workflow · **소스**: [Introducing the Agents API](https://openai.com/index/introducing-the-agents-api/)
- 💡 Codex의 강점은 모델만이 아니라 하니스(세션 유지, 컨텍스트 압축, 복구)였는데, 그 하니스가 이제 API로 분리돼 나왔다.
- 📝 오늘 해볼 것: 직접 만든 에이전트 루프에서 (1) 컨텍스트 압축, (2) 장기 세션 복구, (3) 서브에이전트 분기 — 셋 중 유지보수가 가장 아픈 걸 골라, 그 부분만 Agents API 세션으로 옮기는 실험을 설계한다. 샌드박스는 OpenAI 호스팅으로 시작하고, 통제가 필요해지면 Cloudflare·Vercel 파트너로 옮긴다.
- 🎯 수 시간~수 일 단위로 도는 에이전트를 운영 중인데 하니스 코드가 계속 터지는 팀.
- ⚠️ 퍼블릭 베타라 API 형태가 바뀔 수 있고, 토큰 과금이라 장기 세션 비용을 반드시 모니터링해야 한다. 하니스를 넘기는 만큼 벤더 종속도 커진다.
- ⭐ 당장 이전하지 않더라도, 자기 하니스와의 기능 비교표를 만들어 둘 가치가 있다.

### 🟦 Claude Code — `claude plugin eval`로 플러그인 회귀 테스트

- **카테고리**: Eval · **소스**: [CHANGELOG 2.1.269](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 플러그인(스킬·훅·커맨드)의 동작을 평가 스위트로 돌려 점수화된, 재현 가능한 결과를 받을 수 있게 됐다. 결과는 JSON + HTML 리포트로 나온다.
- 📝 시작점:

```bash
claude plugin eval --help
```

  팀 플러그인 저장소에 eval 스위트를 추가하고, 플러그인 수정 PR마다 CI에서 돌리는 구조로 잡으면 된다.
- 🎯 팀 공용 플러그인을 고칠 때마다 "다른 워크플로가 안 깨졌나" 수동 확인하고 있었다면.
- ⚠️ 평가 스위트는 직접 작성해야 하고, 평가 실행 자체가 토큰을 소비한다.
- ⭐ 플러그인을 "코드"로 취급하는 마지막 퍼즐 조각. 스킬 배포 파이프라인이 있는 팀이라면 오늘 붙여보자.

### 🟪 공통 — 안전 하니스는 ASR만 보지 말고 과차단을 같이 재라

- **카테고리**: Eval · **소스**: [arXiv 2609.05903](https://arxiv.org/abs/2609.05903)
- 💡 EvoSafeHarness의 실무 교훈: 하니스 강도는 배포(모델 × 도메인)마다 최적점이 다르다. 공격 성공률(ASR)만 보고 조이면 효용이 조용히 죽는다.
- 📝 오늘 점검할 것: 가드레일 평가에 (1) ASR과 (2) 정상 작업 통과율(utility)을 한 대시보드에 놓고, 모델을 교체할 때마다 두 수치를 다시 잰다. "이전 모델에서 튜닝한 차단 규칙"이 새 모델에선 과차단의 주범이 되기 쉽다.
- 🎯 백본 모델 업그레이드를 앞두고 있는 팀 — 하니스 재검증을 마이그레이션 체크리스트에 추가.
- ⚠️ 효용 측정에는 대표성 있는 정상 태스크 셋이 필요하다. 없으면 그것부터.
- ⭐ 반나절이면 기존 평가에 utility 축 하나를 추가할 수 있다.
