# 🔥 오늘의 핵심

긴 호흡 에이전트의 컨텍스트 관리가 "히스토리를 얼마나 잘 압축하나"에서 **"세계에 대한 믿음(belief)을 어떻게 유지하나"**로 한 칸 더 이동했습니다. PoS 논문은 대화 로그 대신 '현재 상태 추정 + 미해결 요구사항'을 컨텍스트로 들고 다니는 것만으로 4개 벤치마크 전부에서 최고 성능을 찍었습니다. 학습 없이 추론 시점에 적용하는 구조라, 오늘 바로 프롬프트 수준에서 흉내 낼 수 있습니다.

# 📚 주목 논문

## PoS: 기억을 버리고 믿음을 유지한다

- **저자**: Yu Luo, Jiamin Jiang, Yongqian Sun, Dan Pei 외 (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2610.01415](https://arxiv.org/abs/2610.01415) (cs.AI, 10/1 공개)
- **핵심 기여**: 상호작용 히스토리를 보존·압축하는 대신, **명시적 belief state**(현재 세계 상태 추정 + 미해결 과제 요구사항)를 결정 컨텍스트로 유지하는 추론 시점 프레임워크.
- **방법**: 관찰이 들어올 때마다 belief를 갱신하고 일관성을 검증 → 행동은 계속하는데 진전이 없는 **Belief Trapping**을 감지 → 갇힘 패턴과 미해결 요구사항 유형에 맞춰 복구.
- **결과**: 실행·진단을 아우르는 4개 벤치마크, 3개 LLM 백본 전부에서 최고 성능(논문 보고치). 컨텍스트가 길어져도 성능이 버티는 것도 확인.
- 🛠 **Agent Builder 시사점**: 학습이 필요 없는 구조라 적용 장벽이 낮습니다. 아래 공통 팁 참고.
- **한계**: belief 갱신·검증이 매 턴 추가 추론 비용을 만들고, 구체 수치는 논문 본문 확인이 필요합니다.

![PoS belief 상태 유지 루프](/images/ai-news-2026-10-04/pos-belief-loop.svg)

*PoS의 6단계 루프. 컨텍스트에 쌓이는 건 로그가 아니라 "지금 세계가 어떤 상태이고 뭐가 남았는지"다. (자체 제작)*

## GraphForge: 에이전트 훈련장을 실제 파일로 짓는다

- **저자**: Qisheng Su, Zehui Chen, Tao Gui, Feng Zhao 외 (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2609.38923](https://arxiv.org/abs/2609.38923) (cs.CL, 9/30 공개)
- **핵심 기여**: "파일 읽고 도구 돌려 산출물 내는" 실무형 에이전트의 훈련 데이터를 합성하는 파이프라인. 실제 파일들로 작업공간을 만들고 그 위에 **증거 그래프**를 세워, 과제 지시문과 채점 루브릭을 모두 그래프에서 유도합니다. 루브릭의 각 항목이 검증에 필요한 파일에 앵커링되는 게 핵심.
- **방법**: 직업 기반 시드 → 실제 파일 작업공간 조립 → 증거 그래프 → 과제·루브릭 생성 → 초기 롤아웃으로 실행 가능성 점검 → 수선 에이전트가 과제를 교정.
- **결과**: Qwen3.6-27B를 2,169개 궤적으로 SFT하자 GDPVal 1445.7(+65.7, OpenHands 하네스), Workspace-Bench-Lite 63.7(+7.7)·SpreadsheetBench II 24.0(+13.7, Claude Code 하네스). 루브릭으로 자기 롤아웃을 선별한 rejection fine-tuning이 추가 상승(모두 논문 보고치). 데이터·모델 공개.
- 🛠 **Agent Builder 시사점**: 에이전트 평가 세트를 만들 때 "채점 기준이 어떤 파일로 검증되는지"를 명시하는 것만으로 루브릭 품질이 달라집니다. 모델이 지어낸 가짜 작업공간으로 평가하고 있다면 재고할 것.
- **한계**: 파이프라인 자체가 여러 에이전트 단계로 구성돼 구축 비용이 있고, 보고 수치는 Qwen 계열 중심입니다.

**🟩 Codex — 커스텀 프로바이더에 capability 선언** (Config)
- 소스: [commit c6049eb](https://github.com/openai/codex/commit/c6049ebd9694c941386d85fb3e09acab2af289cb) (#50459, 10/2 머지)
- 💡 LiteLLM·사내 게이트웨이 등 Responses 호환 커스텀 프로바이더에 웹 접근·원격 컴팩션 동작을 명시할 수 있게 됐습니다.
- 📝 `config.toml`에:

```toml
[model_providers.custom.capabilities]
external_web_access = false   # 호스티드 웹서치의 실시간 접근 차단
remote_compaction = "unsupported"  # 로컬 컴팩션 강제 ("v2"면 원격)
```

- 🎯 프록시 뒤에서 Codex를 돌리는데 웹서치가 멋대로 밖에 나가거나, 컴팩션이 프로바이더에서 깨질 때.
- ⚠️ 생략한 capability는 기존 프로바이더 기본값 유지. 방금 머지된 변경이라 안정 릴리스 반영 버전을 확인할 것.
- ⭐ 게이트웨이 운영 팀이라면 바로 적어둘 가치.

**🟦 Claude Code — plugin-dev 툴킷으로 플러그인 스캐폴딩** (Workflow)
- 소스: [plugins/plugin-dev README](https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/README.md)
- 💡 공식 레포에 "플러그인을 만들어주는 플러그인"이 들어 있습니다. 훅·MCP·스킬·커맨드·에이전트 등 7개 전문 스킬과 검증 스크립트 포함.
- 📝 설치 후:

```bash
/plugin-dev:create-plugin DB 마이그레이션 관리 플러그인
```

  요구사항 질문 → 컴포넌트 설계 → 구현 → `validate-hook-schema.sh` 등 검증 → 문서화까지 8단계를 안내받습니다.
- 🎯 팀 반복 워크플로(배포 체크리스트, 리뷰 규칙)를 플러그인으로 포장해 배포할 때.
- ⚠️ 생성물은 결국 마크다운+스크립트이므로, 검증 단계를 건너뛰지 말고 실제 세션에서 테스트할 것.
- ⭐ 어제 소개한 `--max-findings`류 옵션을 자주 쓴다면, 다음 단계는 직접 만드는 쪽입니다.

**🟪 공통 — 컨텍스트에 'belief 블록'을 유지하라** (Context)
- 소스: [arXiv 2610.01415](https://arxiv.org/abs/2610.01415)
- 💡 PoS의 핵심은 프롬프트 수준에서 흉내 낼 수 있습니다: 긴 작업 중 에이전트가 매 N턴마다 **"현재 상태 추정 / 미해결 요구사항 / 최근 3턴의 진전"** 세 줄짜리 블록을 갱신하게 하고, 이 블록을 컴팩션에서 항상 보존하도록 지시.
- 🎯 같은 파일을 반복해서 열어보거나, 실패한 접근을 다시 시도하는 "맴돌이" 증상이 보일 때. "진전 없음이 3턴 지속되면 접근 자체를 바꿔라"는 규칙이 Belief Trapping 복구의 최소 구현입니다.
- ⚠️ 블록 갱신 자체가 토큰을 쓰므로 짧게 유지하는 게 요령.
