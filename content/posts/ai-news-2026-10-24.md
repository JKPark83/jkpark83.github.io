# 🔥 오늘의 핵심

오픈웨이트 2연타. 어제 "아직 없음"을 확인했던 **MiniMax M3.1-Flash**(428B MoE, 1M 컨텍스트, 멀티모달) 웨이트가 당일 낮에 올라왔고, 신생 랩 Recursive는 **맥북 한 대에서 도는 40B 코딩 에이전트 모델 Flint**를 Apache 2.0으로 풀었다. 서빙 쪽에서도 llm-d 1.0이 나와, 데이터센터부터 노트북까지 "에이전트를 어디서 돌릴 것인가"의 선택지가 하루 만에 넓어졌다.

# 🤖 모델 & 릴리즈 레이더

- **MiniMax M3.1-Flash 오픈웨이트 공개** — 예고일(10/23) 아침까지 비어 있던 [HF 저장소](https://huggingface.co/MiniMaxAI/MiniMax-M3.1-Flash)에 당일 낮(KST) 웨이트가 올라온 것을 확인했다. 총 428B·활성 23B MoE, **1M 컨텍스트**, 텍스트+이미지+비디오 입력, 전 레이어 sparse attention에 스펙큘레이티브 디코딩용 draft head까지 포함. 라이선스는 자체 `minimax-community`라 상용 조건은 직접 확인 필요. 에이전트 빌더 관점의 재미 포인트: 모델 카드 벤치마크의 측정 하네스가 OpenCode·Codex·Claude Code·mini-SWE-agent다. 이제 모델 평가 자체가 에이전트 하네스 위에서 돌아간다.
- **Recursive Flint (10/21, Apache 2.0)** — [모델 카드](https://huggingface.co/RecursiveSI/flint) 기준 39.8B 파라미터에 토큰당 활성 약 2.5B인 코딩 에이전트 특화 MoE. 262K 컨텍스트, 지식 컷오프 2026-06. 자체 측정으로 SWE-bench Verified 74.2%, Terminal-Bench 2.1 54.9%. H200/B300 1장용 SGLang 킷이 동봉되고, 전용 로컬 엔진(아래 오픈소스)으로 Apple Silicon에서도 돈다. "작고 많은 호출"을 맡길 로컬 서브에이전트 후보.

# 📚 주목 논문

## Adaptive Skill Granularity for Coding Agents

- **저자**: Dingxuan Zhang, Yanhui Jiang, Jun Wang, Hefeng Zhou (소속 미표기)
- **arXiv**: [2610.31461](https://arxiv.org/abs/2610.31461) (cs.AI, 10/22)
- **핵심 기여**: 스킬 라이브러리를 "검색해서 쓰는 자원"이 아니라 **런타임에 제어하는 실행 추상화**로 다뤘다. 같은 태스크도 매크로 스킬·원시 툴 콜·하이브리드로 풀 수 있는데, 어떤 입도(granularity)로 실행할지를 정책 문제로 정식화.
- **방법**: 피처 기반 입도 컨트롤러가 태스크 구조·실행 상태를 보고 경로를 라우팅하고, 매크로 스킬이 실패하면 FSM 복구 실행기가 마이크로 스텝으로 이어받는다.
- **결과**: 고정 매크로 실행은 맞을 땐 효율적이지만 미스매치에 취약했고, 런타임 라우팅+명시적 매크로→마이크로 복구가 고정 입도로는 못 푸는 실패를 복구했다(검증자 정의 성공 기준).
- 🛠 **Agent Builder 시사점**: Claude Code Skills처럼 스킬을 쌓는 팀이라면, 스킬 문서에 "실패 시 원시 툴로 돌아오는 경로"를 함께 설계하라는 얘기다. 스킬이 안 맞는 입력에서 조용히 망가지는 게 최악이다.
- **한계**: 결정적(deterministic) 코딩 에이전트 프로토콜 위 평가라, 실제 하네스·실모델 노이즈에서의 재현은 숙제.

![Adaptive Skill Granularity 방법 구조 다이어그램 — 입도 컨트롤러와 FSM 복구 실행기](/images/ai-news-2026-10-24/skill-granularity.svg)

*매크로 실패를 받아내는 복구 FSM이 핵심. 수치가 아니라 구조로 기여하는 논문이다.*

## LLM Multi-Agent Systems Are Vulnerable to Herding and Runaway Cascades

- **저자**: Farnoosh Hashemi, Shiyu Ji, Joice Chen, Michael W. Macy
- **arXiv**: [2610.30769](https://arxiv.org/abs/2610.30769) (cs.AI, 10/22)
- **핵심 기여**: 고전 Music Lab 실험을 LLM 에이전트 대집단으로 재현. 다른 에이전트의 누적 추천 수를 보여주자 **폭주 캐스케이드**가 발생해, 곡의 실제 매력과 무관한 극단적 쏠림이 나타났다.
- **결과**: LLM 집단은 인간보다 허딩에 훨씬 취약했고, 인간과 달리 **쏠림을 스스로 교정하지 못했다**.
- 🛠 **Agent Builder 시사점**: 멀티에이전트 평가·투표·추천 설계에서 에이전트끼리 서로의 선택 집계를 보게 하면 앙상블 효과가 사라지고 한 방향으로 폭주한다. 독립 실행 후 외부에서 집계하는 게 기본값이어야 한다.
- **한계**: 음악 추천 도메인 실험이라 코드 리뷰·사실 판단 태스크로의 일반화는 추가 검증 필요.

# 🛠 오픈소스 스포트라이트

- **[llm-d/llm-d](https://github.com/llm-d/llm-d)** (Apache 2.0) — 쿠버네티스 위 분산 LLM 추론 스택. **v1.0.0 태그(10/20)를 클론으로 확인**했다. Red Hat·Google Cloud·IBM Research·CoreWeave·NVIDIA가 창립한 CNCF 샌드박스 프로젝트. prefix-cache 인지 라우팅(README 기준 라운드로빈 대비 처리량 3배·TTFT 2배, Tesla/Red Hat 벤치), KV 캐시 계층 오프로딩(동시 250유저에서 13.9배), prefill/decode 분리. 멀티턴 에이전트 트래픽은 프리픽스 재사용이 생명이라, 어제 다룬 "캐시 엔지니어링" 흐름의 인프라 버전이다. vLLM/SGLang 위에서 동작.
- **[recursive-oss/rec](https://github.com/recursive-oss/rec)** (Go, Apache 2.0) — Flint 전용 로컬 추론 엔진. M4 Pro 이상 + 통합메모리 48GB에서 4비트 가중치로 돌고, 자체 벤치 기준 llama.cpp 대비 디코드 처리량 **1.4~2.6배**. 눈에 띄는 건 10/23 커밋으로 들어온 **Anthropic Messages API(`/v1/messages`) 변환 레이어** — Claude 클라이언트를 로컬 Flint에 물리는 실험이 가능해졌다. 오프라인·민감 코드 환경의 바이브코딩 백엔드 후보.

두 저장소 모두 클론으로 실존·활동(각각 10/22, 10/23 커밋)을 확인했고, 스타 수는 이 세션의 API 제약으로 확인하지 못했다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — Guardian(auto_review) 리뷰 예산·정책 설정 (카테고리: Review)

- **소스**: [openai/codex 커밋 d681745](https://github.com/openai/codex/commit/d6817454d76885e9d0e118bbf82e507aed6f715a) (10/23, 클론으로 확인)
- 💡 Codex에는 에이전트 행동을 별도 모델이 검사하는 **Guardian(auto review)** 레이어가 조용히 쌓이고 있다. 이번 주에만 관련 커밋 11개. 이제 리뷰 전체 예산이 설정 가능해졌다.
- 📝 `config.toml`에서:

```toml
[auto_review]
timeout_ms = 120000      # 기본 90,000ms, 0이면 무제한
policy = "사내 보안 정책 텍스트"   # Guardian 프롬프트에 주입
```

- 🎯 Guardian 리뷰가 타임아웃으로 끊기는 긴 턴, 조직 정책을 리뷰 기준에 넣고 싶을 때.
- ⚠️ 공식 문서에 아직 없는 실험 영역이다. 필드 정의는 `codex-rs/config/src/config_toml.rs`의 `AutoReviewToml`에서 직접 확인했다.
- ⭐ 추천도: 플릿·엔터프라이즈 운영자는 지금부터 추적할 가치.

### 🟦 Claude Code — 2.1.309, 무인 세션이 덜 죽는다 (카테고리: Workflow)

- **소스**: [CHANGELOG 커밋 65823ec](https://github.com/anthropics/claude-code/commit/65823ec0034ed0aa0266bc43903fefd3ff94a327) (10/23, 클론으로 확인)
- 💡 bypass permissions 모드에서 위험한 `rm`/`rmdir`가 확인 대기로 세션을 멈추는 대신 **즉시 거부+재작성 힌트**로 바뀌었다. 무인 파이프라인이 삭제 명령 하나에 밤새 멈춰 있는 패턴이 사라진다.
- 📝 함께 알아둘 변경: `sed -i`가 시뮬레이션 미리보기가 아니라 **실제로 실행**되고 `/rewind`로 복구되지 않는다. 샌드박스가 셸 시작 파일(.bashrc 등)을 샌드박스 밖에서 실행하던 구멍도 막혔다.
- 🎯 CI·크론으로 Claude Code를 돌리는 무인 환경 전부.
- ⚠️ `sed -i`에 의존하던 복구 워크플로는 점검할 것. 삭제는 애초에 이동/휴지통 패턴으로 짜는 게 안전하다.
- ⭐ 추천도: 무인 운영자라면 릴리즈 노트 정독 권장.

### 🟪 공통 — 에이전트 앙상블에 "득표수"를 보여주지 마라 (카테고리: Eval)

- **소스**: [arXiv 2610.30769](https://arxiv.org/abs/2610.30769)
- 💡 병렬 리뷰어·채점자·추천 에이전트가 서로의 중간 결론이나 집계를 보면, 독립성이 깨지고 폭주 캐스케이드가 시작된다. LLM은 인간보다 쏠림이 심하고 자기교정도 못 한다.
- 📝 N개 에이전트 평가 패턴: 각자 **빈 컨텍스트에서 독립 실행** → 결과만 수집 → 집계(다수결·평균)는 에이전트 밖 코드에서. "다른 리뷰어 의견을 참고해 재평가" 단계를 넣고 싶다면 1라운드 독립 결과를 고정한 뒤에만.
- 🎯 LLM-as-judge 앙상블, 멀티에이전트 코드 리뷰, A/B 비교 평가.
- ⚠️ 토론(debate) 패턴이 유리한 태스크도 있다. 단, 그 경우에도 집계 수치가 아니라 논거를 교환하게 하라.
- ⭐ 추천도: 평가 파이프라인 있는 팀은 오늘 점검.
