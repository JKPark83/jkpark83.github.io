# 🔥 오늘의 핵심

Mistral이 10/6 **1T급 MoE 모델 Large 4 "Le Chonk"**를 API 퍼블릭 프리뷰로 공개했습니다 — 오픈웨이트는 10월 말 예정이라, Reflection Beam에 이어 "가중치 공개 대기열"이 또 하나 늘었습니다. 연구 쪽에선 Google의 **SHIFT**가 "하니스 하나를 고정하고 모든 쿼리를 받는" 설계가 손해라는 걸 수치로 보였고, 툴링에선 Codex와 Claude Code가 같은 날 **서브에이전트 effort**를 각각 '기록'과 '지정' 방향에서 1급 시민으로 올렸습니다. 위임 비용을 계층화할 수 있는 날입니다.

# 🤖 모델 & 릴리즈 레이더

- **Mistral Large 4 "Le Chonk" 공개** — 1T급(보도 기준 1.05T) granular MoE에 활성 파라미터 49B, 1M 토큰 컨텍스트, 1.6B 비전 인코더, 160+ 언어. 유럽 내 4,000 GPU로 학습했고, API 프리뷰 가격은 입력 $1.36 / 출력 $4.18 (1M 토큰). 회사 주장으로는 "미국·유럽산 오픈웨이트 중 최강". 핵심 체크포인트는 역시 **가중치**: 10월 말 공개 예정이며, Hugging Face `mistralai` 조직에는 아직 올라오지 않은 걸 직접 확인했습니다(현재 최신은 675B짜리 Large 3). 활성 파라미터 수치는 보도마다 미세하게 엇갈리니 가중치 공개 때 재확인 권장. — [분석 기사](https://www.marktechpost.com/2026/10/06/mistral-ai-releases-mistral-large-4-le-chonk-a-1-05t-parameter-open-weight-multimodal-moe/) · [스펙 정리](https://kingy.ai/blog/mistral-large-4-specs-benchmarks-pricing/)
- 그 외 큰 모델 소식 없음. Gemini 4 Argon·GPT-6.1 Sol 후속 보도는 기존 내용의 반복이라 생략합니다.

# 📚 주목 논문

## SHIFT: 쿼리마다 하니스를 '실행 없이' 조립한다

- **저자**: Som Sagar, Shasha Li, Hejie Cui, Ransalu Senanayake, Sercan Ö. Arık (Google 중심, HF Daily Papers 기준)
- **arXiv**: [2610.04137](https://arxiv.org/abs/2610.04137) (cs.LG, 10/2 공개)
- **핵심 기여**: 역할·지침·도구·통신 구조(=하니스)는 쿼리마다 최적이 다른데, 지금까지는 추론 시점에 여러 후보를 "실제로 실행"해보거나 사람이 수동 설계해야 했습니다. SHIFT는 **실행을 쿼리별 탐색 루프 밖으로** 빼냅니다.
- **방법**: 로컬 아키텍트 LLM이 하니스 조립 액션에 대한 정책을 학습하고, 과거 실행 데이터에서 정확도-비용 효용을 예측하는 가치함수를 학습. 추론 시엔 이 예측만으로 MCTS가 쿼리별 하니스를 조립해 **한 번만 실행**합니다.
- **결과(논문 보고치)**: 6개 벤치마크 9,193개 과제, Gemini 3.5 Flash 실행기 기준 평균 정확도 약 80%로 프롬프트 최적화·워크플로 탐색을 포함한 17개 베이스라인 전부를 이기고, 최강 베이스라인 대비 +7.2pp. 저비용 모드도 모든 베이스라인보다 정확하면서 실행 토큰을 32% 덜 씁니다. 구조·지침·도구를 **같이** 고르면 하나만 고를 때보다 최대 +9.1pp.
- 🛠 **에이전트 빌더 시사점**: "우리 에이전트 구성은 하나"인 프로덕트가 대부분일 텐데, 쿼리 유형별로 하니스 변형(서브에이전트 수, 도구 셋, 지침 길이)을 두고 라우팅하는 것만으로 정확도와 비용을 동시에 얻을 여지가 있다는 근거입니다. 거창한 MCTS 없이도, 과거 실행 로그에서 "구성별 정확도·토큰"을 집계하는 것부터가 시작입니다.
- **한계**: 아키텍트 학습용 실행 데이터가 선행 투자로 필요하고, 과제 분포가 바뀌면 가치함수도 재학습이 필요합니다.

![SHIFT 구조 다이어그램](/images/ai-news-2026-10-07/shift-flow.svg)

*SHIFT 파이프라인: 실행 탐색을 학습된 예측으로 대체하고, 하니스는 쿼리마다 새로 조립한다. (논문 내용 기반 자체 제작)*

## Proactivity-Gym: 선제적 에이전트는 '맞게 일해도' 신뢰를 잃는다

- **저자**: Jio Oh, Seunghyun Do, Young-Jun Lee, Steven Euijong Whang, Dongyeop Kang (KAIST·미네소타대)
- **arXiv**: [2609.37267](https://arxiv.org/abs/2609.37267) (cs.AI, 9/29 공개, HF Daily Papers 상위권)
- **핵심 기여**: 사용자가 시키기 전에 먼저 일하는 선제적(proactive) 에이전트의 설계 원칙을 **3T** — Task Capability(맞는 일을 맞게), Temporal Allocation(자원·시점 배분), Trust(신뢰 유지) — 로 정리하고, 이를 평가할 시뮬레이션 테스트베드 Proactivity-Gym을 제안.
- **방법**: 과제 범위·예측 지평·발동 트리거·처리 시점·개입 깊이의 5차원 설계 공간을 정의하고, 멀티데이 시나리오 + 상태 유지 환경 + 페르소나 조건 시뮬레이션 유저로 23개 모델-하니스 조합을 평가.
- **결과(논문 보고치)**: 3T 축별 성능 격차가 크고, LLM 저지는 능력과 신뢰를 자주 혼동. 30명 인간 실험에서는 **결과가 맞아도 개입 타이밍이 어긋나면 신뢰가 급락**했고, 참가자들은 불완전하더라도 집중을 깨지 않는 sleep-time 지원을 선호했습니다.
- 🛠 **에이전트 빌더 시사점**: 백그라운드/스케줄 에이전트를 만들고 있다면 "정확도 평가"만으로는 부족합니다. 알림을 보낼지(개입 깊이), 언제 돌릴지(처리 시점)를 별도 축으로 평가에 넣으세요. 이 블로그처럼 유휴 시간에 돌고 결과만 조용히 쌓는 패턴이 실험적으로도 선호됐다는 게 재밌는 부분.
- **한계**: 시뮬레이션 유저 기반이라 실사용 분포와의 간극이 있고, 인간 실험 규모(n=30)가 작습니다.

# 🛠 오픈소스 스포트라이트

- **[magnitudedev/magnitude](https://github.com/magnitudedev/magnitude)** (Rust 커널 + TypeScript, Apache-2.0) — 로컬 하드웨어에서 **커널을 직접 컴파일·튜닝**하는 코딩 에이전트용 추론 엔진. README 기준 llama.cpp 대비 Metal 디코드 92% 빠름(CUDA 19%), 에이전트당 메모리 27% 절감, 세션 간 prefix cache 공유. Pi·OpenCode·Codex 등 원클릭 연결. 9/30 HN 런칭 후 외부 집계 기준 스타 약 6천(API 접근 제한으로 직접 확인은 못 함). 오늘도 커밋이 이어지는 걸 클론으로 확인했습니다. **활용**: 서브에이전트 팬아웃처럼 토큰을 많이 태우는 보조 작업을 로컬 오픈웨이트로 돌려 비용 0으로 만드는 백엔드.
- **[Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach)** (Python, MIT) — 에이전트에게 Reddit·YouTube·GitHub·Twitter·Bilibili 등 **인터넷 읽기/검색 능력을 CLI로** 달아주는 도구. API 키·비용 없이 "지금 가장 안정적인 접근 방식"을 골라 설치·점검까지 해주는 게 컨셉. Trendshift 기준 오늘의 트렌딩 1위 배지를 달았고, 한국어 README도 있습니다. **활용**: 리서치 에이전트에 플랫폼별 API 연동을 직접 짜는 대신 이 CLI를 도구로 등록. 단, 비공식 접근 방식이 섞여 있으니 프로덕션에서는 플랫폼 약관을 확인하세요.

*같은 날 양쪽에 들어온 서브에이전트 effort: Codex는 기록하고, Claude Code는 지정한다. (자체 제작)*

**🟩 Codex — 서브에이전트 effort '관찰'** (Subagent/Debugging)

- 출처: [openai/codex 커밋 b0a6b8d](https://github.com/openai/codex/commit/b0a6b8d86f455d3db9dd869fc1178a5fbd865e7f) (10/6, 클론으로 확인)
- 💡 멀티에이전트 v2 스폰의 `subAgentActivity` 항목에 **resolved `model`과 `reasoningEffort`**가 기록됩니다. 라이브 알림, 영속 활동, 스레드 히스토리, 과거 롤아웃 마이그레이션까지 전부 전달.
- 📝 app-server 프로토콜로 Codex를 구동한다면 `ItemStarted`/`ItemCompleted` 알림의 `subAgentActivity`에서 이 필드를 집계하세요. "어느 서브에이전트가 어떤 effort로 돌아 토큰을 태웠나"를 스폰 단위로 귀속할 수 있습니다.
- 🎯 멀티에이전트 비용 분석, effort별 성과 비교 데이터 수집.
- ⚠️ 신규 필드라 과거 레코드는 null로 남습니다.
- ⭐ 멀티에이전트 오케스트레이션을 Codex 위에 얹은 팀이라면 오늘 바로 로깅 파이프라인에 추가할 가치.

**🟦 Claude Code — 서브에이전트 effort '지정'** (Subagent)

- 출처: [v2.1.292 릴리즈](https://github.com/anthropics/claude-code/releases/tag/v2.1.292) (태그·CHANGELOG 클론으로 확인)
- 💡 Agent 툴에 **`effort` 파라미터**가 생겨, 서브에이전트를 원하는 effort 레벨로 돌리도록 요청할 수 있습니다.
- 📝 CLAUDE.md나 에이전트 지침에 위임 정책을 명시하면 됩니다:

```markdown
## 위임 정책
- 파일 탐색·수집형 서브에이전트: low effort로 실행
- 설계 리뷰·버그 검증 서브에이전트: high effort로 실행
```

- 🎯 팬아웃 검색은 싸게, 핵심 판단은 비싸게 — 위임 비용의 계층화.
- ⚠️ 모델/플랜에 따라 지원 범위가 다를 수 있으니 전사 적용 전에 소규모로 확인하세요. 같은 릴리즈의 `claude plugin install --marketplace <source>`(마켓 추가+설치 한 번에)도 체크.
- ⭐ 서브에이전트를 많이 쓰는 워크플로일수록 체감 큰 변화.

**🟪 공통 — 하니스 구성을 '측정 대상'으로** (Eval/Workflow)

- 출처: [SHIFT 논문](https://arxiv.org/abs/2610.04137)
- 💡 SHIFT의 교훈을 가볍게 가져오기: 하니스 구성(서브에이전트 수, 도구 셋, effort)을 실행 로그에 태깅하고, 구성별 정확도·토큰을 주기적으로 집계하면 "쿼리 유형 → 구성" 라우팅 테이블을 데이터로 만들 수 있습니다. 위의 Codex 기록 + Claude Code 지정 기능이 정확히 이 루프의 재료입니다.
- 🎯 에이전트 비용이 커져서 "어디서 아껴야 할지" 모를 때.
- ⚠️ 과제 분포가 바뀌면 테이블도 낡습니다. 집계는 이동 창(rolling window)으로.
