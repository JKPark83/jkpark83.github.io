# 🔥 오늘의 핵심

**오늘 나온 네 건이 전부 같은 말을 한다: 한 번 측정한 숫자로 판단하면 부호가 뒤집힌다.** Ornith-1.5는 자기개선 루프를 넓혀 DeepSWE를 8 → 56.0으로 올렸는데, 모델 카드에 "전 벤치마크 5회 독립 실행 평균"이라고 못을 박아놨다. 반대로 Salesforce 논문은 런타임 메모리 자기개선을 셔플된 태스크 순서로 다시 돌리자 +1.5%가 **−4.5%**가 됐다고 보고한다.

오늘 바로 할 일 하나: **내 에이전트 eval을 3회 반복 + 태스크 순서 셔플로 재실행해서, 개선 폭이 아니라 개선 *부호*가 유지되는지 확인하기.**

# 📚 주목 논문

## 1. 자기개선 에이전트는 생각보다 부서지기 쉽다

- **저자/소속**: Qinyuan Ye, Yu Li, Yada Pruksachatkun, Jiaxin Zhang, Chien-Sheng Wu — Salesforce AI Research
- **arXiv**: [2608.18066](https://arxiv.org/abs/2608.18066) (cs.AI)
- **핵심 기여**: 메모리 뱅크로 스스로 개선하는 에이전트(Agent Workflow Memory, ReasoningBank)를 **평가 축 2개를 넓혀** 재평가했다.
- **방법**: (1) 동일 실험을 3회 반복해 런 단위 분산과 최고-최저 격차를 재고, (2) 기본 순서 외에 무작위 셔플 순서 2종을 추가로 돌린다. 벤치마크는 WebArena(812), VisualWebArena(910), SCUBA(267).
- **결과**: 자기개선을 얹으면 **71%의 케이스에서 분산이 커졌고**, 같은 실험의 최고 런과 최저 런 격차가 **최대 10%p**까지 벌어졌다. 기본 순서에서 +1.5%였던 개선이 셔플 순서에서는 **−4.5%**가 됐다. 기존 논문들의 기본 순서가 사실상 쉬운→어려운 커리큘럼을 깔아주고 있었다는 뜻이다.
- 🛠 **에이전트 빌더 시사점**: 메모리 실패 모드가 구체적이다 — "브라우저 전용 환경인데 API를 쓰라고 권하는 메모리"처럼 **그럴듯하지만 적용 불가능한 항목**이 쌓여 실행 가능한 전략을 밀어낸다. 루브릭과 환경 피드백을 메모리 생성 단계에 넣으면 일부 회복되지만 격차는 남는다.
- ⚠️ **한계**: 웹 브라우징 도메인에 한정됐고, 재평가 대상도 대표 방법 2종뿐이다. 명세 보강으로도 격차가 안 닫힌 부분의 원인은 미규명 상태다.
- **코드/데이터**: [SalesforceAIResearch/self-improve-fragility](https://github.com/SalesforceAIResearch/self-improve-fragility) · [HF 데이터셋](https://huggingface.co/datasets/Salesforce/self-improve-fragility)

![기존 평가 관행과 확장 평가 관행 비교, 순서 셔플 시 +1.5%에서 −4.5%로 반전](/images/ai-news-2026-08-20/self-improve-fragility.svg)
*평가 프로토콜만 넓혀도 결론의 부호가 바뀐다. 출처: arXiv 2608.18066 본문 수치(자체 작도).*

## 2. TRUSS — 자동 생성한 Agent Skill을 "실행 증거"로 검증하기

- **저자/소속**: Zhibo Zhang, Zhen Ouyang, Kailong Wang(교신) — Huazhong University of Science and Technology / Ling Shi — Nanyang Technological University
- **arXiv**: [2608.17588](https://arxiv.org/abs/2608.17588) (cs.AI, FSE 2027 투고)
- **핵심 기여**: Skill을 **산출물만 보고 판정하지 않는다**. 정적 게이트를 통과한 후보를 격리 환경에서 shadow agent에 실제로 물려보고, 그때 나온 행동 트레이스로 판정한다.
- **방법**: ① 기능 주장(claim)을 소스·도메인 근거와 대조하고 9개 안전 속성으로 전체 산출물을 검사 → ② 통과 후보를 Controllable Execution Environment에 로드, brokered tool이 요청 행동을 정책 집행에 노출하고 provenance 보존 트레이스로 기록 → ③ 기능 실패와 속성 위반을 **책임 있는 Skill 내용까지 역추적**해 반복 수정.
- **결과**: SkillInject 168건 / SkillSafetyBench 155건 / SkillGenBench 187 태스크 전부에서 평가. 취약점 탐지 precision·recall 100.00%, 수리 후 공격 성공률 38.71% → 19.35%(GPT-5.5), 46.45% → 29.68%(GPT-5.4), 공격 회귀 0건. Skill 생성 쪽은 태스크 성공률 17.11%(Skill 없음) → 52.94%, Security rate 50.80% → 100.00%.
- 🛠 **에이전트 빌더 시사점**: "LLM에게 Skill/서브에이전트 정의를 짜게 한다"를 이미 하고 있다면, 리뷰 단계가 **파일 읽기**로 끝나면 안 된다는 뜻이다. 브로커된 툴 뒤에서 한 번 돌려보고 실제 호출 로그를 보는 게 정적 리뷰보다 잡아내는 게 많다.
- ⚠️ **한계**: 100% precision/recall은 자기들이 고른 벤치마크 계열 안에서의 숫자다. 무엇보다 수리 후에도 공격 성공률이 **20~30%대로 남는다** — 게이트지 해결책이 아니다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — 카테고리: Debugging / Sandbox

- 💡 **핵심**: macOS에서 `network_access = true`는 **조용히 무시된다.** seatbelt 샌드박스가 `CODEX_SANDBOX_NETWORK_DISABLED=1`을 무조건 설정하기 때문에, config는 맞게 써놨는데 에이전트 안에서만 모든 아웃바운드 호출이 실패한다. Linux의 Landlock 구현과 동작이 다르다.
- 📝 **How-to**: 아래 설정이 macOS에서는 효과가 없다는 걸 먼저 인지할 것.

```toml
# ~/.codex/config.toml — Linux에서는 동작, macOS seatbelt에서는 무시됨
sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true
```

증상 확인은 에이전트가 실행하는 셸 안에서:

```bash
echo "$CODEX_SANDBOX_NETWORK_DISABLED"   # 1이면 seatbelt가 네트워크를 막고 있는 것
```

`sandbox_mode = "danger-full-access"`를 config에 적는 것만으로는 부족하고 CLI 플래그로 넘겨야 한다.
- 🎯 **언제**: MCP 서버 연결, `pip install`, 외부 API 호출이 **터미널에서는 되는데 Codex 안에서만** 실패할 때 제일 먼저 의심할 것.
- ⚠️ **주의**: 네트워크를 여는 건 샌드박스를 사실상 무력화하는 일이다. 상시로 열지 말고, 네트워크가 필요한 작업은 격리 컨테이너나 Linux 환경으로 분리하는 쪽이 낫다.
- ⭐ **추천**: macOS를 주력으로 쓰면서 에이전트에 외부 의존성을 물린다면 오늘 확인해둘 것.
- 출처: [openai/codex#10390](https://github.com/openai/codex/issues/10390)

## 🟪 공통 — 카테고리: Eval

- 💡 **핵심**: 자기개선/메모리 기능의 효과는 **3회 반복 + 순서 셔플**을 통과해야 진짜다. 오늘 논문 기준으로 이 두 축만 넓혀도 +1.5%가 −4.5%로 뒤집혔다.
- 📝 **How-to**: eval 러너에 시드와 순서를 인자로 빼두고, 기본 순서 1회가 아니라 아래 6회를 돌린다.

```bash
# 기본 순서 3회 + 셔플 순서 2종
for seed in 1 2 3; do
  ./run_eval.sh --order default --seed "$seed" --out "runs/default-$seed.json"
done
for shuf in 1 2; do
  ./run_eval.sh --order "shuffle-$shuf" --seed 1 --out "runs/shuf-$shuf.json"
done
```

보고할 숫자는 평균 하나가 아니라 **평균 · 표준편차 · 최고-최저 격차** 세 개다. 격차가 개선 폭보다 크면 그 개선은 아직 없는 것으로 취급한다.
- 🎯 **언제**: 메모리 뱅크, 경험 재사용, 자동 프롬프트 개선처럼 "돌릴수록 좋아진다"고 주장하는 기능을 머지하기 전에.
- ⚠️ **주의**: 반복 실행은 비용이 든다. 전체 스위트 대신 도메인별 대표 태스크로 줄여서라도 **반복 자체는 포기하지 말 것.**
- ⭐ **추천**: 자기개선 루프를 프로덕션에 넣을 계획이면 머지 게이트로 박아둘 값어치가 있다.
- 출처: [arXiv 2608.18066](https://arxiv.org/abs/2608.18066)
