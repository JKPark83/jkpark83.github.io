# 📚 주목 논문

## IterSynth: 딥서치 에이전트의 역할 분리 (arXiv:2609.29444)

- **저자**: Xingyu Wu, Yuchen Yan, Yongliang Shen 외 (총 12명) · cs.CL · 9/24 제출
- **핵심 기여**: ReAct처럼 하나의 정책이 검색 계획과 답 종합을 한 컨텍스트에서 다 하던 구조를, 정보 요구를 식별하는 **Planner**와 증거를 "진화하는 요약 상태"로 통합하는 **Synthesizer**로 분리.
- **방법**: 최종 보상에 턴 단위 평가를 결합한 Role-Decoupled Policy Optimization(RDPO)으로 두 역할을 함께 학습. 학습 없이 프롬프트 패러다임으로만 써도 프런티어 모델에서 zero-shot 개선을 보고.
- **결과**: IterSynth-8B가 5개 벤치마크 평균 50.7로 기존 8B 이하 에이전트 대비 +4.2%p (논문 보고 수치).
- 🛠 **시사점**: 딥리서치 에이전트를 만들 때 "다음에 뭘 찾을지"와 "지금까지 찾은 걸 어떤 상태로 유지할지"를 별도 역할·별도 컨텍스트로 관리하는 설계는 오늘 바로 프롬프트 수준에서 실험 가능.
- **한계**: 8B 학습 결과 중심이라 대형 모델 학습에서의 이득 폭은 미확인.
- [arXiv](https://arxiv.org/abs/2609.29444) · [코드 (Tencent/IterSynth)](https://github.com/Tencent/IterSynth)

## ExplorationBench: 탐색 능력만 따로 재는 벤치마크 (arXiv:2609.30199)

- **저자**: Ming Zhang, Zhenghao Xiang 외 (총 20명) · cs.AI · 9/24 제출
- **핵심 기여**: 에이전트가 "사전학습 지식을 회상"한 건지 "진짜 탐색으로 발견"한 건지 구분하기 위해, 현실 법칙과 일부러 충돌하는 **실행 가능한 Alien World 규칙**을 사용. 규칙이 실행 가능하므로 모든 답이 정확히 검증됨.
- **구성**: AlienCode(발견 타깃 31개/태스크 70개), AlienLogic(타깃 24개/태스크 70개)에서 10개 시스템 평가.
- **결과**: 최상위 시스템은 낯선 규칙을 습득·적용할 수 있지만 궤적별 편차가 크고, 탐색을 계속하면 오히려 이전 성과가 정체되거나 후퇴하기도 함.
- 🛠 **시사점**: long-horizon 에이전트에는 "더 탐색할지 멈출지" 판단 기준이 필요하다는 실증. 자체 평가를 만들 때도 지식 회상과 탐색을 분리해 측정할 것.
- **한계**: abs 페이지 기준 시스템별 세부 점수는 본문 확인 필요.
- [arXiv](https://arxiv.org/abs/2609.30199)

| [soemoescode/guardskill](https://github.com/soemoescode/guardskill) | JavaScript | MIT | 폴더 열기 전 git·에이전트 설정 스캐너 |

**Hindsight** — 대화 이력 회상에 집중하는 기존 메모리와 달리 retain / recall / reflect 3개 연산으로 관찰을 축적하고 "mental model"로 정리하는 메모리 서버입니다. LLM 래퍼 2줄로 붙이거나 MCP 서버로 연결하며, LongMemEval SOTA를 주장합니다(벤더 벤치마크 — README는 Virginia Tech·Washington Post의 독립 재현을 언급). 어제도 커밋이 있을 만큼 활발합니다. 스타 수는 이 세션의 GitHub API 제한으로 미확인이나 GitHub Trending 뱃지를 달고 있습니다. **활용처**: 같은 사용자를 반복 상대하며 선호·실패 패턴을 학습해야 하는 서비스 에이전트.

**GuardSkill** — 위 핵심에서 소개한 스캐너. 읽기 전용·네트워크 호출 0·의존성 0으로, git 설정에서 프로그램을 실행시키는 약 24개 키(`core.fsmonitor`, `core.pager`, filter/diff 드라이버, hooks 경로, 숨은 bare repo 구조 등)와, 저장소에 커밋된 채 배포되는 에이전트 설정 파일(`.mcp.json`, `.claude/settings.json`, `.vscode/mcp.json`, `.cursor/mcp.json` 등)을 심각도 사다리로 보고합니다. 검사 키 목록이 인벤토리 파일로 관리되고 드리프트 테스트로 검증되는 점이 인상적입니다. CI용 action.yml도 제공. **활용처**: 외부 유입 저장소를 다루는 팀의 pre-flight 게이트.

# 🧑‍💻 Codex & Claude Code 실전 팁

오늘은 두 벤더가 **자기 저장소를 리뷰하는 방식**을 나란히 놓고 봅니다.

![Codex vs Claude Code 코드리뷰 분해 비교](/images/ai-news-2026-09-27/review-skills-card.svg)

*Codex의 차원별 스킬 분해 vs Claude Code의 병렬 감사 + 신뢰도 필터. (자체 제작, 각 저장소에서 확인)*

**🟩 Codex · Review/Context** — [openai/codex의 .codex/skills](https://github.com/openai/codex/tree/main/.codex/skills/code-review)
- 💡 오케스트레이터 스킬(`code-review`)이 차원별 스킬마다 서브에이전트 1개를 띄워 전 항목을 보고하게 함.
- 📝 압권은 `code-review-context`: 히스토리 재작성 금지, 컨텍스트 주입 항목은 전부 크기 상한 필수, 10K 토큰 초과 항목 금지, 1K 토큰을 넘는 신규 주입은 P0로 수동 리뷰. 자기 레포의 `.codex/skills/`(또는 Claude Code라면 `.claude/skills/`)에 같은 방식으로 리뷰 기준을 파일 단위로 쪼개 두면 됩니다.
- 🎯 리뷰 기준이 암묵지로 흩어져 있는 팀. ⚠️ 스킬당 서브에이전트 팬아웃이라 토큰 비용은 각오. ⭐ 4.5/5

**🟦 Claude Code · Review** — [code-review 플러그인](https://github.com/anthropics/claude-code/blob/main/plugins/code-review/README.md)
- 💡 4개 병렬 에이전트(CLAUDE.md 준수 감사 ×2, 버그 스캔, git blame 맥락 분석)가 독립 리뷰한 뒤 이슈마다 0–100 신뢰도 점수를 매기고 80 미만을 버림.
- 📝 설치 후 PR에서:

```bash
/code-review            # 터미널로 결과
/code-review --comment  # PR 코멘트로 게시
```

- 🎯 리뷰 봇의 false positive에 지친 팀. ⚠️ 임계값이 보수적이라 미묘한 이슈는 걸러질 수 있음. ⭐ 4/5

**🟪 공통 · Security** — [GHSA-9ccr-r5hg-74gf (Copilot CLI 권고)](https://github.com/github/copilot-cli/security/advisories/GHSA-9ccr-r5hg-74gf)
- 💡 GitSpawn 클래스의 git 쪽 하드닝은 에이전트 패치와 무관하게 지금 적용 가능.
- 📝 핵심 한 줄:

```bash
git config --global safe.bareRepository explicit
```

트리 안에 숨은 bare repo의 설정 적용을 차단합니다(Copilot CLI 1.0.43이 강제한 방식). 추가로: 파일째 받은 저장소는 원격에서 다시 clone(클론은 `.git/config`를 전송하지 않음), 열기 전 `npx guardskill .`.
- 🎯 외부 zip·공유드라이브 저장소를 여는 모든 개발자. ⚠️ 일부 레거시 도구가 이 설정과 충돌할 수 있고, `core.fsmonitor`만 끄는 방식은 전체 경로를 커버하지 못함. ⭐ 5/5
