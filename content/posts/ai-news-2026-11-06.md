# 📚 주목 논문

## 1. Ask, Don't Equip — 질문 주도 코딩 에이전트 (KernelSeek)

- **저자**: Gabriele Oliaro, Jaeseong Lee, Zhaoyuan Su, Sreeram Vennam, Zhihao Jia, Samyam Rajbhandari (CMU 등)
- **arXiv**: [2611.03517](https://arxiv.org/abs/2611.03517) (cs.LG)
- **핵심 기여**: GPU 커널 최적화 에이전트의 두 극단 — 단계가 고정된 스크립트형, 수천 번 시행으로 지불하는 자유형 — 모두에 빠져 있는 것은 "남은 격차가 어디인가"라는 **방향 가설**이라고 지적한다.
- **방법**: 범용 코딩 에이전트 + 검증 가능한 목표를 강제하는 최소 하네스에, 결정 지점마다 짧은 질문을 주입한다. 처음에는 사람이 질문하고, 이후에는 질문 뱅크를 에이전트가 스스로에게 적용한다.
- **결과**: 같은 과제·평가기·하드웨어 조건에서, 도구를 잔뜩 장착한 자율 에이전트는 133 스텝 후 FlashAttention-3의 0.50배에서 정체했지만 KernelSeek은 **1.13배**에 도달했다.
- 🛠 **시사점**: 에이전트가 정체할 때 반사적으로 도구·컨텍스트를 추가하기 전에, "지금 병목이 뭐라고 생각해?" 같은 방향 질문을 프롬프트에 넣어보자. 비용이 거의 들지 않는 개입이다.
- **한계**: CUDA 커널 단일 도메인 검증이고, 질문 뱅크의 출발점은 여전히 사람이다.

![KernelSeek 방법 비교: 스크립트형, 자유형, 질문 주도 에이전트와 0.50배 대 1.13배 결과 막대](/images/ai-news-2026-11-06/kernelseek.svg)

*같은 조건에서 '더 많은 도구'는 0.50×에서 멈췄고, '적절한 질문'은 1.13×에 도달했다.*

## 2. 멀티턴 RL은 LLM 에이전트의 무엇을 좋아지게 하나

- **저자**: Kejian Zhu, Zhuoran Jin, Kang Liu, Jun Zhao 외 (CASIA 계열 연구진)
- **arXiv**: [2611.06483](https://arxiv.org/abs/2611.06483) (cs.LG)
- **핵심 기여**: 샘플링 폭 K와 상호작용 깊이 T를 분리한 Pass@(K,T)로 평가해 보니, 멀티턴 에이전틱 RL의 이득은 **턴 예산이 넉넉할 때만** 유지되고, 예산이 조이면 크게 줄었다.
- **방법**: 궤적 수준 RL의 이득을 단일 스텝 품질 vs 오류 복구·장기 지속력으로 분해 분석. 학습 중 상호작용 예산을 섞어 주는 BudgetMix RL을 대안으로 제시.
- **결과**: RL의 강점은 단일 스텝 판단력보다 오류 복구에 집중되어 있었고, BudgetMix RL은 다양한 실행 설정에서 더 고른 성능을 보였다.
- 🛠 **시사점**: RL로 튜닝된 에이전트 모델을 쓰면서 비용 절감을 위해 최대 턴 수를 조이고 있다면, 벤치마크 점수가 그대로 유지될 거라 가정하지 말 것. 배포 예산과 같은 조건으로 평가하자.
- **한계**: 저자들 스스로 과정 감독(process supervision) 논의는 예비적 수준이라고 밝힌다.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — 백그라운드 압축을 루트 세션으로 한정

- **카테고리**: Context / **소스**: [commit edd0d89](https://github.com/openai/codex/commit/edd0d898204eba8397181deae8e4a238d1f7df27) (11/5, 클론으로 확인)
- 💡 `async_compaction_root_only` 피처 플래그(기본 꺼짐)가 추가됐다. 켜면 백그라운드 압축이 루트 세션에서만 돌고, 리뷰 서브에이전트·Guardian 세션 같은 비루트 에이전트는 제외된다.
- 📝 config.toml의 features 섹션에서:

```toml
[features]
async_compaction_root_only = true
```

- 🎯 서브에이전트는 수명이 짧아 압축 이득이 적고, 리뷰어의 컨텍스트가 중간에 재작성되는 것이 싫을 때.
- ⚠️ 실험 플래그라 스키마에만 들어온 단계다. 동작은 버전에 따라 바뀔 수 있다.
- ⭐ 추천도: 서브에이전트를 많이 띄우는 헤비 유저라면 주시할 가치 있음.

### 🟦 Claude Code — 내장 agents-md 모드로 AGENTS.md 통일

- **카테고리**: Context / **소스**: [mods/agents-md README](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/README.md) (클론으로 확인)
- 💡 Claude Code에 내장된 `agents-md` 모드가 `AGENTS.md`를 `CLAUDE.md`와 똑같은 위치·방식으로 읽어준다. 옵션은 `instructionFiles` 하나.
- 📝 기본값 `claude-md-or-agents-md`는 프로젝트에 CLAUDE.md가 없을 때만 AGENTS.md를 쓴다. 둘을 나란히 쓰려면:

```json
{ "instructionFiles": "claude-md-and-agents-md" }
```

- 🎯 Codex(AGENTS.md)와 Claude Code를 같은 레포에서 쓸 때, 지침 파일을 AGENTS.md 하나로 통일하고 싶다면 CLAUDE.md를 지우기만 하면 된다.
- ⚠️ 프로젝트 어딘가에 CLAUDE.md가 하나라도 있으면 기본 모드에서는 AGENTS.md 전체가 무시된다. 중첩 디렉터리의 AGENTS.md는 해당 디렉터리를 Read할 때 붙는다.
- ⭐ 추천도: 멀티 에이전트 CLI 사용자라면 오늘 바로 정리해 볼 것.

### 🟪 공통 — 추론 기록을 '상태 기록'으로 다시 쓰면 뒤가 짧아진다

- **카테고리**: Context / **소스**: [arXiv 2611.03852](https://arxiv.org/abs/2611.03852)
- 💡 툴 결과가 도착하기 전에, 이전 추론을 간결한 상태 기록으로 **다시 쓰면** 이후 추론 자체가 짧아진다는 인과 분석. 코딩 사례에서는 후보 해법 공유 후 반복 검증이 줄었다.
- 📝 직접 하네스를 만든다면: 툴 호출 경계에서 "지금까지의 결론·열린 질문·다음 행동"만 남기는 압축 프롬프트를 끼워 넣고, 원본 기록 유지 버전과 작업 품질을 A/B 비교.
- 🎯 긴 추론 모델을 에이전트 루프에 돌릴 때 토큰 비용이 아픈 경우.
- ⚠️ 품질·시간 영향은 모델과 압축기에 따라 달라진다. 압축 정책은 모델별로 평가하라는 것이 저자의 결론.
- ⭐ 추천도: 자체 에이전트 루프 운영자에게 특히 유용.
