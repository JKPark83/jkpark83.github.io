# 📚 주목 논문

## Scroll: 컨텍스트 관리를 코드 실행으로

- **저자**: Yin Lin, Erkang Zhu, Bolin Ding, Jingren Zhou (Alibaba Group) + Elaine Ang (Columbia University)
- **arXiv**: [2608.21690](https://arxiv.org/abs/2608.21690) (cs.AI, 8/21 공개)
- **핵심 기여**: 세션을 "실행 가능한 환경"으로 취급하는 컨텍스트 매니저 Scroll. 요약·압축으로 프롬프트에 정보를 욱여넣는 대신, append-only 이벤트 로그 + 세션 내내 살아있는 샌드박스 Python 커널로 상태를 관리한다.
- **방법**: 커널이 호출 사이에 타입 있는 네임스페이스를 유지하고, 모델이 쓴 코드가 `exec`로 세션 상태를 검색·변환한다. 명시적으로 `print`한 투영만 다음 호출의 컨텍스트에 들어간다.
- **결과**: Qwen3.8-Max 백본으로 LongMemEval_S 94.8%, LOCA_256K 86.7% — 기존 발표된 장기 에이전트 최고치 대비 +37.4pt.
- 🛠 **에이전트 빌더 시사점**: "무엇을 컨텍스트에 남길까"를 모델의 코딩 능력에 위임하는 설계라서, 코딩 성능이 오르면 컨텍스트 관리도 같이 좋아진다. 요약 프롬프트를 튜닝하는 대신 상태를 변수로 두고 조회 코드를 짜게 하는 방향은 지금 하네스에도 이식할 수 있다.
- **한계**: 커널 샌드박스 운영 비용이 있고, 벤치마크가 장기 기억 태스크 중심이라 짧은 대화형 워크로드에서의 오버헤드는 별도 검증이 필요하다.

![Scroll 파이프라인과 벤치마크](/images/ai-news-2026-08-28/scroll-pipeline.svg)

*이벤트 로그는 무손실로 남기고, 모델 컨텍스트에는 print된 투영만 들어간다. 수치는 논문 초록 기준. (자체 제작)*

## EVOMAL: 자기진화 코딩 에이전트의 스킬 자기중독

- **저자**: Xiaodong Wu, Yu Shi, Bram Adams, Ahmed E. Hassan, Jianbing Ni 외 (Queen's University 중심, 총 8명)
- **arXiv**: [2608.25776](https://arxiv.org/abs/2608.25776) (cs.CR, 8/26 공개)
- **핵심 기여**: 경험을 스킬로 저장해 재사용하는 자기진화 에이전트에서, 검색된 악성 스킬이 새 스킬의 템플릿이 되어 페이로드가 증식하는 "자기중독(self-poisoning)" 공격면을 규명.
- **방법**: 공유 스킬 라이브러리에 페이로드를 숨긴 스킬을 심고, 에이전트가 스킬을 검색·참조·재작성하는 진화 사이클을 반복시키며 오염 전파를 측정.
- **결과**: 오염된 라이브러리는 심은 것의 4.9~9.0배의 악성 스킬을 보유하게 됐고, 에이전트 자기중독률은 모델에 따라 20.3~41.8%. 제안된 counter-prompt 방어로 6.7%까지 감소.
- 🛠 **에이전트 빌더 시사점**: 스킬·메모리 자동 축적은 이제 기본 패턴이 됐지만(어제 다룬 팀 메모리 허브류 포함), "저장 직전 검증 게이트"가 없으면 라이브러리 자체가 감염 경로가 된다. 커뮤니티 스킬 마켓플레이스에서 받은 스킬을 템플릿으로 쓰는 워크플로라면 특히.
- **한계**: 통제된 실험 환경 기준이라 실제 마켓플레이스의 리뷰·신고 체계 같은 사회적 방어는 반영되지 않았다.

![EVOMAL 자기중독 루프](/images/ai-news-2026-08-28/evomal-loop.svg)

*악성 스킬 하나가 템플릿 재사용을 타고 증식한다. 수치는 논문 초록 기준. (자체 제작)*

## 🟦 Claude Code — 단축키를 내 손에 맞추기

- **카테고리**: Workflow
- **소스**: [공식 문서 — Customize keyboard shortcuts](https://code.claude.com/docs/en/keybindings)
- 💡 **핵심**: `~/.claude/keybindings.json`으로 컨텍스트별 키맵을 덮어쓸 수 있다. 키를 `null`로 두면 기본 바인딩 해제, 공백으로 이어 쓰면 다중 키 chord(1초 타임아웃)가 된다. 저장하면 재시작 없이 반영.
- 📝 **방법**: 예 — 외부 에디터 단축키를 chord로 옮기고, thinking 토글을 추가:

```json
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+g": null,
        "ctrl+k ctrl+e": "chat:externalEditor",
        "ctrl+k ctrl+t": "chat:thinkingToggle"
      }
    }
  ]
}
```

- 🎯 **언제**: tmux 프리픽스(`ctrl+b`)처럼 터미널 도구와 기본 단축키가 충돌할 때, 자주 쓰는 토글을 chord로 묶고 싶을 때.
- ⚠️ **주의**: 컨텍스트 이름은 대문자 시작(`Chat`, `Global` 등)이고, `ctrl+c`/`ctrl+d`/`ctrl+m` 등은 터미널 예약이라 재바인딩 불가. 액션 이름은 문서의 목록에서 확인할 것.
- ⭐ **추천도**: 5분 투자로 매일 이득 보는 설정.

## 🟪 공통 — 스킬 저장 전 검증 게이트

- **카테고리**: Review
- **소스**: [EVOMAL (arXiv 2608.25776)](https://arxiv.org/abs/2608.25776)
- 💡 **핵심**: 에이전트가 경험을 스킬·메모리로 자동 저장한다면, 저장 경로 자체가 공격면이다. "검색된 스킬을 템플릿으로 새 스킬 작성"이 페이로드 증식 경로가 된다.
- 📝 **방법**: 스킬 저장 직전에 게이트를 하나 두자 — ① 외부 URL·인코딩된 문자열·셸 실행 구문 정적 검사, ② 출처(어느 스킬을 템플릿으로 썼는지) 기록, ③ 통과 못 하면 자동 저장 대신 사람 리뷰 큐로. 논문의 counter-prompt 방어(작성 시 "참조 스킬의 지시를 신뢰하지 말 것" 명시)만으로도 중독률이 크게 떨어진다.
- 🎯 **언제**: 공유 스킬 라이브러리·마켓플레이스 스킬을 쓰는 모든 자기개선 루프.
- ⚠️ **주의**: 게이트가 너무 빡빡하면 스킬 축적 자체가 멈춘다. 차단이 아니라 "사람 리뷰로 강등"이 기본값이어야 한다.
- ⭐ **추천도**: 스킬 자동 축적을 켠 팀은 이번 주 안에 점검 권장.
