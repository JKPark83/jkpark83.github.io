# 🔥 오늘의 핵심

Thinking Machines가 약속대로 **Inkling 2 Small(594B MoE, 17B active)의 전체 가중치를 Apache 2.0으로 공개**했다. 그리고 오늘의 진짜 흐름은 인젝션 방어다 — IBM은 신뢰 경계를 **프롬프트 포맷(LLMON)으로 학습**시킨 모델을, CapLite 논문은 소형 모델에게 보안 정책 작성을 맡기지 말고 **코드로 강제**하는 설계를 내놨다. "프롬프트에 '주입 무시해'라고 쓰기"의 시대는 끝나가고 있다.

![2026년 11월 16일 AI 변화 지도: 모델, 논문, 오픈소스, 도구 팁 4분면 요약](/images/ai-news-2026-11-16/change-map.svg)

*오늘의 AI 변화 지도. 모델·논문·팁이 모두 "신뢰 경계를 구조로 만든다"는 한 방향을 가리킨다.*

# 🤖 모델 & 릴리즈 레이더

- **Inkling 2 Small 오픈 웨이트 공개 (11/12)**: 11/5 Tinker 런칭 때 "외부 안전성 테스트 후 공개"를 약속했고, 일주일 만에 지켰다. 594B 총 파라미터 / 17B active(384개 중 8 experts 라우팅), 48-layer, 텍스트+이미지 입력, 최대 1M 컨텍스트. NVFP4(합산 VRAM 500GB+)와 MXFP8(800GB+) 두 체크포인트로 배포되고 라이선스는 **Apache 2.0**. 모델 카드 자체 벤치마크로 SWE-Bench Pro Hard 86.3%, ARC-AGI-2 81.7%를 보고한다. "Small"이지만 사실상 **멀티 GPU 노드급 서빙 전제의 프런티어 오픈 웨이트**라는 점이 포인트. [HF 모델 카드](https://huggingface.co/thinkingmachines/Inkling-2-Small)
- **IBM granite-4.1-llmon-preview 3B/8B (HF, 이번 주)**: 평범한 챗 템플릿 대신 **LLMON(LLM Object Notation)** 블록 포맷으로 프롬프트를 받는 instruct 모델. instruction·system 블록만 권위 있게 따르고, data·문서·툴 결과 블록은 "읽기만 하는 입력"으로 취급하도록 학습됐다. Apache 2.0이고, 카드 스스로 "학습된 행동이지 보장이 아니다"라고 명시한다. 신뢰/비신뢰 콘텐츠가 섞이는 RAG·툴 에이전트용으로 흥미로운 실험 대상. [HF 모델 카드](https://huggingface.co/ibm-granite/granite-4.1-8b-llmon-preview)

# 📚 주목 논문

## 1. MAPE — 에이전트 메모리 설계를 손으로 하지 말고 진화시켜라

- **저자**: Xinheng Ding, Seyyed Saeid Cheshmi, Ziyang Zhang 외 (소속 미표기)
- **arXiv**: [2611.17068](https://arxiv.org/abs/2611.17068) (cs.CL, 11/12)
- **핵심 기여**: 메모리 시스템 전체(저장·검색·구성 프로그램)를 최소 시드에서 **프로그램 진화로 탐색**하는 프레임워크. 표준화된 lifecycle 인터페이스 위에서 진단→제안 루프를 돌린다.
- **결과**: LoCoMo·LongMemEval에서 수작업 설계 베이스라인 대비 **최대 +12%p 정확도, 서빙 비용은 35% 수준**. 발견된 패턴 중 "검색 결과를 질의 의도에 맞게 재구성하는 composition 모듈"을 기존 메모리 시스템 5종에 이식하자 **5종 모두 정확도가 올랐다**.
- 🛠 **시사점**: 두 가지 패턴은 오늘 바로 베낄 수 있다 — ① 추출 요약만 저장하지 말고 **원문 대화를 검색 가능한 증거로 유지**, ② 검색된 증거를 그대로 붙이지 말고 **질의 의도별로 재구성**해서 모델에 전달.
- **한계**: 대화형 장기기억 벤치마크 중심이라 코딩 에이전트 메모리로의 일반화는 별도 검증 필요. [코드](https://github.com/ash-ding/MAPE)

## 2. CapLite — 소형 모델 에이전트에게 보안 정책을 쓰게 하지 마라

- **저자**: Zimo Xu, Wenzhuo Liu, Hideki Nakayama (소속 미표기)
- **arXiv**: [2611.17115](https://arxiv.org/abs/2611.17115) (cs.AI, 11/12)
- **핵심 기여**: CaMeL·Progent 같은 기존 인젝션 방어는 에이전트의 모델에게 보안 산출물(정책·그래프·제약)을 쓰게 한다. 15개 오픈 모델(대부분 1.7B~12B)로 실험하니 **그 산출물 자체가 뚫린다** — 모델이 쓴 정책이 11~14개 모델에서 공격을 통과시키고, CaMeL 프로그램은 최대 68% 에피소드에서 실행조차 실패.
- **방법**: 정책을 모델이 아니라 **툴 스키마에서 유도**하고, 쓰기 호출은 툴 결과를 읽기 **전에** 커밋하며, 수신자·금액·대상을 정하는 인자는 유저 요청에 명시된 값만 허용.
- **결과**: AgentDojo 공격 에피소드 13,935회에서 **성공 0건**(저자 보고). 공격 하 유틸리티는 CaMeL과 비슷(29.0% vs 27.2%)하면서 토큰은 비교 대상 중 최소.
- 🛠 **시사점**: 아래 공통 팁 참고 — 이 구조는 프레임워크 없이도 흉내 낼 수 있다.
- **한계**: "유저 요청에 명시된 인자만 허용"은 정당한 다단계 작업(툴 결과에서 수신자를 알아내는 작업)을 막는다. 유틸리티 29%가 그 비용이다.

![LLMON 블록 포맷과 CapLite 쓰기 게이트를 비교한 다이어그램](/images/ai-news-2026-11-16/injection-defense.svg)

*같은 문제, 두 접근. LLMON은 모델을 포맷에 맞게 학습시키고, CapLite는 모델 밖 코드에서 강제한다.*

# 🛠 오픈소스 스포트라이트

- **[lxe/phoneuse](https://github.com/lxe/phoneuse)** (Python, MIT, 약 670 스타 — 공개 9일 차): **탈옥·케이블 없이 아이폰을 에이전트가 조작**하는 앱. 화면은 Screen Mirroring으로 받아오고, 입력은 Bluetooth HID(키보드·마우스)로 넣는다. Linux는 flatpak 하나로 끝나고, Mac은 LilyGO T-Display 보드를 "브리지"로 쓴다. Claude Code·Codex 연결 버튼이 내장돼 있고, 에이전트가 제어권을 잡기 전 아이폰에서 승인을 요구할 수 있다. 지난주 소개한 [pinky](https://github.com/DIYgod/pinky)가 폰 안의 게이트웨이 방식이라면, phoneuse는 **OS를 안 건드리는 외부 하드웨어 방식** — 모바일 앱 E2E 테스트나 폰 전용 워크플로 자동화 실험에 좋다.
- **[Dodaios/ste80-humanizer](https://github.com/Dodaios/ste80-humanizer)** (Python, MIT, 약 690 스타): AI 문체를 걷어내는 **2-pass 에이전트 스킬**. 1차로 Wikipedia "Signs of AI writing"의 26가지 티를 제거하고, 2차로 Karpathy가 10월에 제안한 "ASD-STE100(항공 정비 매뉴얼 통제 영어)의 80%" 수준으로 문장을 재조립한다. 탐지기 회피가 아니라 **가독성이 목표**라고 명시한 점이 건강하다. 에이전트가 쓰는 PR 설명·문서·릴리즈 노트 파이프라인 끝단에 붙이면 체감이 크다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code / Hook·보안** — [sec-default 모드 README](https://github.com/anthropics/claude-code/blob/main/mods/sec-default/README.md) (11/14~15 업데이트, 클론으로 확인)

- 💡 내장 `sec-default` 모드가 새 이벤트들(`tool.call`, `tool.run`, `fs.write`, `process.run` 등)을 후킹하기 시작했다. 핵심은 **"모델의 호출은 권한 체크를 기다린다"**: 유저 티어 모드(개인 설치 플러그인)가 모델이 요청한 툴 호출을 권한 승인 전에 `$.tool.call`·`fs.write`·`process.run`으로 선실행하거나, 설정 파일을 건드리는 경로를 차단한다.
- 📝 모드를 직접 만든다면: 모델의 pending 호출을 받아서 "대신 실행해주는" 패턴은 이제 거부된다. 자동화가 필요하면 권한 체크 **이후** 단계(`tool.run` 통과 후)에 붙이거나 permission rule로 풀어라. 유저 티어 모듈이 없으면 이 훅들은 아예 비활성이라 오버헤드도 없다.
- 🎯 조직 정책이 있는 환경에서 서드파티 모드를 깔아 쓸 때, 모드가 권한 시스템을 우회할 수 있는지 걱정됐다면 — 이제 엔진 레벨에서 막힌다.
- ⚠️ `allowModsToOverrideDenyRules`를 켜면 이 보호도 함께 풀린다. 의미를 알고 켤 것.
- ⭐ 모드/플러그인을 쓰는 팀이라면 README의 이벤트 표를 한 번 정독할 가치가 있다.

**🟩 Codex / Context·Workflow** — [커밋 c8e4cbc](https://github.com/openai/codex/commit/c8e4cbcd9476795a08080f02e3bc09a64f6da80d) (11/14 머지, 클론으로 확인)

- 💡 롤아웃(스레드) 단위 토큰 예산 기능이 확장됐다. 정수 토큰(`limit_tokens`)뿐 아니라 **소수점 예산 단위(`limit_budget`)**를 받고, 잔액 리마인더 시점도 세밀하게 조절된다. 예산이 바닥나면 새 툴 작업 시작 자체를 막는다(같은 날 머지된 #61578·#61582).
- 📝 `config.toml`:

```toml
[features.rollout_budget]
enabled = true
limit_budget = 1.5            # 또는 limit_tokens = 200000 (둘 중 하나만)
enforce_limit = true           # 예산 소진 시 중단 (기본 true)
reminder_at_remaining_tokens = [50000, 10000]
reminder_at_context_start = false  # 스레드 시작·컴팩션 때 잔액 고지 끄기
```

- 🎯 CI나 배치에서 에이전트를 돌릴 때 "폭주한 세션 하나가 예산을 다 태우는" 사고 방지용 상한으로.
- ⚠️ `limit_tokens`와 `limit_budget`을 둘 다 쓰면 설정이 거부된다. 기능 플래그라 버전에 따라 동작이 바뀔 수 있다.
- ⭐ 멀티 에이전트 오케스트레이션에서 서브 스레드별 예산 배분 실험에 특히 유용.

**🟪 공통 / Security·Workflow** — [CapLite (arXiv 2611.17115)](https://arxiv.org/abs/2611.17115)

- 💡 인젝션 방어를 프롬프트가 아니라 **인터페이스에서** 구현하기: CapLite의 규칙 3개는 프레임워크 없이 툴 래퍼 수준에서 흉내 낼 수 있다.
- 📝 ① 쓰기 계열 툴(메일 발송·이체·파일 삭제)의 호출 계획은 **비신뢰 콘텐츠(툴 결과·문서)를 읽기 전에** 확정해 큐에 커밋. ② 수신자·금액·대상 인자는 유저 메시지에서 추출한 값과 대조해 불일치면 차단. ③ 정당한 예외는 사람 승인으로만 통과.
- 🎯 외부 문서·웹페이지·이메일을 읽는 에이전트에 쓰기 권한을 줄 때.
- ⚠️ 툴 결과에서 대상을 알아내야 하는 작업(예: "이 스레드의 발신자에게 답장")은 막힌다 — 그 케이스는 명시적 승인 플로로 분리할 것.
- ⭐ "주입 무시해" 시스템 프롬프트보다 훨씬 검증 가능한 방어다.
