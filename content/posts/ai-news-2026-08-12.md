# 🔥 오늘의 핵심

오늘 나온 두 보안 논문이 같은 급소를 찌른다: **에이전트에 무엇을 설치·공유하는지가 곧 공격 표면**이다. `ColluSkill`은 개별로는 멀쩡한 스킬을 여러 개 엮어 스캐너를 96% 우회하고, 또 다른 논문은 우리가 공개하는 세션 로그의 **암호화된 추론(CoT) 블록**에서 PII·크리덴셜이 실제로 복호화됨을 보였다.

**오늘 할 일:** 서드파티 스킬/MCP는 설치 전에 스캔을 *게이트*로 강제하고(단일 스킬이 아니라 체인 단위로), 에이전트 세션 로그를 공개할 땐 추론 블록을 민감정보로 취급해 스크럽하라.

# 📚 주목 논문

## 1. ColluSkill — 스킬 조합으로 스캐너를 뚫는다

- **저자/소속:** Puyu Zeng, Simeng Qin, Jingzhi Li, Ju Jia, Zheli Liu, Xiaojun Jia (arXiv, 소속 미표기)
- **arXiv:** 2608.09732 (cs.CR, 2026-08-10)
- **핵심 기여:** 지금의 스킬 스캐너는 대부분 *개별 스킬*만 검사한다는 맹점을 실증하고, 이를 노린 다중 스킬 체인 공격 프레임워크를 제안.
- **방법(2~3줄):** 하나의 악성 의도를 여러 스킬에 나눠 심는다. 각 스킬은 국소적으로 그럴듯해 검사를 통과하지만, 실행 순서·아티팩트 전달·실행 핸드오프로 이어지며 전체가 악성 워크플로가 된다. LLM 체인 플래닝 + 스캐너 피드백으로 개별 스킬의 의심 신호를 줄인다.
- **핵심 결과(검증):** 대표 스캐너 6종에서 평균 **ASR 96.0%**. 방어책 `ChainGuard`(후보 스킬을 *이미 설치된 스킬들과 함께* 문맥 분석)를 붙이면 **22.5%**로 떨어지고, 정상 워크플로는 **99.5%** 통과.
- 🛠 **에이전트 빌더 시사점:** "스킬 하나씩 스캔"은 안전 착시다. 설치 시점에 이미 깔린 스킬과의 의존·데이터 흐름까지 같이 봐야 한다.
- **한계:** 실험은 대표 스캐너 6종 대상. 실제 배포 환경의 커스텀 게이트/런타임 정책과의 상호작용은 별도 검증 필요.
- [arXiv 링크](https://arxiv.org/abs/2608.09732)

![ColluSkill과 ChainGuard의 공격 성공률·정상 통과율 막대 비교](/images/ai-news-2026-08-12/chainguard-chart.svg)
*단일 검사 회피 96.0% → 체인 스캔 방어 22.5%, 정상 통과 99.5%. 수치는 논문 초록에서 확인. (자체 제작 SVG)*

## 2. Stealing Reasoning Traces — 공개 로그의 추론 블록이 샌다

- **저자/소속:** Alexander Panfilov 외 (ELLIS Institute Tübingen, Max Planck Institute for Intelligent Systems 등)
- **arXiv:** 2608.09867 (cs.CR, 2026-08-10)
- **핵심 기여:** 제공사가 감춘 CoT를 클라이언트에 돌려주는 **암호화 블록**이 세션·사용자·모델 간에 호환·교환 가능하다는 구조적 취약점을 지적.
- **방법(2~3줄):** 강한 모델의 암호화 추론 블록을 *같은 제공사의 약한 모델*에 주입하면, 강한 모델을 직접 탈옥하지 않고도 평문 추론을 그대로 뱉게 만든다. Anthropic·OpenAI·Google에서 재현.
- **핵심 결과(검증):** 공개 저장소에서 긁은 **315,320개** 블록을 복호화해 **PII 367건, 크리덴셜 182건** 복원. 최종 출력이 안전하게 거절해도 추론 안엔 위험 정보가 남을 수 있고, 암호화 블록에 프롬프트 주입을 숨겨 공개 롤아웃을 오염시킬 수도 있다.
- 🛠 **에이전트 빌더 시사점:** 세션 로그·rollout을 공개할 때 암호화 추론 블록을 "안 보이니 안전"으로 여기면 안 된다. 민감정보로 간주하고 스크럽하라.
- **한계:** 제공사가 클라이언트-사이드 암호화/시스템 수준 완화를 적용하면 무력화될 수 있음(책임 공개 후 완화책 제안).
- [arXiv 링크](https://arxiv.org/abs/2608.09867)

# 🛠 오픈소스 스포트라이트

## NVIDIA/SkillSpector — 설치 전 스킬 보안 스캐너

- **repo:** [github.com/NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector)
- **언어:** Python (`uv tool`로 배포)
- **star:** 이 환경은 GitHub API/웹 egress가 차단돼 별 수를 검증하지 못했다. 아래는 공식 README·문서 기준 사실만 기재.
- **하는 일:** Claude Code·Codex·MCP 스킬을 설치하기 전에 **17개 카테고리 68개 취약 패턴**(프롬프트 주입, 데이터 유출, 권한 상승, 공급망, 시스템 프롬프트 유출, 메모리 오염, 도구 오용, taint tracking, YARA, MCP 최소권한 등)을 스캔. 빠른 정적 분석 + 옵션으로 LLM 의미 평가의 2단계.
- **에이전트 개발자 활용:** MCP 서버로 띄우면 어떤 MCP 지원 에이전트든 "스캔"을 도구로 호출해 설치를 게이트할 수 있다 — 감사가 아니라 런타임 가드레일.

```bash
# MCP 지원으로 설치
uv tool install --force 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'

# MCP 서버 실행 (stdio)
skillspector mcp
# 또는 HTTP/SSE
skillspector mcp --transport http --host 127.0.0.1 --port 8000
```

> 참고 링크: [skillscan-security](https://github.com/kurtpayne/skillscan-security)(스킬·MCP 번들용 스캐너, IOC/ML 분류기), [awesome-agent-skills-security](https://github.com/LLMSecurity/awesome-agent-skills-security)(공격·방어·벤치 큐레이션). 두 repo 역시 별 수는 egress 차단으로 미검증.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟦 Claude Code — MCP: 스킬 설치를 스캔으로 게이트

- **분류:** MCP
- **출처:** [SkillSpector README](https://github.com/NVIDIA/SkillSpector/blob/main/README.md)
- 💡 **핵심:** 서드파티 스킬/MCP를 "일단 설치하고 나중에 감사"하지 말고, 설치 자체를 스캔 결과에 묶어라.
- 📝 **How-to:** SkillSpector를 MCP 서버로 붙여 두고, 새 스킬을 넣기 전에 에이전트가 스캔 도구를 먼저 호출하게 한다.

```bash
skillspector mcp   # Claude Code의 .mcp.json에 stdio 서버로 등록
```

- 🎯 **언제:** 커뮤니티/마켓플레이스 스킬, 남이 만든 MCP 번들을 도입할 때.
- ⚠️ **주의:** 정적 스캔은 오늘 논문의 ColluSkill 같은 *체인 조합* 공격을 놓칠 수 있다. 이미 깔린 스킬과 함께 보는 체인 단위 분석을 병행하라.
- ⭐ **추천도:** ★★★★☆ — 무료 가드레일. 단일-스킬 스캔의 한계를 인지하고 쓸 것.
