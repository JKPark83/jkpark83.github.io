# 🔥 오늘의 핵심

DeepSeek이 사내 팀이 실제로 쓰던 자율 코딩 에이전트 **dsh-superagent**를 연구 프로토타입으로 공개했다(10/31, 하루 만에 7,000★). "사람의 주의력을 최소로 쓰고 가치를 최대로 준다"는 운영 철학을 코드와 문서로 통째로 보여주는 것이 핵심이다. 논문 쪽에서는 WebAnything이 실제 웹사이트를 실행 가능한 에이전트 환경으로 자동 재구축하는 파이프라인을 보여줬다 — 환경 부족이라는 에이전트 RL의 고질적 병목을 건드리는 작업이다.

# 🤖 모델 & 릴리즈 레이더

- **NVIDIA Nemotron 3.5 Transcribe (10/28 공개)** — 오픈 웨이트 음성 인식 모델. 30B MoE(활성 4B)로 40개 언어 전사, 31개 언어 번역, 최대 1시간 녹음에서 8인까지 화자 분리를 지원한다. 음성 인터페이스를 붙이는 에이전트 빌더에게는 셀프호스팅 가능한 ASR 선택지가 하나 늘어난 것. 벤치마크 수치는 아직 대부분 자체 보고라는 점은 감안할 것. [Hugging Face 모델 카드](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B) · [보도](https://thenextweb.com/news/nvidia-nemotron-3-5-transcribe-granary-v2-open-speech)

# 📚 주목 논문

## 1. WebAnything: 야생의 웹을 에이전트 환경으로

- **저자**: Tianci Xie, Zikun Cai, Chaoyun Zhang 외 (arXiv 피드에 소속 미표기)
- **arXiv**: [2610.37786](https://arxiv.org/abs/2610.37786) (cs.AI, 10/27 제출)
- **핵심 기여**: 실제 URL에서 출발해 사이트별 수작업 없이 재사용 가능한 실행형 웹 환경을 자동 재구축하는 프레임워크. 14개 도메인에서 244개 사이트 환경과 12,984개의 실행·검수 완료 태스크를 생산했다.
- **방법**: 라이브 웹을 크롤링해 실행 가능한 복제 환경으로 변환하고, 그 위에서 태스크를 생성·실행·수용 검사까지 자동으로 돌린다.
- **결과**: 사람 손을 거친 WebHarbor 환경과의 블라인드 비교에서 12승 2무 0패. 자체 생성 궤적 5,856개로 Qwen3.5-9B를 파인튜닝하자 WebArena-Verified 전체 성공률이 13.33%p 상승(논문 보고치).
- 🛠 **에이전트 빌더 시사점**: 웹 에이전트 평가·학습 환경을 직접 만들고 있다면, "사이트당 엔지니어링"을 전제로 한 설계를 다시 볼 때다. 사내 핵심 사이트 몇 개를 복제 환경으로 자동 변환하는 접근이 현실권에 들어왔다.
- **한계**: 재구축 환경이 원본 사이트의 동적 로직을 어디까지 보존하는지는 도메인별 편차가 있을 수밖에 없다.

![WebAnything 규모와 파인튜닝 효과](/images/ai-news-2026-11-02/webanything-stats.svg)

*244개 사이트, 12,984개 태스크, 그리고 파인튜닝 +13.33%p. 모두 논문 초록의 보고치다.*

## 2. VibeGame: 프롬프트에서 2D 게임까지, 적대적 에이전트 팀

- **저자**: Wenbo Hu, Ken Li, Jiazhe Wei 외 (arXiv 피드에 소속 미표기)
- **arXiv**: [2610.33106](https://arxiv.org/abs/2610.33106) (cs.MA, 10/22 제출, HF Daily 상위)
- **핵심 기여**: 자연어 프롬프트(+참고 이미지)에서 완성된 2D 게임 프로젝트를 만드는 시스템. 에이전트에게 검증된 프로젝트 상태와 프레임 동기 제어를 노출하는 AI 네이티브 엔진이 바탕이다.
- **방법**: 8개 전문 에이전트가 구현과 리뷰를 분리해 수정 라운드를 반복하고, 수용된 프로젝트를 학습 없이(training-free) 재사용 컴포넌트로 증류해 다음 작업에 쓴다.
- **결과**: GameCraft-Bench 부분집합에서 같은 기반 모델을 쓴 여러 에이전트 하네스(GPT-6.1-Sol 포함)보다 높은 성적(논문 보고치).
- 🛠 **에이전트 빌더 시사점**: "만드는 에이전트"와 "깎아내리는 에이전트"의 분리, 그리고 통과한 산출물의 컴포넌트화는 게임이 아니어도 그대로 옮겨 쓸 수 있는 패턴이다(아래 공통 팁 참고).
- **한계**: 2D·단일 엔진 전제라 범용 코드베이스로의 일반화는 별개 문제다.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — /subagents 피커, 승인 대기부터 보여준다

- **분류**: Subagent / Workflow · [커밋 181b4a8 (11/1)](https://github.com/openai/codex/commit/181b4a853d396f009a3a02b9c36eb393e6acbe75)
- 💡 서브에이전트를 여러 개 돌릴 때 병목은 "어느 놈이 내 승인을 기다리며 멈춰 있나"를 찾는 일이다. 이제 TUI의 `/subagents` 피커가 승인 대기 스레드를 맨 위에 `(needs approval)` 표시로 묶고, 첫 대기 스레드를 기본 선택해 준다.
- 📝 서브에이전트를 띄워 두고 작업하다가 승인 알림이 오면:

```text
/subagents   → 승인 대기 스레드가 상단에 자동 정렬·선택됨 → Enter로 바로 진입
```

- 🎯 긴 작업을 3~4개 서브에이전트에 쪼개 위임하는 워크플로에서, 승인 때문에 전체가 놀고 있는 시간을 줄일 때.
- ⚠️ 피커가 열려 있는 동안에도 목록이 실시간 갱신되므로, 행이 움직여도 선택은 유지되지만 눈으로 따라가며 확인할 것.
- ⭐ 추천도: 서브에이전트 다중 운용자라면 오늘부터 손에 익혀둘 가치가 있다.

## 🟦 Claude Code — 방치한 장수 세션은 idle compaction이 정리한다

- **분류**: Context · [v2.1.314 릴리즈 노트](https://github.com/anthropics/claude-code/releases/tag/v2.1.314)
- 💡 VS Code와 Claude Desktop의 Code 탭에서, 200K 토큰을 넘긴 대화를 쉬게 두면 유휴 시간에 미리 요약(idle compaction)해 두고, 프롬프트 캐시가 만료된 다음 메시지부터 그 요약을 쓴다. 긴 세션을 하루 종일 열어두는 사람이라면 "돌아왔을 때 첫 응답이 왜 빠른지/문맥이 왜 압축됐는지"가 이것 때문일 수 있다.
- 📝 운용 전략: compaction을 전제로, 세션이 길어질 것 같으면 중요한 결정·규칙은 대화에만 남기지 말고 파일로 외부화한다.

```text
요약돼도 살아남아야 할 것 → CLAUDE.md 또는 docs/decisions.md에 기록
대화에만 있어도 되는 것 → 그대로 두고 compaction에 맡김
```

- 🎯 리뷰 대기, 빌드 대기 등으로 세션을 몇 시간씩 방치하는 워크플로.
- ⚠️ IDE(VS Code·Desktop Code 탭) 쪽 동작이다. 터미널 CLI의 수동 `/compact`·auto-compact 설정과는 별개로 이해할 것.
- ⭐ 추천도: 설정할 것은 없지만, 장수 세션 운용자라면 동작 원리를 알아둬야 당황하지 않는다.

## 🟪 공통 — 빌더/리뷰어 분리 + 통과한 산출물은 컴포넌트로 증류

- **분류**: Workflow / Eval · [arXiv 2610.33106 (VibeGame)](https://arxiv.org/abs/2610.33106)
- 💡 VibeGame이 하네스들을 이긴 구조는 단순하다: 구현 에이전트와 리뷰 에이전트를 분리해 수정 라운드를 돌리고, **리뷰를 통과한 결과물만 재사용 컴포넌트로 승격**해 다음 태스크의 재료로 쓴다. 학습(파인튜닝) 없이 시스템이 점점 좋아지는 메모리 설계다.
- 📝 적용: 에이전트가 만든 코드 조각·프롬프트·스킬 중 리뷰(사람 또는 리뷰 에이전트)를 통과한 것만 `skills/` 또는 스니펫 저장소로 승격하는 규칙을 파이프라인에 박는다. 실패작까지 쌓으면 메모리가 오염된다.
- 🎯 같은 유형의 작업을 반복 위임하는 팀. 승격 기준이 곧 품질 게이트가 된다.
- ⚠️ "통과"의 기준이 느슨하면 나쁜 패턴이 복리로 재사용된다. 승격 문턱은 높게.
- ⭐ 추천도: 에이전트 메모리를 고민 중이라면 가장 싸게 시작할 수 있는 형태.
