# 🤖 모델 & 릴리즈 레이더

- **Nanbeige4.3-33B 공개 (10/24)** — [Nanbeige LLM Lab](https://huggingface.co/Nanbeige/Nanbeige4.3-33B)이 올린 33B 모델. Apache 2.0, 512K 컨텍스트, agentic coding·코워크 특화를 표방하며 "Nanbeige4.3 시리즈의 플래그십 교사 모델"이라고 스스로를 소개한다(3B 증류판 예고). 자체 발표 기준 Terminal-Bench 2.1 80.9, DeepSWE 65.5로 Qwen3.8-27B·Gemma4-31B급 비교군을 크게 앞선다. 에이전트용 권장 샘플링이 temperature 1.0 / top_p 0.95 / 최대 65,536 토큰으로 명시된 점도 체크.
- **DeepSeek-V4.1-Flash-1017 2비트 GGUF (ISTA-DASLab)** — [GSQ-RCO 양자화 3종](https://huggingface.co/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF)이 10/23 올라와 이미 다운로드 41만 회. 텐서별 민감도에 따라 양자화 타입을 다르게 배정하는 방식(GSQ: [2604.18556](https://arxiv.org/abs/2604.18556), RCO: [2605.00649](https://arxiv.org/abs/2605.00649))으로, 권장 빌드 IQ2_XXS(2.00bpw, 248.8GB)가 자체 측정에서 기준 모델 성능 100% 회복을 주장한다. llama.cpp는 아직 V4.1 미지원이라 실행은 아래 Strata 경유.

# 📚 주목 논문

## Agent Mosaic: 에이전트의 "조합 유출"

- **저자**: Daniel Ruiz, Luca Luceri, Emilio Ferrara (USC/ISI)
- **arXiv**: [2610.30418](https://arxiv.org/abs/2610.30418) (cs.CR, 10/21)
- **핵심 기여**: 개별적으로는 접근이 허용된 문서들을 에이전트가 **조합**해 금지된 결론을 만들어내는 "모자이크 효과"를 정량화했다.
- **방법**: 사이버보안·의료·군사 3개 도메인 30개 합성 시나리오. 시뮬레이션에서 LLM 에이전트 3종의 답변 10,800개, 오픈소스 하네스 2종의 라이브 에이전트 답변 1,440개를 분석.
- **결과**: 가장 성적이 좋은 GPT-5.6-Sol조차 악의 없는 질문에서 금지 조합을 7.08% 유출(95% CI 3.75~10.67). 등급 헤더 노출 + 집계 금지 규칙을 넣으면 크게 줄지만, 전체 의도 기준 시뮬레이션 답변의 32.37%에서 유출이 잔존. 심지어 **거부 응답 자체가 금지된 결론을 드러내는** 케이스도 상당수.
- 🛠 **Agent Builder 시사점**: 문서 단위 ACL은 조합 공격 앞에서 불충분하다. RAG/사내 문서 위에 에이전트를 올렸다면 "개별 문서는 무해, 조합이 민감"인 레드팀 케이스를 따로 만들어야 한다.
- **한계**: 합성 시나리오 30개 기반이라 실제 사내 데이터의 복잡도와는 거리가 있다.

## Heartbeat Thinking: 듣는 동안 일하는 음성 에이전트

- **저자**: Zhenyu Zhang, Kewei Fu, Yongqi Tong 외 (소속 미표기)
- **arXiv**: [2610.26233](https://arxiv.org/abs/2610.26233) (cs.CL, 10/19)
- **핵심 기여**: 사용자가 말을 끝내기 전에 추론·툴 실행을 미리 진행하되, 기존 추측 실행(speculative execution)의 고질병 — 트랜스크립트가 갱신될 때 진행 중이던 툴 콜이 인자 미완성 상태로 잘리는 문제 — 을 해결했다.
- **방법**: 주기적("heartbeat")으로 새 Thinker 호출을 띄워 최신 부분 트랜스크립트와 공유 기록(완료된 추론·툴 결과)을 읽게 하고, **진행 중인 호출과 디스패치된 툴은 끝까지 완주**시킨다.
- **결과**: FDBench v3에서 툴 커버리지 +16%p, 최종 응답 평균 지연 -36.4% (SHANKS류 윈도 베이스라인 대비).
- 🛠 **Agent Builder 시사점**: 음성이 아니어도 적용 가능한 패턴이다 — 스트리밍 입력(타이핑 중인 유저, 흘러오는 로그)을 받는 에이전트라면 "갱신 시 전부 취소" 대신 "완주 + 새 호출 추가"가 기본값이 될 수 있다.
- **한계**: 최종 태스크 품질 개선은 벤치마크에 따라 들쑥날쑥하고, 추측 실행이 많아질수록 컴퓨트·부작용(side effect) 관리 비용이 든다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟩 Codex — 카테고리: Debugging(관측성)**

- 소스: [openai/codex 커밋 b82d542 (10/23)](https://github.com/openai/codex/commit/b82d542aefbbcc1f46e508cdeaa4b454877d180f)
- 💡 OTel 트레이스에 **턴·툴·스킬 어트리뷰션**이 들어갔다. 턴이 끝나거나 중단될 때 샘플링 요청 수·재시도 횟수를 담은 `codex.turn_profile` 이벤트가 찍히고, 툴 스팬에 대화·턴 ID와 "디스패치→결과 수신" 소요 시간, 스킬 읽기에는 `codex.skill_read.source_selected`(캐시/클라우드 소스 구분)가 기록된다.
- 📝 `config.toml`에서 트레이스 익스포터를 로컬 컬렉터로 연결:

```toml
[otel]
environment = "dev"
trace_exporter = { otlp-grpc = { endpoint = "http://localhost:4317" } }
```

- 🎯 멀티턴 에이전트가 느릴 때 "어느 턴에서 재시도가 터졌나, 어느 툴이 오래 걸렸나"를 감으로 때려맞추던 팀.
- ⚠️ `trace_exporter` 기본값은 none이라 명시해야 하고, 프롬프트/응답 로깅(`log_user_prompt` 등)은 별도 opt-in — 민감정보가 컬렉터로 나간다는 뜻이니 신중히.
- ⭐ 추천도: 관측성 스택이 이미 있는 팀이면 바로 연결해볼 만.

**🟦 Claude Code — 카테고리: Hook/Plugin**

- 소스: [anthropics/claude-code `mods/` 폴더](https://github.com/anthropics/claude-code/tree/main/mods)
- 💡 Claude Code에 내장된 mod 4종(`diff`, `telemetry`, `agents-md`, `sec-default`)의 **소스가 저장소 mods/ 폴더로 공개·동기화**되고 있다(10/24~25에도 갱신). mod는 훅 모듈 하나(`register(on, options)`)로 동작하는 플러그인 — 커스텀 패널이나 훅을 만들 때 공식 레퍼런스 구현이 생긴 셈이다.
- 📝 소스에서 바로 실행하고, 모의 엔진으로 테스트까지:

```bash
git clone --depth 1 https://github.com/anthropics/claude-code
claude --plugin-dir claude-code/mods/diff   # /diff 패널을 소스로 실행
claude plugin test claude-code/mods/diff    # tests/를 모의 엔진으로 구동
```

- 🎯 `/diff` 같은 사이드 패널, AGENTS.md 로딩 정책(`agents-md`), 조직 정책 보호(`sec-default`)가 각각 어떻게 구현되는지 보고 베끼면 된다. 테스트 킷(`claude-code/testing`의 `mock.clock` 등) 사용례로도 유일한 공식 샘플.
- ⚠️ sec-default는 지금도 시맨틱이 움직이는 중(10/25에 managed 플러그인의 reopen 규칙 문서화) — 참고하되 최신 커밋 기준으로.
- ⭐ 추천도: 플러그인/mod 작성자 필독.

**🟪 공통 — 카테고리: Review(보안)**

- 소스: [arXiv 2610.30418 (Agent Mosaic)](https://arxiv.org/abs/2610.30418)
- 💡 에이전트 보안 리뷰에서 문서 단위 권한만 보지 말 것 — **유출은 조합에서 난다**. 그리고 거부 응답도 정보를 흘린다.
- 📝 체크리스트: ① 문서 등급 헤더를 모델에게 보이게 유지 ② 시스템 프롬프트에 집계·조합 금지 규칙 명시 ③ 평가 세트에 "개별 문서는 무해, 조합이 민감"인 프로브 추가 ④ 거부 템플릿이 거부 사유(= 민감한 결론)를 복창하지 않게 고정.
- 🎯 사내 위키·티켓·문서 위에 RAG 에이전트를 올리는 모든 팀.
- ⚠️ 저자들 측정으로도 가드 적용 후 잔존 유출이 32.37% — 완화책이지 해결책이 아니다.
- ⭐ 추천도: 보안 리뷰 항목으로 오늘 추가 권장.
