# 📚 주목 논문

## 1. Change2Task — 병합된 PR을 "실행 가능한 코딩 태스크"로

- **저자/소속**: Haomin Qi, Xingliang Wang, Minghua Ma 외 12인
- **arXiv**: [2607.28591](https://arxiv.org/abs/2607.28591) · cs.SE
- **핵심 기여**: repo 히스토리에서 **merged PR을 최신 healthy 리비전 위의 검증된 태스크로 자동 변환**. 외부 벤치마크가 아니라 "내 레포"에서 오염 없는 eval을 뽑는다.
- **방법(3줄)**: 병합 PR의 개발자 증거(diff·테스트)를 진화한 코드에 정렬(Code Mapping)하거나, 패치를 되돌리거나(Patch Reversal), 에이전트가 상태를 복원(Agent Reconstruction). 이후 `healthy → task → restored` 라이프사이클로 검증.
- **결과**: 1,130개 소스 변경에서 시작해 **검증 성공률 79.6%**. Bug Fix / Feature 추가 / Test 생성 / API 마이그레이션 / Security 수정 5개 패밀리 지원.
- 🛠 **에이전트 빌더 시사점**: 공개 벤치는 오염·포화된다. 내 repo PR 히스토리를 CI에 붙여 **contamination-free 회귀 셋**을 굴리면 에이전트 성능 변화를 지속 추적 가능.
- ⚠️ **한계**: 20% 이상은 재구성 실패 — 환경 셋업이 복잡한 레포는 여전히 수작업이 든다.

## 2. ORCA-bench — 온콜 RCA, 프런티어도 25%대

- **저자/소속**: Albert Gong, Kyuseong Choi 외 8인
- **arXiv**: [2607.28545](https://arxiv.org/abs/2607.28545) · cs.CL
- **핵심 기여**: 실제 OpenTelemetry(Prometheus·Jaeger·OpenSearch) 위에서 도는 **프로덕션급 온콜 root cause 분석 벤치마크**. 1,079개 RCA 태스크, 6일치 메트릭·로그·트레이스 + 전체 소스코드 접근.
- **방법**: 모호한 사용자 리포트에서 시작해 노이즈 많은 텔레메트리를 추론. LLM-as-judge를 사람이 재채점(Cohen's κ=0.90)해 신뢰도 확보.
- **결과**: 프런티어 5종 중 최고가 Medium(현실 입력) **25.3%**, Hard **10.0%** — Claude Fable 5도 이 격차를 못 넘음. 최약체 모델은 리포트의 **40%에서 근거 없는 원인을 환각**.
- 🛠 **에이전트 빌더 시사점**: **소스코드 접근을 빼면 모든 지표 하락.** 온콜 에이전트엔 로그·트레이스뿐 아니라 코드 접근이 필수. 아직 사람 대체는 무리 — "가설 + 근거 링크" 보조로 스코프를 좁혀라.
- ⚠️ **한계**: 단일 마이크로서비스 시스템 기반 — 조직마다 텔레메트리 스택이 달라 일반화엔 주의.

- **[microsoft/SWE-bench-Live](https://github.com/microsoft/SWE-bench-Live)** · Python · ~135★
  자동 큐레이션으로 **매달 갱신되는** SWE 태스크셋(현재 1,890 태스크 / 223 repo, 다국어·다OS). Change2Task와 같은 철학 — 오염 없는 최신 평가. 내 에이전트를 "최근 이슈"로 검증하고 싶을 때.
- **[SWE-bench/SWE-bench](https://github.com/SWE-bench/SWE-bench)** · Python · ~5.5K★
  실제 GitHub 이슈를 패치로 해결하는 원조 벤치마크. 에이전트 회귀 테스트의 사실상 표준 하네스.
- **[All-Hands-AI/OpenHands](https://github.com/All-Hands-AI/OpenHands)** · Python · ~82K★
  가장 많이 쓰이는 오픈소스 자율 코딩 에이전트. 위 태스크셋을 **실제로 돌려볼 러너**로 붙이기 좋다.

즉, `OpenHands(에이전트)` × `SWE-bench-Live(최신 태스크)` = 로컬에서 굴리는 오염-없는 평가 루프.

# 🧑‍💻 Codex & Claude Code 실전 팁

### 🟩 Codex — Subagent로 병렬 팬아웃

- **category**: Subagent · [공식 문서](https://developers.openai.com/codex/subagents/)
- 💡 **core idea**: Codex는 자동으로 서브에이전트를 안 띄운다. **명시적으로 지시**해야 병렬 팬아웃 → 결과 취합.
- 📝 **how-to**: 대규모 리팩터/탐색에서 프롬프트에 직접 지시.

```text
이 모노레포를 두 에이전트로 병렬 탐색해줘:
- agent 1: services/ 아래 결제 흐름 정리
- agent 2: packages/ 아래 공용 유틸 의존성 맵
각자 구조화된 리포트만 반환하고, 내가 합칠게.
```

- 🎯 **when**: 코드베이스 탐색, 다단계 계획 실행처럼 병렬성이 큰 작업.
- ⚠️ **caveat**: 서브에이전트마다 자체 모델·툴 호출 → **토큰이 단일 실행보다 많이 든다.**
- ⭐ **추천**: 탐색·조사엔 강추, 순차 의존이 큰 작업엔 오히려 비효율.

### 🟦 Claude Code — `claude -p`를 CI 린터로

- **category**: Workflow · [Headless 문서](https://code.claude.com/docs/en/headless)
- 💡 **core idea**: `-p`(비대화) 모드로 Claude Code를 **프로젝트 전용 린터/리뷰어**로 스크립트화. diff를 파이프로 넘기면 Bash 권한도 불필요.
- 📝 **how-to**: `package.json`에 한 줄.

```json
{
  "scripts": {
    "lint:claude": "git diff main | claude -p \"you are a typo linter. for each typo in this diff, report filename:line on one line and the issue on the next. return nothing else.\""
  }
}
```

CI에선 `--bare`를 붙여 로컬 훅·MCP·CLAUDE.md 자동 로딩을 끄고 머신 간 결과를 재현.

- 🎯 **when**: PR 자동 리뷰, 오타/규칙 린팅, 구조화 출력이 필요한 CI 게이트(`--output-format json`).
- ⚠️ **caveat**: `--bare` 없이는 로컬 `~/.claude` 훅/MCP가 딸려와 결과가 머신마다 달라진다.
- ⭐ **추천**: 위 Change2Task 태스크셋과 결합해 "diff → 자동 검증" 게이트로.

### 🟪 공통 — 내 repo PR로 eval 셋을 만들어라

- **category**: Eval · [arXiv 2607.28591](https://arxiv.org/abs/2607.28591)
- 💡 **core idea**: 벤치마크를 기다리지 말고 **병합된 PR = 정답이 있는 태스크**로 재활용. 오염 없고 도메인에 딱 맞는다.
- 📝 **how-to**: (1) 최근 병합 PR 20개 선별 → (2) 패치를 되돌려 "before 상태" 재구성 → (3) PR의 테스트를 정답 검증기로 → (4) 에이전트에게 그 이슈를 던지고 테스트 통과율 측정.
- 🎯 **when**: 모델/스캐폴드 바꿀 때마다 회귀를 잡고 싶을 때.
- ⚠️ **caveat**: 환경 셋업이 복잡한 PR은 재구성 실패율이 높다(논문도 ~20% 실패). 셋업이 단순한 PR부터.
- ⭐ **추천**: 소규모 10~20개라도 **CI에 붙여 상시화**하는 게 일회성 벤치보다 낫다.
