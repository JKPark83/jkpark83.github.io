1. 도입 — 훈련 0번, 점수 3배: 이번 주의 논쟁

ARC-AGI-3는 2026년 3월 ARC Prize 재단이 공개한 상호작용형(interactive) 추론 벤치마크입니다. 설명서 없는 미니 게임 환경에 에이전트를 떨어뜨려 놓고, 스스로 탐색하고 규칙을 알아내 목표를 달성하는지를 봅니다. 공개 당시 프론티어 모델 전원이 1% 미만을 기록해 화제가 됐던, 그 악명 높은 벤치마크입니다.

그런데 8월 마지막 주, Prime Intellect가 arXiv에 올린 기술 논문 Prime Agent: A Self-Improving RLM Harness가 Hugging Face 데일리 페이퍼 트렌딩과 Hacker News 첫 페이지에 동시에 올랐습니다. 주장은 단순하고 도발적입니다. 같은 모델(Claude Opus 5)을 기본 하네스로 돌리면 30% 수준인데, 자기네 하네스에 태웠더니 Best@1 95.5% — 인간 전문가 기준선 95.4%를 넘었다는 겁니다. 파인튜닝도, RL도 없이요. 오픈소스 저장소 prime-agent는 공개 하루 만에 GitHub 스타 2,200개를 넘겼고, 커뮤니티에서는 "이제 병목은 모델이 아니라 하네스"라는 진영과 "self-improvement 루프가 벤치마크 취지를 우회한 것 아니냐"는 진영이 맞붙었습니다.

이 글은 그 논쟁의 재료인 Prime Agent를 뜯어봅니다. 점수 자체보다 중요한 건 설계입니다. Prime Agent는 요즘 코딩 에이전트의 두 가지 고정관념 — "도구는 tool call 스키마로 준다", "프롬프트·스킬·메모리는 개발자가 설계 시점에 고정한다" — 를 둘 다 버렸습니다. 그 자리에 들어온 것이 RLM(Recursive Language Model) 런타임과 Continual Harness입니다.

이 글에서 얻어 갈 것. ① 하네스가 왜 에이전트 성능의 병목이 되는지, ② 도구 호출 대신 Python 커널 하나만 주는 RLM 런타임의 동작 원리, ③ 서브에이전트를 rlm() 함수 호출로 띄우고 메시지로 조율하는 법, ④ 프롬프트·스킬·메모리를 에이전트가 스스로 고치는 Continual Harness와 /refine, ⑤ 95.5%라는 숫자를 읽을 때 걸러야 할 것들.

2. 배경 — 하네스란 무엇이고, 왜 병목이 됐나

하네스(harness)는 LLM을 감싸고 있는 실행 루프 전체를 말합니다. 시스템 프롬프트를 조립하고, 모델이 요청한 도구를 실행해 결과를 돌려주고, 컨텍스트가 넘치면 압축하고, 세션을 저장하는 — Claude Code나 Codex CLI 같은 코딩 에이전트에서 모델을 뺀 나머지 전부입니다. 말이 몸통(모델)이라면 하네스는 마구(馬具)입니다. 같은 말이라도 마구가 엉망이면 수레는 똑바로 가지 못합니다.

전통적인 하네스는 도구 호출(tool calling) 루프로 돕니다. 모델이 JSON으로 도구를 호출하면, 하네스가 실행하고, 결과 텍스트를 대화에 붙여 다시 모델에게 보여 줍니다. 단순하고 견고하지만, 작업이 길어지면 두 가지 비용이 쌓입니다.

첫째, 모든 중간 결과가 컨텍스트를 통과해야 합니다. 로그 파일 5만 토큰을 grep 한 번 하려 해도 일단 5만 토큰을 읽어야 하고, 그 결과는 이후 모든 턴에서 입력 토큰으로 다시 과금됩니다. 이 블로그에서 다룬 context rot — 컨텍스트가 길어질수록 정확도가 떨어지는 현상 — 도 함께 옵니다. 둘째, 하네스 자체는 성장하지 않습니다. 시스템 프롬프트, 스킬 목록, 서브에이전트 구성은 개발자가 설계 시점에 박아 둔 그대로입니다. 에이전트가 오늘 삽질 끝에 알아낸 "이 저장소는 테스트 전에 pnpm build를 먼저 해야 한다" 같은 교훈은 세션이 끝나면 증발합니다.

첫 번째 문제의 해법으로 나온 것이 재귀 언어 모델(RLM, Recursive Language Model)입니다. 예전 글에서 자세히 다뤘는데, 요지는 이렇습니다. 긴 컨텍스트를 attention으로 통째로 읽는 대신 Python REPL의 변수로 두고, 모델이 코드로 슬라이싱·검색하고 필요한 조각만 서브 LM에게 재귀적으로 맡기는 추론 전략입니다. 당시에는 "긴 문서 QA를 위한 추론 기법"에 가까웠습니다. Prime Agent는 이 아이디어를 코딩 에이전트 하네스 전체의 설계 원리로 밀어붙였고, 두 번째 문제를 위해 Continual Harness를 얹었습니다. 순서대로 보겠습니다.

3. RLM 런타임 — 도구 대신 Python 커널 하나

Prime Agent가 모델에게 주는 내장 도구는 단 하나, ipython입니다. 파일 읽기·쓰기, 셸 명령, 데이터 가공, 스킬 호출, 서브에이전트 생성까지 전부 이 지속(persistent) IPython 커널 안에서 코드로 합니다. 도구 30개의 JSON 스키마로 시스템 프롬프트를 채우는 대신, "Python으로 뭐든 하라"는 겁니다.

핵심은 컨텍스트를 변수로 다룬다(prompt-as-a-variable)는 점입니다. 5만 토큰짜리 테스트 로그는 logs라는 변수에 담기고, 모델의 컨텍스트에는 실행 결과 중 print()한 부분만 들어옵니다. 다음 턴에 그 로그가 다시 필요하면 원문을 재입력하는 게 아니라 fails[:5]처럼 슬라이싱해서 봅니다. Python 상태는 턴 사이는 물론 컨텍스트 컴팩션(압축) 후에도 유지되므로, 변수·import·헬퍼 함수가 세션의 "외부 기억" 역할을 합니다.

셸 명령도 커널 안에서 bash()로 부릅니다.

{{< highlight python >}} # 각 bash() 호출은 독립 프로세스지만, # os.chdir / os.environ 변경과 Python 변수는 커널에 계속 남습니다 result = await bash("npm run check") print(result.output[-2000:]) # 끝부분만 컨텍스트로 가져오기 from pathlib import Path big_configs = [p for p in Path(".").rglob("*.toml") if p.stat().st_size > 10_000] {{< /highlight >}}

서브에이전트는 함수 호출이다

서브에이전트도 별도 도구가 아니라 커널에 미리 로드된 rlm() 호출입니다. 호출하면 독립 컨텍스트를 가진 진짜 자식 세션이 만들어지고, 부모에게는 접수 핸들(admission handle)만 즉시 돌아옵니다. 여기서 재밌는 설계가 하나 있는데, rlm()은 자식의 답을 절대 반환값으로 돌려주지 않습니다. 결과는 자식이 agent_message로 회신하거나 파일로 남길 때만 도착합니다. 부모가 자식을 기다리며 블로킹하는 대신, 여러 자식을 병렬로 띄워 놓고 턴을 끝내면 됩니다.

{{< highlight python >}} # 자식 셋을 병렬로 띄운다 — 반환값은 결과가 아니라 접수 핸들 api_review = await rlm("공개 API 표면을 리뷰해 줘", name="api-reviewer") test_review = await rlm("테스트 커버리지 구멍을 찾아 줘", name="test-reviewer") slow_audit = await rlm("느린 통합 감사를 백그라운드로 돌려 줘", name="integration-audit") # 자식 쪽에서는 답할 게 생기면 부모에게 메시지를 보낸다 await agent_message.send(message, receiver_role="parent") # 부모는 나중에 살아 있는 자식에게 후속 지시를 보낼 수 있다 await agent_message.send( "새로 추가된 회귀 테스트도 확인해 줘", receiver_role="child", receiver_name=api_review.name, ) {{< /highlight >}}

메시지 전달 모드는 세 가지입니다. steer는 작업 중인 상대의 컨텍스트에 즉시 끼워 넣고(방향 수정), follow_up은 현재 작업이 끝날 때까지 기다리며, auto는 상대가 바쁘면 steer, 놀고 있으면 즉시 전달합니다. 자식 목록은 rlm.list_subagents()로 조회하는데, 이 레지스트리는 컴팩션·커널 재시작·부모 복원 후에도 살아남습니다. 형제(sibling) 에이전트끼리도 데몬을 거쳐 직접 메시지를 주고받을 수 있어서, 사용자를 경유하지 않는 에이전트 간 조율이 가능합니다.

4. Continual Harness — 하네스도 상태다, 그래서 고칠 수 있다

여기까지가 "실행"이라면, Prime Agent의 두 번째 축은 "축적"입니다. Continual Harness는 하네스의 구성 요소를 H = (프롬프트 ρ, 서브에이전트 G, 스킬 K, 메모리 M)이라는 상태로 정식화하고, 에이전트가 자기 트래젝터리(작업 기록)에서 배운 것을 이 상태에 CRUD — 생성·조회·수정·삭제 — 할 수 있게 합니다. 커널에는 create_prompt_note(...), create_memory(...), create_skill(...), create_subagent(...)와 각각의 update_*/delete_*, 그리고 list(kind)/get(kind, id)가 준비되어 있습니다.

수동으로도 할 수 있지만, 대표 진입점은 /refine 명령입니다. 현재 트래젝터리를 되돌아보고, 근거가 있는 작은 업데이트 — 새 스킬 하나, 메모리 노트 하나, 서브에이전트 프롬프트 다듬기 — 를 제안·적용합니다. 중요한 안전장치가 두 개 있습니다. 기반 시스템 프롬프트는 불변(immutable)이라 /refine이 건드릴 수 없고, 모든 변경은 스냅숏으로 기록되어 ID로 롤백할 수 있습니다.

익숙한 그림 아닌가요? Agent Skills의 SKILL.md, 메모리 파일, AGENTS.md 같은 것들을 개발자가 손으로 다듬는 워크플로우를, 에이전트 자신의 루프 안으로 끌어들인 겁니다. 실제로 Prime Agent의 스킬은 Agent Skills 마크다운 형식과 호환되고, 여기에 Python-backed 스킬을 얹었습니다. SKILL.md로 발견·라우팅되는 것까지는 같지만, 스킬이 Python 패키지를 품고 있어서 커널에서 await release_audit(repository=".", target_version="0.4.0")처럼 타입 있는 함수로 부를 수 있습니다. 시작 프롬프트에는 스킬 메타데이터만 올라가고, 본문은 작업이 맞을 때만 로드됩니다 — 컨텍스트 절약의 기본기죠.

왜 "self-improving"이라 부를 수 있나. 모델 가중치는 한 번도 바뀌지 않습니다. 바뀌는 건 하네스 상태 H뿐입니다. 그런데 에이전트의 실전 성능은 (모델 × 하네스)의 곱이므로, H가 세션을 거듭하며 좋아지면 시스템 전체는 학습 없이도 점점 잘하게 됩니다. ARC-AGI-3 결과가 바로 이 루프 — 게임을 하다 알아낸 규칙을 스킬·메모리로 축적 — 에서 나왔습니다.

5. 장시간 실행 장치 — 데몬, heartbeat, goal, autonomous mode

몇 시간짜리 작업을 맡기려면 "터미널을 닫으면 죽는 프로세스"로는 부족합니다. Prime Agent는 세션을 로컬 데몬이 소유한 상주 워커에서 돌립니다. 터미널 UI를 닫는 건 detach일 뿐이고, 워커는 큐·스케줄·커널·자식들을 계속 안고 갑니다. prime-agent attach로 언제든 다시 붙습니다. 그 위에 재진입 장치가 몇 겹 얹혀 있습니다.

장치소유자하는 일
/heartbeat사용자현재 세션에 보이는 반복 지시 1개. "10분마다 배포 상태 확인해서 의미 있는 변화만 보고해."
rlm_heartbeat에이전트에이전트가 코드로 만드는 내부 반복 지시 여러 개. 테스트 완료 폴링 같은 것.
prime-agent schedule사용자·자동화일회성/cron 프롬프트를 특정 에이전트에 예약. 크래시 시 중복 재생 방지, 밀린 틱은 병합.
/goal사용자완료될 때까지 턴마다 계속 제시되는 지속 목표. 토큰 예산 지정 가능, goal.complete()만이 성공 처리.
/autonomous사용자사람 입력 없이 계속 이어 가는 모드. 턴·토큰·시간 예산과 품질 게이트(quality gate)로 제한.

autonomous mode의 게이트가 특히 실용적입니다. --autonomous-gate "npm run check"처럼 걸어 두면, 게이트 명령이 통과할 때까지 세션이 끝나지 못하고, 실패 출력이 에이전트에게 되돌아가 다음 시도의 재료가 됩니다. 작업 공간에 변화가 없으면 같은 게이트를 다시 돌리지 않는 것도 잔돈 아끼는 디테일입니다. 컨텍스트가 넘치면 자동 컴팩션이 오래된 메시지를 요약하는데, Python 커널은 컴팩션을 통과해도 살아 있으므로 변수·헬퍼 함수·작업 상태는 잃지 않습니다. 이 조합 — 커널에 상태, 트랜스크립트에 기록, 데몬에 생명주기 — 이 장시간 작업의 바닥을 받칩니다.

6. 숫자 읽기 — 95.5%를 어디까지 믿어야 하나

먼저 벤치마크의 성격부터. ARC-AGI-3의 점수 RHAE(Relative Human Action Efficiency)는 정답 여부만 보지 않습니다. 레벨 점수가 min(1, (인간의 행동 수 / AI의 행동 수))²로 계산되어, 인간보다 10배 많은 행동으로 깬 레벨은 1%밖에 못 받습니다. 즉 95.5%는 "다 깼다"가 아니라 "인간 전문가만큼 효율적으로 깼다"는 뜻이라 더 인상적인 숫자입니다. 논문은 ARC-AGI-3 외에도 긴 컨텍스트 코딩(OOLONG 128k: 0.700 vs 기본 하네스 0.420), 에뮬레이터 구축(EmulatorBench: 0.208 vs 0), 그리고 자율 연구 태스크인 nanoGPT speedrun — 124M 파라미터 GPT를 고정 검증 손실까지 학습시키는 스텝 수를 에이전트가 얼마나 줄이는가 — 에서 인간 기록 2,990스텝을 깬 2,930스텝(8시드 평균 검증)을 보고합니다.

이제 걸러 읽을 차례입니다. 세 가지를 기억해 두세요.

첫째, 전부 벤더 자체 보고입니다. 95.5%는 Prime Intellect가 자기 하네스로 돌린 수치이고, 아직 독립 재현이 없습니다. 둘째, Hacker News에서 제기된 방법론 쟁점이 있습니다. ARC-AGI-3는 몇 번의 시도 안에 새 환경에 적응하는 능력을 재려는 벤치마크인데, 스킬·메모리를 축적하는 self-improvement 루프가 이 취지와 충돌하는 것 아니냐는 겁니다. "그 축적이야말로 우리가 원하는 지능"이라는 반론도 있어서, 이 논쟁 자체가 이번 주 이 논문이 화제가 된 이유이기도 합니다. 셋째, 비교 대상인 "기본 하네스 30%"는 같은 모델을 일반적인 도구 호출 루프로 돌린 결과라, 하네스 간 비교이지 모델 간 비교가 아닙니다. 결론은 이렇게 잡는 게 안전합니다. "하네스 설계가 벤치마크 점수를 3배 움직일 수 있다"는 방향성은 신뢰할 만하고, 소수점 숫자는 검증을 기다리는 중.

7. 실전 — 설치하고 서브에이전트 굴려 보기

백문이 불여일런입니다. macOS/Linux에서 설치는 한 줄입니다(설치 스크립트는 버전 지정 릴리스를 받아 SHA-256 체크섬을 검증합니다).

{{< highlight bash >}} curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh cd /path/to/project # 일회용 클론이나 깨끗한 worktree를 권장 prime-agent # 첫 실행 후 /login 으로 프로바이더 선택 {{< /highlight >}}

구독형 프로바이더 외에 ANTHROPIC_API_KEY 같은 API 키, Ollama·vLLM의 OpenAI 호환 서버로 셀프호스팅 모델도 붙일 수 있습니다. 백그라운드 세션 운영에 쓰는 명령 몇 가지:

{{< highlight bash >}} prime-agent agents # 실행 중 · 유휴 · 저장된 세션 브라우저 prime-agent attach # 떠 있는 세션에 다시 붙기 prime-agent send "마이그레이션 검증 다시 해 줘" # 셸에서 에이전트에게 메시지 prime-agent schedule add worker "0 9 * * 1-5" -- "열린 작업 리뷰" prime-agent shutdown # 모든 에이전트와 서비스 정지 {{< /highlight >}}

감을 잡기 좋은 첫 실험은 "병렬 리뷰 + 게이트"입니다. 세션 안에서 이렇게 시켜 봅니다.

{{< highlight python >}} # 커널 안에서 — 리뷰 관점별로 자식 에이전트를 병렬로 띄운다 security = await rlm("인증 흐름을 보안 관점에서 리뷰해 줘", name="sec-reviewer") perf = await rlm("핫패스의 성능 문제를 찾아 줘", name="perf-reviewer") # 자식들의 회신은 agent_message로 도착한다. 목록 확인: children = await rlm.list_subagents() for child in children: print(child.session_name, child.status) # 스스로 5분마다 확인하는 내부 heartbeat도 걸 수 있다 await rlm_heartbeat.create("리뷰 자식들이 끝났는지 확인하고 종합해", interval="5m", label="review-merge") {{< /highlight >}}

작업이 끝나면 /refine을 호출해 보세요. "이 저장소는 테스트 전에 빌드가 필요하다" 같은 교훈이 프롬프트 노트나 스킬로 제안되는 걸 볼 수 있습니다. 마음에 안 들면 스냅숏 ID로 롤백하면 됩니다. 무인 실행이 필요하면 게이트를 걸어 둡니다.

{{< highlight bash >}} prime-agent \ --autonomous \ --autonomous-gate "npm run check" \ # 이 명령이 통과해야 세션이 끝날 수 있다 --autonomous-max-turns 20 \ "요청된 변경을 구현하고 검증까지 마쳐 줘" {{< /highlight >}}

8. 흔한 실수 · 팁

커널은 샌드박스가 아닙니다. 공식 문서가 명시적으로 경고합니다 — Python 커널은 모델이 생성한 코드를 사용자 권한 그대로 실행합니다. 워커 프로세스 분리는 생명주기 격리이지 보안 격리가 아닙니다. 신뢰할 수 없는 저장소·지시·서드파티 스킬은 반드시 외부 샌드박스(컨테이너, 일회용 VM)에서 돌리세요. 특히 "명령 실행 + 메모리 영속화 + 스케줄링"이 한 몸이므로, 프롬프트 인젝션이 성공하면 악성 지시가 기억으로 저장되어 다음 세션까지 살아남을 수 있습니다.
self-improvement는 오염도 축적합니다. /refine이 저장하는 건 "검증된 진리"가 아니라 "그럴듯한 교훈"입니다. 잘못 배운 규칙("이 프로젝트는 테스트를 건너뛰어도 된다")이 메모리에 박제되면 이후 모든 세션이 물려받습니다. 스냅숏 롤백이 있는 이유입니다. refine 결과를 코드 리뷰하듯 주기적으로 list("memory")로 열어 보고, 낡거나 수상한 항목은 지우세요.
비용의 꼬리가 깁니다. 재귀 서브에이전트는 병렬성만큼 과금도 병렬입니다. RLM 계열 연구는 일관되게 긴 꼬리(long-tail) 비용 이상치를 보고합니다 — 계획이 나쁘면 자식이 자식을 부르며 호출 수가 곱으로 늘어납니다. 재귀 깊이 기본값(루트→자식 1단계)을 이유 없이 올리지 말고, goal·autonomous의 토큰 예산을 항상 지정하세요.
게이트 통과 ≠ 작업 성공. 문서 스스로 강조하는 부분입니다. 게이트는 그 게이트가 검사하는 것만 보장하고, 예산 한도 도달은 성공이 아닙니다. "테스트 통과"를 게이트로 걸었다면 테스트가 검증하는 범위까지만 믿으세요. 이 감각은 reward hacking 글에서 다룬 것과 정확히 같은 근육입니다.
아이디어는 하네스와 무관하게 훔칠 수 있습니다. Prime Agent를 안 쓰더라도 ① 대용량 도구 출력을 컨텍스트가 아니라 파일/변수에 두고 요약만 넣기, ② 서브에이전트에게 "필요한 컨텍스트만" 잘라 주기, ③ 세션에서 배운 교훈을 구조화된 파일(AGENTS.md, 스킬)로 남기고 다음 세션에 주입하기는 오늘 여러분의 에이전트에 바로 적용할 수 있는 패턴입니다.

9. 마무리 (TL;DR)

  • 이번 주의 화제: Prime Intellect의 논문 "Prime Agent: A Self-Improving RLM Harness"(arXiv:2608.23552). 모델 훈련 없이 하네스만으로 ARC-AGI-3 RHAE Best@1을 30% → 95.5%(인간 전문가 95.4%)로 올렸다고 보고하며 HN·HF 트렌딩을 점령했습니다.
  • RLM 런타임: 내장 도구는 ipython 하나. 도구 결과를 컨텍스트가 아니라 지속 Python 커널의 변수에 두고, 모델은 코드로 필요한 조각만 봅니다. 커널 상태는 턴과 컴팩션을 넘어 살아남습니다.
  • 서브에이전트 = 함수 호출: rlm("...")이 독립 컨텍스트의 자식 세션을 만들고 접수 핸들만 반환합니다. 결과는 agent_message나 파일로만 도착 — 병렬 위임이 기본형입니다.
  • Continual Harness: 프롬프트·서브에이전트 스펙·스킬·메모리를 상태 H=(ρ,G,K,M)로 두고 에이전트가 CRUD합니다. /refine이 트래젝터리에서 교훈을 뽑아 반영하고, 기반 프롬프트는 불변, 변경은 스냅숏으로 롤백 가능합니다.
  • 장시간 실행: 데몬 상주 워커 + heartbeat + cron 스케줄 + 지속 goal + 예산·게이트 있는 autonomous mode. 터미널을 닫아도 작업은 계속됩니다.
  • 걸러 읽기: 95.5%는 벤더 자체 보고이고 독립 재현 전입니다. self-improvement가 ARC-AGI-3의 취지와 충돌하는지 논쟁 중입니다. 커널은 샌드박스가 아니며, 자기 수정 메모리는 오염도 축적합니다.
  • 큰 그림: "모델은 그대로, 하네스가 학습한다"는 방향은 Agent Skills·메모리 통합·컨텍스트 엔지니어링이 각자 가리키던 지점의 합류입니다. 하네스 엔지니어링이 독립된 분과가 되어 가고 있습니다.
