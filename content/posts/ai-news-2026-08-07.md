# 🔥 오늘의 핵심

Meta가 **Muse Code(beta)**로 터미널 코딩 에이전트 3파전에 뛰어들었다. 자랑거리가 성능 벤치가 아니라 **영속 백그라운드 에이전트 + 이벤트 로그 기반 재시작-안전 실행**이라는 점이 중요하다. 오늘 arXiv에 올라온 두 논문이 같은 곳을 찌른다 — 하나는 **툴을 제대로 고르는지**(Canary Tools), 하나는 **긴 작업을 안 흘리고 끝내는 harness**(OneDayAgent). 즉 오늘의 축은 "장기 실행 신뢰성"이다.

*오늘의 변화 지도 — 모델·논문·툴을 "터미널 코딩 에이전트 × 신뢰성" 한 축으로 묶었다. (출처: 각 항목 원문)*

# 🤖 모델 & 릴리즈 레이더

- **Meta Muse Code 출시 (beta, 8/5~6).** Meta Superintelligence Labs의 첫 전용 코딩 에이전트로, **Muse Spark 1.2** 모델로 구동된다. 큰 레포에서 계획→작성→검증까지 맡는 터미널 에이전트다. 설치는 한 줄(`curl -fsSL https://dev.meta.ai/install.sh | bash`). → **Codex·Claude Code의 정면 경쟁자**가 하나 더 생겼다. 차별점이 흥미로운데, (1) 세션 내내 살아 있는 **영속 백그라운드 에이전트**가 후속 작업을 돌리고 필요할 때만 메인 에이전트에 보고하고, (2) 모든 model call·tool run·승인·편집을 **로컬 이벤트 로그에 append** → 크래시가 나도 멈춘 지점에서 정확히 재개된다. 기본 스킬은 `/plan`(승인 게이트 계획), `/grill`(그 계획을 stress-test), `/goal`. 가격은 표준 티어 **입력 $1.25 / 출력 $4.25 / 캐시 입력 $0.15 (per MTok)**. **주의**: "24시간 테스트에서 tool call 1,000+" 같은 수치는 전부 벤더 발표 기준이고 독립 평가는 아직 없다. ([Meta AI Research 발표](https://research.meta.ai/blog/introducing-muse-code-and-muse-spark-1-2))
- **프런티어 LLM은 조용함.** 어제 다룬 Qwen3.8-Max 외 새 최상위 모델 소식 없음. 이번 주 무게중심은 모델이 아니라 **코딩 에이전트 harness**로 넘어갔다.

# 📚 주목 논문

## 1) Canary Tools — 툴 선택 실패를 "진단"으로 바꾸기

- 저자: Atul Anand, Sourav Chattaraj (arXiv, 2026-08-05)
- arXiv: **2608.04719** (cs.AI)
- 문제: 기존 평가는 "툴을 틀리게 골랐다"까지만 알려주고 **왜 틀렸는지**는 안 알려준다.
- 방법: 에이전트의 **MCP 툴킷에 미끼(canary) 툴을 심어** 실패의 원인 유형을 6종으로 분해한다 — 의미 미끼, 파라미터 함정, 능력 신기루, 전제 무시, 시간 미끼, 세분화 함정. 실패 하나를 **다차원 취약도 프로필**로 바꾸는 셈.
- 결과(검증): 8개 모델·3티어·120태스크·**8,640런**(+ablation 2,880). 모델 간 취약도가 **약 36배** 차이. **Claude Opus 4.8이 가장 낮고 Llama 3.1 8B가 가장 높음**. 취약도는 실제 태스크 실패를 예측(Spearman **−0.34**), 평가자 일치 κ=0.75.
- 🛠 agent-builder 시사점: 툴 선택 문제를 "정답/오답"이 아니라 **원인 유형별로** 봐야 고칠 수 있다. 내 MCP 서버에 미끼 툴을 몇 개 심어두면 "우리 에이전트는 능력 신기루에 약하다" 같은 **회귀 지표**를 뽑을 수 있다.
- 한계: 진단 프레임워크지 학습법은 아님. 미끼 툴 설계에 도메인 지식 필요.
- 링크: <https://arxiv.org/abs/2608.04719>

![Canary Tools 방법 다이어그램: 6종 미끼 툴을 MCP 툴킷에 심어 에이전트를 실행하고 모델별 취약도 프로필을 만든다. 모델 간 약 36배 차이, 취약도와 실패의 상관 Spearman -0.34](/images/ai-news-2026-08-07/canary-flow.svg)
*Canary Tools 핵심 — 미끼 툴 6종으로 "왜 틀렸나"를 프로파일링. (출처: arXiv 2608.04719, 막대는 상대 크기 예시)*

## 2) OneDayAgent — 긴 작업을 안 흘리는 harness

- 저자: Jingsheng Zheng, Xinyuan Fang, Jintian Zhang 외 (arXiv, 2026-08-04)
- arXiv: **2608.05013** (cs.CL)
- 문제 진단: 장기·개방형 작업에서 에이전트는 **목표 표류(goal drift)·상태 유실·컨텍스트 오버플로**로 무너진다.
- 방법: 세 축을 한 harness로 통합 — ① **작업 분해**(비정형 요청 → 경계 있는 서브태스크), ② **실행 메모리 관리**(컨텍스트 제약 안에서 핵심 정보 보존), ③ **검증 & 수정**(최종 산출물 검증·교정). 모델별 튜닝 없이 여러 백엔드 LLM에서 동작.
- 결과(검증): AgentIF-OneDay(104 태스크)에서 **GLM-5.2 백엔드로 0.821** 달성, SOTA. 3개 모델 패밀리 5개 LLM에서 일관된 효과.
- 🛠 agent-builder 시사점: 위 Muse Code의 "이벤트 로그 + 백그라운드 에이전트"와 **같은 설계 문제**를 논문 쪽에서 정리한 것. 장기 에이전트는 프롬프트가 아니라 **분해·메모리·검증 루프**로 잡는다. 특히 ③ 검증/수정 단계는 오늘 바로 붙여볼 만하다.
- 한계: harness 오버헤드 + 벤치 도메인 특화.
- 링크: <https://arxiv.org/abs/2608.05013>

# 🧑‍💻 Codex & Claude Code 실전 팁

오늘 팁은 하나의 주제로 묶었다: **두 툴의 코드 리뷰를 워크플로에 심기.**

### 🟩 Codex — `/review`로 커밋 전·PR·CI 3단 리뷰
- 카테고리: Review / Workflow
- 소스: <https://developers.openai.com/codex/app/review>
- 💡 핵심: Codex의 `/review`는 diff를 읽고 **코드를 건드리지 않고** 우선순위 있는 지적만 돌려준다. 터미널·PR·CI 어디서든 같은 리뷰어를 쓸 수 있다.
- 📝 how-to:
  - 터미널: 세션에서 `/review` 실행 → 현재 diff 리뷰.
  - PR: 코멘트에 `@codex review` 멘션(설정에서 Automatic reviews를 켜면 새 PR마다 자동 리뷰).
  - 팀 규칙은 코드에서 가장 가까운 `AGENTS.md`에 아래 섹션으로:
```markdown
## Code Review Rules
- 공개 API 변경 시 반드시 CHANGELOG 갱신 여부 확인
- 새 의존성 추가는 라이선스 명시 없으면 지적
```
- 🎯 언제: 리뷰 기준을 사람마다 다르게 적용하는 팀, PR 리뷰 병목이 있는 레포.
- ⚠️ 주의: `rust-v0.146.1`(8/5)에서 **사이버-역량 모델의 auto-review 기본값이 더 보수적으로** 바뀌었다 — 최신으로 올려 권한 설명을 확인하자.
- ⭐ 추천: PR 자동 리뷰 + `## Code Review Rules`부터. 규칙을 코드 옆에 두는 게 핵심.

### 🟦 Claude Code — `/code-review`에 effort 레벨 붙이기
- 카테고리: Review / Workflow
- 소스: <https://code.claude.com/docs/en/changelog>
- 💡 핵심: **v2.1.223(8/6)**에서 `/review`가 `/code-review`의 별칭이 되고 **effort 레벨**을 받는다. 가벼운 확인부터 깊은 검토까지 세기를 조절.
- 📝 how-to:
```bash
/code-review           # 표준 리뷰
/code-review ultra     # 클라우드에서 더 깊게 검토
```
- 🎯 언제: 작은 diff는 표준으로 빠르게, 위험한 리팩터링·보안 민감 변경은 `ultra`로.
- ⚠️ 주의: 같은 릴리스에 **Bash 권한 우회 버그 수정**(탭·비가시 유니코드로 승인 프롬프트를 숨기던 문제)과 **worktree 격리 강화**가 포함됐다 — 보안 픽스라 **업그레이드 권장**.
- ⭐ 추천: 위험도에 따라 표준/`ultra`를 나눠 쓰고, 릴리스는 2.1.223 이상으로.

### 🟪 공통 — 장기 실행은 "이벤트 로그 + 검증 루프"로 재시작-안전하게
- 카테고리: Context / Workflow
- 소스: <https://arxiv.org/abs/2608.05013> · <https://research.meta.ai/blog/introducing-muse-code-and-muse-spark-1-2>
- 💡 핵심: Muse Code(이벤트 로그)와 OneDayAgent(실행 메모리+검증/수정)가 같은 답을 낸다 — **모든 tool call·승인·편집을 append-only 로그에 남기고, 끝에 검증/수정 단계를 둔다.**
- 📝 how-to: 긴 에이전트 잡을 짤 때 ① 각 스텝을 JSONL 한 줄로 append(입력·출력·승인 여부), ② 크래시 시 마지막 완료 스텝부터 replay, ③ 종료 전 "산출물이 목표를 만족하나" 검증 서브에이전트를 한 번 태운다.
- 🎯 언제: 수십 스텝 이상, 중간에 죽으면 처음부터 다시 하기 아까운 워크로드.
- ⚠️ 주의: 로그에 비밀값이 그대로 쌓이지 않게 마스킹 필수(Claude Code의 sandbox credential `mode: "mask"` 참고).
- ⭐ 추천: replay-exact 로그부터. 재현 안 되는 장기 잡은 디버깅이 불가능하다.
