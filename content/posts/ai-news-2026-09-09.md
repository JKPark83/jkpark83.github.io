# 🔥 오늘의 핵심

GitHub이 Copilot CLI에 **HydraFusion** 리서치 프리뷰를 열었다. 모델을 하나 고르는 게 아니라, 작업마다 여러 모델의 초안·비평·승격 워크플로를 즉석에서 조립한다. 자체 평가로는 Opus 5 수준 품질을 36~67% 낮은 비용으로 낸다고 한다. "어떤 모델을 쓸까"라는 질문이 "어떤 모델 조합 워크플로를 쓸까"로 바뀌는 신호다. 논문 쪽에서는 기존 오픈웨이트 모델에 디퓨전 가중치를 붙여 품질 손실 없이 최대 3× 빨라지는 **Uno**가 코드와 함께 공개됐다.

# 🤖 모델 & 릴리즈 레이더

- **HydraFusion (GitHub, 리서치 프리뷰)** — Copilot CLI의 `/experimental`에서 모델 고르듯 선택하면, 런타임 플래너가 작업별로 Single / Cascade(품질 게이트) / Critique(다른 계열 모델이 교차 검토) 중 하나를 조립한다. TerminalBench 2.1에서 Opus 5 단독 대비 품질 +4.9%p, 추정 비용 -67%(자체 오프라인 평가). 과금은 실제 사용한 모델들의 표준 단가 합산. 에이전트 빌더에게는 "라우팅·캐스케이드가 플랫폼 기본 기능이 되고 있다"는 신호다. [GitHub 블로그](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/) · [커뮤니티 공지](https://github.com/orgs/community/discussions/206492)
- **MiniCPM5-2B (OpenBMB, 9/7)** — 온디바이스용 2B 밀집 모델. 자체 비교군 평균 53.9로 2B급 오픈소스 최고 성능을 주장하고(자기보고), 코딩·툴 사용·에이전트 과제에 강점을 뒀다. Apache-2.0에 GGUF·MLX·GPTQ 변환본, 그리고 에이전트 SFT 데이터 50만 건(UltraData-SFT-Agent-2609)까지 공개. 로컬 툴-콜링 에이전트의 기본 모델 후보로 테스트해볼 만하다. [Hugging Face](https://huggingface.co/openbmb/MiniCPM5-2B)
- **Claude Code 2.1.265** — `--plugin-dir`가 플러그인 폴더 전체를 로드하고 실행 중 추가·삭제도 반영. 서브에이전트 재개·팀메이트의 프롬프트 캐시 재사용을 깨뜨리던 버그 수정, 툴 결과 디스크 저장 1GB 상한 추가. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

# 📚 주목 논문

## Uno: 디퓨전으로 여는 무손실 LLM 가속

- **저자/소속**: Subham Sekhar Sahoo 외 18인 — IFM(MBZUAI)·Cerebras 등 (지난 이틀 다룬 K2 Horizon 팀의 후속 결과물)
- **arXiv**: [2609.04010](https://arxiv.org/abs/2609.04010) (cs.LG)
- **핵심 기여**: AR 모델의 분포는 그대로 두고, 경량 "디퓨전 가중치"를 추가 학습해 여러 토큰을 병렬로 샘플링한다. Ψ-Spec 샘플러로 **드래프트 모델 없이** 무손실 가속을 달성.
- **결과**: 모든 배치 크기에서 기반 AR 모델 대비 최대 3× 처리량. 8B Uno가 26B DiffusionGemma와 상용 Mercury 2를 에이전트 툴 호출·코딩·롱컨텍스트 벤치마크에서 앞선다고 보고.
- 🛠 **에이전트 빌더 시사점**: 에이전트의 체감 속도는 곧 디코딩 속도다. speculative decoding처럼 드래프트 모델을 따로 관리할 필요 없이, 쓰던 오픈웨이트 모델에 사후 부착이 가능하다는 점이 실무적으로 크다.
- **한계**: 디퓨전 가중치 추가 학습이 필요하고, 공개 체크포인트는 아직 Qwen3-8B·K2-Horizon 0.9B/7B 세 종뿐이다.

## FlowBalance: 검증기로 보정하는 자기개선

- **저자/소속**: Zixun Huang, Kishan Panaganti, Haitao Mi, Leowei Liang (소속은 arXiv 페이지에 미표기)
- **arXiv**: [2609.03241](https://arxiv.org/abs/2609.03241) (cs.LG, cs.AI)
- **핵심 기여**: 모델이 자기 추론 경험으로 학습할 때, 같은 모델이 주는 밀집 가이드는 "틀린 확신"을 강화할 수 있다. FlowBalance는 이 자기 가이드 점수를 **verifier가 준 그룹 어드밴티지로 보정**한다 — 긍정 궤적에서는 유지, 부정 궤적에서는 반전, 판정 불가면 차단.
- **결과**: Qwen3-4B/8B에서 FlowRL 대비 평균 성능·학습 안정성 개선, 응답 길이 붕괴 없이 정답 전략 다양성 유지(AIME24 진단).
- 🛠 **에이전트 빌더 시사점**: 어제 다룬 BCR과 같은 결론의 학습판이다. 에이전트 자기개선 루프(메모리·프롬프트·정책 갱신)는 자기 평가가 아니라 외부 검증 신호로 방향을 정해야 한다.
- **한계**: 수학 추론 중심 실험이라 장기 에이전트 과제로의 일반화는 미검증.

# 🧑‍💻 Codex & Claude Code 실전 팁

## 🟩 Codex — 세션 포크로 병렬 실험

- **분류**: Workflow · [소스: codex-rs/exec CLI 소스](https://github.com/openai/codex/blob/main/codex-rs/exec/src/cli.rs)
- 💡 **핵심**: `codex exec fork`는 기존 세션을 복제해 새 세션으로 갈라낸다. 같은 컨텍스트에서 서로 다른 접근을 병렬로 시도할 수 있다.
- 📝 **방법**:

```bash
# 탐색·설계까지 진행한 세션을 두 갈래로 fork
codex exec fork <SESSION_ID> "접근 A: 미들웨어에서 처리해줘"
codex exec fork <SESSION_ID> "접근 B: DB 레이어에서 처리해줘"
# 세션 id 대신 스레드 이름도 되고, -i 로 이미지 첨부도 가능
```

- 🎯 **언제**: 설계 분기점에서 어느 쪽이 나은지 확신이 없을 때. 컨텍스트 쌓기를 반복하지 않고 분기 지점부터 비교할 수 있다.
- ⚠️ **주의**: fork된 세션 수만큼 토큰이 든다. 분기 전 세션을 `/compact` 등으로 정리해두면 비용이 줄어든다.
- ⭐ **추천도**: ★★★★☆ — git 브랜치를 대화에도 적용하는 감각.

## 🟦 Claude Code — `--plugin-dir`를 플러그인 작업대로

- **분류**: Workflow · [소스: CHANGELOG 2.1.265](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- 💡 **핵심**: 2.1.265부터 `--plugin-dir`에 플러그인 하나가 아니라 **플러그인들이 든 폴더**를 지정할 수 있다. 매니페스트가 있는 하위 폴더가 각각 로드되고, 실행 중 폴더를 추가·삭제해도 반영된다.
- 📝 **방법**:

```bash
# 개발 중인 플러그인들을 한 폴더에 모아두고
claude --plugin-dir ~/dev/my-plugins
# 세션을 켠 채로 새 플러그인 폴더를 만들면 바로 잡힌다
```

- 🎯 **언제**: 마켓플레이스에 올리기 전 여러 플러그인을 동시에 개발·테스트할 때. 재시작 없이 반복 수정이 된다.
- ⚠️ **주의**: 폴더 안 모든 매니페스트가 로드되므로, 실험용 잡동사니 폴더를 지정하면 컨텍스트가 오염된다.
- ⭐ **추천도**: ★★★★☆ — 플러그인 개발 루프가 한 단계 짧아진다.

## 🟪 공통 — 캐스케이드 + 품질 게이트를 직접 구현하기

- **분류**: Workflow · [소스: GitHub HydraFusion 블로그](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)
- 💡 **핵심**: HydraFusion의 비용 절감은 마법이 아니라 패턴이다 — "싼 모델이 먼저 시도 → 검증 가능한 게이트(테스트·린트·스키마 체크) 통과 시 종료 → 실패 시에만 상위 모델로 승격."
- 📝 **방법**: 파이프라인에서 1차 시도를 저가 모델로 돌리고, 게이트는 LLM 판단이 아니라 결정적 검증(테스트 통과 여부 등)으로 둔다. 게이트 실패 시에만 프런티어 모델을 호출하고, 이때 1차 시도의 실패 로그를 함께 넘긴다.
- 🎯 **언제**: 대량 반복 작업(테스트 수정, 마이그레이션, 리뷰 1차 필터)에서 토큰 비용이 병목일 때.
- ⚠️ **주의**: 게이트가 느슨하면 저품질 결과가 그대로 통과한다. 게이트 설계가 모델 선택보다 중요하다.
- ⭐ **추천도**: ★★★★★ — 플랫폼이 검증한 패턴을 자기 스택에 맞게 축소 구현할 가치가 있다.
