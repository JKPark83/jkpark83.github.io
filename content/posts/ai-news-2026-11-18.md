# 📚 주목 논문

## 1. SWE-CoWork — 코딩 에이전트를 "회사원"으로 평가하면

- **저자**: Xinping Lei 외 (TokenWave AI, 전체 저자는 부록 기재)
- **arXiv**: [2611.20218](https://arxiv.org/abs/2611.20218) (cs.SE, 11/15)
- **핵심 기여**: 실제 레포 101개·11개 언어 위에, **책임·지식 범위가 다른 가상 동료 26명이 있는 시뮬레이션 조직**을 얹은 벤치마크. 에이전트는 짧은 핸드오프만 받고 동료와 사내 기록에 흩어진 요구사항을 모아 구현해야 하며, 비공개 테스트로 채점된다.
- **결과**: 11개 모델 평가에서 선두 2개 모델이 F2P 테스트 약 63%를 통과하지만 **과제 완주는 8% 미만**. 요구사항을 전부 미리 줘도 F2P만 +16p 오르고 완주율은 그대로. "완료"라고 보고된 요구사항의 31%가 테스트 실패.
- 🛠 **시사점**: 병목은 코딩이 아니라 **요구사항의 수집·추적·검증**이다. 질문 상대는 93% 맞게 고르면서 정작 답을 64%밖에 못 받아내는 패턴(미룬 질문을 다시 안 물음)은, 에이전트에 "미해결 질문 큐"를 명시적 상태로 들고 있게 해야 한다는 뜻.
- **한계**: 동료가 스크립트된 시뮬레이션이라 실제 사내 커뮤니케이션의 모호함과는 거리가 있다.
- [벤치마크 코드](https://github.com/TokenWave-AI/swe-cowork-bench)

![SWE-CoWork 결과: F2P 테스트 63% 대비 과제 완주 8% 미만, 요구사항 누수 파이프라인](/images/ai-news-2026-11-18/swe-cowork.svg)

*테스트 통과율과 과제 완주율의 격차, 그리고 요구사항이 새는 세 지점. 수치는 논문 초록 기재값.*

## 2. Accelerate Bench — 앱 전체를 빠르게 만드는 에이전트 평가

- **저자**: Bowen Liu 외 (Tencent Hy 팀 중심)
- **arXiv**: [2611.20882](https://arxiv.org/abs/2611.20882) (cs.AI, 11/16)
- **핵심 기여**: 과학 계산·슈퍼컴퓨팅 대회에서 가져온 **CPU 최적화 과제 32개**. 워크로드·정확성 요건·허용 수정 범위만 주고, 어디를 어떻게 최적화할지는 에이전트가 정한다. 공개 테스트로 반복 개발, 별도 검증기로 최종 채점.
- **결과**: 16개 에이전트(모델+하네스)의 Score@1이 25.5%~67.4%. 정확성은 대부분 지켰고 **차이는 스피드업 크기에서 갈렸다**. 통제 재실행에서 같은 소스 코드가 빌드·런타임 설정만으로 0.29x~2.12x를 오갔고, 한 코드 변경의 가치가 다른 변경 여부에 따라 1.01x 또는 6.4x가 됐다.
- 🛠 **시사점**: 최적화 에이전트에게 코드 diff만 시키면 반쪽이다. **빌드 플래그·런타임 설정을 에이전트의 행동 공간에 포함**시키고, 변경 간 상호작용을 보려면 조합 단위로 측정하게 해야 한다.
- **한계**: CPU 과제만 다루고, 32개 규모라 분산이 클 수 있다.

# 🧑‍💻 Codex & Claude Code 실전 팁

**🟦 Claude Code / Workflow** — [Code Mode 문서](https://code.claude.com/docs/en/code-mode) + 2.1.326 변경로그 (클론으로 확인)

- 💡 Code Mode(모델이 툴을 하나씩 호출하는 대신 **JavaScript를 써서 툴을 오케스트레이션**하는 실험 기능)가 2.1.326부터 **agent teams와 동시에 켜진다**. 지금까지는 둘 중 하나를 포기해야 했다.
- 📝 둘 다 실험 기능이라 명시적으로 켜야 한다:

```bash
# agent teams (실험): 환경변수 또는 settings.json의 env에
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
# Code Mode는 문서의 opt-in 절차로 — 이미 켜뒀다면
# teams 세션도 이제 Code Mode로 시작된다
```

- 🎯 팀 리드가 여러 teammate의 결과를 모아 반복 가공하는 세션. 툴 호출 루프가 코드 한 블록으로 줄면 토큰과 왕복이 같이 준다.
- ⚠️ 변경로그 기준으로 이번 주에도 Code Mode 관련 수정이 세 건(스킬의 인라인 `!` 명령 승인, 백그라운드 서브에이전트, 모드의 `$.tool.call`) — 가장자리가 아직 거칠다는 뜻이다.
- ⭐ 비대화형(`-p`)에서는 teammate가 뜨지 않고 일반 서브에이전트로 돌아간다는 점은 그대로다.

**🟩 Codex / Debugging** — [커밋 2df2947](https://github.com/openai/codex/commit/2df29476aef67dd879fbd30ddd635bce25309078) (11/17 머지, 클론으로 확인)

- 💡 `codex login --device-auth`가 **config server 로그인에도 디바이스 코드 플로를 쓴다**. 지금까지는 조직 설정 서버 인증 차례가 오면 브라우저를 억지로 열어서, SSH로 들어간 헤드리스 박스에서 막혔다.
- 📝 브라우저 없는 머신에서:

```bash
codex login --device-auth
# 터미널에 검증 URL과 코드가 뜬다 → 아무 기기 브라우저에서 입력
# config_server.oauth.device_authorization_url 미설정이면 명시적 에러
```

- 🎯 CI 러너, 원격 개발 서버, 컨테이너처럼 브라우저가 없는 곳에서 조직 설정 서버 뒤의 Codex를 쓸 때.
- ⚠️ 서버 쪽 OAuth 설정에 device authorization URL이 선언돼 있어야 한다. 크리덴셜당 로그인은 프로세스 간 1개로 예약된다(동시 로그인 거부 후 재시도).
- ⭐ 어제 소개한 `codex exec --remote`와 묶으면 "중앙 인증 서버 + 헤드리스 클라이언트" 구성이 완성된다.

**🟪 공통 / Eval** — [SWE-CoWork, arXiv 2611.20218](https://arxiv.org/abs/2611.20218)

- 💡 에이전트의 "완료했습니다" 중 31%가 테스트 실패였다. **자기 보고를 완료 신호로 쓰지 말 것.**
- 📝 베낄 패턴: 태스크 시작 시 요구사항을 ID 달린 원장(ledger) 파일로 뽑게 하고, 완료 선언 시 원장 항목별로 "검증 방법 + 실행 결과"를 채우지 못하면 미완료로 처리하는 체크 단계를 루프에 넣는다. 미해결 질문도 같은 원장에 큐로 쌓는다.
- 🎯 멀티턴으로 요구사항이 흘러들어오는 장기 태스크. 특히 사람·다른 에이전트에게 물어봐야 정보가 나오는 환경.
- ⚠️ 원장 자체도 모델이 쓰는 산출물이다 — 원장 누락을 잡으려면 결국 실행 가능한 테스트와 짝지어야 한다.
- ⭐ 원장 파일은 그대로 핸드오프 문서가 되므로 사람 리뷰 비용도 줄어든다.
